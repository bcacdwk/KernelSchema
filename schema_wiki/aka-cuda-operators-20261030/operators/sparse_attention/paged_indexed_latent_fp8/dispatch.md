# paged_indexed_latent_fp8

## 范围

任务范围（共享 Contract 要求实现的有效域，定义见 [root](root.yaml)）：qk_dim ∈ {512,576}，head_count ∈ {8,16,32,64,128}，page_size ∈ {1,32,64,128}，topk_budget ∈ {128,512,1024,2048,2052}，token_count/page_count 按请求域构造。page_size 对全部设计透明：host 将 kv_cache 编码为 page_count*page_size 个物理行的 2-D tensor map，kernel 只按 block_tables 中的物理行 ID gather。caller 的 workspace_buffer 与 multi_ctas_kv_counter_buffer 从未传入扩展，三份设计都不使用。

实现范围（本次固定实现实际进入的路径）：host 入口 candidate/solution.py::Model.forward 只接受 qk_dim ∈ {512,576} 且 head_count ≤ 128，否则 ValueError；out=None 时候选自行分配输出只是候选侧宽松，不属任务域（参考实现与输入构造都要求真实 out）。candidate/launch.cu::s4_tc_forward 做 ABI/dtype/连续性检查后：token_count==0 直接返回（声明域 token_count ≥ 1，此为域外防御）；随后三个互斥分支——

1. token_count ≤ 32 且 head_count ≤ 64 且 topk_budget ≥ 1024 → split8+merge 双 kernel（s4_split_forward，qk_dim 两种取值各有例化）；
2. 否则 qk_dim==576 且 head_count==128 → 2-CTA cluster kernel aka_s4_indexed_h128_d576；
3. 否则 → 单 CTA kernel，按 qk_dim 取 aka_s4_indexed_m64_d576 / aka_s4_indexed_m64_d512。

分支 1 要求 head_count ≤ 64，与分支 2 的 head_count==128 互斥，分派无重叠歧义。split 路径的 fp32 partial/stats 由 host 每次调用经 at::empty 内部分配、同流由第二个 kernel 消费，不占用 caller 的两个 scratch 缓冲。

共同机制骨架（三族 kernel 共用一套 warp 专门化组织，族间差异见完整设计表，精确取值以各 YAML 为准）：512 线程 16 warp，m64 本体（root 的 MAIN step 与 split8_merge 的 ATTENTION step）为七个并发角色——warps0-3 SOFTMAX（从 TMEM 读 S，exp2 域在线 max/sum，按 staged 索引 ballot 掩掉 -1 列并按 active_topk 掩掉超界列，P 以 E4M3 写入 smem 双相缓冲）；warps4-7 CORRECTION（逐 tile 按 acc_scale=exp2((old_max−new_max)·ssl) 重缩放 TMEM 中的 O，末 tile 后归一并写出）；warp8 QK MMA（tcgen05.mma kind::f8f6f4，S 落 TMEM 0-255 列双相）；warp9 INDEX（把 block_tables 行内 ID 以 cp.async 分级进 6 级环，每级 256 个 int32、供两轮 128 行 tile）；warp10 CLC 调度（clusterlaunchcontrol.try_cancel 取消未启动 CTA 并接管其 work item，2 槽响应环 + throttle 限流；各角色工作循环跑 total_work_items+1 轮，读到无效 CLC 响应统一退出）；warp11 PV MMA（O += P×V，落 TMEM 256-511 列）；warps12-15 LOAD（Q 整块 TMA，K/V 按 staged ID 用 TMA gather4 逐 4 行收集，写入 feature*16384+group*512 的特征×行组 swizzle）。cluster 族在同一 warp 范围内把装载组登记为两个独立的环生产者，故为八个角色条目：LOAD_K = warps12-13（Q 整块加 K/K-tail 环，每 warp 8 组、每组 4 主 + 1 tail 的 gather4 multicast，swizzle feature*8192+group*512），LOAD_V = warps14-15（独立 V 环，等自己的 v_empty、只由 PV 释放，swizzle feature*16384+group*512），index_ring 因此由 LOAD_K、LOAD_V、SOFTMAX 三个角色归还；源码里两者是同一条装载工作循环内按 load_warp_rank 分岔的两条分支（kernel_cluster.cu:578、644），各有独立的 stage 游标与 k_empty/v_empty 屏障，该文件头注释仍按一个装载角色称“七个并发角色”；精确成员、环容量与事件以 cluster_m128.yaml 为准。KV tile 固定 128 行；数值路径：S 为 E4M3 输入、FP32 累加的精确点积，softmax 全程 exp2 域，P 量化为 E4M3 后参与 PV MMA——范围控制分族：m64/split8 取 max_scaled = ssl×max − 8，即量化前 256 倍预缩放（kernel_m64.cuh:1161-1163），行 sum 取量化前的 fp32 exp2 值（1420-1440）；cluster 无 −8 项（kernel_cluster.cu:1050-1051），改以 max 滞后规则把 P 上界压到 2^8=256，行 sum 取量化后再反量化的概率质量（详见 cluster_m128 行）。最终 1/sum 与 bmm2_scale 在 CORRECTION（split 路径在 merge kernel）一次收口。

非机制残迹（三族共有的编译期禁用或死代码，正文不建模为动作、不计入 Ledger）：has_sinks=0 的 sink 种子分支（kernel_m64.cuh:751-755 以 256.0f 配平 256 倍预缩放，kernel_cluster.cu:803-808 以 1.0f 配平无预缩放路径）；LOAD 角色 `else if (0)` 的独立 V 装载分支（kernel_m64.cuh:574 起）——m64/split8 的 V 即 K 缓冲本身；cluster 的 v_col 死变量（kernel_cluster.cu:652，实际列坐标见 675）；SOFTMAX 中读入即弃的 tmem_ld_x4（kernel_m64.cuh:805-806、kernel_cluster.cu:850-851）；只初始化而全文无 arrive/wait 的 s_seeded、q_pair_ready、kv_pair_ready、pv_pair_ready 屏障（两族同）与 m64 的 tmem_dealloc_peer（cluster 实际用它做配对 TMEM 退休）；m64 中声明未用的两块 warp-pair 交换区（166912/167936，共 1536 字节，仍计入 191104 字节 smem 预算，cluster 用同名区做跨半区 max/sum 合并）；cluster 的 EPI_O_PAD（191008，480 字节）只保留不用。

已定位来源限制（零 tile 工作项的屏障失配，三族本体同构；受影响设计按来源限制保留，不增删等待、不写成已具备的保证）：非 split 路径的工作项有效性仅判线性 id < total_work_items（kernel_m64.cuh:290-292），active_topk==0（即 n(t)==0）的 token 会以 num_kv_tiles==0 进入本体，此时各角色的等待与到达无法配对——SOFTMAX 的 stats arrive 在逐 tile 循环内、本项 0 次到达（1156-1159），而 CORRECTION 的首个 stats 等待无条件执行并在同一块 arrive o_empty（1591-1603），warp11 只逐 PV tile 等 o_empty、commit o_full（2386、2440），本项完全不执行；warp8 无条件进入首 tile MMA 块、等待本项永不生产的 k_full（1890-1896），而 LOAD 下一工作项的 Q 装载又被 warp8 处理完本项才 commit 的 q_empty 门住（499-501、2148-2150），在 CTA 内形成循环等待；warp8 的排空还等待本项从未生产的 tile cursor+1 的 s_empty（2151-2160）。零行的数值路径确实存在（total_sum==0 → inv_sum=0 → 输出零行，1668-1673），但它来自 sum 取值而非屏障协议配平，在该失配下不可达。kernel_cluster.cu 对应结构同构：无条件首个 stats 等待与 o_empty arrive（1474-1486）、无条件首 tile 块等待 k_full、q_empty 在 MMA 序列后才 commit（2102-2106）、final s_empty 排空指向 last+2（2107-2117）。去向：root 与 cluster_m128 均已在各自 REALIZATION.Forbid 保留该来源限制并列出受影响角色（root 为 CORRECTION/QK/LOAD，cluster_m128 为 CORRECTION/QK/PV/LOAD_K），Reason 各自说明失配点，对应源码行号即本段上文所引；split 路径不适用——s4_split_has_work（cuda_primitives.cuh:278-284）把 split×chunk ≥ tiles 的工作项判为空，六个消费角色用同一谓词一致跳过，空项不进入本体，只有 SCHED 单纯领取。域限制：输入构造恒有 visible = n − nq + j + 1 ≥ 1、count = min(visible, topk) ≥ 1、lens[row] = len(slots) ≥ 1（input.py:11-14、126-134），构造与采样域内 active_topk ≥ 1，零 tile 工作项不可达；仅 Contract 声明的 seq_lens 下界 0 允许该输入。是否登记 kernel issue 由 Supervisor 决定，本目录不写台账。

目录收录范围：下表三份完整设计加一条 D576 tail 局部记录，覆盖上述实现范围的全部六个 kernel 入口（kernel_decl.cuh 声明的 aka_s4_indexed_m64_d512、aka_s4_indexed_m64_d576、aka_s4_split8_d512、aka_s4_split8_d576、aka_s4_indexed_h128_d576、aka_s4_split8_merge），也覆盖 Contract 全域：qk_dim=512 的非 split 域由 root 承担，split 域由 split8_merge 承担；qk_dim=576 的非 split 域按 head_count 分为 cluster_m128（=128）与 root 加 tail 记录（≤64），split 域由 split8_merge 加 tail 记录承担。没有已研究但未完整展开的独立方案。验收事实（ACCEPTANCE.json 的 fixed/domain 段、PRECISION.md）：固定域 10 个 shape、共 20 例（每 shape 2 个记录 seed）与声明域 10 个 shape、20 例全部通过，即 20/20 与 20/20；其中 shape 4（heads=128、dim=576、1024 tokens）走 cluster 分支、由 cluster_m128 承担，两个 seed 的 67108864 个输出元素零失配（0/67108864）；shape 6（heads=64、dim=576、24 tokens、topk=2052）走 split8 加 tail 的组合、由 split8_merge 加本目录的 tail 记录承担，两个 seed 分别有 4 与 6 个元素超差、均在 786 的容许数内。这两条实测结果分别旁证 cluster_m128 的输出覆盖与 split8 加 tail 的组合成立。

正文明细的落点（不影响本目录的选择与记录判断）：M64/M128 MMA 的 TMEM lane-列精确布局（i_desc 69206032、71368720、136314896、138477584）、16x32bx2 与 32x32b 载入模式的行映射，以及 smem P 与 epilogue slot 的 swizzle 位运算精确形式（如 kernel_cluster.cu:1598），都属实现细节，三份设计的三区不依赖其精确位形式。root 与 split8_merge 的 tmem_acc 只按列区分 S 相区与 O 区，行归属由各角色的消费端代码给出。cluster_m128 已把 cta_group::2 M128 累加器的折叠登记为 REALIZATION.Require（每 CTA 持自己 64 行、乘积列折进两个 64-lane 半区），并据此写清两处读取坐标与 epilogue store 坐标：S 区读取 raw_score(n) 时 lane 半区即本成员的两个 KV 半区、列半区由 warp 而非 lane 决定（SOFTMAX 的 compute:score；tmem_score_row_base = warp%4×32、行 = warp%2×32 + lane、n_half = warp%4/2，kernel_cluster.cu:768-772）；O 区按 warp 取 value_acc 的 64 列盒（CORRECTION 的 compute:o_stage；corr_row = (warp%2×32)<<16、o_base_epi = taddr + 256 + box×64 + corr_row，地址中不含 n_half 项，1438-1442、1578），输出的特征半区只由 store 坐标 z = n_half×4 + box 承担，行基 epi_head0 = bid%2×64 + warp%2×32 与 box 的 32 行恰好铺满本 CTA 的 64 head（CORRECTION 的 store:out，1566、1603-1605）。这套行/列分工由该折叠统一解释，与 root 的按 lane 分半区折叠（kernel_m64.cuh:694-698、1534-1538）不同、不可照抄；shape 4 的 67108864 个元素零失配是该映射自洽的实测旁证。D576 tail 的 box（128 字节）宽于逻辑维（64 特征）时的零填充语义已由固定源码注释直接说明（kernel_m64.cu:5-9、kernel_cluster.cu:5-9），不列为未知项。

## 变体与组合

### D576 64 特征 tail（局部）

- 基线：[root](root.yaml) 的 `DESIGN.Tile_pipeline::MAIN.Storage.q_slot`（64×512 E4M3 单槽）与 `kv_ring`（128×512，2 级）、`MAIN.LOAD` 的 `load:q` 与 `load:kv`（REALIZATION 中公布的 32768 / 65536 字节）、`MAIN.QK` 的 `matmul:q(u)@k(n)`（16 段 32 特征乘累加）、`MAIN.Storage.tmem_acc` 的 `raw_score(n)` 列区、`DESIGN.Math_reshape::raw_score`（点积跨全部 qk_dim 特征），以及 gather4/tensor map 与 191104 字节动态 smem 的两条 Require。同一变化并列适用于 [split8_merge](split8_merge.yaml) 的 ATTENTION 本体（实例 aka_s4_split8_d576）：其 `DESIGN.Tile_pipeline::ATTENTION.Storage` 的 `q_slot`（64×512，32768 字节）、`kv_ring`（128×512，2 级，131072 字节）与 `tmem_acc`（含 `raw_score(n)` 列区）与 root 同名同容量，`ATTENTION.LOAD` 的 `load:q` 与 `load:kv`、`ATTENTION.QK` 的 `matmul:q(t)@k(n)`（16 段 32 特征）与 root 同名同构，只是把 root 的工作项索引 `u` 换成本节点的非空项序号 `t`，REALIZATION 同样公布 65536 与 32768 字节；共同差额只写这一次。
- 差异与联动：host 增编 query_tail_map/cache_tail_map 两个 tensor map（基址 data_ptr+512 字节、逻辑维 64 特征、box 128 字节、OOB_FILL_NONE），kernel 签名相应多两个 tensor map 参数；smem 增 Q tail 8192 字节（偏移 191104，与 q_slot 同寿命、由同一 q_empty 释放）与每 kv_ring 级 tail 16384 字节（偏移 199296 + 级×16384，由同一 k_empty 释放），动态 smem 191104→232064，上述 smem Require 的总量随之改变；`load:q` 的 expect_tx 32768→40960（多一次 3-D tail 拷贝），`load:kv` 的 expect_tx 65536→81920（每个 index group 多 1 次 gather4，tail 均分给 4 个 load warp 各 8 组，而非集中 warp0）；`matmul:q(u)@k(n)` 与 `matmul:q(t)@k(n)` 每 tile 追加 4 段 32 特征 tail 乘累加（A=Q tail、B=本级 K tail，累加进同一 `raw_score(n)` 相位列），点积由此覆盖 512+64=576 特征，k_empty 的 commit 相应移到 tail 段之后。两个基线的 `Decomposition.Strategy` 中「qk_dim = 512 … blocks are 64x512 and 128x512」一句（root 的 `DESIGN.Work_schedule::MAIN`、split8_merge 的 `DESIGN.Work_schedule::ATTENTION`）在 d576 例化下随 tail 区改为 576 特征的块：Q 块增一个 64 行×128 字节的 tail 区、每级 KV 块增一个 128 行×128 字节的 tail 区，点积覆盖 512+64，而 `Partition`、`Mapping`、`Worktile_order` 与 `Worktile` 中 `feature: qk_dim` 的表达式不变。不变：角色与成员、index_ring 分级、屏障及其 init 计数、TMEM 分区、工作项映射、SOFTMAX/CORRECTION/PV 与数值路径；PV 仍只读 kv_ring 的前 512 特征，tail 区不参与 V，故 value_dim=512 不受影响。
- 条件与依据：qk_dim==576 且进入 kernel_m64.cuh 本体——单 CTA 分支的 head_count ≤ 64（实例 aka_s4_indexed_m64_d576，S4_ROPE=1/S4_SPLIT=0）或 split 分支（实例 aka_s4_split8_d576，S4_ROPE=1/S4_SPLIT=1）；cluster_m128 自带 tail 机制（Q tail 在 207872、每 K 级 tail 8192 字节起于 216064、expect_tx 40960），不引用本记录。依据为 kernel_m64.cuh 的 S4_ROPE 条件段、kernel_m64.cu 的宏例化与 launch.cu 的 tail map 编码；tail box 的 128 字节宽于 64 特征逻辑维、越界部分零填充由固定源码注释直接说明（kernel_m64.cu:5-9），因此 4 段 tail 乘累加中多出的 64 字节对点积贡献 0，与 Contract“点积跨全部 qk_dim 含 576 的 64 特征尾”一致；dim=576 的各验收 shape（含 shape 6 的 split 加 tail 组合）全部通过，可作旁证。
