## 范围

**任务要求实现的范围**：[root](root.yaml) 保存的共享 Contract 全部有效域——head_count ∈ {8,16,32,64,128}、request_count ≤ 32、query_len[b] ≤ 4096、total_query_tokens ≤ 16384、Σ seq_lens ≤ 1048576、swa_window ≤ index_width ≤ 8320 且为 4 的倍数。host 对每组合法元数据都解析出合法 plan，`dispatch` 对每个 plan 都有承接分支：索引行预取在 index_width > IDXW_MAX(1152) 时回退 shipped 全局路径，元数据并行 burst 在 request_count > META_R_MAX(64) 时回退串行链，packing probe 超时或不可用时回退非 packing tile，无 tcgen05 的构建把全部 tc/packing plan 折叠回 mma.sync tile。任务要求的范围与下述收录范围一致，无缺口子域。

**目录收录范围**：shipped auto 策略的全部生产路径——四份完整设计 [root](root.yaml)、[split_kv](split_kv.yaml)、[tcgen05](tcgen05.yaml)、[tcgen05_packed](tcgen05_packed.yaml) 均已交付，加 host 编排（packing probe 门控与双流隐藏、CUDA graph replay、注册 fastcall）与已实测的参数/局部/组合记录。源码 `kCfgs` 表的 127 个 cfg id 绝大多数是 force-only 的开发/测量臂；源码选择分支不与设计节点一一对应，本目录按机制归口。两项跨设计关系只由目录承载、不写入任一 `when`：dual 隐藏编排使一次 call 按 token range 混合 tcgen05_packed 与替代 mma.sync tile（见“Packing probe 门控与双流隐藏编排”），graph replay 与注册 fastcall 是 host 机制、不改变任一设计的提交语义（见“CUDA graph replay”“注册 fastcall”）。

**冻结十用例的实测落点**（`performance/ncu/result.json` 记录的 certified 采样，L20D、148 SM；与 `make_plan → cta_plan → dispatch` 的规则推演逐项一致）：

- case 0 → `attn_kernel<16,8,32,1,128,1,SPLIT=false,EI=6,DQ=2>`（cfg125），单 launch 直出 → root 家族（非 split），几何与 EI/DQ 差额由下方参数、局部记录承载；
- case 2 → `attn_kernel<16,8,32,1,64,3,SPLIT=false,EI=6,DQ=4>`（cfg124），单 launch 直出 → root 家族；
- case 3、5、6 → `attn_kernel<16,…,SPLIT=true>` + `combine_kernel<16,512|128,CM=1>`（splits=18/10/5）→ split_kv 家族的 hb16 几何；case 5 同时带 DQ=4、case 3/5/6 同时带 EI=6；
- case 4 → `attn_kernel<32,8,32,1,64,3,SPLIT=true,EI=0,DQ=1>` + `combine_kernel<32,512,CM=1>`（splits=37）→ split_kv 的选定实例；
- case 7 → `tc_attn_kernel<…GT=1…QIS2=true,PV2=false>`（cfg90 的 default 臂）→ tcgen05 的选定实例；
- case 1、8 → `tc_attn_kernel<…GT=2…>`，采样中无 probe → tcgen05_packed（gt=2 ≤ 阈值 2.6，按 ratio ≤ gt 恒等式先验免 probe）；
- case 9 → `overlap_probe_t<4096,true,0,false>` + 两次 `tc_attn_kernel<…GT=4…>` → tcgen05_packed 的 dual 路径（probe 与一波 packed 重叠，源码记录的实测 union ratio 1.005 选中 packing 侧）。

**root 选定实例的收录边界**：root 承载 `dispatch` case 2 的真实实例 `attn_kernel<HB=64,WARPS=8,QKS=16,KSPLIT=1,KC=64,STAGES=2,SPLIT=false,QOV=false,MODE=0,EI=0,DQ=1>`（cfg2 = `kCfgs` 的 hb64_w8_q16_ks1_k64_r2，也是 `auto_cfg(H≥64)` 的入口值）。shipped auto 策略下没有找到“cfg2 且 splits=1”的可达路径：`narrow_ring_cfg(64)` 虽然就是 cfg2，但 narrow-ring 重选只对 stages==1 的 plan 且 base_ctas < SM 才进入，而 auto 下唯一的 stages==1 hb64 plan（cfg6）只由 wide-chunk 规则在 T·ceil(H/64) ≥ SM 时产生，此时收缩循环因 here.ctas ≥ SM 立即 break、hb 保持 64 且 base_ctas ≥ SM，两道门互斥；低于一波时 req 保持 cfg2，但 cfg2 的 stages=2 使 narrow-ring 门根本不进入，且 splits=1 时收缩循环因 CTA 数翻倍把 hb 降到 32/16，nchunk_max>4 时得到的是 hb64 的 split 形态（cfg2 + splits>1，属 split 家族、不在 root 的 `when` 内）。故 root 实例的实际承接方式是 forced cfg（`DSV4_CFG=2`），其保留用途是家族基线与阅读入口。root 的 `when` 子域（head_count ≥ 64、单整批提交、无 key split）在 auto 下由 hb64 非 split 家族的其他几何承接：无 tcgen05 构建中一波满的 shape 解析为 cfg6（hb64/kc128/ring1，源码 cov2 的十一点含 T=148/H=64 的边界点全部落 cfg6），tc 构建中同一子域走 tcgen05，低于一波时则收缩 hb 或触发 split 而离开该子域。冻结十用例不含 cfg2 实例（case 0/2 落 hb16 几何）。目录据此不声称 cfg2 承接全部 H≥64 shape；root 的保留理由是家族基线与阅读入口（单 launch、直接输出、无 workspace 依赖），不是 auto 策略的落点，root.yaml 的 `when` 也按设计承担范围写实、不作 selector 声明。

**Host 路径**：`Model.forward` 保持冻结 ABI（`__call__` 直指 forward，实测省 2.7 us/call），只保留三个 assert（kv_layout=='HND' 且 cum_seq_lens_q 非空、三个保留槽为 None）；sinks 为 None 时以空 fp32 tensor 顶替（C++ 侧按 numel>0 判 nullptr），out 为 None 时 `empty_like` 分配，经 workspace 绑定后调用 `ext.run`（tensor ABI）。C++ 端 `dsv4_run` 校验 contiguous/dtype/D=512，再 `make_plan` → dual 处理（隐藏或串行 probe）→ graph replay 缓存 → `dispatch`；plan 所需字节超过 caller workspace 时另分配私有 buffer。workspace 最小 32 MiB（`_MIN_SCRATCH`）、不足或缺失时静默顶替、按对象 identity 缓存校验——这些是四份设计共用的 host 事实，已落入 root.yaml 的 `REALIZATION.Require`（workspace_buffer 条），不晋升 Contract。

**构建与硬件边界**：按 gencode sm_103a → sm_100a（带 `-DDSV4_TCGEN05`，仅 cap ≥ 10）→ 普通 sm_103/sm_100（不带）顺序编译，首个成功者生效。无 tcgen05 的构建中 `make_plan` 把全部 tc/packing plan 折叠回 mma.sync tile 且 dual 门控不触发，因此 tcgen05 与 tcgen05_packed 两份设计只存在于 'a' 后缀目标构建，其 `when` 已注明该前提。现有认证与 GPU 来源证据覆盖 L20D 上的 fixed 十用例与 domain 十采样点；源码注释中的 dv_* job 与百分比是固定来源的设计依据声明，本目录据此说明取舍理由。这些样本与来源声明不能证明四份设计及其完整适用域均已独立验证。来源材料未提供完整的外部 comparator 定义，已知阈值保留在 root.yaml 的 `Golden_reference.Tolerance`（atol/rtol/max_mismatch_fraction 已知，公式与相对误差基准未提供），不影响机制判断与代表选择。

**排除项（开发专用，auto 策略不可达，不作变体记录）**：

- `naive_kernel`：fp32 直接计算对照源，仅经 `ext.naive` 供 experiments/ 交叉验证，源码注明不在生产 dispatch 路径；
- `gather_rate_kernel` 与 `dsv4_gather_rate` 绑定：gather 机制测速仪器（cp.async/bulk/gather4 对比），非数值路径；
- 错误数值测量臂（wrong numerics by construction，仅归因计时）：mma.sync MS_* 家族（cfg 93–108）与 tc MODE/POL/CP 削减臂（cfg 15–20、32–35、42–47、51–54、68–81、88），各只删除一个 producer 或一个 wait；EI/DQ 的 A/B 对照臂（cfg 109–122）为 force-only，其 shipped 形态由下方 EI 与 DQ 记录承载；
- 数值正确但 force-only 的开发/对照配置（auto 不选，不单独交付，机制差额并入相应参数/局部记录）：serial-ring bisection（cfg 14）、packing 对照（cfg 28/29）、ring 几何变体（cfg 30/31/55/56/57）、策略史与机制臂（cfg 13、36–41、48/49、59–67、89、91/92）、16-warp mma.sync（cfg 82–87）、KSPLIT=2 与 kc192 几何（cfg 9–12、21–27）；其中 PR paired tile（cfg 61/62）按下条单列；
- `dsv4_run_ptr` 指针 ABI 绑定：dev harness 入口，pool 行数恒为 0 故 TMA gather4 loader 拒跑，生产路径为 tensor ABI 的 `ext.run`。

**已研究但未完整展开的独立方案**（不交付完整 schema，不改称参数或局部变化，不占完整名额）：

- fused_combine（融合 split-KV 归并，`g_fuse_combine` 默认 0）：`attn_kernel` 的 SPLIT epilogue 不把 partials 交给 `combine_kernel`，改为每输出行一个 tagged 64-bit 计数器（`(FUSE_TAG<<32)|count`；免 epoch：tag 不符即重装 count=1，末位到达者清零本行），每行恰收 S 个 producer 到达（空 split 也到达），最后到达的 CTA 把 `CombSmem` 覆叠在已死的 KV ring 上、复用 `combine_row(CM=1)` 归并该行；无 CTA 自旋等待他 CTA，rows>grid 亦安全，release/acquire 由 `__threadfence` 对保证。grid-wide barrier 首版实测 +538%/+286% 废弃；per-row 版源码注记实测 +88%/+40% 仍慢于双 kernel，且 `run_cfg` 拒绝 DQ>1（到达数变 S·DQ）与 fp16 partial 组合。未交付理由：默认关闭、实测更差，生产只交付双 kernel 形态。
- Paired cluster tile（PR，cfg 61/62，force-only）：`cta_group::2` 的 cluster 双 CTA 合成一个逻辑 M=128 tile——各持 64 行、phase-1 各供 CK/2 键、phase-2 各持 D/2 列（KV ring 分 P1/P2 两区，1/4 chunk 重叠存两份以满足共享 B descriptor），rank0 leader 经 multicast commit 发射全部 MMA；softmax 的行 max/行和经 `exch_s` 共享内存与命名 barrier 跨 warp 交换（替代单 CTA 的 `shfl_xor(.,16)`）；launch 走 `cudaLaunchKernelEx` + clusterDim(2,1,1)，配 `tc_alloc2/tc_dealloc2` 与 cluster sync。实测每 chunk -12.78% 但未晋升 auto 策略：要求 gt = 1、nb 偶数，与 MBA（cp.async 完成无法到达 peer barrier）和 SX2（`static_assert` 互斥）不相容。未交付理由：非 shipped 策略，其主协作差异相对 tcgen05 主线属待验证区域。

**已识别机制与实测依据的最终去处**：host 事实（32 MiB workspace 下限与静默顶替、identity 缓存校验、三个 assert 缩减集、sinks 空 tensor 顶替、`--use_fast_math` 与 gencode 链）落在四份 YAML 的 `Schedule.Strategy` 与 `REALIZATION.Require`（root 与 split_kv 另含 `workspace_buffer` 条，两份 tc 设计不读写 workspace 故无此条）；split 段几何、环槽原点 `(c-chunk_lo)%3`、越过 chunk_hi 的空组提交与两条零权重守卫落在 split_kv.yaml 的 `Tile_pipeline::ATTENTION`/`::COMBINE` 与 `REALIZATION.Require`；union 构建、成员掩码、TMEM 列预算、smem 预算与 gather4 落在两份 tc 设计的 `Tile_pipeline` 与 `REALIZATION`；跨设计 host 编排落在下方三条组合记录；已研究未展开的完整机制（fused_combine、PR paired tile）在本节诚实登记；其余几何、发射与归并差额在“变体与组合”逐条直链基线对象。上述去处覆盖已识别的全部机制与实测依据。

固定源码的 bar_land 与 tmem_base_s/packed union 控制区重叠仍未修复，沿源实现缺陷分流保留；schema 的完整抽象设计不要求复制坏地址，也不据此声称 GPU 正确性已验证。

## 完整设计

当前完整集合共 4 份（含 root），在 10 份上限内；每份承载 `candidate/dsv4_kernel.cu` 的一个真实模板实例，从共享 Contract 的输入贯通到全部输出。四份的三个 Design 区域全部本地定义，引用图中没有任何 `from` 边，唯一共享内容是 root 保存的 Contract；精确参数、`when` 与修订号以各 YAML 为准。

| 设计 | 具体机制与保留理由 | 关系 |
| --- | --- | --- |
| [root](root.yaml) | mma.sync 非 split 单 kernel flash-decoding tile，实例 `attn_kernel<64,8,16,1,64,2,SPLIT=false>`（`dispatch` case 2）。一 CTA 承担 (token, HB=64 头块)，grid=T·nb 单次 launch：槽索引先全部读入再发射 cp.async 16B，把双 pool 的 1 KiB KV 行聚集进两级 XOR-swizzle ring，下一 chunk 的 gather 与当前 chunk 的 tensor-core 工作重叠；phase-1 S=Q·Kᵀ 用 warp 发射的 mma.sync m16n8k16 bf16/fp32 累加，前 QKS=16 个 k-step 的 A fragment 常驻寄存器；块级 online softmax（warp shuffle + smax/psum 共享归约，m_run/l_run/scale_s）把 P 写成 bf16 共享 tile；phase-2 O=O·scale+P·V（ldmx4t 转置读 V）。epilogue 加 sink 项、除 l、乘 bmm2，一次 bf16 收窄后经 staging 直写 out。保留理由：家族的基线端到端方案——单 launch、直接输出、无 workspace 依赖；ring 聚集、寄存器 A fragment 与块级 online softmax 是全部 mma.sync 记录的公共骨架，HB=64 与 tcgen05 tile 的 M=64 行块对齐，便于比较。 | 阅读入口，保存唯一 Contract；三区全部本地定义，不引用其他节点 |

## 变体与组合

本节每条记录直接定位至少一个当前完整 YAML 及其中已有对象（以数学符号、step、role、存储或唯一 rewrite 名称定位），多基线并列时说明各自对象对应与必要区别，共同差额只写一次；记录不改变任一基线的参数或 `when`，也不构成 patch 应用顺序，实施时仍以各 YAML 的完整有效 Design 为准。源码锚均指冻结修订的 `candidate/dsv4_kernel.cu`。

### Tile 几何与 plan 选择（参数）

- 基线：[root](root.yaml) 的 `DESIGN.Work_schedule::MAIN.Decomposition`（`Strategy` 的 kc=64、`Partition.head_block` 的 tile=64）、`Mapping.Worker_count`、`DESIGN.Tile_pipeline::MAIN.Storage`（`kv_ring` 的 depth=2、`q_fragments` 的 k_step=16、`query_tile`/`p_tile` 的行数与列宽）与 `DESIGN.Math_reshape` 的 Rewrite “Fixed key slots, validity mask and chunk range”（kc、chunk_count）；同一 `attn_kernel` tile 主体也是 [split_kv](split_kv.yaml) 的共同基线，其对应对象为 `DESIGN.Tile_pipeline::ATTENTION.Storage` 的 `kv_ring`（depth=3）与 `q_fragments`（k_step=32）、`Role.MAIN.Using_verb` 的 `await:kv_landed`/`await:chunk_release`/`load:kv`，以及同名 Rewrite 的 kc、chunk_count。
- 差异与联动：取值域 HB∈{16,32,64}（root 取 64，即 `Partition.head_block` 的 tile 与 `query_tile`/`p_tile`/`o_acc` 的行数）、WARPS=8（16-warp 仅见 force-only cfg 82–87）、KC∈{64,128,192}（联动 Math 的 chunk_count=ceil_div(N,kc) 与 `kv_ring` 每槽字节，尾块掩码与 validity 语义不变）、STAGES∈{1,2,3}（即 `kv_ring` 的 depth，联动预取深度与 `await:kv_landed`/`chunk_release` 的槽证书范围）、QKS∈{0,8,16,32}（即 `q_fragments` 缓存的 k-step 数；QKS=32 时 A fragment 全缓存且 query 可能改占 ring slot 0，即 split_kv 的 `kv_ring` 视图 `query_block` 与 `partial_block` 同落 slot 0）、KSPLIT∈{1,2}（root 取 1；auto 从不取 2，KSPLIT=2 仅 cfg 9–12 force-only）。STAGES 的两点联动已落入 split_kv 基线：其一，split 路径的环槽原点随段移动为 `(c-chunk_lo)%STAGES` 而非 root 的 `c%STAGES`，即 split_kv 的 `kv_ring` 视图 `kv_rows(c)` 与 `validity` 视图 `v(c)` 都写作 `(c-chunk_lo)%3`；其二，预热与循环中“越过 chunk_hi 提交空组”在 STAGES≥3 时承重——`cp.async.wait_group` 计的是组数而非字节，丢弃空 commit 会使段末最后一次真实 gather 未退休即被读取，对应 split_kv 的 `load:kv` describe（“past chunk_hi commits empty”）与 `REALIZATION.Require` 的 cp.async 组计数条及其 “wait_group counts groups, not bytes” 依据（STAGES=2 时等待深度为 `wait_group 0`，空组不承重）。QTILE/QPRE 由 QKS==32、KC≤128 与 STAGES/预算联动（QOV 把“STAGES==1 才有 query tile”的推断换成共享内存预算问题，实测 +0.27/-0.30/+0.32% 即无收益，未 shipped）；smem 预算由 `smem_bytes` 与 `run_cfg` 的 launch TORCH_CHECK 兜底。auto 选择策略链（force_cfg≤0）：`auto_cfg(H)`（≥64→cfg2、≥32→cfg4、其余→cfg8）；tc 门（`tc_eligible`：H≥64 且 T·ceil(H/64)≥SM → cfg90）与 packing 门（H<64 且 `pack_gt`>1 且替代 mma plan splits==1）；wide-chunk 规则（T·ceil(H/hb)≥SM → cfg6/7/8 的 kc128/ring1）；hb 收缩循环（CTA 数增加才收缩、平局取 splits 少者、达一波即停）；splits 规则（nchunk_max>4 且 base<SM 才分裂、向一波逼近不过一波；base≥4 且不足半波时允许每 split ≥64 键的亚 chunk 细分；硬上限 SPLIT_CAP=COMB_SMAX=128，再受 workspace 字节 cap）；narrow-ring 重选（先过 stages==1 与 base_ctas < SM 两道外层门，再过 solo/ring_fills/chunk_pads 三门，结果不得损失 CTA 数，`g_pad_rule=1`；hb64 的 cfg6 因 base_ctas ≥ SM 永不进入，故 `narrow_ring_cfg(64)`=cfg2 在 auto 下不生效）；DQ 门（见下条）。
- 条件与依据：同机制其他取值，联动明确（预算与 launch 检查）；测量依据见源码注释（split 规则 dv_282e9b387555、wide-chunk dv_1a5c0e64cb5b、narrowring/splitfine 实验注记）；冻结 case 0（hb16/kc128/ring1）、case 2/3/5（hb16/kc64/ring3）、case 4（hb32/kc64/ring3）、case 6（hb16/kc128/ring1）为本记录的实测取值点，root 的 hb64/kc64/ring2 为家族基线取值点。其中 HB 取 16/32 的取值点超出基线 `when`（head_count ≥ 64、64 头块）的范围，本记录据实说明其条件：适用输入为 Contract 域内的 head_count ∈ {8,16,32}，或 head_count ≥ 64 但 auto 的 hb 收缩循环把 head block 降到 32/16 的 shape；联动是头块划分改为 ceil_div(head_count, HB)、`Worker_count` 与 `query_tile`/`p_tile`/`o_acc`/`softmax_ctrl` 的行数按 HB 缩放，而 Math 的逐头公式、ring 纪律与 epilogue 归一化不变；依据为 `hb_for_H`/收缩循环的解析规则与上述冻结用例的实测落点。

### EI 早发重排（局部）

- 基线：[root](root.yaml) 的 `DESIGN.Tile_pipeline::MAIN.Role.MAIN.Using_verb` 中 `compute:meta`（cu_q→seq_lens→topk 串行链）、`compute:init_state`、`compute:q_fragments`、`load:kv`（槽索引来源）、`load:query`，以及 `Storage.softmax_ctrl` 的 warp_max/warp_sum 区域（root 实例 EI=0）；同一 `attn_kernel` prologue 主体也是 [split_kv](split_kv.yaml) 的共同基线，其对应对象为 `DESIGN.Tile_pipeline::ATTENTION.Role.MAIN.Using_verb` 的同名 `compute:meta`/`compute:q_fragments`/`load:kv`/`load:query` 与 `Storage.softmax_ctrl` 的 `warp_max(c)`/`warp_sum(c)` 视图——冻结 case 3/5/6 的 SPLIT=true 实例实测携带 EI=6。
- 差异与联动：EI_IDXPRE 把整 token 索引行（≤IDXW_MAX=1152）以独立 load 预取入寄存器并发布到共享 slab（新增 IDXPRE_BYTES=4624 B 共享内存，计入 `smem_bytes` 预算），`load:kv` 的 chunk 槽查询改读共享；EI_METAPAR 把 cu_q/seq_lens/topk（request_count ≤ META_R_MAX=64）一轮并行 stage 进 `softmax_ctrl` 的 warp_max/warp_sum slab（两 slab 在首 chunk 前不被 phase-1 写入），替代 R+2 次串行冷 round trip；超限各自回退 shipped 全局/串行路径。输出位同（只重排独立内存操作，`Pipe` 的动作与事件集合不变）；`compute:init_state` 与 `q_fragments` 的先后关系保持，barrier 发布点不变。EI_QHOIST（query cp.async 提升）实测 +0.048 us 无效，未 shipped。
- 条件与依据：shipped 于 cfg5/cfg8（`dispatch` case 5/8 与 DQ 臂 cfg123–126 同时携带 EI_IDXPRE|EI_METAPAR），其余几何保持 EI=0；实测 -0.652 us mean cold device time、7/8 点超 0.40 us bar（dv_fa70e0b6f320）。

### DQ 输出 D 分区（局部）

- 基线：[root](root.yaml) 的 `DESIGN.Work_schedule::MAIN.Decomposition.Partition`（token/head_block）与 `Mapping.Worker_count`、`Step.MAIN.Target.Single_tile.out_block`、`DESIGN.Tile_pipeline::MAIN.Role.MAIN.Using_verb` 的 `matmul:pv`（每 warp 64 输出列）、`compute:out_stage`、`store:out` 与 `Storage.o_acc`（root 实例 DQ=1）；同一 tile 主体也是 [split_kv](split_kv.yaml) 的共同基线，其对应对象为 `DESIGN.Work_schedule::ATTENTION.Decomposition.Partition`（token/key_split/head_block）与 `Mapping.Worker_count`、`DESIGN.Tile_pipeline::ATTENTION.Role.MAIN.Using_verb` 的 `matmul:pv`/`compute:partial_stage`/`store:partial`、`Storage.o_acc` 与 `DESIGN.Math_reshape` 的 Rewrite “Per-segment partial row in scratch”——冻结 case 5 实测 SPLIT=true 且 DQ=4。
- 差异与联动：DQ∈{2,4} 个 CTA 共担同一 (token, head-block, key split)，各持 out 的 D/DQ 不相交列切片：`Partition` 增加 dq 轴且 `Worker_count` 乘 DQ，dq 为 grid 最快变化维（使重复的 gather 命中 L2）；phase-1 与 gather 重复 DQ 份，`matmul:pv` 只算本切片（每 warp 输出列数变为 D/(WARPS·DQ)），`o_acc` 相应缩小，`compute:out_stage` 与 `store:out` 只写本切片（staging 按绝对列 swizzle，切片是行内连续段），无 chunk 的防御性零行分支（`c0 >= c1`，只在 splits > chunk_count 时可达；in-domain N ≥ 1 使 root 的 splits=1 路径不触发，而选中行全为无效槽的零行按 Math 的同一 inv 路径产生、没有独立分支）同样按 D/DQ 列切片写；切片不相交故无跨 CTA 归并、无数学变化（位同）。与 split 组合时：SPLIT epilogue 只写本切片的 partial 列，m/l 由每个 DQ CTA 写相同值，combine 读整行归并；`run_cfg` 拒绝 DQ>1 与 fused combine 组合（每行到达数变为 S·DQ）。
- 条件与依据：门 ctas·DQ ≤ SM（一波内才收益，超波实测 +4.2~17.3 us 损失）；仅 hb16 的 cfg5/cfg8 几何有定价，hb32/hb64 未定价故保持 DQ=1；shipped（`g_dq_part=1`，解析到 cfg123–126 并同时携带 EI）；冻结 case 0 落 DQ2、case 2 与 case 5 落 DQ4；测量 dv_995250614ffb（一波内 dq2 5/5、dq4 4/4 点胜，超波全败）。

### Combine 形态与 partial 格式（参数）

- 基线：[split_kv](split_kv.yaml) 的 `DESIGN.Work_schedule::COMBINE`（`Decomposition.Strategy` 的一 CTA 一输出行、`Mapping.Worker_count`、`Schedule.Strategy` 的 512 线程 = 4 个 128 线程段组）、`DESIGN.Tile_pipeline::COMBINE.Role.MAIN.Using_verb` 的 `load:prefetch`/`compute:merge`/`compute:group_sum`/`store:out`、`Storage` 的 `split_stats`/`prefetch_vectors`/`group_scratch`/`group_vectors`/`merge_acc`、`DESIGN.Math_reshape` 的 Rewrite “Per-segment partial row in scratch” 与 “Cross-segment merge, sink fold and output”，以及 `REALIZATION.Require` 中挂在 `DESIGN.Work_schedule.Flow.Handoff` 下的 partial 几何条与“保留两条零权重守卫”条、挂在 `DESIGN.Tile_pipeline::COMBINE` 下的线程与预取规模条，和挂在 `DESIGN.Work_schedule.Flow.Launch` 下的两次 stream-ordered launch 条。
- 差异与联动：`combine_kernel` 的模板参数（CT、CM、PB、COPT）、partial 行几何（pstride/ml_off/pfp16，host 侧 `set_partial_geom` 解析）与 launch 方式。CT∈{128,512}：split_kv 取 512（G=CT/128=4 段组），`launch_combine` 按 combine grid（p.T·nb·HB）不足一波取 512、否则取 128，一体服务两形态；CT=128 时 G=1，`group_scratch`/`group_vectors` 退化为单组、`compute:group_sum` 的跨组和成为恒等，其余动作与数学不变，冻结 case 3/4/5 实测 512、case 6 实测 128。CM∈{0,1}：两种形式都对零权重段的向量 load 做地址重定向（`combine_row` 的四深跨步循环与尾循环无条件写 `(w != 0) ? row0 + s*sstep : row0`），CM=1 另加两点——把前 PRE=4 个 split 的 float4 在 m/l 往返之前无条件预取（即 split_kv 的 `load:prefetch` 与 `prefetch_vectors`），并以值判据 `(w != 0 ? w*v : 0)` 丢弃零权重值；split_kv 取 CM=1，其 `REALIZATION.Require` 的“保留两条零权重守卫”条与 `compute:merge` 的 describe（“value dropped where w = 0 … w = 0 reads segment 0”）即该形式的准确表述。COPT bit0 NB（去三个 barrier，位同：`compute:row_max`/`compute:weight`/`compute:normaliser` 的发布改由每线程自行归约，动作集合不变）、bit1 PD（预取深度 4→8，重结合），默认 0；取 PD 时 `prefetch_vectors` 的 quad 深度加倍，增加每线程保留值；源码的 64 寄存器讨论是 launch-bound 预算，非实测分配值，冻结 case 4 的同一 COMBINE 实例记录为 48。PB=fp16 预归一 partial（pstride 减半、权重改 u_s=w_s·l_s，数学为重结合等价）实测无 fixed-suite 收益且数值裕度更小，未 shipped（`g_partial_fp16=0`）；split_kv 的 partial 几何条已按“一个 kernel 实例同时服务 f32 与 fp16 两种格式、shipped f32 几何由 host 固定”记录。PDL programmatic dependent launch（`griddepcontrol.launch_dependents/wait`）实测 +2.1~11.5% 被拒（`g_pdl=0`），即 split_kv 的 `Flow.Launch` 条“两次普通 stream-ordered launch、PDL 关闭”。`combine_skip`/`combine_empty` 为定价臂（wrong numerics）。

### tc Tile 几何与次序（参数）

- 基线：[tcgen05](tcgen05.yaml) 与 [tcgen05_packed](tcgen05_packed.yaml) 的同名对象——`DESIGN.Work_schedule::MAIN.Decomposition.Strategy`（两者的 kc = 64；packed 侧另含 gt 的三条解析约束）、`DESIGN.Tile_pipeline::MAIN.Storage` 的 `kv_ring.shape` 的 stage=2 与 `p_tile.depth=2`（两份相同；kv_ring 为 depth=1 的整块分配，kv_rows(c) 选 stage 区域）、`tmem_alloc` 的 `s_lo(c)`/`s_hi(c)` 列视图、`DESIGN.Math_reshape` 的 Rewrite “Split scores, lazy maximum, BF16 fork”（tcgen05）与 “Split scores, member masking, lazy maximum”（tcgen05_packed）中的 RD = 1、`DESIGN.Work_schedule::MAIN.Schedule.Worktile_order` 的 descending 方向，以及各自 `REALIZATION.Require` 的 TMEM 列与 smem 预算条。两份基线的这些对象取值一一对应，故共同差额只写一次。
- 差异与联动：模板参数 CK、STG、RD、QP、SPIN、REV、PREFETCH。shipped 为 CK=64、STG=2、RD=1、QP=true、REV=true、PREFETCH=true。其他取值与联动：RD=2（Rewrite 中 lazy hold 阈值由 1 log2 单位变 2，pf 上界由 2 变 4，`compute:rescale` 触发更少但概率动态范围更大；与 RD=1 同噪声，取扰动更小者）；SPIN（以轮询 wait 替代挂起，即反转 `REALIZATION.Require` 的 “Suspending mbarrier.try_wait.parity waits (no polled substitution)” 条；实测 +2.4~3.0% 拒）；REV=false（`Worktile_order` 的 direction 由 descending 改 ascending，longest-job-first 失效，正序对照）；CK=32 配 STG=3/4（联动 `Decomposition.Strategy` 的 kc、`kv_ring.shape.stage`、`p_tile`/`validity` 的 depth 与每 stage 字节、`tmem_alloc` 的 `s_lo(c)`/`s_hi(c)` 列宽；pre-QIS 实测 +29%，且 packed 侧 `union_set` 工作集挤占一级 ring）；CK=128 配 STG=1（64 KiB `query_tile` 使宽度深度不可兼得，`kv_ring.shape.stage` 降为 1 则 `load:kv` 与 `matmul:qk` 的重叠消失）；PREFETCH=false（串行 ring 纪律，bisection 辅助；LOADER `Pipe` 的 `load:kv(0)` 预热与 `if(c+1 < chunk_count)` 续填退化为循环内同步 load）。QP 把 query tile 的 cp.async 提到 union 构建之前，即两份 tc 设计的 `Pipe` 中 `load:query` 位于 `compute:union`（packed 侧）或 `acquire:tmem`（tcgen05 侧）之前（实测四点同向 -1.4~-4.1 us 晋升）。总联动为 `tc_smem_bytes` 预算与 TMEM 列预算（score buffer ≤128 列，QIS2 下 256 列，与 O 的 256 列恰满 512），即两份 YAML `REALIZATION.Require` 中 “Exactly 512 TMEM columns …” 条的取值依据；cfg 注释块（TC_CFG_RD1/RD2/QP/SPIN/REV/K32/K128S1）逐条列出测量 job。
- 条件与依据：同机制其他取值，联动明确（预算与 launcher 的 smem/TMEM TORCH_CHECK）；packed 侧的额外事实是 gt 与 kc 无关、由 `Decomposition.Strategy` 单独解析，故 CK/STG 取值不改变 `Partition.group` 的 tile=gt。

### tc loader 与发射机制替代（局部）

- 基线：[tcgen05](tcgen05.yaml) 的 `DESIGN.Tile_pipeline::MAIN.Role.LOADER`（`load:kv` 的 gather4 与 expect_tx、`signal:kv_valid`、`await:query_landed`）、`Role.SOFTMAX` 的 `matmul:qk`（两个发射者写 `s_lo(c)`/`s_hi(c)`）、`matmul:pv`、`compute:row_max` 与 `Storage.score_regs`、`await:kv_valid` 的 “not the KV rows' landing”，以及 `REALIZATION.Require` 的 gather4 条与 mbarrier 条；[tcgen05_packed](tcgen05_packed.yaml) 的对应同名对象（其 `await:kv_valid` 表述为 “not the union rows' landing”）。
- 差异与联动：shipped 组合为 TMA gather4 loader（每 loader 线程 expect_tx 512B 于 bar_land，跨 pool 四行组解析式回退 cp.async 16B）+ MBA（cp.async/gather4 完成直接到达 barrier，loader 组不再阻塞于自身拷贝，bar_land 由发射者等待；即 `await:kv_valid` 只发布 validity/membership 字节而非 KV 行落地这一分工）+ QIS（phase-1 从 softmax warp1 lane0 发射，发射 stall 不再拖住 loader 组）+ QIS2（phase-1 k-sweep 16/16 拆给 tid32/tid64、双 score buffer、bar_qk 计数 2，softmax 相加两半——重结合，经 frozen 参考 0-mismatch 门控；对应 `matmul:qk` 的两个发射者、`tmem_alloc` 的 `s_lo(c)`/`s_hi(c)` 两个视图与 `compute:row_max` 把两个 32 列切片加进 `score_regs` 的 `sc(c)`）+ SX2（16x32bx2 读使 32 lane 全部工作，行归约加一次 `shfl_xor(.,16)`）+ IS（union 构建前整组索引行 cp.async 入共享）。替代项与实测：单发射者（QIS2 前形态，QIS2 实测 window -4.7~-7.6%）；PV2（phase-2 双发射，-0.04% 不 binding、位同、未 shipped）；LA（phase-1 前瞻，+3.3~+5.6% 拒）；ET（早传输，+41~49% 拒）；DB（确定性 union 构建，+12~15% 拒，且 gt ≤ 4）；IP（索引 batch32，被 TMA 路径取代）；EG（早 gather，被 MBA/ET 次序史取代）；cp.async 16B loader（TMA 前形态，gather4 实测 1.5x 机制速率且 SWIZZLE_128B 与 tc_sw128 字节级同布局）。IS 项的基线归属须单列：其索引行 cp.async staging 整段位于 `if (GT > 1)` 的 union 构建内（`dsv4_kernel.cu:2206` 起的分支，staging 在 `2250-2277`），在 gt = 1 下完全惰性，tcgen05.yaml 也未登记 `load:index_rows` 动作，故 IS 只锚 [tcgen05_packed](tcgen05_packed.yaml) 的 `Role.SOFTMAX`/`Role.LOADER` 的 `load:index_rows`、两份 `Pipe` 中 `load:index_rows` 位于 `compute:union` 之前、`Storage.kv_ring` 的 `index_rows` 视图（stage 区域 [1,2)）与 `Storage.union_set`；同族的一层前探（每个 item 的索引 load 提前一个 item 发射）同样只属于 packed 侧，记在 tcgen05_packed.yaml 的 `REALIZATION.Prefer`。同记录其余项（TMA gather4、MBA、QIS、QIS2、SX2）同时适用两份 tc 设计。
- 条件与依据：各项均有同 job A/B 与 frozen 参考 0-mismatch 记录（issue 数 dv_ad76ee325a26、QIS2 dv_8eb1e52d1836、gather4 dv_73879cb02fba/dv_1ddc6f85e90f、QIS dv_d989aa6c55a6、MBA dv_771e57eea482、SX2 dv_c25b7f27928d、IS dv_bb1188a3acda）；替代围绕 loader 与发射 step，ring 协议、softmax 主体与输出形成仍成立，故记局部而非整体。

### Packing probe 门控与双流隐藏编排（组合）

- 基线：[root](root.yaml) 的 `DESIGN.Work_schedule::MAIN.Flow.Launch`（单次提交）与 `Mapping.Worker_count`——probe 拒绝时它就是被选的替代 tile（`make_plan(allow_tc=false)` 且 splits==1 的 alt plan，其几何经“Tile 几何与 plan 选择”记录取值）；wave 侧与当选侧基线为 [tcgen05_packed](tcgen05_packed.yaml) 的 `DESIGN.Work_schedule::MAIN.Decomposition`（`Partition.group` 的 tile=gt、`Strategy` 中 gt 的三条解析约束，含 gt·index_width ≤ 2560 即 TCUCAP）、`Mapping.Worker_count` = ceil_div(total_query_tokens, gt)、`Flow.Launch`（单次提交）与 `DESIGN.Math_reshape` 的 Rewrite “Deduplicated group union and chunk range”（`union_key`/`member_mask` 的 nkeys 上界）——gt 对 union 的静态界定正是“对任意重复率均正确”的依据。
- 差异与联动：dual plan（gt>2.6）的 packing 收益取决于索引内容重复率，元数据不可判：`overlap_probe_t`（8 CTA×1024 线程、4096 槽 64-bit 静态共享 hash、采样 8 组、ratio=union·gt/Σ|K_g|，跨请求的组不投票）把每组 ratio 写入 mapped pinned buffer，host 有界自旋取均值（≤TCPACK_THRESH=2.6 取 packed，否则取 alt；超时或不可用回退 alt）。shipped 隐藏编排（`g_probe_hide=1`）：probe fork 到非阻塞侧流，caller 流先跑前 (SM−8)·gt 个 token 的一波 packed plan（`pack_gt` 已静态界定 union，故对任意重复率均正确），自旋与该波重叠，随后剩余 token 以当选 plan 在侧流并发执行（避免排在 wave 最慢 CTA 之后），event 汇合回 caller 流；token range 经 `Params.tok0/tok1/tile0` 传入且 p.T 保持绝对值，range launch 与 combine 互斥（两侧 splits=1 才准入）。门：ngroups ≥ 2·(SM−8)、侧流/事件/pinned 可用；任一失败同 call 回退串行 probe 路径。gt ≤ 2.6 时按 ratio ≤ gt 恒等式先验免 probe 直接 pack（省约 12.5 us 串行设备时间）且可进 CUDA graph。probe 变体 1–4（宽表/read-first/warp-match）实测未晋升（隐藏编排已使 probe 设备时间离开关键路径）。
- 条件与依据：一次 call 内按 token range 混合两种设计，该关系由本记录承载、不写入任一侧 `when`；阈值再拟合 dv_16505642dd31/dv_3428c0743d61；隐藏编排实测 -1.4~-6.0%（fixed 9 -6.0%、fixed 8 -2.5%、fixed 1 -1.4%、domain 7 -2.9%；dv_39ce3203ffbf、dv_ffd5c81b3511），queue 首版 +15.9 us 被拒改侧流（dv_d434a5429d6a）；冻结 case 9 为该路径的实测样本。

- 基线：[root](root.yaml) 的 `DESIGN.Work_schedule::MAIN.Flow.Launch`（`dispatch` 产出的 kernel 序列与参数）与 `Schedule.Strategy` 的 host 校验链；同等适用于 [split_kv](split_kv.yaml) 的 `DESIGN.Work_schedule.Flow.Launch`（ATTENTION 与 COMBINE 两次提交一并入图）与 [tcgen05](tcgen05.yaml)、[tcgen05_packed](tcgen05_packed.yaml) 的 `Flow.Launch`（单次提交；packed 侧限非 dual 的直 pack 分支）。

- 条件与依据：gate 与测量见 graph 注释块（job88：splits>1 点 median -9.43%/-2.17 us、splits=1 点 -2.70%/-0.62 us、91 us 重对照 -0.28%；splits>1-only 门实测 +1.07% 被拒，全 eligible shape 保留；dv_c9aeb838eb45）。

### 注册 fastcall（组合）

- 基线：与 graph replay 同一 forward→`ext.run`→`dsv4_run` host 调用路径，即四份设计各自的缩减校验集——[root](root.yaml)、[tcgen05](tcgen05.yaml)、[tcgen05_packed](tcgen05_packed.yaml) 的 `DESIGN.Work_schedule::MAIN.Schedule.Strategy` 与 [split_kv](split_kv.yaml) 的 `DESIGN.Work_schedule::ATTENTION.Schedule.Strategy`（其 `COMBINE.Schedule.Strategy` 只承接已解析的 grid 与线程数）；workspace 绑定条见 root 与 split_kv 的 `REALIZATION.Require` 中 `CONTRACT.Algorithm_requirement::workspace_buffer` 条，两份 tc 设计不读写 workspace 故无此条。
- 差异与联动：`dsv4_register` 把 guards/plan/workspace/launch 一次解析进 4 槽 round-robin registry（generation 令牌防槽复用），`dsv4_replay(handle)` 以单整数重发同一 launch；Python 侧仅当十个 tensor 参数与注册对象同一（`is`）、两 scale 相等、kv_layout 为 HND 且三个可选槽为 None，且模型持有各对象引用（防地址回收）才走此路，任何差异落回完整校验路径；dual shape 每次 replay 重跑 probe（答案是当前索引内容的属性）；每槽有独立 GraphState，私有 workspace 由槽持有以防悬垂。提交语义与直接路径等价，不缓存数值、不改变任一设计的 `Flow`。
- 条件与依据：默认关闭（`DSV4_FASTCALL=1` 才启用），实测无窗口收益（geomean 61.12→61.29 us，dv_a325f709b8f8）；保留记录以免后续把 replay 语义误读为生产路径，不进入任何设计的提交语义。
