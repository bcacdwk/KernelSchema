# mla_absorbed_fp8

## 范围

- 共同 Contract 与任务域：[root.yaml](root.yaml) 保存唯一共享 Contract，覆盖完整 ABI 与声明动态域——uniform-4D 与 varlen-3D 两种调用布局、heads ∈ {12,16,32,64,96,128}、page_size ∈ {1,32,64,128}、可选 sinks 与自然对数 lse、固定 bottom-right causal 且无滑窗。范围较窄的设计不改变共同输入域、参考入口、误差与硬件要求。metadata 的 `validation.status = native_unsupported`（8 passed / 6 native_unsupported）说的是原生生产对照 `problem/solution.py`（FlashInfer TRTLLM 入口）的支持子域，该对照不在提取范围，也不缩小本 Contract 或设计域。
- 目录收录范围：3 份完整设计（[root](root.yaml)、[split_kv](split_kv.yaml)、[simt](simt.yaml)，三区均本地定义、无整区 `from`）与 5 条锚定这些设计已有对象的正式记录。默认构建（HILO=1、MLA_TARGET_CTAS=1024）下三份设计的 `when` 合计覆盖整个 Contract 域：设备 capability ∈ {(10,0),(10,1),(10,3)} 或 `MLA_FORCE_IMPL=v1` 时按 host split 策略二分（splits=1 走 root，splits>1 走 split_kv），其余设备或 `MLA_FORCE_IMPL=v0` 走 simt，而 simt 的 `when` 覆盖整个 Contract 域。HILO 与 MLA_TARGET_CTAS 都只在 v1 路径生效，simt 与两者无关：HILO=0 构建没有独立完整设计，只影响 root 与 split_kv，按下文（参数）记录处理；非默认 MLA_TARGET_CTAS 下解析为 splits>1 的调用在机制上仍是 split_kv，却落在其 `when` 已核对的保守子域之外，同样按下文（参数）记录处理，root 不隐式兜底。
- 实现范围：固定实现是 `candidate/` 七个文件编译成的单翻译单元（`launch.cu` 包含 `kernel_simt.cuh` 与 `dispatch.cuh`，后者级联 `combine.cuh` → `kernel_tcgen.cuh` → `cuda_primitives.cuh`），host 入口为 `solution.py:Model.forward`。host 侧的连续性/dtype/几何检查、page_size 为 2 的幂、几何导出与 `qk_scale = bmm1_scale·log2(e)` 折算是 Contract 与 host 层事实，已在 root.yaml 的 Contract 与 Math 层定义，三份设计共用，不由单个节点重新决定。
- 验收边界：固定验收证据是 SM103（`sm_count` 148）上的采样——固定域 10 shapes 与声明域 10 shapes 各 2 seeds，`status = passed_sampled`，材料自述不代表全域零误差；只覆盖默认 v1 路径。simt（v0）没有 GPU 验收记录，其源码自述为 reference-grade，用于校验 ABI、几何、masking、sinks、LSE 与存储语义。数值判定沿用冻结 checker，其组合公式未随材料提供，这一来源缺口只影响外部测试通过边界，不阻塞设计提取。环境记录只含 host/gpu_uuid/torch/cuda/sm_count/cpu_affinity 与 nvcc，未记录任何 `MLA_*` 开关，图缓存与快速调用是否生效只能按源码默认值（开启）理解。
- 来源限制：`cuda_primitives.cuh` L44 的注释 "180224 + 1024" 已过期，`SMEM_TOTAL` 实际是 8192 + 73728 + 73728 + 32768 = 188416（与 `dispatch.cuh` 发射处一致）；`kernel_tcgen.cuh` L700 与 `dispatch.cuh` L27 提到的 `mla_api.cu` 是历史文件名，实际为本次的 `launch.cu`；`kernel_tcgen.cuh` L22 对 partial_o 的 "fp32, unnormalized" 注释只描述 `MLA_PART_FP16=0` 臂，默认交付是按自身 dsum 归一的 fp16 部分和（kPartWords=256）。两条设备路径还原 (batch, index) 时都按 `cum_q == nullptr` 分支并以 uniform_q 作除数（`kernel_simt.cuh` 的 `map_row`、`kernel_tcgen.cuh` 的 `resolve_item`），而 3D packed query 的 host uniform_q 为 0；Contract 的 Token_layout 要求 varlen 布局必带 cum_seq_lens_q，故这是域外调用才触发的共有脆弱点，不改变任何设计在声明域内的定义。诊断/消融参数（pv_mode、skip_qk、skip_softmax、stub_loads、dbg_*）在 kernel 体内被 constexpr 固定为生产值，host `do_launch` 也只传这组固定值，不构成设计变体。
- 已研究但未完整展开的独立方案：`MLA_PERSIST=1/2` 的持久工作列表布局。一波至多 `kSplitWaveTarget=148` 个 CTA 以 `w = blockIdx.x + k·gridDim.x` 轮转遍历全部 `n_work = items·splits` 个工作索引，死索引 `continue` 而非退休 CTA；level 2 把 512 列 TMEM 分配提升为每 CTA 一次（walk 前 alloc+relinquish、walk 后统一 dealloc），level 1 每工作索引分配、walk 后单独 relinquish；`balanced_tpc` 每 CTA 只算一次（tpc_cta）。它改变工作归属与跨工作资源寿命，若交付须为完整设计而非 root 的局部变化。固定源码默认 `MLA_PERSIST=0`，host 与环境没有启用路径，验收证据只覆盖非持久布局，因此本次不展开完整 schema，仅在此登记。
- 已知范围边界：root 与 split_kv 的 `when` 以 host split 策略的解析结果划分，已核对的保守写法是「workspace 缺失或无元素，或 items ≥ 148」→ splits=1（root），否则 splits>1（split_kv）。还有一种解析为 splits=1 的情形未逐字写入 root 的 `when`：workspace 存在但按 `rows_cap·(kPartWords+2)·items` 折算后连一份部分和都放不下（by_ws=0），`dispatch.cuh` 末尾的钳制把 splits 压回 1。该情形执行的是同一份 root 设计，属保守子域留下的边界，不是缺失的第四份设计。

## 完整设计

选定 3 份完整设计（含 root，低于 10 份上限），各自从 Contract 输入贯通到全部输出，机制互不替代；三区全部本地定义、不使用整区 `from`，因此没有跨节点共享区需要一并展开阅读。精确参数、`when` 与修订号以各 YAML 为准。

| [root](root.yaml) | 单 kernel tcgen05 attention（`mla_attention_hilo` = `mla_v1_attention_body<HILO=true>`，splits=1）：一个 CTA（256 线程、188416 B 动态 SMEM、全部 512 列 TMEM，独占资源使每 SM 恰一个常驻 worker）承担一个 128 行 (token,head) work item 的整段可见 KV；每 64-key tile 由单 lane 发 tcgen05.mma(kind::f8f6f4) 的 18 个 32-dim k-step 把 S 累入 TMEM[448,512)，两个四-warp 列组各自读回全部 64 列并独立归约同一行最大，因此 rescale 决策与因子天然一致、dsum 只在 epilogue 跨组合并一次；懒惰 log2 域 rescale（阈值 2.75、headroom 2.0，命中时读-乘-写回 TMEM O）；P 量化为 E4M3 hi/lo 双字（prescale 64）；PV 把 dims[0,448) 累入 TMEM O、dims[448,512) 借用 S 列作临时累加并每 tile 抽干到寄存器；KV 双缓冲 cp.async 预取＋块表 LDG；epilogue 直接完成 inv、sink 的 log 域合并、base_lse 与 bf16 out / 自然对数 lse 的终写（valid_rows > 32 时经释放的 Q+KV SMEM 分级整行拷出）。保留理由：目标硬件的默认路径，最完整体现主机制，单 kernel 直写两个输出最便于理解与比较 | 阅读入口，保存唯一 Contract；验收采样中 items ≥ 148 的 shape 2/3/7/8（items = 384/2306/512/386）走本设计 |

## 变体与组合

### P 的 lo 残差字关闭（参数）

- 基线：[root](root.yaml) 的 `DESIGN.Math_reshape` rewrite「Probability as an E4M3 word plus a residual」（p_hi/p_lo、p_scale=64）、`DESIGN.Tile_pipeline::MAIN.Storage.smem_p`（view p_hi(t)/p_lo(t)）与 `matmul:p@v_main`、`matmul:p@v_tail`；[split_kv](split_kv.yaml) 的同名 rewrite 与 `DESIGN.Tile_pipeline::ATTENTION.Storage.smem_p`、`matmul:p@v_main`、`matmul:p@v_tail`。这组对象在两节点同名同义，唯一区别是 split_kv 的双缓冲槽索引按窗口计为 (t - t_begin)%2，故差额只写一次。
- 差异与联动：`MLA_HILO=0`（进程级环境开关，`_resolve_impl` 读取一次，只经 v1 host 入口下传）使 host 改发 `mla_attention_standard` = `mla_v1_attention_body<HILO=false>`：softmax 不再生成 lo 残差字（kLoF16 的 f16x2 差值链与 rn3 半路两条实现都不执行），`smem_p` 的 plo 半区不写（SMEM_TOTAL 仍按每 slot 两个字预留，容量不变，lo 描述子退回 hi 描述子），三个 PV chunk（`p@v_main` 的 dims[0,256) 与 [256,448) 两段、`p@v_tail`）在每个 32-key step 各少发一次 lo 字 MMA，每 tile 的 PV 产品由 12 次降为 6 次。数值上 P 由 E4M3 hi/lo 双字补偿退化为单 E4M3：「Probability as an E4M3 word plus a residual」的 e、p_hi 定义与 p_scale=64 不变，其 Ledger 中「概率 tile 翻倍、value 产品翻倍」的 Cost 消失（实际写入与产品各减半，预留不变），代价是权重误差由 fp16 级退化为单 E4M3 级。「Value accumulation with the tail regrouped」中 o_un 与 tail_tile 各自的 Σ_u p_lo·v_row 项随之消失（两节点同名 rewrite 各两处），累加递推、tail 重组、工作分配、事件与输出形成不变；split_kv 的部分和发布与跨 split 归并在结构上同样不变，因为 pnrm = 1/dsum、part_ms/part_ds 与归并权重只依赖 dsum 与 m_shift，不依赖 lo 字。
- 条件与依据：设计成立条件是权重仍用 E4M3 表示且 SMEM 描述子布局不变；host 按 `_HILO` 选入口，GraphKey 含 hilo，两种入口不会互相重放。本记录只适用于 v1 两节点：v0 host 路由不传 hilo，simt 全程 FP32 自然域、无 P 量化，与 HILO 无关。实验覆盖只有 HILO=1（默认构建），HILO=0 无实测记录。

### host 图捕获重放与快速调用缓存（局部）

- 基线：[root](root.yaml) 的 `DESIGN.Work_schedule.Flow.Launch`（单次提交 `[{step: [MAIN]}]`）；[split_kv](split_kv.yaml) 的 `DESIGN.Work_schedule.Flow.Launch`（`[{step: [ATTENTION]}, {step: [COMBINE], start_after: [ATTENTION.kernel_done]}]`）。同一机制把 split_kv 的两段提交整体录制为一个图，重放时设备重新读取 seq_lens/block_tables 与发布字，两基线的差额只写一次。
- 差异与联动：同一调用重复出现且 GraphKey 命中时，提交由 kernel launch 改为 `cudaGraphLaunch` 重放已录制的同一 launch 序列。GraphKey 是九个指针（q/kv/block_tables/seq_lens/cum_q/out/lse/sinks/workspace）＋ workspace_floats ＋全部几何标量（rows/items/heads/uniform_q/batch/page_shift/tstride/rows_max/max_seq_len/split_request）＋ hilo ＋ qk_scale/bmm2 ＋ stream。设备工作、部分和布局与 per-item split 粒度决策都不因此改变：重放时设备重新读取 seq_lens/block_tables 与发布字，`balanced_tpc` 与每 item 粒度在设备端重算，所以键内指针与几何不变时数值可变。必要联动与保证：录制在私有非阻塞捕获流、ThreadLocal 模式、单锁保护下进行，`cudaFuncSetAttribute` 由 `mla_v1_prewarm_attrs` 预热到录制之外；16 槽 LRU、被逐出的 exec 有意泄漏、总捕获预算 64、同键第 2 次命中才录制；任何非图发射清空 active token/exec 并释放 C 端 fastcall 缓存，因此 Python `_FAST`（id 九元组＋标量 → token/result/强引用参数）与 C 端 METH_FASTCALL（参数按对象同一性、float/long 按值比较）只能重放最近一次完整调用实际选中的图；`MLA_STREAM_CACHE=1`（默认）时重放固定在录制流，不随调用者当前流切换。
- 条件与依据：仅 v1 路径，simt 不经过图缓存与 token 机制；`MLA_GRAPH/MLA_STREAM_CACHE/MLA_PYFAST/MLA_FASTCALL/MLA_CFAST` 可分别关闭。分类依据是 DOC4「提交及完成事件以实际计算为准，录图只记录执行结构」以及提交方式变化按设计划分原则处理，故记为局部而非新节点。实验覆盖：验收环境记录未列出 `MLA_*` 开关，只能按默认开启理解。

### 编译期调优旋钮族（参数）

- 基线：[root](root.yaml) 的 `DESIGN.Tile_pipeline::MAIN.MAIN`（role 的动作契约与 Pipe 顺序）、`Storage` 各项与 Math_reshape 的常量符号；[split_kv](split_kv.yaml) 共用同一主体（`DESIGN.Tile_pipeline::ATTENTION.MAIN` 与 `Storage`），并额外拥有 split/combine 侧旋钮，其锚点是 `DESIGN.Work_schedule::ATTENTION.Mapping.Strategy` 中 splits 表达式的常量（1024 = `MLA_TARGET_CTAS` 默认值经负 split_request 到达、148 = `MLA_SPLIT_CAP`、296 = 2·kSplitWaveTarget、64 = kMaxTilesPerCta、9/32 的分子分母来自 `MLA_SPLIT_TRAFFIC_FP16=1` 的 kPartWords·4 臂）、Math_reshape 的「Window decomposition of the key range」（`MLA_BALANCED_SPLITS`、`MLA_TPC_WALK`）、`DESIGN.Tile_pipeline::COMBINE` 的 `load:spec_stats`（`MLA_COMB_SPEC`）与 `compute:gather_stats` 读发布字（`MLA_COMB_PUBNS`），以及 `REALIZATION.Prefer` 的合并批宽（`MLA_COMB_UNROLL`/`MLA_COMB_UNROLL_WIDE`）。simt 没有这一族旋钮：`kernel_simt.cuh` 不含任何 `#ifndef` 编译期开关。
- 差异与联动：交付构建全部取默认值。已计入 root 正文的默认开启臂：`MLA_PV_EARLY=2`（p@v_tail 先发、bar_pv2 本 tile 内等待，bar_pv 推迟到下一 tile QK 发射后）、`MLA_EPI_STAGE=1` 与 `MLA_EPI_STAGE_MINROWS=32`（valid_rows > 32 的分级整行拷出与行目的地址发布）、`MLA_SM_OWNFIRST=1`（本组半区优先的两次 S 读回）、`MLA_UNIFORM_BRANCH=1`（由 warp 首行——query-major 下最被 mask 的一行——导出 t_fast 即该 warp 第一个带 mask 的 tile，钳到 [t_begin,t_end]；t_fast 之前的 tile 走无 mask 专门化、其余走 mask 专门化，以一次 warp 一致的寄存器比较取代 nval/nloc/full/warp_nval 谓词链，置 0 时 t_fast=t_begin 使全部 tile 走 mask 专门化而结果不变。rescale 分支的 `__any_sync` warp 投票与此无关：它无条件存在，且已作为实现条件记在 root.yaml 的 ### combine slab 家族（参数）

- 基线：[split_kv](split_kv.yaml) 的 `DESIGN.Work_schedule::COMBINE.Decomposition.Strategy`（Single 512-dim slab：一个 split 组、128 线程、线程 dt 拥有 dims [4·dt, 4·dt+4)）、`Mapping.Worker_count = items*rows_cap`、`Partition.row.size = rows_cap`、`DESIGN.Tile_pipeline::COMBINE.Storage.s_acc`（本配置闲置）与 `compute:merged_dims` 的四批宽（同 `REALIZATION.Prefer` 登记的合并批宽）。
- 差异与联动：发射器以 base = items·rows_cap 起步，在 slabs < 512/kCombMinDims = 16 且 base·slabs < kCombTargetCtas = 1776 时把 slabs 倍增，再按 DIMS = 512/slabs 选实例 `mla_combine_d512<512,1>` … `mla_combine_d32<32,16>`。差异是 slab 宽度与 split 组数的互换：grid 第三维 slabs 不再恒为 1（grid = (items, rows_cap, slabs)），NSG = 512/DIMS = slabs，而 NSG·(DIMS/4) 恒为 128 线程，故每 CTA 的线程数与 `Partition.row`（size = rows_cap）不变；`Mapping.Worker_count` 由 items*rows_cap 变为 items*rows_cap*slabs，`Decomposition.Strategy` 的「单个 512 维 slab」改为每 CTA 负责 DIMS = 512/slabs 维、线程 dt 拥有 slab·DIMS + 4·dt 起的四维；NSG > 1 时 `s_acc` 不再闲置，多出一次跨组共享内存归并（组 0 在 barrier 后求和）；合并展开系数 UR 在 NSG = 1 取 kCombUnrollWide、否则 kCombUnroll（默认同为 4）。DIMS = 16 与 8 的实例因 slabs ≤ 16 不可达。归并数学、部分和布局与跨 kernel 可见性依据都不变，`compute:merged_dims` 仍按每线程四维端到端归并。
- 条件与依据：只在 splits > 1 路径出现，接口与部分和布局不变，因此是同一 COMBINE 机制的参数变化而非新设计。按 `input.py` 的 128 MiB workspace 与默认 `MLA_TARGET_CTAS` 推得，采样 shape 0/1/6 → d512（base = 2048/4096/2048）、shape 5 → d256（base = 1024，slabs = 2）、shape 4/9 → d32（base = 64/12，slabs = 16）；已选实例 `mla_combine_d512`（slabs = 1）只是家族代表，采样计时为整算子口径。

### CTA 目标改变 splits 上界（参数）

- 基线：[split_kv](split_kv.yaml) 的 `DESIGN.Work_schedule::ATTENTION.Mapping.Strategy` 中 splits 表达式里取 1024 的 by_ctas 项（默认 `MLA_TARGET_CTAS=1024`，host 以负 split_request 送达），以及 `DESIGN.Work_schedule::ATTENTION.Partition.split`（range [2, 148]）。
- 差异与联动：`MLA_TARGET_CTAS` 是进程级环境开关（`_resolve_impl` 读取一次，非整数值回落 1024），只替换 by_ctas 一项，因此只改变 splits 的上界。同一 min 之后还有 kSplitCap = 148 的钳制，故取值 ≥ 148 与默认 1024 等效；取值 ≤ 0 时 host 传 split_request = 0，by_ctas 退回 kDefaultCtaTarget = 148，同样等效；只有 1 ≤ target < 148 会真正收紧上界。收紧后 `Schedule.Strategy` 的 by_grid 与 by_ws 仍是硬界，⌈tiles_cap/64⌉ 的临界路径下限可以把结果抬回，末尾仍由 max(1, …) 托底；设备端「Window decomposition of the key range」按新的 splits 重新解析 tpc、s_item、chunk 与窗口，`Partition.split` 的 [2,148] 范围、部分和布局与 COMBINE 侧都不变。若解析结果为 splits = 1，调用离开本设计而执行 root（root 的 `when` 以 host split 策略的解析结果为准，与「范围」登记的 by_ws = 0 边界同类）。
- 条件与依据：GraphKey 含 split_request，不同 CTA 目标的调用不会互相重放图。split_kv 的 `when` 保守限定「默认 1024 CTA 目标」，因此非默认取值下解析为 splits ≥ 2 的调用在机制上仍由本设计承担，却落在其已核对的保守子域之外，root 不隐式兜底，这一留白随交付保留。验收环境记录未列出任何 `MLA_*` 开关，只有默认 1024 的采样覆盖，非默认取值无实测记录。
