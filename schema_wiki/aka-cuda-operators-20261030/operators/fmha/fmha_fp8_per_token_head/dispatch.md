# fmha_fp8_per_token_head

## 范围

**共同 Contract 与任务域。** 任务域以 root.yaml 保存的唯一 Contract 为准（shape_range.json：batch 1–32、q_len 1–8192、kv_len 1–262144、total_q≤16384、Σkv≤1048576、head_dim∈{64,128,256}、page∈{16,32,64,128}、HND/NHD，六组 (heads,kv_heads,head_dim)=(4,1,128)/(8,1,256)/(8,2,64)/(12,12,64)/(32,8,128)/(32,32,128)）。distribution 是生成器轴，声明值为 normal/tiny/zero/balanced。

**目录实际收录。** 固定实现是 AKA arm-b 统一候选（SELECTION.json：selected_arm=b、line l20d/b/l20d-15、fixed 与 domain full_pass；L20D/sm_103、CUDA 13.0、torch 2.9）。solution.py 只做 ABI 绑定、编译与 host 路由，设备数值在拼进同一 extension 的 fmha.cu + fmha_tc.cu + fmha_pre.cu 中。默认环境（冻结调用 `Model.forward`，全部默认开关生效）下实际可进入的实现分两族：own mma.sync 族（fmha.cu 的 `fmha_main`，加 host 规划 n_split>1 时的 `fmha_combine` / `fmha_combine_w`）与 merged tcgen05 prefill 族（fmha_pre.cu 的 `fa_prefill_tc` / `fa_prefill_w8`，单 launch、n_split≡1、无 workspace）。本目录收录三份完整设计（含 root 共 3 份，上限 10 份）：own 族由 root（prefill 带）与 decode_split_kv（decode/MTP 带）分担，merged 族由 tcgen05_prefill 承担；其余配置按“变体与组合”的正式记录表达，不以开关或选择公式留在任何 YAML 中。

**host 路由主干**（solution.py 的 `_pick`/`_plan`，fmha.cu 的 `launch_plan`/`launch_one`，fmha_pre.cu 的 `launch_mypre`；rows = max_seqlen_q * g）：

- rows < {64:64, 128:64, 256:32} → decode/MTP 带：cfg 3/4/5 = `fmha_main<64,16,32,1,4>` / `<128,16,16,1,4>` / `<256,16,16,1,2>`。
- rows ≥ 该阈值 → own prefill 带：cfg 9/8/2 = `fmha_main<64,128,64,4,1>` / `<128,128,32,4,1>` / `<256,64,32,4,1>`；cfg8 即 root。
- 同带内若 rows > 64 且 peer_ctas = (ceil_div(total_q,128)+batch)*heads ≥ _PF_MIN_CTAS={64:36,128:128,256:64}，或 d128 短 KV 放宽（msk≤512∧peer_ctas≥12、msk≤1024∧peer_ctas≥96）→ merged tcgen05：cfg 30/31/32；d128 且 msk<6144 改 cfg39（同 kernel 的 f16-QK 形）。阈值是同 job A/B 的拟合，未测间隙保守留给 own 路径。
- merged 侧再由 `launch_mypre` 选驱动与 kernel：grid_orig=(ceil_div(total_q,128)+batch)*heads、slots=(D==256?1:2)*sms、diag=2*msq≥msk、band=diag∧slots≤grid_orig≤2*slots；fold = band ∧ D≠64 ∧ 非 D128-band，persist = !fold ∧ (D128-band ∨ 4*grid_orig ≥ 5*slots)，persist 的 grid=min(grid_orig,slots)。kernel：D128 的 fold ∨ band → `fa_prefill_w8<128,64,true,true>`（默认构建下 D128 fold 不可达，实为 band-persist）；D64 persist → `fa_prefill_w8<64,96,true,true>`、D64 static → `fa_prefill_tc<64,64,PIPE=true,NM=false>`；D128 其余 → `fa_prefill_tc<128,64,PIPE=true,NM=true>`（NM_STATIC 默认开）并按 msk≥6144 决定 F8Q；D256 → `fa_prefill_tc<256,64,PIPE=false,NM=persist>`。默认构建下 tc fold 实际只有 D256 band 可达。
- 非 merged 路径的 n_split 规划（base、target=6*sms、chunk floor 256 与 FILL 减半、wave cap、ws cap）已在 root.yaml 的 Work_schedule 定清，由 root 与 decode_split_kv 两个 own 族节点共用同一 host 规则，各自的 bm 与 _SPLIT_RES 驻留值不同；tcgen05_prefill 走 merged，host 直接强制 n_split=1（单 launch、无 partial、无 workspace），不进入该规划、也没有 bm/_SPLIT_RES 取值参与。d256 STARVE 条款不在 root.yaml 内（root 的 `when` 限定 head_dim=128），它只在 d==256 ∧ rows<_PREFILL_MIN_ROWS[256] 时生效，即只作用于 cfg5，记录在“变体与组合”的 decode tile 参数族与数值替换门条目。
- own prefill 带内 base = ceil_div(total_q*g,BM)*kv_heads 与 sms=148 的关系分两种情形。**rows>64**：crossover 门运行，own 侧要求 peer_ctas 低于 {64:36,128:128,256:64}，而 BM=128 时 base ≤ peer_ctas、BM=64（d256）时 base ≤ 2*peer_ctas，故 base<148、base≥sms 的快捷项不生效，n_split 由 ceil_div(max_seqlen_k,chunk) 与 wave/ws 上限决定，短 KV（max_seqlen_k ≤ chunk）即得 1。**rows==64**：门的条件是 rows > _PF_ROWS=64，故这一边界完全不受 peer_ctas 约束，快捷项在声明域内可达——见证 (32,32,128)/B=32/每请求 q_len=64、kv_len=4096：rows=64 → cfg8，tiles_est=ceil(2048/128)=16、base=16*32=512 ≥ 148 → n_split=1（直写、不提交 COMBINE）；同形若走非快捷分支则为 n_split=min(ceil(888/512)=2, ceil(4096/256)=16, cap=1024)=2（unit=tiles_ub*kv_heads=1024、wave//unit=296//1024=0<8 → wave 归零、cap 退回 1024），会提交 COMBINE——即这是提交存在性差异，不只是取值差异。该形显式落在 root 的 `when` 内（rows = 64），root.yaml 的 split 分区已含 “1 if base>=sms” 分支；(12,12,64)/B=32/每请求 q_len=64 同理给 base=192。decode 带的快捷项同样可生效（(32,32,128)/B=32/每请求 q_len=16 → base=1024），decode_split_kv.yaml 的 split 分区含同一分支。结论仍成立：快捷项与短 KV 两条到 n_split=1 的路径在 own prefill 与 decode 两带都在域内，不得把任一条当作不可达。

精确参数与各节点承担范围以其 YAML 的 `when` 为准；root 的 `when` 写明 merged 排除式与 warp-per-row 归并门的排除，decode_split_kv 的 `when` 写明 decode 带与同一归并门的排除，tcgen05_prefill 的 `when` 写明 merged 命中门、f16-QK 形（msk<6144）与 persist 驱动门。

**族级陈述的边界。** 上面是族级划分，不等于任何单一节点的范围：own 族由 root 与 decode_split_kv 两份完整设计分担，crossover 带由 tcgen05_prefill 节点与 W8/F8QK/static/fold/D64-D256 记录共同覆盖。不得把族范围抄成单一节点的 `when`，目录记录也不扩展任何节点的有效 Design 与 `when`。

**实测覆盖（冻结材料内）。** fixed 10 case 即 shape_cases.json，其实际 kernel 由 performance/ncu/result.json 逐个记名：merged 为 case 0（`fa_prefill_tc<128,64,1,1,1>` persist）、1（`fa_prefill_w8<128,64,1,1>`）、7（`fa_prefill_w8<64,96,1,1>`）、9（`fa_prefill_tc<128,64,1,1,1>` static）；own decode 为 case 2（`fmha_main<128,16,16,1,4>`+`fmha_combine_w<128,1>`）、3（`fmha_main<256,16,16,1,2>`+`fmha_combine<256,1024,16,0>`）、4/5/6（`fmha_main<128,16,16,1,4>`+`fmha_combine<128,1024,0,0>`）、8（`fmha_main<64,16,32,1,4>`+`fmha_combine<64,1024,0,0>`）。四个 prefill case 全走 merged，因此 root 的 cfg8 与 own prefill 参数族（cfg9/cfg2）在 fixed 套件内无实测；solution.py 另记 fixed prefill 的 peer_ctas 为 320–832、declared domain 的 prefill 配置为 56（d256，走 own）与 396（d64）/448、544（d128），即 d128 的 own prefill 只存在于连续域，而 d256 的 own 配置属 tile 参数族、不是 root 的实例（domain 套件文件本身不在固定来源内，这里引用的只是 solution.py 对它的记述）。tcgen05_prefill 的所选实例（persist + F8Q=false）同样无 fixed 实测——case 0/9 是 F8Q=true 实例、case 1/7 是 W8。这三者的可达性由声明域内的见证形状给出（见“完整设计”），都不得引用 fixed 计时作为自身证据。decode_split_kv 的所选实例 cfg4 有 fixed 实测（case 2 与 case 4/5/6）。

**来源限制（随交付保留）。**

- 验收材料（CERTIFIED_BEST.json、shapes.csv、ncu/）只有 promotion、计时与逐 case kernel 名，没有外部比较器公式或相对误差基准（P1 已登记缺口），root 的 Tolerance 因此是来源记录；decode_split_kv 与 tcgen05_prefill 经共享 Contract 使用同一来源界，正文均未补造比较器或默认简写解释。
- 冻结材料只含 fixed 10 case；solution.py 注记引用的 domain 10 config 及其逐行路由不在固定来源内，本目录不据此陈述覆盖。
- 三类未校验前提（page_size 与 g 为 2 的幂、batch≤32，纯由索引算术要求）与 FP16 加宽的上溢侧偏差已在 root.yaml 的 `when` 与 Math_reshape 保留；decode_split_kv 与 tcgen05_prefill 各自的索引算术前提与 FP16 加宽偏差已在自身 `when` 与 Math_reshape 保留（前者记 page/g 为 2 的幂与 batch≤32，后者记 page_size 为 2 的幂），未继承 root 的表述。fmha_forward 入口的 1≤B≤32 与 g 为 2 的幂检查不在生产路径上（该入口自标 stale，solution.py 只调 fmha_run/fmha_capture/fmha_replay）。
- sms（本机 148）在 root.yaml 中仍是散文字义，Hardware_specification 按 P1 政策留占位；硬件区落实或登记设备规模后，cap/ws_cap、8*sms 归并门、2*sms 驻留与 slots 都应改为引用登记项，三节点一并复核。

**已研究但未完整展开的独立方案**（默认路由不可达或已关闭，均有取舍依据，明确不交付完整 schema）：

- `prefill_tc/` peer 模块：v4.12-full-suite-pass 的 verbatim 拷贝、独立 extension、`--use_fast_math` 与其 exp2_precise 是自带数值前提，自带同公式的 fold/persist host 门；仅 FMHA_MY_PRE=0 或 FMHA_PF_FORCE 可达。其 fa_decode/fa_combine 编译但死代码——solution.py 只在 rows > _PF_ROWS=64 时路由过去，而 peer host 自己的判定是 decode = rows ≤ BM=64。PROVENANCE.md 记的 prefill 优势（四个 prefill case 0.60–0.64）是跨 job 比、不是同 job 加速声明；默认路由下 crossover 形状全部走 merged 栈，peer 作为 merged 的直系祖先与 A/B 对照保留。
- `fmha_tc.cu` cfg16/17：第一代自研 tcgen05 prefill（8×8 core-matrix 原子 tiling、bf16-only UMMA、线程本地行 softmax），实测比 mma.sync prefill 慢 1.35–1.76×，从未 promoted，仅 FMHA_CFG_OVERRIDE 可达。
- `fa_prefill_rt2p`：D128 双行组 persist（256 线程、两个 128 行组共享一条 K/V convert+prefetch 路径、TMEM 512 列 → 1 CTA/SM），opt-in、默认不编译。测量状态按两处来源分别记：peer 把它作为 `#ifdef MYPRE_RT2P` 的 arm 而非默认交付、未随附任何测量（solution.py 的 _RT2P 注记）；而本树 PF2 的拒用注记引用了它的占用率交易读数 “MYPRE_RT2P measured +22.0% for exactly that trade”（fmha_pre.cu），即“丢掉第二个 CTA/SM”这一 trade 曾被量化为 +22.0% 变慢。取舍结论不变（未 shipped、不展开），但不得写成毫无测量。
- cluster DSMEM split-KV prefill（MYPRE_CLUSTER + cl_split）：CL 个 rank 分走同一 item 的 KV 切片并经 DSMEM 归并 (m,l,O)，item 因此不再是调度原子；null probe 本身 never shipped，split arm 实测 shared 地址的 rank 位污染与 peer 生命周期竞争（rank 0 领到队尾票先退会让 peer 读死 CTA 的共享字，需第二道 cluster barrier 关闭），未 shipped。
- FM fused split-merge decode（FMHA_DEC_FUSEMERGE）：1<n_split≤32 时最后到达的 CTA 以 threadfence-reduction arrival 直接把组内 partials 归并进 out，删除 combine launch；opt-in、默认不编译；大 split 形状（case 3 的 592）仍须 block combine。
- DS dim-split d256 decode（cfg37）：每 (tile,split) 两 CTA 各担半个 V/O（K 复制、QK/softmax 复制，同 n_split 下 bit-identical），combine 的 MAXS 计的是条目数所以 n_split 上限减半到 512；opt-in。
- 已测被拒或默认关闭的机制 arm：peer 路由 f16-PV（收益低于“PV bit-identical”的价值）、MYPRE_VF16 prefill f16-P（'tiny' 分布 rel_l2 约 2.0e-2–2.5e-2，超 1e-2 界 2–2.5 倍，已回退；decode 侧由 VSHIFT 修复后才 shipped）、FMHA_PRE_PF2 双缓冲 staging（+13.35%）、FMHA_PRE_NBSYNC tc 分裂 barrier（真实几何 case 9 死锁）、MYPRE_KSFOLD（精度未测，默认关）、MYPRE_VBF16/VBF16P（本平台 ptxas 13.0 拒绝 native fp8→bf16x2 拼写，工具链级关闭）、combine WPR>1（对 WPR 单调变差）、FMHA_SPLIT_FILL_WAVE（combine 成本盖过收益）、FMHA_DIRECT（当初支持它的“分布更紧”已反转，现在是 graph 侧紧、direct 侧双峰）。

- 条件与依据：源码选择条件是 !fold ∧ 非 D128-band（band_w8p 假）∧ 4*grid_orig < 5*slots，即基线 `when` 中 persist 门 P.persist=!fold ∧ (band_w8p ∨ 4*grid_orig ≥ 5*slots) 的补集——D128 的 band 形状恒 persist 并发射 `fa_prefill_w8<128,64,true,true>`，永不进入 tc static，那个角只归“fa_prefill_w8 8-warp kernel”记录（哪怕它同时满足 4*grid_orig<5*slots，例如 (32,8,128)/B=2/q=[512,512]/kv=[512,512]：grid_orig=320、band 真、4*320=1280<5*296）；D64 的 band_w8p 恒假、D256 的 band 归 fold 而已被 !fold 排除，故该排除只影响 D128。D128 static 在 NM_STATIC 默认下仍取 NM=true，D64 static 取 NM=false（`fa_prefill_tc<64,64,true,false>`）。依据：`launch_mypre` 的 P.persist 门与 grid 计算，nm-static 的 case 9 记录（662.8→644.8，0.9728，另两个 arm -2.64%/-2.72%）。声明域见证 (32,8,128)/B=1/q=512/kv=1024 → cfg39、grid_orig=160、band 假（160<slots=296）、4*160<5*296 → static；fixed case 9 是 static 但为 F8Q=true 实例，不是本条实例可引用的计时。

### tc fold 镜像配对（局部）

- 基线：[tcgen05_prefill](tcgen05_prefill.yaml) 的 `DESIGN.Work_schedule.Thesis` 与 `MAIN.Decomposition.Strategy`/`Partition.item`（单一 (请求,128 q 行 tile,head) item）、`MAIN.Mapping.Worker_count`、`DESIGN.Tile_pipeline::MAIN.Index` 的 t/i/g 与 `Role.MAIN` 的主循环动词序列。
- 差异与联动：item 变成 (tileA, n-1-tileA) 镜像对（diagonal-causal 下头尾工作量相等），trows=2*TCBM；CTA 内 driver 循环顺序跑两 item（which 0/1，tileB==tileA 时退回单 item）；grid=(ceil_div(total_q,2*TCBM)+B, H)。只移动 item→CTA 映射，主循环、TMEM 与数值路径沿用基线，故 bit-identical。
- 条件与依据：源码选择条件是 diag(2*msq≥msk) ∧ slots≤grid_orig≤2*slots ∧ (D≠64 ∨ d64_fold，默认构建 d64_fold=false) ∧ 非 D128-band（v4.9 起 D128 band 改 W8-persist）→ 默认构建实际只有 D256 band 走 tc fold。依据：`launch_mypre` 的 P.fold 公式与 v4.9 的 persist 胜 fold 记录（case 1 118.8→110.6 中位、0.9310、bit-identical，因为只移动 item→CTA 映射）。

### fa_prefill_w8 8-warp kernel（局部）

- 基线：[tcgen05_prefill](tcgen05_prefill.yaml) 的 `DESIGN.Tile_pipeline::MAIN.Role.MAIN.Info.Member`（warp[0:4]）与 `Using_verb` 的 compute:softmax（每线程独占一行、零 shfl）、store:p_bf16、matmul:q_image@k_image / matmul:p_bf16@v_image、await:qk_done/pv_done，`MAIN.Storage` 的 score_p/o_run（TMEM），`Tile_pipeline.Thesis` 的双缓冲与 mbarrier 相位，以及 `Work_schedule.Flow` 的单 launch。
- 差异与联动：256 线程/8 warp，每 warp 经 TMEM 的 16-lane 半区（列地址加 16<<16，warp 4–7 取 +16 lane 半区）担 16 行；softmax 变每线程 2 行×16 列、4-lane quad shfl 归约；P store 零 shuffle（tcgen05.ld 的寄存器直接构成 st fragment）；D64-persist 用 BNT=96（TMEM NEED=2*96+64=256=ACOLS，保 2 CTA/SM）；该 kernel 没有 F8Q 模板参数，故 D128 走 W8 时 host 的 f8ok 被忽略。判局部而非完整设计的依据：worker 数与 fragment/softmax 数据通路重写，但 8 步主循环、mbarrier 链、驱动模式、TMEM 布局与单 launch 直写全部沿用基线。
- 条件与依据：默认路由：D64 全部 persist → `fa_prefill_w8<64,96,true,true>`（MYPRE_W8BNT96 默认开，BNT64 版永不发射）；D128 fold ∨ band-persist → `fa_prefill_w8<128,64,true,true>`。依据与覆盖：fixed case 1（D128 band-persist）与 case 7（D64 persist）实测；D64 采纳记录 c7 +1.7%（3/3 rep），BNT96 在其上按几何类再得 +10.9%～+20.4% 且驻留不变；D128 band 的 v4.9 记录 case 1 0.9310/0.9282。

### F8QK fp8-direct QK（局部）

- 基线：[tcgen05_prefill](tcgen05_prefill.yaml)（仅 D128 的 tc 路径适用）的 `DESIGN.Math_reshape::Operand narrowing and score scaling`（k_f16 精确转换、q_f16 一次性加宽）、`DESIGN.Tile_pipeline::MAIN.Storage` 的 k_image/scale_image、`Role.MAIN.Using_verb.store:kv_image`（K→FP16 image）与 `matmul:q_image@k_image`（8 段链式 depth-16 UMMA、kind f16）。
- 差异与联动：K 不再转 f16——native e4m3 字节经 SW128 K-major descriptor 直入 tcgen05.mma kind::f8f6f4（删除 store:kv_image 的 K 半、K image 减半）；Q 每行做 2 的幂归一化 dual-e4m3 split（单 pass：uint4 寄存器存活、width-16 rowmax、scale shfl 广播、约 8 位恢复尾数），行 scale 以精确 2 幂 fmaf(s,invr,-mnt) 折入 softmax；QK 发射变 D/32 两段链。非 bit-identical：score 级 scheme 误差 1.03e-4，冻结门 PASS（rel_l2 占界 +0.4%）。
- 条件与依据：源码选择条件是 kernel 侧 F8QK = F8Q ∧ D==128；host 侧 msk ≥ 6144 → cfg31（F8Q=true）、< 6144 → cfg39（f16 QK，其余全同，即基线所选实例）；D64（SWIZZLE_64B 原子未探测）与 D256（双原子行）保持 f16。依据与覆盖：fixed case 0（persist）0.9792 与 case 9（static）0.9846，其余 fixed case 与 D64/D256/W8/decode canary bit-identical；6144 落在实测间隙（kv4096 flat 0.9994、kv8192 win 0.9792）；已披露的连续域回退类是 d128 tc-static 短走 normal 分布形状（r1 q1024/kv2048 +2.8%）。

### tc D64/D256 实例化（参数）

- 基线：[tcgen05_prefill](tcgen05_prefill.yaml) 的 `DESIGN.Tile_pipeline.Thesis`（S0/S1 双缓冲与 PIPE 重叠）、`MAIN.Storage` 的 score_p/o_run（TMEM 账）与 `DESIGN.Work_schedule::MAIN.Mapping`（slots=2*sms 与 Worker_count）。
- 差异与联动：D64 → PIPE=true、NEED=2*64+64=192 → ACOLS=256、slots=2*sms、static NM=false、FMHA_PRE_TPRW64=4 的多 pass staging（默认开、只被 `fa_prefill_tc` 的 D64 读、bit-identical，收益属连续域的 D64 static prefill 类）；D256 → PIPE=false（顺序 v2 环）、NEED=2*64+256=384 → ACOLS=512、slots=1*sms、NM 仅随 persist。smem/TMEM 预算决定驻留（2 对 1 CTA/SM）。
- 条件与依据：源码选择条件是 host 按 head_dim 取 cfg30/cfg32，merged 门取 _PF_MIN_CTAS={64:36,256:64} 与短 KV 放宽；驱动模式沿用同一 persist/fold/static 门。覆盖：fixed 套件内 D64 只有 case 7（走 W8-96）、D256 merged 无 case，故这两个实例化在冻结材料内无计时，不得引用 fixed 计时。
