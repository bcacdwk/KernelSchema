# Reviewer：当前文档的独立验收

Reviewer 对当前产物截至本阶段已完成的全部内容负责，依据本任务适用的 schema_docs 核实表达完整、自洽、分层正确，且无需历史上下文即可理解。前序批准和检查器通过不免除此责任；依靠隐含定义、目录补写 YAML 或旧稿补足含义的产物不能放行。

这是 worker 自查与 reviewer 独立验收共用的方法。阶段页定义完成对象，具体任务限制写入文件与字段；修改范围有限，不缩减应审阅的有效全文。维护、裁决或恢复操作依其授权与[工具协议](tools/README.md)，不因阅读阶段页取得额外权限。

## 当前产物先行

先读适用规范、当前 YAML 和目录，再按具体问题核对固定源码。工具先保存 worker 原稿、整体规范化、核权限与来源并严格重读，reviewer 审落地后的 raw。当前问题与范围另列，从当前产物建立理解；P6 随后读取必要机制记录和 P5 新事实反查去向。过程记录提供核查线索，正文仍须完整。裁决中的各候选也须各自完整可读。

可以分段、分文件阅读并保存进度，批准前须完成本阶段范围内的有效全文审阅，包括引用、复制和本轮未修改内容。同一当前共用定义可按实际文件读一次；每个使用节点的范围、参数绑定、跨区接口和 Realization 仍分别核对。填写或审阅某段前读取其字段、分层与语义规则。源码用于核实事实，不能代替应写在产物中的计算和设计定义。

root 定义唯一共享 Contract，各完整设计由本地定义与 [Design 整区引用](../schema_docs/0.common.md#design-整区引用)构成。实际来源闭包是阅读依赖，借鉴说明不产生内容继承。核对 raw 中的引用、本地定义及全部中间来源；展开视图只辅助阅读，不证明来源完整或使用适用。

目录中的参数、局部或组合条目按[记录规则](../schema_docs/0.common.md#局部记录与完整方案)借助明确完整基线表达差额，不要求每条重述整个算子。审阅须读懂基线，再核对变化、联动及接口外主体仍成立；记录不能补齐完整 YAML 的缺失内容，也不授权自动实施组合。

## 四项判断

1. **独立理解。** 当前已完成内容及允许的明确依赖足以解释本阶段的任务、具体设计或记录。输入、输出、符号、条件和引用均可定位；需要历史解释的地方属于缺项。
2. **分层正确。** Contract 定义任务，数学层定义计算、精度与保留，调度层定义工作与提交，流水线层定义角色、依赖和资源，Realization 只补必要实现条件。下层不能补入或改写上层决定，目录不能覆盖 YAML。
3. **全文一致。** 一份 YAML 表达一套具体已选方案，其输入引起的尺寸、工作量、尾块、空工作和必要条件照常核对。对改变提交、成员、物化或事件存在性的情形分别贯通，不把未提交、没有工作与已执行动作的 no-op 混为一谈；无数据效果的已声明动作仍有事件，不能用正文取消。按[差异规则](../schema_docs/0.common.md#参数变化与结构变化)区分其他配置、局部记录和完整设计，不能为少建文件拼接不相容机制。
4. **内容必要。** 保留必要数学、策略、动作契约、设计理由及影响理解的来源限制。退修、待办、历史批准和重复决定留在过程记录。正式范围中的研究取舍与规范允许的来源缺口不是无关过程，不能只因涉及未知便删除。

依[结构与扩展](../schema_docs/0.common.md#结构与扩展)区分填写实例和修改语言：具名对象、开放取值、自定义动作及数学记法按各字段规则使用；新增固定字段、封闭取值或未定义记法须按规范变更处理。旧稿、源码写法或检查器接受都不授予扩展权限。不要求自然语言成为可执行代码，也不按关键词或篇幅判定质量；语义正确、必要信息齐备就通过。

涉及录图、缓存或调用前缀时，依 DOC4 的[提交身份](../schema_docs/4.design.work_schedule.md#提交身份与字段)和[调用边界](../schema_docs/4.design.work_schedule.md#调用边界)核对实际工作与副作用，源码调查见 [P2](prompt/phases/02_dispatch_draft.md)。条件等待按[动作声明](../schema_docs/5.design.tile_pipeline.md#基础动词与动作声明)及[索引窗口](../schema_docs/5.design.tile_pipeline.md#依赖的索引窗口)核对跨 role 前驱，不能藏在正文或无依据地增加等待。

## 各阶段覆盖范围

| 阶段 | 必须独立审阅的当前内容 |
| --- | --- |
| P1 | 任务元数据、共享算法 Contract、逐输出验收材料与最小执行单元登记；Design 可未完成，不批准 root 代表选择。 |
| P2 | P1 已完成内容、机制概览、root 来源与初步范围、拟完整集合和记录线索；核实足以影响选择的有据疑点及调查止点。 |
| P3 | 完整具体 root 的元数据、Contract、Design 和必要 Realization，结合当前目录草案核对承担范围。 |
| P4 | 完整 root、目录、相关现有基线与有限未来计划；核对实际材料是否支持已定差异与保留依据，以及已知知识去处，未来内容只审计划。 |
| P5 | 本节点有效全文、共享 Contract、实际来源闭包和使用上下文；实质差异与完整输入到输出关系，以及新事实的影响判断。 |
| P6 | 全部最终完整设计与正式记录；核对含 root 至多十份、每份独特价值、实际基线、共享适用性、机制去向与真实范围。 |

执行单元登记、其余硬件占位和 GPU 边界见 [P1](prompt/phases/01_contract.md#第-3-段硬件占位)，豁免不扩大到其他字段或普通设计、实现任务。全文审阅每次覆盖上述范围，源码复核围绕差异、风险和有据疑点深入，不要求每阶段重复整套源码调查。

P1/P2 允许未完成 Design，不豁免本阶段元数据、Contract 或机制草案的完整性。P4 可以批准明确未来计划，不能据此批准尚未存在的定义或 `from` 同一性。P3/P5 从当前节点输入贯通到全部输出，并覆盖改变当前执行关系的各类情形。

另行授权的候选评议或局部片段核对，结论只覆盖实际提供并已核实的对象。可以判定候选有保留价值，或某条依赖表达正确，同时明确尚未审阅的完整关系；这些结论不代替正式阶段批准，也不要求限域任务提前补做整个 P1/P3。正式放行仍满足上表范围和阶段前提，手工工作的实施边界见[执行器对齐说明](EXECUTOR_ALIGNMENT.md#手工推演与阶段结论)。

### 完整设计的保留与降级

独特价值相对于本算子已保留的设计判断。root 提供一份具体完整基线；对其他完整候选，P2 reviewer 须独立核对它相对最相关基线新增了哪项主要计算、输出形成、工作分配或主协作机制，以及为何基线主体加目录中的差额说明仍不足以表达。判据沿用 [common](../schema_docs/0.common.md#参数变化与结构变化)，不以源码分支、配置名称或改动篇幅代替依据。

P2 在现有审阅结论中明确候选的记录层级及理由；后续确需纠正取舍时沿用同一判据：

- 新的主体机制需要贯通解释，且值得当前任务完整保留：保留完整设计候选
- 参数、局部改动或已知组合足以说明全部差额：要求降为 `dispatch.md` 记录，不保留为独立完整写作任务
- 没有新增设计信息：合并重复项或删除冗余记录

取舍所需的具体事实或关系尚未核实时，定向补查并说明受阻判断，不能仅凭 worker 声称独特而放行。确实独立但未选入当前完整集合的方案，诚实说明未完整展开，不因名额限制假称参数或局部变化。

P2 独立审定机制识别、root 与其他完整代表的取舍及记录去处。后续作者沿已选实例完成正文和目录，reviewer 从当前有效全文与固定源码核实实际内容是否支持已定差异和保留依据；阶段切换不要求重新搜索候选或逐份重作取舍。已选机制写错或漏写时先修定义；具体事实或关键关系缺口影响原判断时，按下文返回受影响处。

### 共用定义与使用节点

provider 的审阅核实其本地定义的来源和规范推导及其在该设计中的正确性。使用节点仍须审阅自身范围、名称与参数绑定、数值路径、三区域接口、生产消费、工作归属、事件、存储寿命和复用。通用定义可读一次，所有使用上下文均须覆盖；来源批准不能证明适用性。

每个完整节点相对有意义基线的实质差异须有依据，引用写法变化本身不构成独立价值。Realization 与反馈不继承；当前 Contract 和有效 Design 之外仍必要的实现约束，即使别处已有，也须在本节点显式填写。引用证据来自实际 raw 引用行、中间来源及 provider 定义，不能使用有效视图的虚拟位置代替。

## 源实现缺陷与设计分流

发现源 kernel 正确性问题时，按 schema_docs 的抽象边界判断它是否妨碍确定设计。固定源码的声明、容量预算、生产消费与使用点共同支持同一完整设计，且无需重新决定算法、精度、数据版本、逻辑依赖、角色、提交、容量、生命周期或复用策略时，边界之外的实现偏差不阻塞提取。保留缺陷与证据，继续完成有据的 Design；无需先确定损坏后的实际值，除非它仍影响设计决定。不能只凭作者意图或“修一行即可”作此判断。

具体地址或同步指令的落实偏差不自动等于设计改变；关键是逻辑依赖和资源策略是否已有来源依据。缺少生产者、需要补造依赖、增加缓冲或改变复用的修复不能借此放行；不能删掉源码已明确的计算提交或副作用，或凭数学正确性另选算法。必须猜测或改变这些设计决定才能完成时，指出具体关系及缺失依据，阻塞受影响范围；当前产物写错或漏写已知设计则退修。

调用边界规定了设计应满足的关系，不证明固定源码已经实现它。审缓存或侧流时，分别找出当前输入就绪、所用地址和元数据有效、前次消费者完成及共享存储可再用的依据；对象身份命中或一次上传完成不能替代这些事实。只将有源码或固定调用材料支持的关系写成已具备的保证，其余必要条件保留来源限制并说明影响，不补成默认隔离或等待。

源实现问题在既有回执与 issue 中定位，说明影响及继续或阻塞的依据，由 Supervisor 按需登记 kernel issue；worker/reviewer 不写台账，不将 kernel 缺陷冒充框架问题。缺陷详情留在问题记录，YAML 保留必要约束和来源限制，不把坏地址或错误复用写成 `REALIZATION.Require/Forbid`。TMEM 等计算资源、完整数据对象的容量与寿命、数据与复用依赖仍须表达，不能与返回基址槽等实现元数据一起省略。

可继续不等于可批准残稿：完整 Design、四项判断、必要产物与源码依据及适用检查仍须满足。Schema 批准不证明源 kernel 已正确。修 kernel、运行 GPU 或取得实测结果不是本次提取角色的职责，也不是有据设计继续提取的先决条件。

## 来源缺项

按缺口对当前阶段的实际影响判断，不要求 P1 提前完成 Design。当前所需任务数学、IO、副作用、参考入口和设计关系有据，而外部验收器的公式、相对误差基准、归一化或检查路由未提供时，依[验收来源记录](../schema_docs/1.contract.algorithm_requirement.md#固定实现提取中的验收记录)在对应 `Golden_reference.Tolerance` 保留已知判据和明确限制，说明未采用默认简写解释。既有来源问题记录说明缺项、来源、为何不影响当前提取及补齐途径；不新增 YAML 字段，也不挪入 `Golden_reference.Gap`。

只影响外部测试通过边界的缺口不阻塞提取，本阶段内容完整时可批准并保留问题。后续确认已知事实未遗漏、未知内容未作保证、限制仍在交付中，不因比较器仍未补齐再次阻塞。计算、精度转换、输出副作用或依赖必须靠猜测时阻塞具体范围；来源已明而产物写错或漏写则退修。可用材料仍须读取，不无限追索未提供的验收器。

## 发现问题与批准

审阅范围大于修改权限。发现问题时指出实际文件/字段或待核实关系、相关规则、依据、影响和可执行修正要求。已选机制的正文错误或遗漏先修定义，由有权作者在 P3/P5 或 P6 明确授权范围内完成。当前已能核实判断而只缺文字或证据定位时，由有权作者补齐记录，无需重开 P2。

具体事实表明机制识别或代表取舍错误，或定向核实后已定位的必要关系仍无法核实、不能支持某项取舍时，回 P2 修相应判断。须说明具体关系及其对取舍的影响；既有源码中的误读也可纠正，泛泛的“理由不足”不构成返回依据。取舍改变后，由 P4 按需落实受影响的集合、目录和依赖；只调整已定代表的登记、写作先后或未来依赖时，由 P4 处理。共享 Contract 错误回 P1，真实任务或固定来源改变沿手册另建提取。

本 P5 内的完整本地化或改用已存在已审的相同整区，沿本节点独立审阅；provider 错误回定义处，正确但不适用则修改使用节点。普通记录及不改变已定取舍或任务义务的已研究但未展开独立候选，按 [common](../schema_docs/0.common.md#选择条件与索引)保留：P3 交 P4 落实，P5 在既有交接中汇集，由 P6 按需集中落实并再审。具体写权限见 [P5](prompt/phases/05_branch.md#新事实与定点返回) 和 [P6](prompt/phases/06_final.md#worker按需加入与可写范围)；重大选择或依赖变化先解决，未受影响内容保留。

先判断能否按已有规则修正产物。规则确有不适配、缺失或冲突时，通过 framework_candidates 提供稳定标识、具体条款、反例、最小建议与影响。worker 提候选，reviewer 独立核实后沿用 ID 确认，也可补充已核实的新发现；未确认项在结论说明理由。Supervisor 按根因处理，正式采用前仍使用当前语义。依靠自造规则才能读通的产物不能批准，可选建议也不扣住正确产物。

批准结论分别覆盖上述四项判断，并引用当前产物。源码忠实性的结论仍须实际来源支持；产物结构或格式问题定位当前文件，不能把源码缺口、转录、计算、数值和选择问题改称格式问题来省略来源依据。具体回执字段和证据编码见[工具协议](tools/README.md#回执与短交接)，不以检查器退出码或“之前已审”替代判断。

退修或阻塞须有具体且有据的问题，阻塞还须说明恢复条件；未完成审阅时不伪装四项判断已通过。修订后重新审阅当前有效全文，反馈本身不成为产物的额外语义。

当前 run 的维护保留固定身份、草稿和预算。完整候选可以先独立审阅；有据问题由授权 worker 按明确文件/字段修补再审，未完成稿继续普通写作。已有批准核真实性与当前适用性，等价保留须有实际来源、Contract 和完整使用上下文依据。每次新派 reviewer 仍审本阶段完整范围，最终交付需要新的 P6。

reviewer 始终只读。裁决补丁由 Runner 应用，执行相同规范化、权限与严格检查，再由全新 reviewer 一次签收最终 raw；未签收改稿不能成为批准。直接选择已审阅且不再变化的规范候选无需新增签收。具体限制见[裁决协议](tools/README.md#定点返回与一次裁决)。
