## 计价公式与缓存

用户在本轮对话提供每百万 token：普通输入 $10，输出 $50，缓存读取 $1，缓存写入 $12.50（30 分钟）或 $25（12 小时），并引用 `blog.laozhang.ai`。本次访问 OpenAI Docs 的官方模型/价格页面收到 HTTP 403，因此没有把这个用户给定价表描述为独立核实的官方价格。

原生 usage 中的缓存读和缓存写都是输入子集，`output_tokens` 已包含 reasoning。按以下公式折算，不额外重复加 reasoning：

```text
普通输入 = input_tokens - cached_input_tokens - cache_write_input_tokens
费用 USD = (普通输入 × 10 + 缓存读 × 1 + 缓存写 × 写入单价 + 输出 × 50) / 1,000,000
总 token = input_tokens + output_tokens
```

token 记录未给出可核实的每次写入 TTL，因此上述两列为两个价目情景，不是已证明的实付上下限。默认 30 分钟的费用构成：

| 费用组成 | 重构以来 | 2.5.0 部分 |
| --- | ---: | ---: |
| 普通输入 | $0.65 | $0.29 |
| 缓存读取 | $2,836.04 | $1,231.70 |
| 缓存写入（30 分钟） | $2,585.46 | $876.09 |
| 输出（含 reasoning） | $971.93 | $390.33 |

2.5.0 的缓存读占输入 **94.61%**，但读缓存仍产生 $1,231.70；写入缓存另产生 $876.09。输入量很大并不等同于全部按 $10/M 收费，也不等同于免费。

从现有数据可以判断：

1. **P5 分支提取是费用中心。** 最新版 299 次尝试、$2,187.41，占 87.6%；MoE 一项占最新版费用 76.1%。初次交付共 77 节点，而暂停时六算子计划合计 220 节点（MoE 从初次 60 节点扩到 154，FMHA 从 8 扩到 43）。范围扩大与多版本重做本身就是主要成本来源，不能把全部增长归因于单次模型效率下降。
2. **每次派发实际经历很多轮模型交互。** 最新版 351 次已派发 CLI 对应 9,774 次有新用量的模型响应，平均每次 CLI 约 27.8 轮；每轮平均输入约 133.2k token。输入计数是反复送入上下文的累计量，不是源文件只有这些唯一 token。全量范围有 21,728 次有用量响应，失败且无用量的请求不计入该数。
3. **Reviewer 的开销与 Worker 相当。** 最新版 Reviewer 占费用 51.0%。这个比例本身不能说明审阅没有价值，但表明优化角色输入和逐节点审阅组织会直接影响总成本。
4. **Runner 检查处理已是明显的时间项。** 最新版 14.67 h，占 CLI + processing 累计工时的 21.7%。MoE 处理累计 12.30 h；FMHA 最新 5 次尝试的处理 1.89 h，超过 CLI 0.61 h。最大单条处理约 60.6 min。执行记录同时存在历史绑定校验的长等待，后续值得专门定位重复历史/依赖校验；当前统计不能进一步精确拆成 CPU、文件 I/O 和具体校验函数。
5. **最新版的显式 CLI 失败不是主要费用项。** 18 条失败尝试已记录 $11.13，约 0.45%。12 条返回 `revise/reopen` 的尝试约 $82.81；7 条 CLI completed 但当时无 receipt 的尝试约 $71.28。这些只是不同标签下的调用本身开销，类别可能重叠，不是所有重做成本的完整拆分，也不应相加称为“浪费”。

因此，后续优先研究 P5 节点划分与公共材料复用、Reviewer 输入/审阅组织、以及 Runner 的重复检查开销，有直接的数据依据。此次只做统计，不修改提取机制或恢复运行。
