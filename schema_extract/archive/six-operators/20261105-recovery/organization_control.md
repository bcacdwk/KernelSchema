明确推荐：主代理保持唯一全局 Supervisor；“两两推进”指每个新代理负责一个有结束条件的任务，同时最多两项，不是一人包两个算子。共享恢复工程先占一项，另一项做小算子内容准备。之后按算子分派有限任务，完成即结束会话，不设长驻算子 Supervisor。

> 归档说明：六算子恢复阶段的历史记录。正文中的运行状态、预算、命令和分工对应记录时点，不作为新的执行授权。 [归档索引](../../README.md)。

主代理负责 prompt、命令、预算、调度、验收和沟通。子代理可读固定来源与状态、提出逐范围方案，或在指定隔离目录实施工程改动；不给跨算子控制权，也不直接写 state、账本、checkpoint、批准或正式目录。每个 run 仍由唯一持写锁 Runner 派发、检查、合入和发布；会编排 CLI 的代理只是控制请求者。正式 schema 由 Runner 的 worker 修改许可产物、独立 reviewer 审完整当前内容；代理报告不能替代批准。桥接独立评审可登记 Supervisor 评审身份，但不新增全局运行总控。

并发必须分两层核算。已核对当前及三个旧冻结执行器：普通 P5 的 next_calls 枚举全部依赖就绪节点，Runner 为各调用启动线程，每节点同时一个调用，没有固定槽位或现成全局模型并发上限。因此两代理、两算子都不等于两次模型调用；即使只恢复 FMHA 一个 run，也可能同时发起多个调用。初期保持最多两项代理工作，只放行一个生产 run；这仅控制算子数，不承诺调用数。若供应商需要硬并发上限，应另立经验证的调度维护任务，不能虚构参数，也不能把 resume --scope 当作限流器。

三个旧 run 均冻结 gpt-6-astra/xhigh，403 配额是否恢复仍未知。先依据可用服务信息判断，不发探测调用；小任务的实际成功也只证明当次服务可用。主代理按实际 scope 余额、审阅预留及已过期墙钟决定追加，不能按总 attempts 统一充值。hold、升级、修订和恢复都不清零用量或已用裁决。

最先分派以下两个全新 xhigh、无聊天继承的任务：

| 任务 | 输入与权限 | 输出及完成标志 |

| A：共用桥接工程候选 | 恢复汇总、三份原冻结规则/源码锁、2.4.1 候选；独立工作树内开发及离线合成验证，不控制真实 run | 候选目录和摘要、逐旧基线差异、定向验证记录、清算/迁移操作表。覆盖 own raw、批准依赖、账目、request/drain/prepare/apply；完成只代表可独立评审，不能自认证兼容 |

A 完成后换新代理独立审阅完整差异和验证依据，主代理核对后才采用。共用的是工程实现与验证方法；三套旧语义仍分别绑定目标、报告和真实 checkpoint，不能一份兼容结论覆盖全部。B 准备完成后由主代理启动正式小任务，Runner 完成独立审阅与当前 P6；准备报告不算交付。

FMHA 适合作为离线保稿验证的重点样本，不宜直接承担首次生产试错：29 个有效节点及各自草稿价值高，且 P5 会展开并发。建议先完成离线桥接验证和独立认证，再以 MLA 小型新任务试行当前服务及交付流程；明确这不验证旧 run 迁移。真正的首个生产桥接优先 Sparse，先解决其 Contract 范围疑点并认证 2.2.9 桥接，再以八节点任务观察迁移；随后采用单独认证的 2.2.7 桥接处理 FMHA。代价是 FMHA 稍后恢复，收益是先在较小前沿暴露运行问题；MoE 不因停 P2 就被当作小任务，其后续计划规模仍待审定。

共享控制由主代理串行提交：清算旧调用并确认 active/unconfirmed/unsettled 全空，再确定真实 checkpoint、兼容报告、升级、修订及恢复顺序。同一 run 的清算/升级/修订/恢复不得重叠，新旧语义调用不并行；候选目标冻结评审后不得被另一代理边改边用。全局 hold 释放前先落实其他 run 的逐项暂停，核对实际控制结果，不能批量放行。桥接目标、预算、hold、新输出位置、来源/配置及范围变化都由主代理统一决策。

每项任务交一张短任务卡：目标和禁止事项、run/lineage、source/rules/executor 身份、checkpoint SHA、相关文件与问题锚点、可写路径、预算和停止条件。结束交回产物路径/摘要、实际验证、未决项及下一动作；主代理只核对差异和关键证据，不再重复全量六算子审计。后继代理读取任务卡和所需文件；正式 reviewer 仍由 Runner 清除历史批准与反馈，保留独立审阅。来源/目标、父依赖、checkpoint、字段权限变化或发现范围外问题时重新限定任务，不能借换代理扩大权限或重置机会。新代理要求适用于独立委派任务；Runner 内既定 P1→P2、节点内返工续用规则仍保留。

现有授权足以由主代理判断这些组织安排、必要恢复与合理预算，不需再问“是否继续”。确实改变用户任务目标或出现无法据授权解决的取舍，才交用户决定；本轮仅形成方案，未执行运行控制、模型调用或修改仓库。
