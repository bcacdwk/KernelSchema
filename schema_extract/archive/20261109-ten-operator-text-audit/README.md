# 十算子与全部 dispatch 的文字语义审计
2026-11-09 暂停样本；按用户要求，以五轮、每轮两个新的 high 代理完成十份独立报告，Supervisor 复核与汇总。

**结论：当前文本字段确实承担核心设计语义，四个模板也如此；同时，存在可明确删短的重复，以及本可写进现有结构的内容。主要问题不是一个统一的“字数过多”，而是开放动作语义、已有结构未充分使用、重复说明，以及调用/状态边界混在同一批字段里。**

这次是全清单审计：193 份有创作内容的 YAML、10 份 dispatch、算子内去重后的 5,875 个文本组全部阅读、标注，并核对每个节点及实际 provider 组合。另有5份失败骨架、43个未开始节点单列，不用于证明简洁。所有原始 schema、规范、运行状态保持原样；本研究没有恢复提取或运行 GPU。

阅读顺序：先看下面的十项结果和 Supervisor 判断；具体字段、原句、结构替代与源码依据进入各算子报告。统一口径见 [METHOD](METHOD.md)，实际共同指令见 [AUDIT_PROMPT](AUDIT_PROMPT.md)，五轮身份与校准记录见 [rounds](supervision/rounds.json) 和 [QA记录](supervision/qa_log.json)。

2026-11-10 后续研究：先读[五个问题的通俗讨论稿](SCHEMA_DISCUSSION.md)，了解问题、原因、影响与建议改法。需要核对细节时，再看[核心文本与 schema 缺口复核](SCHEMA_LANGUAGE_GAPS.md)及其逐项分流记录。本页原统计不变。

**文字里是什么：全字段分类与数量边界**

以下主标签覆盖全部5,875组。列中的声明面积应用了上下文override；同一文本组在已批准节点和缺条件草稿中可有不同判断，因此主标签组数与声明分类并非一一同分布。

| 主类别 | 主标签组数 | 声明字符面积（含dispatch） | 含义 |
| --- | ---: | ---: | --- |
| DUPLICATE | 120 | 90,487 | 当前其它定义已覆盖全部含义 |
| NONCORE | 7 | 616 | 整段为当前设计不需要的内容 |
| STRUCTURABLE | 29 | 28,562 | 已有具体的现行结构替代 |
| ESSENTIAL_TEXT | 434 | 741,841 | 文字承担必要事实，现有简洁结构解法尚未落实 |
| FORMAL | 842 | 626,243 | 公式、谓词、参数与正式标识 |
| SOURCE_LIMIT | 43 | 15,856 | 整段为必要来源限制 |
| EXPLANATION | 2,588 | 736,827 | 摘要、标题、理由或导航 |
| MIXED | 1,808 | 2,594,344 | 必要事实与重复/解释等混合 |
| UNRESOLVED | 4 | 108,375 | 证据、选择域或绑定仍未决 |

按算子内精确去重字符看，MIXED 占 63.2%。这正是不能按字段名或句长整段删除的原因：一个字段可能只有一句独占核心，其余内容却可以明显缩短。NONCORE整字段少，也不意味着代码细节都重要，它们大量混在MIXED里。

共收集 **264 条精确 quote→replacement 候选**，英文YAML开放文本声明净减 **115,456** 字符，其中W/T/R **103,999**，中文dispatch另 **151**。这些不是全部潜在冗余的估计：代理只对有明确保留依据的局部提出候选，未以统一优化预算寻找最短稿，也没有把整批候选应用后做独立等价审阅。不能用此数量推算“剩下的都不可压缩”，或据候选比例给算子排简洁程度。

一个有代表性的 Supervisor 纠偏来自 MoE 的全量结果：7组gather strategy、63次声明原被判为可整段删除。复核发现其中 `Offs[E]` 是唯一明确的读取绑定，保留的 `Offs` 视图只有1元素shape、没有offset；数学上能推导M的值，不等于这次物理读取已经写清。最终改为保留读取及guard短句，7组改MIXED，候选量下调3,374字符。证据见 [gather_offset_qa](work/extract_moe/gather_offset_qa.json)。这同时说明：专职精简可以有效缩短长段，但局部“看起来重复”不够，必须逐事实保住唯一定义。

**哪些是现有结构没用好**

182项去重机制finding中，27项指出了现有结构可用或已承载的关系；只有29个完整字段组归STRUCTURABLE，更多可迁移子句在MIXED中，不能把29当成全部机会。下面列的是机制入口，完整覆盖来自每份annotations，不是以这些例子替代统计。

| 机制 | 全量审计定位 | 现有做法与限制 |
| --- | --- | --- |
| 已命名跨角色前驱藏在文字中 | 模板decode F06；模板QSA F09 | zero→reduce-add与条件PV退役等待可用wait/repeat/member事件；QSA需要按真实warp展开，不能无条件加全组等待 |
| 自定义动词重复上游计算/已有等待 | GDN F09/F11、GEMM F11、MoE F13/F16等 | 使用通用wait/compute/produce并更新全部引用；不能仅删verb定义留下未知词 |
| 参数和片段关系写成解释 | 模板GDN F06/F13、Sparse F07/F10、MoE F12等 | 数值落到tile/slot/合法symbol.value或表达式；视图落到offset/part；保留必要绑定，避免循环引用 |
| 完整区域相同却复制 | 模板FA4 prefill F08；模板decode F15 | 已核对的7个math父子对和q1_global可用现行from_parent；局部相同不能冒充整区相同 |
| 资源/完成语义已经存在但反复解释 | 十项均有对应finding | slot_count、view、release、kernel_done、初末/空域规则已有定义；不要把它们误报成“缺一个新事件” |

MoE的BN2绑定和通用compute两份独立副本通过了`--standalone --skip-hardware`结构检查，具体副本和验证记录见其报告；这不等于全树修订或语义等价已批准。其它复杂展开多数只是有证据的可表达方向。

**哪些仍是 schema 自身的表达问题**

必要文本主要有两种：一是目前规范有意开放的动作/原语定义，二是结构作用域没有覆盖的host或跨调用关系。不能因为“允许写在meaning”就说结构已完整，也不能因为尚无专用字段就断言必须扩成一门新DSL。

原始finding中有50项标为open_semantics、17项为representation_cost、6项标为missing_field_or_event候选，其余为无缺口或未决；标签可用于定位，不能相加成“73个独立漏洞”。特别是同一外部别名问题在不同算子中被叫作开放合同或缺专用字段，Supervisor按同一机制理解，不把命名差异当作事实差异。

| 优先研究的机制 | 证据范围 | Supervisor判断 |
| --- | --- | --- |
| 动作的读写/结果组成、capture、完成与退休保证 | 全部十项的动作finding | 当前结构依赖这些定义。优先提炼少量共享语义/动作接口，减少每个实例重写；不是先发明更多barrier名字 |
| role内部的子集协作、分片先后与独立推进 | 两份GDN、decode/QSA、GEMM、Sparse、FMHA等 | 多数已有角色/域/边可以展开，但会明显增大文档；问题是紧凑表达与粒度，不是已经证明无法表达 |
| 外部对象身份、可写区域、逻辑值与全局backing | 多份Contract、GDN/MoE等 | 现行规则有意放在meaning/math。若目标是结构独立承载，应试验通用alias/mutation/view表达；不为每个算子各加专用字段 |
| host准备、caller入口/返回、全设备host完成 | MLA F18、Sparse F05、MoE F25 | 现有GPU phase事件没有这些直接端点。先决定IR是否包含完整operator/host时序；纳入则研究service/外部事件，排除则形成明确的环境约束，不能直接删掉事实 |
| 跨调用存储、缓存/观察状态及复用 | GDN F16、MLA F10、QSA F10、Sparse F06、MoE F07/F15 | invocation内的handoff与worker资源不能直接表达这些owner/版本。先收束生命周期模型；源镜像竞态另作源缺陷，不能擅自补generation或同步当成既有设计 |
| 跨节点局部相同定义与选择谓词复用 | GDN、GEMM、FMHA、MoE及部分模板 | 当前整区引用有明确边界；复制成本可观，但局部patch/隐式继承会引入另一个一致性问题，需用真实重复集合评估 |

这六类不是六个必须马上新增的字段。当前证据支持“规范需要收束哪些核心语义由结构/共享定义负责”，尚不支持“一律取消文本字段”或给所有字段同一个硬长度上限。

**来源缺项、草稿和统计不确定性**

所有开放文字都已阅读，但有137个精确组至少一个上下文未决，对应290次声明：GDN的连续化来源问题，以及FMHA缺when/局部混稿等上下文。另有286组核心重要性在至少一个上下文为uncertain，主要涉及实现绑定及未闭合的草稿域。不能把主标签UNRESOLVED只有4组解释成只有4处疑问。

必须独立保留的来源限制包括：GDN final-mini读退役、GEMM TMEM寻址、Sparse的barrier/元数据错误别名及gate竞争、decode PageIndex复用、QSA padding/HalfMax，以及MoE旧host mirror和未捕获前缀。它们不都是新语法需求，批准状态也不证明源kernel正确。FMHA的5个空when和一处wide数学/narrow管线混稿属于需要作者补齐的现稿问题；已有字段足够。

六项硬件Contract空值属于提取明确允许的`--skip-hardware`范围，不是违规，也不要求本轮填补；它限制硬件/容量结论，不能拿零硬件正文说“比模板简洁”。模板也保留pending资料和数值界限，不能当作无缺口金标准。

MoE的verb声明为1,158,927字符，alias展开为2,162,721；差额1,003,794不是再次创作的文字。其全区域引用还会增加有效视图大小。所有表格已区分raw声明、alias实例和effective，不能把它们相加来夸大冗余。

**下一步怎么改**

1. **先落实已有规则与模板写法。** 动词只补独有作用/完成条件；上游公式、数量、槽位和已声明边直接引用。条件跨角色等待必须入图；参数绑定要唯一、可定位。对待修字段给真实长短对照，不能只重复“less is more”。
2. **再做小范围语义收束实验。** 从高频capture/读写组成/退休保证，以及host/跨调用边界各取一个完整同源节点，比较“现有字段重写、共享原语定义、小量新结构”三条路径的完整性与总表示成本。不要只把长文搬到另一个自由字段，也不要只统计实例缩短而忽略共享规范变长。
3. **引入精简角色时让它交付三种结果。** 有据删除/短写；核心迁回现有结构；无法简洁承载的必要事实清单。每项写明保留依据及受影响provider/使用节点，完整修订后重新检查整个有效设计与源码；禁止为了字数达标删除未知事实。
4. **长度先作审计触发条件。** 按字段族对齐模板的短定义风格，超长时检查重复、职责和粒度；数学、选择谓词、必要来源限制分别处理。此批数据没有建立一个语义安全的统一字数阈值。

本轮已提供后续实验的反例与基线，不实施生产schema、规范或精简工作流变更。保守候选尚非一套经独立审阅的最短schema，更不是信息论不可压缩性的证明。
