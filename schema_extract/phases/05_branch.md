# P5：派生节点

本页每次只完成一个计划内的派生节点。

## 准入与应读材料

P1–P4 放行有效，本节点属于当前计划；其计划指定的直接父节点已经独立审过并合入。Runner 提供节点 ID/文件名、直接父节点、计划修订、P4 已审清单中本节点条目及短交接、已审 root 与所需祖先、固定路径源码、起始 checkpoint、依赖摘要及可写范围。本节点新开一对独立 worker/reviewer，节点内返工续用原角色。

本节点条目的 `evidence` 编号属于 P4 回执；调用中的 `node_evidence` 已解析出对应固定源码锚点，`plan_receipt` 可只读回查。本轮回执的证据独立编号。

定位只含本节点、`ancestor_entries` 中的实际祖先、P4 短交接和当前反馈；审批提供固定回执路径，按当前路径核对相关依据和未决项。不为普通派生调用加载无关兄弟的计划或审批正文。裁决另提供本节点候选 checkpoint 的只读位置。

先读 P4 交接与清单中本节点的 workload、差异和选择依据，再读共享 Contract、root 和已审直接父节点。按[公共派生规则](../../schema_docs/0.common.md#派生节点与-dispatch)核对身份；沿本路径的 host 条件与实际实现追踪差异。撰写时读取 [P3 的节点逐段方法](03_root.md#节点逐段方法)及其链接的规范 3–6，**只复用该方法，不继承 P3 的 root 准入条件和写入权限**。

## worker：可写范围与操作

Runner 在私有目录放入已审 root 和所需祖先，从计划指定的已审直接父节点复制本节点 `<id>.yaml`，移除全部 `contract`，设置新 `dispatch.id`、直接 `parent` 和 `version: 1`。worker 先核对准备结果，不能自行改选父节点。私有目录不放兄弟的在写草稿。

worker 只可改本节点 YAML 并返回验证回执。root、祖先、其他节点、`dispatch.md`、源码、规范、检查器和运行状态只读。新节点保留与 root 相同的 `meta_data.name` 和 `describe`，核对 `source` 指向本路径实际设计依据；节点 ID 与文件名、parent 与计划一致。初版从 1 开始，后续本节点内容修订按[版本规则](../../schema_template/README.md#3-填写与修订)递增，不能每次返工重置为 1。

调用中的 `first_draft` 区分首次撰写与已有节点的修订。已有 ID 因计划重开或删除后再加入时，沿 Runner 提供的版本继续，原调用、退修、时间与裁决账本仍有效。

1. 写本节点自己的非空英文 `when`，在 root 的整个契约有效域内独立给出充要选择条件。必要派生量和运行时事实在本节点说明，不叠加父 `when`，不复制或收窄 Contract。
2. 对照 P4 指定的差异和实际源码，依次执行 [P3 第 4–7 段](03_root.md#节点逐段方法)。只深入当前路径及其差异，但必须核实复制来的数学、调度、流水线、引用和适用范围；未改的内容也不能凭父节点已审而跳过适用性核对。
3. 每个节点保留完整 Design 和适用的 Realization，不依赖 parent 拼接设计。尤其核对复制来的 `realization`、替代反馈及实验引用是否仍适用于本节点；不适用的反馈不能作为新证据沿用，没有新增实现交接时按规范省略。
4. 选择本节点范围内的一例调用，按 P3 方法贯通输入到输出；记录相对父节点的已证实差异、核实过的共用内容、关键源码锚点和未决项。硬件只存在于只读 root，保持 starter 占位；GPU 验收与实测不在本阶段范围。

如果计划或父节点不合适，返回新源码证据和申请重开 P4 的具体理由；不自行换父、改索引或写兄弟。涉及 root、选择条件或共享 Contract 的问题交 Runner 按[修订规则](../tools/README.md#并行合入与计划修订)路由。算子自身缺项与框架候选遵循[分流规则](../../EXTRACT_SCHEMA.md#框架问题分流)。

## reviewer：放行门槛

在独立检查点副本中读取本节点、已审 root 和所需祖先。从仓库根目录调用现有检查器，把路径换成本节点的私有工作副本：

```sh
python3 schema_template/check_yaml.py --skip-hardware path/to/private-task/node_id.yaml
```

检查会扫描同目录直属全部 YAML，因此必须具备 root 和所需祖先并隔离兄弟草稿。退出 `0` 才满足脚本门槛；`1` 交当前修改者修复输入，若问题来自只读祖先则报 Runner 处理；`2` 作为参数、工具或环境问题分别记录，不当成设计退修。

对照固定源码确认本节点的差异、独立条件、完整设计和复制内容的适用性；核对输入到输出的主线及 P3 各段检查项。确认没有 Contract、ID/parent/文件名正确、引用能从本节点与共享 Contract 解析，其他文件未改。审阅绑定本次输入与依赖，父节点或计划改变后不能自行宣称旧审阅仍有效。

## 回执与下一位

按[回执约定](../tools/README.md#回执与短交接)只提交本节点 YAML 的改动和节点回执：来源定位、相对父节点差异、复制内容的核对、检查命令/退出码、适用调用与未决项；框架候选放 `framework_candidates`。本阶段不另生成 `handoff.md`，退修按本节点计数并遵循[统一裁决规则](../tools/README.md#退修与裁决)。

reviewer 通过后，Runner 还须核对尝试、许可差异和实际依赖，将本节点串行合入最新已审目录并复查，保存不可变 checkpoint 后才解锁子节点。子节点读取已审父产物；独立兄弟继续工作。本节点阻塞只阻塞后代。当前计划所有节点已有效合入且 P1–P4 仍有效时，Runner 启动 [P6](06_final.md) 的新 reviewer。
