# P5：其他完整设计

每次完成一个已选的非 root 具体代表，全部非 root 最多九份。worker 只写本节点 YAML，reviewer 独立审阅其有效全文。

## 准入与应读材料

P1–P4 前提仍成立，本节点属于当前拟完整集合。准备节点身份、具体源码实例、P4 的差异与共享计划、当前共享 Contract、本节点已有稿件、相关完整基线及实际内容来源。计划中的未来文件不能充当定义；采用整区引用前，来源必须已经实际存在并独立审阅。

每节点新开一对 worker/reviewer，节点内返工续用原角色；已有完整候选可先交 reviewer。worker 可沿 P4 交接定位；reviewer 按[当前文档验收](../REVIEW.md)先理解当前产物、共享 Contract 与实际来源闭包，再核对固定源码。历史批准和交接不能补足正文，也不能证明共享内容适用于本节点。

身份与整区共享遵守 [common](../../schema_docs/0.common.md#派生节点与-dispatch)，具体写作复用 [P3 的节点逐段方法](03_root.md#节点逐段方法)及规范 3–6，不继承 P3 的 root 准入条件和写入权限。

## worker：可写范围与操作

仅可修改本节点完整 YAML。root、实际来源、其他节点、`dispatch.md`、源码、规范、检查器和运行状态只读。已有草稿和修订保留自己的 raw，读取更新后的来源不能覆盖本节点正文。

1. 核对文件与节点身份、与 root 一致的任务 `name/describe`、自身真实 `source` 和版本；不复制共享 Contract。首次内容从版本 1 开始，后续按[版本规则](../../schema_template/README.md#3-填写与修订)演进；仅引用来源改变而本文件未改，不伪造本地版本增长。
2. 按已选源码实例落实本份具体配置，写自己的非空英文 `when`，说明其承担的输入和必要调用条件。范围不继承来源的条件，也不改写共同 Contract；当前参数定义和输入引起的尺寸、工作量、尾块、空工作及退出仍在本节点表达。
3. 对照实际源码，依次完成 [P3 第 4–7 段](03_root.md#节点逐段方法)。相同完整 Design 区域按[整区规则](../../schema_docs/0.common.md#design-整区引用)使用 `from`，三区可以采用不同来源，整个实际引用图无环。引用不附加 patch；需要改变内容的区完整落为本地定义。拟共享来源的批准不代替当前参数、名称、数值、接口和生产消费关系的核实。
4. 本节点独立填写必要 Realization；来源的元数据、`when`、版本、Realization 与反馈不随引用带入。当前 Contract 与有效 Design 之外仍必要的实现约束，即使其他节点也有，仍须在本节点显式填写。只有确无必要交接时才省略。
5. 用本节点范围内的具体调用贯通输入到全部输出，并覆盖会改变执行关系的其他情形。核对工作归属、提交、生产者、事件、handoff、资源寿命与复用；相对有意义基线的差异须有源码依据，引用写法变化本身不是独立设计价值。硬件和 GPU 边界沿用 [P1](01_contract.md#第-3-段硬件占位)。

## 新事实与定点返回

P5 发现有关机制与记录的新事实时，写入既有交接/问题：给出事实与来源、相关实例或基线对象、建议记录位置及对当前与后续前提的影响。不得因没有目录写权限而丢失，也不并发编辑共享 dispatch；不新增回执字段或固定报告。

| 影响 | 处理 |
| --- | --- |
| 不改变已定取舍、任务义务或其他节点前提/安排的记录增补或纠正，包括已研究但未展开的独立候选 | 继续当前节点，在 P6 由新 reviewer 核对后，按需 worker 集中更新目录并再审。 |
| 仅将本节点某区完整本地化，或改用已存在已审的真正相同整区 | 当前 P5 核对实际来源、引用图和完整适用性并独立审阅；汇集实际引用与目录摘要，在 P6 对齐，不自动回 P4。 |
| 机制识别或代表取舍须纠正，或已定位的关键关系仍未能核实、影响某项取舍 | 按 REVIEW 的[返回分工](../REVIEW.md#发现问题与批准)回 P2 修受影响判断；涉及完整集合变动时，由 P4 落实相关目录与依赖后继续。普通有价值新发现不自动触发换 root 或新增完整文件。 |
| 不改变取舍，仅已定代表的登记、写作先后、未来依赖或其他节点安排变化 | 先回 P4 修相关安排；依赖新前提的工作等待解决，未受影响稿件保留。 |
| 实际 provider 的本地定义错误 | 回定义所在的 P3/P5 修复并独立复审，核对真实使用者与相关记录。provider 正确而不适用于本节点时，按上述普通共享边界处理，不反改 provider 迁就本节点。 |
| 共享 Contract 错误 | 回 P1 修唯一定义并复核受影响前提；真实任务或来源改变按[手册边界](../README.md#输入与输出)处理。 |

本节点已选机制的正文漏项、细节错误或自身 `when` 的错误，在本 P5 修正并独立复审。重大选择与依赖变化不能拖到收尾；未受影响的稿件和历史账目保留。源缺陷及框架问题按 [REVIEW](../REVIEW.md#源实现缺陷与设计分流)和[总览分流](../../EXTRACT_SCHEMA.md#框架问题分流)处理。

## reviewer：放行门槛

覆盖本节点有效全文、共享 Contract 及实际内容来源，既审差异，也审未改和共享部分。当前 provider 的通用定义可按实际文件读一次，每个使用上下文仍逐一核对范围、名称/参数绑定、数值、跨区接口、生产消费、事件、存储寿命和本地 Realization。

独立沿固定源码完成输入到全部输出的贯通，不能靠来源批准或一段差异说明放行。核对本节点实际内容支持已定差异和保留依据，引用真实存在且已审，raw 的引用与实际本地定义可定位，适用结构检查按 `--skip-hardware` 政策通过；检查不能替代语义审阅。只读来源有误时交回定义处，不越权修复。

## 回执与下一位

通过既有回执保留实质差异、共享内容适用性、完整贯通、实际检查、真实来源和新事实去向；具体编码见[工具协议](../tools/README.md#回执与短交接)。不另生成本节点固定交接文件。

本节点经检查与独立审阅后，才可作为后续内容来源。所有选定完整设计完成后进入 [P6](06_final.md)，由新的 reviewer 对最终全部内容及待补目录事实重新验收。
