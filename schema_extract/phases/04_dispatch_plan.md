# P4：设计目录与变体记录

本页以真实 root 落实正式记录，并明确有限的非 root 写作计划。P2 已解决主要机制和代表选择；P4 不重新枚举全路由。

## 准入与应读材料

P3 完整 root 已通过适用检查与独立审阅，P1、P2 的前提仍成立。准备当前 root、dispatch 草案、P3 交接、相关固定源码及写入范围；修订时一并读取受影响的现有完整设计与计划。首次 P4 使用新的一对 worker/reviewer。

worker 可沿交接定位；reviewer 按[当前文档验收](../REVIEW.md)先读完整 root 和当前目录，再核对相关源码与实际依赖。dispatch 的正式格式只以 [common 的选择条件与索引](../../schema_docs/0.common.md#选择条件与索引)为准。

## worker：可写范围与操作

只写 `dispatch.md` 及既有过程交接中的计划说明。root 和现有完整 YAML 只读，不提前创建未来文件，不改运行状态。

1. 用完整 root 核对 P2 的机制判断和 P3 新发现，使已知知识有明确去处。参数、局部变化及已知组合按[记录规则](../../schema_docs/0.common.md#局部记录与完整方案)表达；不把每个配置差异都留成 P5 新文件。
2. 对实际存在的完整基线，落实正式记录与已有对象的对应，核对差额、联动、条件和依据。源码选择条件、设计成立条件与实验覆盖分别使用各自证据；精确参数和 `when` 以 YAML 为准。
3. 核对拟完整集合含 root 不超过十份，非 root 最多九份，每份有独特的完整设计价值。为每份未来代表说明具体源码实例、保留理由、相对有意义基线的实质差异、预计本地或共享的区域、必要先后顺序及待落实位置。不得只为提供共享区域增加没有独立设计价值的文件。
4. 未来文件用普通文本文件名并标明“仅计划”，不创建可点击的假链接。依赖未来基线的条目也仅是记录计划：已知机制、差异和依据先保留，实际对象命名及接口绑定待正文落实。尚无正文的对象不能写成已经定义，拟共享不能写成已经证明相同。
5. 对照计划核实剩余未知。P2 的暂拟名称在已有基线中落实后，才能成为正式记录的定位；依赖未来正文的条目继续作为计划。若只缺正文中的命名、位置或完整展开，可以明确交给对应作者落实；若尚不能判断实际差异、必要值、生产者或完成条件，应补研究或阻塞受影响任务，不能伪装成待命名事项。

共享意向用于安排写作，不冻结 P5 的写法。P5 在审过实际来源后，可以将本节点某区完整本地化，或改用已存在已审的真正相同整区；仅影响本节点且引用图合法时，由当前 P5 独立审阅，实际引用和目录摘要在 P6 对齐。改变完整集合、名额、未来依赖或其他节点前提/安排时，才先回本阶段修订相关计划。

新证据动摇代表选择回 [P2](02_dispatch_draft.md)，root 定义或自身范围错误回 [P3](03_root.md)，共享 Contract 错误回 [P1](01_contract.md)。只修受影响判断，未受影响代表不重选。来源限制照实保留，不缩小 Contract 或虚构 fallback；其余边界见[提取总览](../../EXTRACT_SCHEMA.md#来源缺项与验收边界)。

## reviewer：放行门槛

独立读懂完整 root、目录及当前相关实际依赖，包括未改内容；先前 P3 批准不免除本次阅读，也不要求再发一份 P3 批准。按[保留与降级判据](../REVIEW.md#完整设计的保留与降级)，对每份拟完整设计明确保留、转为目录记录或合并的理由；未能有据说明完整身份必要性的候选不得派发 P5。核对记录是否准确定位现有基线与差额，已知知识是否均有去处。

非 root 任务应足以让新作者定位实际实例、理解实质差异和必要依赖。尚未生成的正文不作完整设计验收，未来 `from` 的同一性也不在本阶段获批。计划的先后顺序必须可成立，不能依赖相互等待的未来定义；正式记录与计划内容应当清楚可辨。已知机制缺少语义依据时不能放行，已有基线存在的问题交回定义处。

## 回执与下一位

在既有回执及 P4→P5 短交接中保存经审阅的代表选择、具体实例、差异、拟共享来源、待落实对象和影响范围，不另建永久配置或知识台账。编码见[工具协议](../tools/README.md#回执与短交接)。

放行后按实际内容依赖推进 [P5](05_branch.md)，每个完整代表使用新的一对 worker/reviewer。没有非 root 时跳过 P5，仍进入 [P6](06_final.md) 的独立全目录终审。
