# 定点返回

具体事实或关键关系表明上游决定有误时，可使用本次 reopen_targets；填写稳定 issue_id、target、reason 和本次 source_evidence 索引。普通提案的 reopen 为 null。

共享 Contract 回 P1，机制或代表判断回 P2，root 定义及自身 when 回 P3，已定代表的登记或写作安排回 P4。真实任务或固定来源改变用 external，交 Supervisor 另建运行。固定源码中的具体误读同样可纠正，不要求必须首次发现新行。

P5 的 provider_reopen_targets 只来自当前实际来源。定义本身错误回真实 P3/P5 定义处；来源正确但不适用于当前绑定时，修本节点。issues.scope 定位真实文件与 DESIGN 区域，artifact_evidence 引用 raw 定义，相关 issue 与 reopen 共享至少一个本次源码证据索引。

本轮刚写入 from 时，reopen_targets 中已提供且独立审过的节点仍需通过最终 raw 的真实来源关系核验；仅被列为可读材料不构成返回资格。P6 可返回最终全目录中实际定义所在的 P5 节点。稳定 issue_id 不因重写问题文字、变更引文范围或 provider 版本而改变。

普通记录、新发现或本节点整区本地化不自动重开。P3 交 P4 落实记录，P5 交 P6 汇集核对；未受影响稿件、已用预算与稳定问题身份保留。
