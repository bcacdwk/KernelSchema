# P4：设计目录与变体记录

本页将 P2 已定机制和代表取舍落实为目录、对象定位与有限的非 root 写作计划。

## 准入与应读材料

P3 完整 root 已通过适用检查与独立审阅，P1、P2 的前提仍成立。准备当前 root、dispatch 草案、P3 交接、相关固定源码及写入范围；修订时一并读取受影响的现有完整设计与计划。首次 P4 使用新的一对 worker/reviewer。

worker 可沿交接定位；reviewer 按[当前文档验收](../roles/reviewer.md)先读完整 root 和当前目录，再核对相关源码与实际依赖。dispatch 的正式格式只以 [common 的选择条件与索引](../../../schema_docs/0.common.md#选择条件与索引)为准。

## worker：可写范围与操作

只写 `dispatch.md` 及既有过程交接中的计划说明。root 和现有完整 YAML 只读，不提前创建未来文件，不改运行状态。

1. 依据 P2 已定机制与取舍，结合 P3 的实际定义和新发现，落实已识别知识的去处。参数、局部变化及已知组合按[记录规则](../../../schema_docs/0.common.md#局部记录与完整方案)表达；不把每个配置差异都留成 P5 新文件。
2. 对实际存在的完整基线，落实正式记录与已有对象的对应，核对差额、联动、条件和依据。源码选择条件、设计成立条件与实验覆盖分别使用各自证据；精确参数和 `when` 以 YAML 为准。
3. 核对已选完整代表含 root 不超过十份，非 root 最多九份，每份有独特的完整设计价值。为每份未来代表说明具体源码实例、保留理由、相对有意义基线的实质差异、预计本地或共享的区域、必要先后顺序及待落实位置。不得只为提供共享区域增加没有独立设计价值的文件。
4. 未来文件及依赖未来基线的线索放在现有“范围”中，文件名用普通文本并标明“仅计划”；正式变体条目只直链实际存在且完整的基线。依赖未来基线的内容仍是记录计划：已知机制、差异和依据先保留，实际对象命名及接口绑定待正文落实。尚无正文的对象不能写成已经定义，拟共享不能写成已经证明相同。
5. 对照计划核实剩余未知。P2 的暂拟名称在已有基线中落实后，才能成为正式记录的定位；依赖未来正文的条目继续作为计划。若只缺正文中的命名、位置或完整展开，可以明确交给对应作者落实；若尚不能判断实际差异、必要值、生产者或完成条件，应定向核实，仍不明则按 REVIEW 的[返回分工](../roles/reviewer.md#发现问题与批准)阻塞受影响判断或任务，不能伪装成待命名事项。

共享意向用于安排写作，不冻结 P5 的写法。P5 在审过实际来源后，可以将本节点某区完整本地化，或改用已存在已审的真正相同整区；仅影响本节点且引用图合法时，由当前 P5 独立审阅，实际引用和目录摘要在 P6 对齐。

已定代表的登记、写作先后、未来依赖或其他节点安排需要改变时，由本阶段修订；涉及机制识别或代表取舍纠错，先按 REVIEW 的[返回分工](../roles/reviewer.md#发现问题与批准)回 P2，再落实相关计划。root 定义或自身范围错误回 [P3](03_root.md)，共享 Contract 错误回 [P1](01_contract.md)。只修受影响判断和安排，未受影响代表不重选。来源限制照实保留，不缩小 Contract 或虚构 fallback；其余边界见[提取总览](../../../EXTRACT_SCHEMA.md#来源缺项与验收边界)。

## reviewer：放行门槛

独立读懂完整 root、目录及相关实际依赖，包括未改内容；先前 P3 批准不免除本次阅读，也不要求再发一份 P3 批准。核对当前材料是否支持 P2 已定机制、差异与保留依据，正式记录是否准确定位已有基线及差额，已知知识是否有去处。具体内容与原判断不符时，按 REVIEW 分清正文落实与选择纠错。

非 root 任务应足以让新作者定位实际实例、理解实质差异和必要依赖。尚未生成的正文不作完整设计验收，未来 `from` 的同一性也不在本阶段获批。计划的先后顺序必须可成立，不能依赖相互等待的未来定义；正式记录与计划内容应当清楚可辨。已知机制缺少语义依据时不能放行，已有基线存在的问题交回定义处。

## 回执与下一位

plan 每项为 `{id, wait_for}`，恰好覆盖已选非 root；wait_for 可空或含多个已选 ID，禁止自依赖和循环。它约束本实例在该等待集合下的首次派发准入；实例或等待集合改变时重新核验。实际共享由 P5 raw 的整区 from 决定，来源批准持续核对。P2 的 ID 与具体实例不在本阶段更改。

在既有回执及 P4→P5 短交接中保存已定代表的具体实例、差异和经审阅的写作安排，包括拟共享来源、待落实对象和影响范围，不另建永久配置或知识台账。编码见[工具协议](../operations/response.md)。

放行后按已审写作安排推进 [P5](05_branch.md)，每个完整代表使用新的一对 worker/reviewer。没有非 root 时跳过 P5，仍进入 [P6](06_final.md) 的独立全目录终审。
