# P3：root 设计

本页按 P2 已选具体实例完成 root 的 Design 和必要 Realization；“节点逐段方法”也供 P5 使用。

root 的 Math_reshape、Work_schedule、Tile_pipeline 全部本地完整定义。P5 复用本节时，按其阶段规则审阅本地与显式整区引用构成的完整有效 Design；名称、参数及跨区接口在使用节点中绑定，Realization 始终本地。

## 准入与应读材料

P1 共享 Contract 与 P2 的机制识别、代表选择已通过。准备当前 root 草稿、dispatch 草案、P2 短交接、所选具体实例的固定源码入口和本次可写范围。P3 新开一对独立 worker/reviewer。

worker 可沿交接定位；reviewer 按[当前文档验收](../roles/reviewer.md)从当前 root 和目录草案建立理解，再沿选定实例核对 host、提交与实现。按当前段读取规范，不要求预先通读全部源码。来源遵守[公共规则](../../../schema_docs/0.common.md#来源与证据)，文件修订见[模板说明](../../../schema_template/README.md)。

## worker：可写范围

只修改 `root.yaml` 的 Design、必要 Realization、自身实际 `META_DATA.Dispatch.when` 及随本文件内容修订递增的版本。共享 Contract、已选代表身份及来源、dispatch 草案和其他文件只读。

完善自身 `when` 是把已选具体方案的真实范围写全，不授权加入其他配置的选择逻辑或改变共同 Contract。同一已选机制的范围、细节及已知内容的补写在本阶段完成。具体事实或关键关系缺口影响 root 的识别与代表取舍时，按 REVIEW 的[返回分工](../roles/reviewer.md#发现问题与批准)修 P2 的相应判断；共享 Contract 错误回 [P1](01_contract.md)。新事实和影响在既有交接中说明，不在下层补写上层缺失定义。

## 节点逐段方法

本节第 4–7 段只写当前选定的一套机制。定义自己的参数和关系，保留随输入变化的尺寸、索引、工作量及必要循环、尾块、空工作和退出；其他配置的取值、模式或组合交目录记录，不在 YAML 中用开关或公式选路。区别见[参数变化与结构变化](../../../schema_docs/0.common.md#参数变化与结构变化)。

每段围绕本段问题读源码，写入、保存并回查后再继续；复杂段可以分轮完成。授权范围内的上层定义有误时，先修唯一定义，再复核下游。保留设计事实与代价，源缺陷和资料缺项按[共用分流方法](../roles/reviewer.md#源实现缺陷与设计分流)处理，硬件与 GPU 边界沿用 [P1](01_contract.md#第-3-段硬件占位)。

### 第 4 段：数学改写

读取[数学改写规范](../../../schema_docs/3.design.math_reshape.md)。对照共享 Contract，追踪当前方案的实际求值、舍入、状态推进和物化，将变化写成从输入到全部输出的数学关系。会改变数值行为的协作关系深入源码核实，再抽象为分组、映射或递推；数学区不写线程布局、屏障编号或指令组织。留给下游确定的参数按规范绑定。

写完 `DESIGN.Math_reshape`，沿公式核对值的定义、精度路径、初末状态与寿命。用可核对的量表达收益和代价，包括实际执行的掩码、补齐和辅助计算；算法名称和源码注释不能代替公式或证据。

### 第 5 段：工作调度

读取[工作调度规范](../../../schema_docs/4.design.work_schedule.md)。从一份完整可分配工作出发，回看提交、工作索引、循环与领取逻辑，写清输入、局部遍历、产物和执行者，再确定 step、映射、分配、提交与交接。数据块描述整份工作，不把每线程 fragment 当作 worktile；辅助计算和部分结果合并也须有实际执行者。

涉及录图、缓存或调用前缀时，按[提交身份](../../../schema_docs/4.design.work_schedule.md#提交身份与字段)和[调用边界](../../../schema_docs/4.design.work_schedule.md#调用边界)核对实际发生的工作与副作用，不把 host 返回或拒绝误作在途工作已经结束。写完 `DESIGN.Work_schedule`，核对所有数学计算有工作归属，局部归约未被误拆为独立工作，生产区域覆盖消费区域，step、launch 与 handoff 符合实际调用关系。

### 第 6 段：微流水线

读取[微流水线规范](../../../schema_docs/5.design.tile_pipeline.md)。在已确定的工作边界内，追踪影响推进与重叠的值和状态，包括主数据缓冲、寄存器预取、辅助统计量与工作领取协议。沿产生、保留、发布、全部读取、覆盖或重置划分动作，再落实执行角色、重复索引、依赖和资源视图。分别核实操作发射、数据可读与存储可覆盖的保证，将同步调用还原为所保护的关系。动作内对象、跨动作接口和说明深度按 DOC5 的[动作声明](../../../schema_docs/5.design.tile_pipeline.md#基础动词与动作声明)处理；从当前作用域沿值的实际使用追查，不按源码临时变量逐一增加 schema 对象。

写完 `DESIGN.Tile_pipeline`，检查首轮、稳态、末轮、未取得工作和终止情形，追到相邻工作及跨调用状态。既确认下一份工作何时可开始，也确认前一份工作的哪些读取或写回仍继续。被丢弃或没有消费者的值若仍发生求值、搬运或状态更新，应如实保留；源码未排空的流水不能隐含重置。当前机制必要的条件等待照常表达，不用其他配置的等待位置替换本方案。

### 第 7 段：实现交接

读取[实现交接规范](../../../schema_docs/6.realization.md)。对源码中的实现选择做删除测试：替换它会破坏哪项既定语义或执行关系，或有什么具体成本理由需要交接？`REALIZATION` 只保留上游尚未表达的必要条件与有依据的选择，不因“源码使用了它”就列为硬要求；没有必要交接时省略。

原语顺序、近似误差和容量判断须有匹配版本的依据。已有实验或替代反馈只支持实际覆盖的版本与范围，不虚构实验，不把某次实现记录升级为设计保证。

最后选本节点适用范围内的一例具体调用，将各层从输入连到全部输出，核对符号、工作、资源和事件引用，并回查关键决定的源码或资料依据。记录输入条件、主线定位和未决问题；这是一轮源码对照，不要求 GPU 运行。

## reviewer：放行门槛

通读完整 root，包括元数据、算法 Contract 和本轮未改内容，按[当前文档验收](../roles/reviewer.md)检查独立理解、分层、全文一致和内容必要性。对当前方案中改变提交、成员、物化或事件存在性的各类情形分别贯通，不能以一个正常例子代替其他结构情形，也不能以此重新容纳其他配置。

独立沿 Contract、P2 所选实例和固定源码核对数学改写与数值路径、全部输出的工作归属、局部动作依赖、寿命和复用。特别核对跨迭代、相邻工作和末轮仍在继续的读取或写回；压缩不能漏掉已有关系或补造逻辑依赖。必要实现条件、引用与范围应足以解释计算、访存和重叠的主要因果。

完成与任务规则匹配的适用结构检查，按 `--read-only --skip-hardware` 政策跳过硬件；结构检查不代替[完整语义审阅](../../../schema_template/README.md#校验边界)。检查范围使用当前 root 及所需材料，不混入无关草稿；只读前提的问题交回定义处，不能越权修改。

## 回执与下一位

在既有回执和 P3→P4 短交接中保留具体调用的贯通结论、关键源码依据、实际检查、已定理由、影响代表或变体记录的新发现及后续入口。编码见[工具协议](../operations/response.md)。

放行后进入 [P4](04_dispatch_plan.md)，新开一对 worker/reviewer，从真实完整 root 落实目录和有限的非 root 计划。
