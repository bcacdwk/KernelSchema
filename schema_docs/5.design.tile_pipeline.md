#### 核心思想

`tile_pipeline` 在已经确定的 worktile 和 worker 内，描述执行角色怎样推进计算、交接数据和复用资源。它接收 `math_reshape` 给出的值、精度、初值及物化决定，接收 `work_schedule` 给出的工作归属、执行成员、工作序列与跨 phase 关系，再将这些设计转化为 Coder 必须保持的局部执行约束。

本区的基本对象是 **lane**。一个 lane 是承担一类动作的 warp 或协作 warp group，不是单个线程，也不一定是独占的硬件执行引擎。例如，MMA lane 可以是负责发射异步矩阵乘的一个 warp，而不是执行矩阵乘的全部硬件。

<!-- SYNC(2.contract)：lane 所用的执行单元名称取自该区的 `execution`；warp 与 warp group 只是 NVIDIA 上的实例，其他设备登记的是 wavefront、Cube/Vector 核等。改完删除本注释。 -->

本区保留四类信息：

| 信息 | 回答的问题 |
| --- | --- |
| 角色与动作 | 哪些 warp 承担什么工作，各自怎样推进 |
| 索引与重复 | 动作属于哪次工作、哪次局部迭代 |
| 依赖与发布 | 消费者何时可以继续，哪些结果可以提前使用 |
| 资源与别名 | 什么继续存在，哪些逻辑值共用存储，何时可以覆盖 |

`phase` 使用上游相同的身份，不复制 `work_schedule.flow`。phase 映射的书写顺序不代表执行顺序，新增一个 phase 标签也不自动产生 kernel launch、全量屏障、物化或资源重建。

`team` 是可选的公共上下文，只容纳多个 lane 共用的索引域、执行作用域引用和必要的对外交接里程碑。它不是第二张流程图。lane 的实际协作仍由 `pipe`、`edge` 和 `resource` 表达；没有公共上下文时，不填写空的 `team`。

动作采用设计级粒度，而不是源码调用级粒度。两个连续动作之间，只有出现重要的数据发布、资源归还、执行角色切换、独立循环或重叠机会，才值得拆开。数学内部步骤由上游定义，地址计算、线程级 layout、指令语法及普通原语的实现细节交给 Coder。

本区交付的是依赖和资源约束，不是实测时间线。没有依赖，只表示设计没有禁止重叠，不保证硬件一定同时执行；存在数据边，也不代表存储已经可以覆盖。

#### 字段定义

**结构轮廓**

下面是字段层次示意，不是可直接填写的 YAML。尖括号表示具名映射的实例键，不是模板字段。

```text
tile_pipeline
  thesis
  resource.<resource_id>
  phase.<phase_id>
    team
      scope
      domain.<index_id>
      port.<port_id>
    resource.<resource_id>
    lane.<lane_id>
      info
      pipe
      edge
```

本版保留 `lane.info / pipe / edge`，使用嵌套 `repeat` 表达多段循环，使用可选 `team` 提供公共上下文。省略规则、`flatten` 及同步动作例外是本区当前版的局部填写约定，不表示已经完成事件展开或实现验证。

**固定结构与开放位置**

| 位置类型 | 路径 | 允许的内容 |
| --- | --- | --- |
| 固定结构 | `tile_pipeline` | 只允许 `thesis / resource / phase` |
| 固定结构 | `phase.<id>` | 只允许 `team / resource / lane` |
| 固定结构 | `team` | 只允许 `scope / domain / port` |
| 固定结构 | `lane.<id>` | 只允许 `info / pipe / edge` |
| 固定结构 | 资源条目、view 条目、info、pipe、edge、动作契约 | 只允许本节字段表列出的字段 |
| 具名映射 | `phase / resource / lane / domain / port / view` | 可以增加当前案例的身份、资源名、角色名、索引名、端口名或视图名；条目仍遵守固定结构 |
| 受控内容扩展 | `info.verb` | 可以增加动作词及其短契约，不能在此加入任意调度字段或重写数学算法 |
| 受控内容扩展 | 域定义、索引表达式、view 模式 | 可以使用已声明语法填写新的域和映射，不能自行增加运算符、函数或域类型 |

未知字段必须报错，不能被忽略或收进 `notes / misc / extra`。增加一个 lane 名不属于修改模板；增加一个新的 lane 同级字段则属于结构修改。

本版没有允许实例任意新增模板字段的位置。确需扩展域类型、事件类型或资源属性时，应先补充该扩展的含义、值形式、适用条件和实例，再纳入相应固定结构。

**外层与公共上下文**

下表中的路径均相对于 `tile_pipeline`。

| 字段路径 | 值的形式 | 填写条件 | 含义与约束 |
| --- | --- | --- | --- |
| `thesis` | 非空英文字符串 | 必填 | 用一句话概括局部组织的主要取舍，不复述完整依赖图 |
| `phase` | 非空具名映射 | 必填 | 键集合与上游对应的 phase 定义一致 |
| `phase.<id>.lane` | 非空具名映射 | 必填 | 当前 phase 的执行角色 |
| `resource` | 资源具名映射 | 有跨 phase 共享的物理分配时填写 | 同一物理分配只定义一次；每个条目显式绑定上游作用域 |
| `phase.<id>.resource` | 资源具名映射 | 有需要保留的角色规模、容量、存续或别名约束时填写 | 默认属于该 phase 继承的执行作用域 |
| `phase.<id>.team` | 固定结构映射 | 使用其中至少一项内容时填写 | 没有公共上下文时省略 |
| `team.scope` | 上游驻留身份引用字符串 | 无法唯一继承，或需要明确绑定同一驻留实例时必填 | 只引用既有身份，不创建融合、launch 或新 worker |
| `team.domain` | 索引域具名映射 | 多个 lane 共用索引，或使用派生连续索引时填写 | 统一索引身份和边界，不要求各 lane 锁步推进 |
| `team.port` | 端口具名映射 | 上游实际需要引用局部里程碑时填写 | 不为每个普通输出机械建立端口 |
| `team.port.<id>` | 非空事件引用列表 | 定义端口时必填 | 所列事件全部满足时，该里程碑成立；不增加动作或同步机制 |

省略 `team.scope` 表示继承上游唯一确定的驻留身份，不表示“每个 phase 自动建立一个新作用域”。无法继承时必须报告缺少接口。

**待确认：** 上游尚需确定驻留身份和 port 连接在 `work_schedule` 中的具体承载位置。本节只规定引用对象及其语义，不反向增加上游字段。下文案例的作用域均由案例前列出的只读执行条件唯一确定。

**资源条目**

根部 `resource.<id>` 与 phase 内资源使用同一种条目结构。

| 字段 | 值的形式 | 填写条件 | 含义与约束 |
| --- | --- | --- | --- |
| `scope` | 上游驻留身份引用字符串 | 根部资源必填；phase 内通常省略 | phase 内显式填写时，必须与该 phase 的有效作用域一致 |
| `space` | `warp / smem / tmem / register` | 必填 | 本版封闭枚举；全局中间量的分配由上游负责 |
| `member` | `each` 或非负整数 CTA member ID | 多 CTA worker 的成员局部资源必填 | `each` 表示每个 CTA member 各有一份；省略表示 worker 范围内的一份资源 |
| `slot` | 正整数或可求值的整数表达式 | 多槽资源必填 | 省略等于一槽；只统计物理槽数 |
| `shape` | 非空维度列表 | 张量容量或 warp 池必填 | 表示每槽容量，不包含 `slot` 和 `member` 的重复次数 |
| `dtype` | 上游已明确、位宽可确定的数据类型 | 使用 `shape` 的存储资源必填 | warp 池不填写；本节不另造一套数据类型命名 |
| `byte` | 正整数 | 非张量存储预算使用 | 表示一份分配的总字节数；与 `shape / dtype / slot` 互斥 |
| `view` | 逻辑视图具名映射 | 需要表达槽位轮转、物理别名或重要子区域时填写 | 不要求为每个普通值建立视图 |
| `register` | 非负整数 | 只用于 `space: warp`，且需要共同寄存器预算时填写 | 池内默认的每线程 32-bit register 数量 |
| `meaning` | 非空英文字符串 | 资源名、容量和视图仍不足以说明必要约束时填写 | 只补充资源契约，不作为一般说明的收纳区 |

<!-- SYNC(1.contract)：1.contract.algorithm_requirement.md 与 work_schedule 的 shape 写成具名轴（轴名: 大小），本区资源 shape 只写大小。修改时决定统一写法，或写明差异理由。改完删除本注释。 -->

`space: warp` 使用一维 `shape` 表示每份 warp 池的规模，不填写 `dtype / byte / slot / view`。其成员范围与 `lane.info.member` 必须一致。

`space: register` 的张量描述需要保留的逻辑状态，不是精确的线程级寄存器布局。其元素数不能再次叠加到已经登记的每线程寄存器预算上。未列出编译器临时量，不等于临时量或 spill 为零。

资源预算中的默认值只负责解释省略，不能覆盖上游任务条件。例如，省略 `slot` 可以解释为一槽，但省略一个实际存在的双缓冲资源不能被解释为“不重要”。

**逻辑视图**

`view` 的键可以是逻辑对象名，如 `X`，也可以是带索引的模式，如 `K(n)`。

| 字段 | 值的形式 | 填写条件 | 含义与约束 |
| --- | --- | --- | --- |
| `slot` | 整数或受限整数表达式 | 父资源多槽时必填 | 选择物理槽，结果必须落在父资源槽范围内 |
| `part` | 区域选择字符串 | 只占用物理槽的一部分时填写 | 省略表示整槽 |
| `dtype` | 数据类型 | 视图解释不同于父资源类型时填写 | 省略继承父资源类型，不产生新分配 |

`view` 模式中的索引名是局部形参。例如，`K(n)` 中的 `n` 用于将实际逻辑版本映射到物理槽，不会声明或扩大一个执行循环。

`part` 先按父资源的物理形状和数据类型解释，再应用视图类型。比如在 FP32 的 `[128,128]` 槽中，`column[64:128]` 选中后半部分存储；将其解释为 BF16 不增加容量。逻辑张量形状仍来自上游，不能只凭 dtype 转换猜测。

**lane 与 info**

| 字段路径 | 值的形式 | 填写条件 | 含义与约束 |
| --- | --- | --- | --- |
| `lane.<id>.info` | 固定结构映射 | 必填 | 角色的成员、默认执行性质和动作契约 |
| `info.member` | 成员选择字符串 | 除单 CTA、单 lane、唯一 warp 池的情形外必填 | 如 `cta[0].warp[0:4]`、`cta[*].warp[14:15]` |
| `info.mode` | `sync / async` | 必填 | 该 lane 动作的默认执行模式 |
| `info.order` | 受限列表 | async lane 必填；sync lane 可省略 | sync 只允许 `[done]`，省略与其等价；async 允许 `[issue]` 或 `[issue, done]` |
| `info.verb` | 动作词列表，或动作契约具名映射 | 使用通用契约之外的动作语义、同步例外或特定原语保证时填写 | 仅使用通用动作时可省略 |
| `info.register` | 非负整数 | 该角色需要单独的寄存器预算时填写 | 覆盖所属 warp 池的默认预算，不与默认值相加 |
| `lane.<id>.pipe` | pipe 块 | 必填 | 当前角色的动作和重复结构 |
| `lane.<id>.edge` | 依赖分类映射 | 存在不能由本角色顺序及已声明原语契约保证的前驱条件时填写 | 没有额外依赖时省略 |

省略 `info.member` 的短写只适用于：上游 worker 是一个 CTA、当前 phase 只有一个 lane，且可见资源中只有一个对应的 warp 池。此时该 lane 使用整个池。其他情况不得通过省略来猜测成员归属。

动作契约映射的值允许以下两种等价写法：

```yaml
verb:
  load: Load the member-local partition.
```

```yaml
verb:
  load:
    meaning: Load the member-local partition.
```

长写只允许以下字段：

| 字段 | 值的形式 | 填写条件 | 含义与约束 |
| --- | --- | --- | --- |
| `meaning` | 非空英文字符串 | 定义或收紧案例动作契约时必填 | 说明该动作承诺的输入使用、结果、发布或归还边界 |
| `mode` | `sync` | async lane 中保留同步控制动作时填写 | 本版只支持这种例外，不支持在 sync lane 中隐式插入异步动作 |
| `source` | 固定版本源码定位字符串 | 特定保证不能由通用契约或已有固定资料入口唯一确定时填写 | 使用 `repository@ref:path::symbol`；不复制源码 |

`source` 不是免责说明。动作仍须用 `meaning` 交代设计依赖的保证，不能要求读者先读完源码才能知道它何时完成。

**pipe 与重复域**

每个 pipe 块只允许 `repeat / prologue / steady / epilogue`，子块结构相同。

| 字段 | 值的形式 | 填写条件 | 含义与约束 |
| --- | --- | --- | --- |
| `repeat` | 域名、域切片引用，或单项局部域定义映射 | 当前块包含重复主体时填写 | 不填写时，三个区域各执行一次 |
| `prologue` | 动作或子块的有序列表 | 有一次性开头动作时填写 | 在当前块开始时执行一次 |
| `steady` | 动作或子块的有序列表 | 有主体动作时填写 | 有 repeat 时按域重复，否则执行一次 |
| `epilogue` | 动作或子块的有序列表 | 有一次性收尾动作时填写 | 在当前块的全部主体之后执行一次 |

域定义只允许以下形式：

| 形式 | 含义 |
| --- | --- |
| `[lower, upper]` | 半开整数域，依次取 `lower` 至 `upper-1` |
| `{range: [lower, upper], step: width}` | 以 `width` 为步长的块起点域 |
| `assigned_worktile` | 上游给当前 worker 的有序工作序列；本区只枚举其本地序号 |
| `{flatten: [outer, inner]}` | 将已定义的有序域积展平为一个连续序号，后一个域变化更快 |

局部域短写如：

```yaml
repeat: {k: [0, 8]}
```

它只在当前 lane 的该块中定义 `k`。多个 lane 需要共同解释同一个域时，应在 `team.domain` 定义一次，然后各自使用 `repeat: k`。

本版 `flatten` 用于有限、固定内层范围的有序域积。不在这里引入不规则循环树、任意生成器或条件执行语言。

**edge 与 port**

`edge` 只允许三种分类：

| 字段 | 含义 |
| --- | --- |
| `data` | 操作数、计算结果或显式发布已经满足 |
| `reuse` | 旧内容的必要使用已经结束，允许覆盖其存储 |
| `sync` | 数据与复用之外的协议放行条件 |

每一类均采用：

```text
等待动作引用 → 非空前驱事件引用列表
```

三类边具有相同的“必须满足”约束作用，分类用于保留原因，不代表三种不同的调度机制。

`port` 只给实际事件组增加一个对外名称。它不能生成数据可见性、设备通知、跨 CTA 轮询或其他原本不存在的机制。

**空值与省略**

<!-- SYNC(1.contract)：1.contract.algorithm_requirement.md 规定没有内容的可选字段直接省略，不写 {} 或 []。本节“{} / [] 与省略等价”改为只保留省略；pipe: {} 若确有含义，应像 work_schedule 的 partition: {} 一样作为明确的数据值单独说明。改完删除本注释。 -->

`null`、空字符串和重复 YAML 键均不合法。

可选映射的 `{}` 与省略等价；pipe 区域的 `[]` 与省略等价，推荐省略。`pipe: {}` 可以表示明确没有持续动作的角色，但不应仅为列出空闲 warp 而创建 lane。

`phase`、`lane` 必须非空。已定义的 edge 规则和 port 必须有非空引用列表；没有前驱或没有里程碑时，应省略该条目。资源条目不能为空。

#### 语法规则

**名称、身份与顺序**

自定义 ID 使用英文标识符：字母或下划线开头，后接字母、数字或下划线，大小写敏感。真实仓库路径、源码函数名和外部符号保持原样。

phase、lane、resource、domain 和 port 使用各自的具名映射。增加实例键不改变固定字段集合。

映射的书写顺序没有执行含义。执行顺序只来自 pipe 列表、repeat、edge、已声明的原语顺序，以及上游工作组织。`flatten` 中域名列表的顺序具有含义，因为它确定连续序号的映射。

动作身份由上游执行实例、phase、lane、CTA member 和规范化动作名共同确定。重复展开后，身份必须唯一。不能在多轮 repeat 中重复一个没有索引区分的固定动作，再由检查器暗中附加轮次。

**动作写法与通用动作**

动作采用：

```text
verb:object
verb:object(index)
mma:A(index)@B(index)
```

动作名同时是引用身份。对象位置可以是上游张量、局部状态、已定义的联合计算或协议目标，不要求每个对象名都代表新张量。联合名称如 `T_beta`、`State_Local` 必须能从动作契约明确知道其内容，不能依靠拆分下划线猜测。

常用动作的基础契约如下：

| 动作词 | 基础含义 |
| --- | --- |
| `load` | 将已定义值读入本角色使用的局部存储；不自动发布给其他角色 |
| `store` | 将已有结果写入上游规定的物化位置；异步源缓冲的提前归还需另行表达 |
| `zero` | 将目标累加状态初始化为零 |
| `compute` | 执行上游已经定义的计算，不隐含全局物化或跨角色发布 |
| `produce` | 执行目标对应的上游计算，并写入上游规定的物化位置 |
| `mma` | 执行已指定操作数和精度的矩阵乘累加；初始化、分段和特殊顺序保证须明确 |
| `rowsum` | 更新上游定义的行分母状态，不自行改变数学递推 |
| `publish` | 除形成目标值外，还满足声明的消费范围所需的可见性和发布条件 |

`wait / release / update / scan / solve / advance` 等动作可以使用，但其案例含义必须在 `info.verb` 中明确，或由已经固定的通用动作契约唯一确定。不能只因为名字常见，就默认某个 release 释放了全部缓冲，或某个 solve 同时产生了所有中间量。

`info.verb` 的三种用法分别是：

- 省略：从 pipe 取得实际动作词，全部使用通用契约及上游定义。
- 列表：声明使用的基础动作词，集合必须与 pipe 一致；不改变动作含义。仅为重复 pipe 中可推导的词汇时，通常可以省略。
- 映射：只登记需要补充或收紧的动作契约，其余实际动作继续使用通用契约。

映射不是部分白名单。一个未出现在映射中、但具有通用契约的 `rowsum` 或 `load` 仍然合法；一个既没有通用定义、也没有案例契约的动作则必须报错。

动作契约可以合并内部计算，但不能改写上游公式、精度或物化决定。

**事件与 lane 内顺序**

通用事件只有：

| 事件 | 含义 |
| --- | --- |
| `issue` | 动作已经发射或开始执行 |
| `done` | 该动作承诺的完成条件已经获保证 |

`done` 是设计可以依赖的完成保证，不是测得的硬件时间戳。不同动作可以共享同一次原语完成通知，只要该通知确实覆盖它们的完成条件。

每个动作自身满足 `issue → done`。lane 内的规则为：

| lane 情形 | 顺序规则 |
| --- | --- |
| `mode: sync` | 当前动作 done 后，才推进到下一个动作 |
| `mode: async, order: [issue]` | 按 pipe 顺序发射，不规定异步完成顺序 |
| `mode: async, order: [issue, done]` | 分别保持发射顺序和异步完成保证顺序，不增加“前一个 done 后才能发射下一个”的边 |

async lane 中的 `verb.mode: sync` 是明确的同步例外。它在 pipe 的对应位置发射，完成后该 lane 才继续后续动作；已经发射的其他异步操作可以继续在途。它等待什么，由自己的契约和前驱决定，不默认等待此前所有异步操作完成。

在这种混合 lane 中，发射顺序覆盖所有动作；`order` 中的异步 done 顺序只约束异步动作，不把同步控制动作偷偷变成全队列排空点。

本版没有通用 `@begin` 或 `@read` 事件。`read:final_high(t)` 是一个普通动作，其完成事件仍是 `done`。需要表达源缓冲已可归还时，应定义有明确原语依据的动作，例如 `release:O_high(t)`；它不能冒充整个目标写入完成。

**事件引用**

完整形式为：

```text
Lane[member]/action@event
```

省略规则如下：

| 写法 | 解释 |
| --- | --- |
| `action` | 当前 lane、当前 CTA member 的动作 |
| `Lane/action` | 引用该 lane 的唯一执行实例；存在多个匹配成员时不得省略 member |
| `Lane[0]/action` | 指定 CTA member 0 |
| `Lane[self]/action` | 与等待方相同的 CTA member |
| `Lane[*]/action` | 全部匹配的成员实例，前驱取并集 |
| edge 左侧省略事件 | 使用 `issue` |
| edge 右侧或 port 引用省略事件 | 使用 `done` |

动作末尾的 `@issue`、`@done` 是事件后缀；矩阵乘中间的 `@` 是动作名的一部分，二者不能混淆。

edge 左侧必须属于当前 lane。右侧可以引用当前 phase 的其他 lane，但不能直接越过 phase 引用对方的内部动作。

同一事件匹配多条规则时，前驱取并集，包括不同 edge 分类中的规则。YAML 重复键不是合并规则，必须拒绝。

**域、重复与边界**

`[lower, upper]` 一律是半开区间。例如 `[0, 8]` 表示八次迭代，不包含 8。

`{range: [0, 128], step: 64}` 产生块起点 0、64。动作使用该起点对应的块；块宽为 64，末块的有效范围不能超过上界。若存在非整除尾块，动作契约必须明确其有效区域处理，不能靠丢弃整轮隐藏尾块。

一个 repeat 块按以下顺序展开：

```text
prologue 一次
steady 对域中每个索引执行一次
epilogue 一次
```

嵌套块按所在列表位置执行。一个 lane 的两段独立循环应写成两个相邻子块，而不是展开固定索引动作，也不是新建 kernel。

当前循环变量只在其 steady 中绑定。prologue 和 epilogue 可以使用外层已绑定变量、常量及域查询，不能使用当前循环变量的某个隐含“最后值”。`last(k)` 查询域，不要求当前已经绑定一个 `k` 值。

多个 lane 使用同一个域，不代表它们同时进入同一轮。每个 lane 独立推进，受自己的顺序和 edge 约束。

<!-- SYNC(1.contract)：1.contract.algorithm_requirement.md 的 shape 表达式用 / 表示整除前提下的精确除法（如 "2*I/G"），本段规定 / 不作整数运算符。修改时统一各区整数表达式的运算符约定。改完删除本注释。 -->

本版支持整数、已绑定索引、上游明确的整数值，以及 `+ / - / * / // / %` 和括号构成的受限整数表达式；这里的 `/` 不作为整数运算符。域查询使用 `count(d)` 和 `last(d)`。不接受任意 Python、函数调用或说明文字代替表达式。

空域可以使 steady 执行零次，但不会自动删除 prologue、epilogue。`last` 不能用于空域；固定引用首项或末项的写法必须具有非空前提。

**连续索引**

FA4 使用：

```yaml
domain:
  t: assigned_worktile
  i: [0, 64]
  n: {flatten: [t, i]}
```

`t` 是当前 worker 已分配工作序列的本地序号，不是全局 worktile ID。`n` 是有序域积的连续序号，在此例中等价于 `64*t+i`，但实例只维护 flatten 定义。

| 写法 | 含义 |
| --- | --- |
| `n[t,i]` | 指定工作和局部迭代对应的连续序号 |
| `n[t]` | 当前工作包含的完整连续序号切片 |
| `n[t,a:b]` | 当前工作中局部索引落在 `[a,b)` 的切片 |
| `n[t,1:]` | 当前工作去掉首项后的切片 |
| `n+3` | 连续序号前进三项，允许跨 worktile |

绑定 `n` 时，可以唯一恢复其 `t / i` 坐标；若外层已经绑定 `t`，二者必须一致。

`n[t,i+1]` 与 `n+1` 不完全等价。前者要求 `i+1` 仍属于当前 worktile 的局部域，不能在越界时自动进位到下一份工作；后者明确使用跨 worktile 的连续序号。

**执行索引与数学值索引**

循环域限制循环变量的取值，不限制所有数学对象只能使用相同的索引范围。

例如，GDN 的 `c` 取 0 至 63，但上游状态包含 `S(0)` 至 `S(64)`。因此末轮的 `advance:S(c+1)` 合法，并不代表执行了一次 `c=64` 的循环。

相反，一个声明只在非首轮执行的 `rescale` 动作，不会因为 `Y(0)` 这个数学值存在，就自动产生 `rescale:Y(0)`。

**edge 的索引窗口**

pipe 和 edge 使用不同的边界规则：

| 位置 | 边界规则 |
| --- | --- |
| pipe | 按显式 repeat 域展开；不能因为某个动作越界就静默删除整轮 |
| edge | 带变量移位的规则按声明的索引窗口实例化；移位越界时跳过该条实例 |
| 固定引用 | 越界必须报错 |
| 窗口内引用 | 对应动作不存在时必须报错，不能跳过 |

窗口来自已经声明的循环域或数学值域，不能从“实际生成了哪些动作”倒推一个刚好不报错的窗口。

例如，FA4 的 `n[t,i+1]` 在末轮越过局部域，因此相关跨轮规则不在该轮生成；末轮由明确的 terminal 规则连接。拼错动作名、漏掉合法域内的一次发布，均不是边界情况。

折叠模板中的跨轮依赖不能直接判为同轮回边。事件环检查应针对有界实例及其真实索引关系。

**物理成员、别名与存续**

成员选择使用半开 warp 区间：

```text
cta[0].warp[0:4]
cta[*].warp[14:15]
```

CTA member 必须来自上游 worker，warp 编号必须落在对应资源池中。两个角色名称不同，不代表它们占用不同的物理 warp。

物理 warp 按驻留实例、CTA member 和 warp 编号识别。不同 phase 在同一驻留中复用这组 warp 时，只计算一次；若角色实际同时活跃，其成员重叠必须有明确、可实现的执行关系，不能将同一 warp 当成两份独立资源。

物理存储共享通过一次资源定义及其 view 表达。跨 phase 共用的分配放在根部 `resource`；phase 内引用它，不复制同一分配。独立作用域中的同名资源则是不同实例。

view 只定义存储关系，不产生数据边、发布动作或同步。两个逻辑版本落在同一槽中，必须分别检查旧版本的全部必要消费者和新版本的写入时刻。

新分配的资源没有旧版本使用者，不代表内容已经初始化为零。初始化来自上游定义及对应动作。正常建立和最终安全回收可以由资源与原语契约承担；若建立、回收或提前释放本身改变协作和 overlap，则需要显式动作。

资源作用域结束前必须满足相应的安全回收条件，但不得将这个义务复制成每个 worktile 末尾的全量排空。

**跨 phase 交接**

本区只暴露上游实际需要的 port，不复制宏观依赖图。

生产侧里程碑绑定本 phase 内真实的完成或发布事件；上游需要约束消费方时，其连接必须最终落实到消费 phase 内的实际等待位置。数据可见性、通知方式和消费方驻留条件均不能由一个 port 名字凭空产生。

普通独立 kernel 的完成交接可以直接使用上游 kernel 完成条件，不必为每个 store 再建 port。存在分块提前消费时，才需要将相应分块发布事件作为局部接口。

省略 port 表示没有额外导出的局部里程碑，不表示该 phase 没有结果。

#### 关键原则

**按外部边界决定动作粒度。**  
内部初始化、转换和计算若没有被其他角色利用的中间边界，可以合成一个已定义的动作。提前发布、统计量捕获、源缓冲归还等边界不能因“源码连续”而被合并掉。

**同一事实只维护一次。**  
数学计算引用 `math_reshape`；工作分配和跨 phase 组合引用 `work_schedule`；本区只增加局部组织。`team` 不再登记 lane 顺序或 overlap 图，`port` 不再复制宏观依赖。能够由角色成员、资源 shape 和 slot 推导的数量不重复填写。

**发布与复用分别检查。**  
生产者发布只说明消费者可以读取。覆盖存储还必须等待全部必要消费者结束，或依赖已经明确的原语保证。一个消费者读完不代表所有消费者读完，源缓冲可归还也不代表目标写入完成。

**没有依赖不等于已经实现 overlap。**  
计划可以保留重叠机会，但不填写 `overlap: true`，不依靠图中并排、高度或源码相邻关系表达同时执行。硬件资源竞争和编译结果可能进一步限制重叠。

**原生顺序必须有明确适用范围。**  
特定原语允许省略软件等待时，应在动作契约中写清原语和保证，并有固定源码或硬件资料依据。不能从 `mode: async`、同一个 lane 名或同一个对象名推导硬件 hazard 处理。尚未闭合的原语映射应标明缺口，而不是新增一个任意事件来假设它已经成立。

**作用域不随标签自动重置。**  
phase 是工作身份，worktile 是可分配工作，二者都不是资源重建指令。同一 worker 可以连续处理多份工作；输入环位置、输出源缓冲、统计量及在途操作应各按自己的使用边界接续。

**简单工作应保持简单。**  
单个 cooperative CTA 可以只有一个 lane，没有 team、edge 和专职异步角色。不能为套用 FA4 的形式，把 Triton 的一段合作计算拆成虚构的 TMA、Softmax 或 Epilogue lane。

**说明密度与实例密度分开。**  
通用规则放在本节；案例仅保留特有且影响设计的契约。`info.verb` 不是源码说明书，`resource.meaning` 不是注释替代品。精确 barrier 编号、寄存器编号、线程地址和普通 lowering 细节不进入本区。

以下案例是当前格式下的设计整理。源码核对、人工静态阅读、事件展开、独立盲重建、数值测试和性能测试是不同层次；没有执行的检查不能宣称已经通过。

```yaml
              rescale: Apply the upstream correction and publish Y readiness.
              release: Return the final low-statistic credit.
              read: >
                Copy final statistics into registers until the LSE store
                and release their SMEM.
              publish: Normalize Y into BF16 O SMEM, publish O, and release Y.
              store: Store both FP32 LSE blocks from the retained statistics.
          pipe:
            repeat: t
            steady:
              - repeat: "n[t,1:]"
                prologue:
                  - "wait:alpha_high(n[t,0])"
                  - "wait:alpha_low(n[t,0])"
                steady:
                  - "rescale:Y_high(n)"
                  - "rescale:Y_low(n)"
                epilogue:
                  - "release:statistic_low(t)"
                  - "read:final_high(t)"

              "wait:alpha_low(n[t,0])":

              "rescale:Y_high(n[t,i+1])":

              "rescale:Y_low(n[t,i+1])":
                - "Softmax_low[self]/update:alpha_low(n[t,i+1])"
              "read:final_high(t)":

              "read:final_low(t)":
                - "Softmax_low[self]/publish:final_low(t)"
              "publish:O_high(t)":
                - "MMA/mma:P_high_tail(n[t,last(i)])@V(n[t,last(i)])"
              "publish:O_low(t)":
                - "MMA/mma:P_low_tail(n[t,last(i)])@V(n[t,last(i)])"
            reuse:
              "publish:O_high(t+1)": ["Epilogue[self]/release:O_high(t)"]

        Epilogue:
          info:
            member: "cta[*].warp[13:14]"
            mode: async
            order: [issue]
            verb:
              store: Issue and commit a TMA store to global O.
              release:
                mode: sync
                meaning: >
                  Wait for the corresponding TMA source read and return
                  its O SMEM credit, without waiting for the destination write.
                source: "Dao-AILab/flash-attention@ce088ab9:flash_attn/cute/flash_fwd_sm100.py::FlashAttentionForwardSm100.epilogue_s2g"
          pipe:
            repeat: t
            steady:
              - "store:O_high(t)"
              - "store:O_low(t)"
              - "release:O_high(t)"
              - "release:O_low(t)"
          edge:
            data:
              "store:O_high(t)": ["Correction[self]/publish:O_high(t)"]
              "store:O_low(t)": ["Correction[self]/publish:O_low(t)"]
```

锚点 `softmax_verb` 只复用同一 YAML 文档内的动作契约，不创造共享存储或新角色。允许这种字面量复用，但不允许跨案例隐含继承。

稳态 Correction 依赖本轮 alpha，而 alpha 已经依赖本轮 QK 的累积完成保证，覆盖之前发射的 PV；最终输出仍显式等待最终 PV。这里省掉的是可推导的重复前驱，不是 Y 的就绪条件。

`release:O` 与 `store:O@done` 不同。前者遵循源码的 TMA source-read wait，后者表示目标写入完成；对应区别也见 [CUDA 13.0.0 PTX 的 bulk async-group 等待定义](https://docs.nvidia.com/cuda/archive/13.0.0/parallel-thread-execution/index.html)。本例不建立 `Epilogue(t) → TMA(t+1)` 的整份工作屏障。

资源表可导出每 CTA 的 SMEM 预算为 227 KiB，P 视图不额外计数，TMEM 单独统计。这是静态容量预算，不是编译后的资源报告。

**Case 2：GDN 五趟 Triton 分块前向**

本例固定为 B200 / SM100，来源为 `fla-org/flash-linear-attention@954438d1`，选定 Triton 3.7.1。不启用 FlashQLA、context parallel、额外 Q/K 归一化或 gate/beta 激活路径。

| 包装与分支 | [`fla-org/flash-linear-attention@954438d1:fla/ops/gated_delta_rule/chunk.py`](https://github.com/fla-org/flash-linear-attention/blob/954438d1/fla/ops/gated_delta_rule/chunk.py) |

| prepare | [`fla-org/flash-linear-attention@954438d1:fla/ops/gated_delta_rule/wy_fast.py`](https://github.com/fla-org/flash-linear-attention/blob/954438d1/fla/ops/gated_delta_rule/wy_fast.py) |

只读条件如下：

| 项目 | 条件 |
| --- | --- |
| 输入 | 等长序列；B 为正整数，L=4096，head=8，dk=dv=128，chunk 长度 64 |
| 类型 | Q/K/V 为 BF16；g、beta、S_init、S_final 为 FP32；g 为单步自然对数衰减，beta 已激活 |
| 工作归属 | gate、solve、prepare 按 batch/head/chunk；advance 按 batch/head/32 个 dv 列并顺序遍历全部 chunk；output 按 batch/head/chunk/64 个 dv 列 |
| 执行作用域 | 五个独立计算 kernel，各工作对应一个 cooperative CTA；没有跨 kernel 局部资源共享 |
| G | 长度 64 的 FP32 块内累计衰减；逻辑值与源码 log2 存储表示的对应必须由上游明确 |
| T | 64×64 BF16 逆矩阵，对应源码变量 A；未写上三角块由既定包装路径预先置零 |
| W、U | 各为 64×128 BF16 |
| S(c) | 进入 chunk c 的 FP32 状态；数学状态索引包括 0 至 64 |
| S_bar、R_bar | 分别为保存给输出的 BF16 状态快照和未加权修正量 |
| R | FP32 修正量；保存 R_bar 与状态更新使用不同的 BF16 窄化路径 |

输出 scale、G 的表示转换及求解精度必须沿用上游绑定。本例不因源码存在默认值就替任务选择 scale，也不根据输出 dtype 补造误差阈值。当前上下文未提供的数值验收条件仍属于上游输入缺口。

本例展示单 lane 的短格式、两段顺序列循环及跨 chunk 的常驻状态。warp 数和切片选择在正式资源与 repeat 字段中给出；它们是本例配置，不声称为 B200 最优。

```yaml
tile_pipeline:
  thesis: >
    Use one cooperative CTA role per phase, preserving local loop
    boundaries and the resident state across the chunk loop.

  phase:
    gate:
      resource:
        Warp: {space: warp, shape: [1]}
      lane:
        CTA:
          info:
            mode: sync
            verb:
              scan: Scan one chunk and store G in its upstream representation.
          pipe:
            steady: ["scan:G"]

    solve:
      resource:
        Warp: {space: warp, shape: [4]}
        Gram: {space: register, shape: [10, 16, 16], dtype: fp32}
      lane:
        CTA:
          info:
            mode: sync
            verb:
              init: Load G and beta; zero Gram.
              accumulate: Accumulate the lower Gram blocks from one dk slice of K.
              solve: >
                Apply the upstream solve and store the lower blocks of BF16 T.
                The unwritten upper blocks are pre-zeroed.
          pipe:
            repeat: {k: {range: [0, 128], step: 64}}
            prologue: ["init:Gram"]
            steady: ["accumulate:Gram(k)"]
            epilogue: ["solve:T"]

    prepare:
      resource:
        Warp: {space: warp, shape: [4]}
        T_local: {space: register, shape: [64, 64], dtype: bf16}
        Beta_local: {space: register, shape: [64], dtype: fp32}
      lane:
        CTA:
          info:
            mode: sync
            verb:
              load: >
                T_beta loads T into T_local and beta into Beta_local;
                retain both through the U and W loops.
          pipe:
            prologue: ["load:T_beta"]
            steady:
              - repeat: {u: {range: [0, 128], step: 64}}
                steady: ["produce:U(u)"]
              - "load:G"
              - repeat: {w: {range: [0, 128], step: 64}}
                steady: ["produce:W(w)"]

    advance:
      resource:
        Warp: {space: warp, shape: [2]}
        State:
          space: register
          shape: [128, 32]
          dtype: fp32
          view:
            "S(c)": {slot: 0}
        Residual:
          space: register
          shape: [64, 32]
          dtype: fp32
      lane:
        CTA:
          info:
            mode: sync
            verb:
              snapshot: Store BF16 S_bar from the current register S.
              compute: Form FP32 R in Residual from U, W, and resident S.
              produce: Store unweighted BF16 R_bar from FP32 R.
              advance: >
                Weight FP32 R, narrow it separately to BF16, and update
                resident S; do not use the saved R_bar.
          pipe:
            repeat: {c: [0, 64]}
            prologue: ["load:S_init"]
            steady:
              - "snapshot:S_bar(c)"
              - "compute:R(c)"
              - "produce:R_bar(c)"
              - "advance:S(c+1)"
            epilogue: ["store:S_final"]

    output:
      resource:
        Warp: {space: warp, shape: [4]}
        State_term: {space: register, shape: [64, 64], dtype: fp32}
        Local_term: {space: register, shape: [64, 64], dtype: fp32}
      lane:
        CTA:
          info:
            mode: sync
            verb:
              accumulate: >
                Accumulate State_term and Local_term over one dk slice
                using Q, K, and S_bar.
              produce: >
                Finish the local term and its R_bar product,
                combine with the state term, and store o.
          pipe:
            repeat: {k: {range: [0, 128], step: 64}}
            prologue: ["zero:State_term", "zero:Local_term"]
            steady: ["accumulate:State_Local(k)"]
            epilogue: ["produce:o"]
```

这里不写 `team` 和 `edge`：没有跨角色共享循环域，也没有需要额外表达的角色间前驱。五趟的宏观交接由上游负责，不在本区重新串联。

`solve:T` 合并了没有独立交接意义的求解内部步骤；`prepare` 的 U、W 循环仍保留为同一角色的两段工作。advance 的状态从 S_init 初始化一次，快照来自当前寄存器状态，最后的 `advance:S(64)` 合法。

“五趟”指五个主要计算 kernel，不排除包装路径中的清零等其他 GPU 活动，也不意味着算法必须永远保留五个不可融合的阶段。

**Case 3：一个 kernel 内的融合双 GEMM**

这是 **B200 设计候选**，不是现成 SM100 融合实现的性能复现。

融合结构参考 [`NVIDIA/cutlass@v4.2.1:examples/13_two_tensor_op_fusion/README.md`](https://github.com/NVIDIA/cutlass/blob/v4.2.1/examples/13_two_tensor_op_fusion/README.md)。该目录中的旧架构实现不作为 B200 参数依据。

SM100 原语与单 GEMM 组织参考 [`NVIDIA/cutlass@v4.2.1:examples/70_blackwell_gemm/70_blackwell_fp16_gemm.cu`](https://github.com/NVIDIA/cutlass/blob/v4.2.1/examples/70_blackwell_gemm/70_blackwell_fp16_gemm.cu)。该来源不证明下面的完整双 GEMM 已经实现。

本候选的只读输入固定为：

| 项目 | 固定选择 |
| --- | --- |
| 硬件与实现环境 | B200 / SM100；CUDA C++，CUDA Toolkit 13.0.0，CUTLASS v4.2.1 |
| 输入 | BF16 A[4096,512]、B[512,128]、C[128,128] |
| 第一段 | X = A×B，FP32 累加 |
| 中间转换 | H = BF16_RNE(ReLU(X)) |
| 第二段 | Y = H×C，FP32 累加 |
| 输出转换 | O = BF16_RNE(Y) |
| worktile | 128 行，完整产生并消费 H[128,128]，写出 O[128,128] |
| worker | 一个 8-warp CTA，一次处理一份 worktile |
| reduction | 第一段 8 个长度 64 的块，第二段 2 个长度 64 的块 |
| phase | 只有 projection；一个 kernel，无全局 H 物化 |

每份工作拥有第二段所需的完整 H，不需要跨 worker 交接。该工作归属是本候选的固定输入，不是“融合双 GEMM”普遍具备的性质。

本例展示同一 MMA lane 的两段 reduction、片上中间量发布、累加器别名和独立权重预取，不增加新的组织层。

```yaml
tile_pipeline:
  thesis: >
    B200 candidate: retain H inside one CTA, reuse the accumulator
    across two GEMM loops, and prefetch C independently.

  phase:
    projection:
      team:
        domain:
          k: [0, 8]
          j: [0, 2]

      resource:
        Warp: {space: warp, shape: [8]}

        A_buffer:
          space: smem
          slot: 2
          shape: [128, 64]
          dtype: bf16
          view:
            "A(k)": {slot: "k%2"}

        B_buffer:
          space: smem
          slot: 2
          shape: [64, 128]
          dtype: bf16
          view:
            "B(k)": {slot: "k%2"}

        C_buffer:
          space: smem
          slot: 2
          shape: [64, 128]
          dtype: bf16
          view:
            "C(j)": {slot: j}

        H:
          space: smem
          shape: [128, 128]
          dtype: bf16
          view:
            "H(j)": {part: "column[64*j:64*(j+1)]"}

        Accumulator:
          space: tmem
          shape: [128, 128]
          dtype: fp32
          view:
            X: {slot: 0}
            Y: {slot: 0}

        Protocol:
          space: smem
          byte: 1024
          meaning: Synchronization storage and alignment budget.

      lane:
        TMA:
          info:
            member: "cta[0].warp[4:5]"
            mode: async
            order: [issue]
          pipe:
            steady:
              - repeat: k
                steady: ["load:A(k)", "load:B(k)"]
              - repeat: j
                steady: ["load:C(j)"]
          edge:
            reuse:
              "load:A(k+2)": ["MMA/mma:A(k)@B(k)"]
              "load:B(k+2)": ["MMA/mma:A(k)@B(k)"]

        MMA:
          info:
            member: "cta[0].warp[5:6]"
            mode: async
            order: [issue, done]
            verb:
              mma: >
                Use single-CTA BF16 tcgen05 with FP32 accumulation.
                Initialize X at k=0 and Y at j=0.
          pipe:
            steady:
              - repeat: k
                steady: ["mma:A(k)@B(k)"]
              - repeat: j
                steady: ["mma:H(j)@C(j)"]
          edge:
            data:
              "mma:A(k)@B(k)": ["TMA/load:A(k)", "TMA/load:B(k)"]
              "mma:H(j)@C(j)": ["Transform/publish:H", "TMA/load:C(j)"]

        Transform:
          info:
            member: "cta[0].warp[0:4]"
            mode: sync
            verb:
              publish: >
                Read X, apply the upstream activation and cast,
                and publish complete H in SMEM.
              produce: Read Y, apply the upstream output cast, and store global O.
          pipe:
            steady: ["publish:H", "produce:O"]
          edge:
            data:
              "publish:H": ["MMA/mma:A(last(k))@B(last(k))"]
              "produce:O": ["MMA/mma:H(last(j))@C(last(j))"]
```

第二段必须等待完整 H 发布，因此不会在 X 尚未被读取时覆盖共用的 TMEM；这条既有数据依赖已经保护 X/Y 别名，不再复制同义 reuse 边。

C 使用独立缓冲，TMA 在第一段输入发射循环之后即可继续准备 C，不必等待 H 转换或最终输出。第一段和第二段仍由同一个 MMA lane 执行，Transform 则是另一组协作 warp。这里保留的是依赖图允许的重叠机会，未执行事件展开、GPU 正确性或性能验证。
