#### 核心思想

`contract.algorithm_requirement` 从调用者视角定义计算任务：接收什么、返回什么、输入输出满足什么数学关系，以及如何调用指定的 PyTorch 对照。读者不看 Design，也应能据此写出朴素参考计算。

本区以输入输出关系为中心，而不是按源码中的 kernel、phase 或优化步骤组织。公式可以引入中间量和递推状态，但不要求实现物化这些量，也不规定工作划分、存储位置或执行调度。Planner 和 Coder 都不能为了实现方便改变这里的任务边界、精度转换或输出语义。

本区向 Design 提供不可擅自修改的算法要求，向实现检查和数值测试提供比较依据。数学改写、状态保存方式、工作组织和流水线属于 Design；具体代码属于 Coder。

本节同时约定 `meta_data` 的最小写法。它位于整份 Plan 最前面，只负责识别任务和记录设计出处，不属于 Contract。必须区分：

| 信息 | 回答的问题 |
| --- | --- |
| `meta_data.source` | 这份设计依据什么实现或材料？ |
| `compute` | 调用者要求计算什么？ |
| `pytorch_reference` | 使用哪个参考入口，怎样传参和取得结果，目前有哪些核验或适配限制？ |

设计出处不是数值对照；存在参考入口也不等于已经获得独立、经过验收的 golden。

#### 字段定义

**结构轮廓**

下图中，`?` 表示可省略，`<name>` 表示案例自行命名的映射键，`[]` 表示列表条目。这些记号不写入实例。

```text
meta_data
  name
  describe
  source?

contract.algorithm_requirement
  constant?
    <name>: value / meaning
  input
    <name>: meaning / shape / dtype / range? / default?
  output
    <name>: meaning / shape / dtype
  compute[]
    step / name / math
    symbol?
      <name>: meaning / shape / dtype
  pytorch_reference
    source / input / output / status
```

**`meta_data`**

| 字段路径 | 值的形式 | 填写条件 | 含义与约束 |
| --- | --- | --- | --- |
| `meta_data.name` | 非空字符串 | 必填 | 算子的标准名称。识别计算任务，不加入 tile、CTA、架构或实现分支。 |
| `meta_data.describe` | 非空字符串 | 必填 | 一句话说明任务，不写优化理由或性能结论。 |
| `meta_data.source` | 非空来源字符串 | 有真实设计依据时填写；无对应依据时省略 | 记录一项主要出处。省略只表示未记录设计来源，不表示没有数学定义或无需数值对照。 |

代码来源使用 `repository@ref:path`，需要定位入口时加 `::function`。`ref` 必须能固定所依据的版本；需要复现时优先使用 commit 或固定 tag。非代码材料使用真实、可定位的出处，不伪装成仓库路径。

从现有实现提取设计时填写其出处；在已有设计上独立优化时，只要原材料仍是实际依据，就可以保留。自创方案并不自动排除真实参考材料，但不能为填满字段而伪造源实现。这里不记录版本谱系、任务进度或实验结果。

**算法要求的主要字段**

以下路径省略共同前缀 `contract.algorithm_requirement`。

| 字段路径 | 值的形式 | 填写条件 | 含义与约束 |
| --- | --- | --- | --- |
| `constant` | 具名映射 | 存在需要具名引用的固定数值时填写 | 固定值只定义一次。仅出现一次的固定维度可以直接写入 shape。 |
| `input` | 具名映射 | 必填 | 调用者提供的对象，包括可缺省输入。 |
| `output` | 具名映射 | 必填 | 调用者实际得到的对象，不包括内部 workspace。 |
| `compute` | 非空列表 | 必填 | 定义数学关系、递推、分支、边界和必要转换。 |
| `pytorch_reference` | 固定结构映射 | 必填 | 指定参考入口、调用映射及其状态。 |

`constant: {}` 与省略 `constant` 都表示没有登记常量，通常直接省略。`input` 或 `output` 的空映射只表示确实没有该类边界对象，不能表示尚未填写，也不能借此隐藏隐式输入或副作用。本文三个案例的输入输出均非空。

**常量、输入输出与数学步骤**

| 字段路径 | 值的形式 | 填写条件 | 含义与约束 |
| --- | --- | --- | --- |
| `constant.<name>.value` | 数值或固定数值表达式字符串 | 登记常量后必填 | 表达式只能依赖固定值，不能依赖运行时输入。 |
| `constant.<name>.meaning` | 非空字符串 | 登记常量后必填 | 说明该数值的含义。函数定义不放入 `constant`。 |
| `input.<name>.meaning`、`output.<name>.meaning` | 非空字符串 | 必填 | 说明对象的外部含义，不重复展开 shape 和 dtype。 |
| `input.<name>.shape`、`output.<name>.shape` | 有序的具名维度列表 | 必填 | 每个列表元素是一个“维度名 → 大小”的单项映射。标量使用 `[]`。 |
| `input.<name>.dtype`、`output.<name>.dtype` | 数值格式名称 | 必填 | 外部对象的格式，例如 `bf16`、`fp32`、`int64`、`fp8_e4m3fn`。这些例子不是封闭枚举，但格式必须有明确含义。 |
| `input.<name>.range` | 二元素列表或约束字符串 | 存在 dtype 和 `compute` 尚未表达的取值限制时填写 | 描述输入值的有效域。省略表示没有额外的值域限制，不表示未知。 |
| `input.<name>.default` | 标量值或明确的默认值表达式 | 调用者可以省略该输入时必填 | 无此字段表示调用者必须提供输入。张量的 `default: 0` 表示该 shape、该 dtype 的全零张量。 |
| `compute[].step` | 正整数 | 必填 | 从 1 开始按列表顺序编号，不能重复。它是定义编号，不是执行调度。 |
| `compute[].name` | 非空字符串 | 必填 | 用简短名称概括这一组数学关系。 |
| `compute[].math` | 非空字符串，通常使用多行文本 | 必填 | 包含完整的定义、范围、归约、分支和必要 cast。 |
| `compute[].symbol` | 具名映射 | 存在需要登记的局部对象时填写 | 登记重要中间量、递推状态以及需要跨步骤或跨区引用的数学对象。没有这类对象时可省略。 |
| `compute[].symbol.<name>.meaning` | 非空字符串 | 登记 symbol 后必填 | 说明对象及其索引范围，例如“固定 token 索引上的状态”。 |
| `compute[].symbol.<name>.shape` | 具名维度列表、属性引用或 `not_applicable` | 登记 symbol 后必填 | 定义逻辑形状，不规定物理 layout。 |
| `compute[].symbol.<name>.dtype` | 数值格式名称、属性引用或 `not_applicable` | 登记 symbol 后必填 | 数值对象的参考格式或计算精度，不表示必须按该格式物化。 |

`symbol: {}` 与省略 `symbol` 都表示没有登记局部对象，通常直接省略。登记后的条目不能缺少 `meaning / shape / dtype`。

Contract 的 symbol 使用上述较窄结构，不包含 `life`。数学状态随递推索引变化，不等于实现必须保存状态历史。统一展示工具若需要显示生命周期列，应显示“不适用”，不能据此向 Contract 添加存储约束。

**`pytorch_reference`**

| 字段路径 | 值的形式 | 填写条件 | 含义与约束 |
| --- | --- | --- | --- |
| `pytorch_reference.source` | 固定入口字符串 | 必填 | 使用 `repository@ref:path::function` 定位实际存在的参考入口。 |
| `pytorch_reference.input` | 参数名到绑定值的映射 | 必填 | 左侧是实际函数参数；右侧是契约对象、常量、必要转换或固定参数值。 |
| `pytorch_reference.output` | 契约输出名到返回表达式的映射 | 必填 | 必须覆盖全部契约输出。右侧使用 `result`、返回值索引或必要转换。 |
| `pytorch_reference.status` | 非空短说明字符串 | 必填 | 写明映射是否核对、是否运行，以及已知的适配缺口或关键共享依赖。没有默认的“已验证”状态。 |

`status` 是参考绑定的限定说明，不是测试平台状态枚举。`Mapping checked; not run.` 表示检查过源码映射，但没有执行测试；它不表示已经证明数值独立性。

真实入口尚不存在时，不能伪造 `source`、函数参数或返回映射。已有适配起点可以照实填写，并在 `status` 中说明限制。完全缺少入口的草稿属于未完成参考绑定；其统一机器可读占位写法待确认，不用空字符串或 `null` 冒充合法入口。

**固定结构与开放边界**

| 位置类型 | 本区位置 | 允许的变化 |
| --- | --- | --- |
| 固定结构 | `meta_data`、`algorithm_requirement`、各常量条目、输入输出条目、compute 条目、symbol 条目、`pytorch_reference`、属性引用对象 | 只使用本节声明的字段。未知字段应报错，不能静默忽略。 |
| 具名映射 | `constant`、`input`、`output`、`compute[].symbol`，以及 shape 中的维度名称 | 可以增加案例所需的名称，但条目结构不随名称开放。 |
| 外部接口映射 | `pytorch_reference.input`、`pytorch_reference.output` | 输入键受真实函数签名限制；输出键受契约输出限制。不是任意键值收纳区。 |
| 受控扩展位置 | 当前没有开放新增 schema 字段的路径 | 可以在已有 `math`、`range`、`meaning`、`status` 中填写职责范围内的内容，但不能据此新增同级字段。 |

增加一个张量名或数学 symbol，不是修改模板。新增一个通用字段则是结构变更，必须另行确认其含义、值形式、填写条件和真实案例。不得通过 `notes`、`misc`、`extra` 绕过结构限制。

上述固定结构约束只针对本节负责的对象，不限制整份 Plan 中已经另行定义的其他区域。

#### 语法规则

**名称、语言与顺序**

Schema 字段使用单数。真实仓库路径、函数名、参数名和外部枚举值保持原名，例如 `topk_ids` 不改名。

YAML 的名称、说明字符串和数学步骤名称使用英文，不允许独立注释或行内注释。通用约定写在文档中；案例特有且影响结果的事实必须写入正式字段。

自定义对象名使用英文字母、数字和下划线，不能以数字开头。常量、输入、输出和已登记 symbol 在同一契约内不得重名，保证简短引用可以唯一解析。公式中的局部下标可以在不同求和或函数调用中复用。

映射顺序没有计算语义。`compute` 列表按定义关系排列，`step` 必须与列表顺序一致；编号本身不要求顺序执行、独立提交或同步。

**shape 与规模**

shape 的列表顺序表示逻辑轴顺序。例如：

```yaml
shape: [batch: BatchCount, token: SequenceLength, head: HeadCount, d: 128]
```

每个维度条目只能包含一个名称，大小可以是非负整数、已绑定的规模名称或能得到整数的规模表达式。表达式使用字符串，例如 `"2*I/G"`；它必须在该任务的有效域内成立，不能隐含截断、补齐或整除假设。

运行时规模可以由输入 shape 引入，不需要再创建同名标量输入。首次使用时应明确其合法范围；同一契约中的同名规模必须一致。固定维度直接写入 shape，不需要为每个数字重复登记常量。

局部函数可以引入自己的规模参数，例如 `L in {H,I}`。函数内部 symbol 的 shape 可以引用该参数，但其绑定范围必须由 `math` 明确给出，不能变成来源不明的全局规模。

**symbol 与属性引用**

是否登记一个局部量，与登记后是否完整填写属性，是两个不同问题。

只在一条公式内使用、含义和范围已经清楚的下标或临时量，可以不登记。重要中间量、递推状态和需要被其他区域引用的对象不能为了省略属性而移出 symbol 表。已经由输入输出定义的对象也不在 symbol 表重复登记。

`symbol.shape` 和 `symbol.dtype` 可以使用单字段引用：

```yaml
shape: {same_as: S0.shape}
```

`same_as` 的值采用 `对象名.属性名`。对象必须是同一 `algorithm_requirement` 内已定义的输入、输出或 symbol，属性只能是对应的 `shape` 或 `dtype`。引用可以跨 compute 条目，但必须唯一、无循环，并最终解析到实值或明确的不适用标记。

该写法与直接填写目标属性的值等价，不表示两个对象共享内存，也不表示它们数值相同。引用整个 shape 会沿用轴名称、顺序和大小；轴含义不同的对象应重新填写，而不是勉强复用。

本区不从 Design 反向引用属性。外部任务的数学含义不能等待下游选择存储方式后才确定。

| 写法或情况 | 含义 |
| --- | --- |
| `shape: []` | 标量，不是未知 shape。 |
| `shape: [element: 0]` | 零长度张量；只有任务有效域允许时才合法。 |
| `shape: not_applicable` | 对象不是具有张量形状的值，例如纯数学函数或集合。 |
| `dtype: not_applicable` | 该对象不具有需要指定的数值格式，例如纯数学函数或未指定机器整数表示的数学下标。 |
| `{same_as: S0.shape}` | 属性已经由其他对象定义，不是尚待确定。 |
| 未知或等待绑定 | 不等于 `not_applicable`，也不能用合法 dtype 代填。关键数学属性未确定的 Contract 尚不完整。 |

纯数学下标通常直接在公式中绑定；确需登记时，可用 `shape: []` 表示标量，在 `meaning` 中说明它是整数下标，不擅自指定 `int32` 存储。数值张量则必须填写已知的参考 dtype，不能因“不要求物化”而统一写成 `not_applicable`。

`life` 不属于本区。比如 GDN 的 `S[t]`，symbol 的 shape 描述固定 `t` 上的状态；它没有 token 轴，并不要求保存所有 `t` 的状态。

**数学表达与参考精度**

`math` 是供人和检查工具理解的数学描述，不是可执行 Python 或 GPU DSL。允许使用简短定义、求和、递推、分情形和必要的说明句；不放正确性证明、源码分析或优化理由。

使用以下共同约定：

| 记号 | 含义 |
| --- | --- |
| `0 <= i < N` | 从零开始的整数索引范围。 |
| `sum_{i=0}^{N-1}` | 包含所写上下界的归约。 |
| `x[a:b]` | 包含 `a`、不包含 `b` 的切片。 |
| `x[:]` | 相应轴的全部元素。 |
| `fp32(x)`、`bf16(x)` | 转换到相应数值格式。 |
| `fp8_e4m3fn_RNE(x)` | 按 RNE 转换到 E4M3FN；饱和范围需要由公式另行明确。 |
| `exp(x)`、`ln(x)` | 自然指数和自然对数。 |
| `clamp(x,a,b)` | 将值限制到闭区间 `[a,b]`。 |

浮点参考计算与累加默认使用 FP32，窄化转换显式写出；涉及舍入时沿用 RNE，即舍入到最近值，正好居中时取偶数。该口径不适用于索引、集合或布尔条件，也不宣称所有数学恒等式的不同求值方式都逐位相同。

输入 dtype 不等于默认计算精度。例如 BF16 输入可以在 FP32 中计算，再按公式转换为 BF16 输出。已知的中间窄化、量化或重建必须写出，不能由参考函数的临时张量 dtype 暗中引入。

批量和 head 的独立下标可以省略，但必须说明独立性。归约轴、迭代范围、初始条件、分支条件和边界输出不能依靠读者猜测。数学递推中的前后关系定义取值依赖，不规定物理执行步骤。

函数在首次使用处定义，不放进 `constant` 伪装成字符串常量。公式中的 `-inf` 可以是掩码或约定输出，不因此允许输入包含非有限值。

**range、default 与空值**

`range: [a, b]` 表示闭区间，张量按元素解释。开端点、有限值约束或符号范围使用明确字符串，例如 `finite` 或 `"0 <= route_id < E"`。`range` 与 shape、dtype、`compute` 中的约束共同成立，不能互相覆盖。

省略 `range` 表示没有额外值域限制，不自动附加“有限”“非负”或某个激活函数的取值区间。

省略 `default` 表示该输入必须提供。`default: 0` 对张量表示按声明 shape 和 dtype 构造全零值；引用该输入时，引用的是已经应用缺省规则后的对象。

YAML `null` 在参考参数映射中可以表示真实的 Python `None`。它不表示零张量、未知属性或省略字段。空字符串、横杠和数值 NaN 也不作为通用元数据占位。

**参考入口与调用映射**

`pytorch_reference.input` 左侧保留真实参数名，右侧使用契约对象名、常量名或简短转换表达式。固定数值、布尔值、`null` 和列表可以直接使用 YAML 值。表达式若要传递字符串常量，应保留该字面量自身的引号，避免与对象引用混淆。

`result` 专指函数返回值，返回元组从 `result[0]` 开始索引。`pytorch_reference.output` 左侧必须是契约输出名，右侧说明如何从返回值取得它。额外返回的调试量或中间量不因此成为契约输出。

参数可以省略，但必须同时满足：已经检查固定版本的默认行为；该默认行为符合 `compute`；没有尚未固定的外部设置影响该行为。改变任务语义的非默认参数必须显式填写。

调用映射不复制完整参考代码。若入口缺少所需参数、依赖共享关键 helper，或无法直接满足契约精度，应在 `status` 中记录适配缺口，不能编造一个不存在的参数，也不能反过来修改 `compute` 迁就入口。

#### 关键原则

**先定义调用者要什么，再选择怎样实现。**

输入的有效域、因果对齐、路由解释、量化定义、初末状态和输出边界属于本区。源码中的 tile 对齐、最大支持长度、分块大小、kernel 数量和 CTA 配置不能直接升级为算法要求。GDN 的 token 递推不要求某个 chunk 大小；MoE 的量化组长则直接影响数值定义，必须保留。

**压缩重复，不压缩会改变结果的条件。**

维度已经固定在 shape 中，就不再为同一个数字维护无用常量；同一函数被多次使用，就定义一次；已有唯一属性来源，就用 `same_as` 引用。相反，全部 key 不可见的输出、更新前后状态的选择、两次量化的舍入边界，不能因为“通常可以猜到”而删除。

`meaning` 说明对象是什么，`math` 定义对象怎样得到。不要把整条公式复制进 `meaning`，也不要只写一个模糊名称，把实际约束留在案例外。

**数学中间量不等于实现缓冲。**

为说明算法而定义完整 score、概率矩阵或状态序列，不要求实现创建对应大小的张量。是否融合、分块、保存或重算由 Design 决定。Contract 既不能强迫朴素物化，也不能因担心物化而省掉重要数学对象。

**参考入口服从契约，设计出处不代替参考入口。**

一个源码路径可以说明原实现做了什么，不能证明它是硬件必需、数值独立或最优实现。`meta_data.source` 与 `pytorch_reference.source` 即使来自同一仓库，也承担不同角色，不能合并。

检查参考入口时，要沿调用路径核对 mask、量化、激活、路由和状态处理。函数名包含 `torch` 或 `ref`，不构成独立性的证明。已知依赖必须保留在 `status` 中。

**数学定义、实现误差与测试验收分开。**

本区的参考精度与显式 cast 定义比较依据，但不自动给出实现允许的误差。实现采用近似计算，也不能通过 `status` 或调用映射获得隐含许可。

当前尚未确认完整的 accuracy 字段格式、逐输出指标和验收阈值。不得自行添加 `rtol/atol` 后宣称任务已经验收完整，也不得把缺少阈值解释为允许任意差异或必须逐位相等。attention 的空行约定、GDN 的最终状态等外部结果仍必须纳入检查，不能只比较其中一个输出。

源码映射核对、代码执行、数值验收、性能测试和独立盲重建是不同的事实。只完成其中一项时，不使用笼统的“已验证”覆盖其他项。

#### 具体案例

以下三个案例沿用已讨论的任务分支，只展开本节负责的 `meta_data` 和 `contract.algorithm_requirement`。参考入口已进行源码层面的映射核对，没有执行本轮 GPU 数值测试、性能测试或独立盲重建。

**Case 1：因果 Attention**

本例采用 BF16 Q/K/V/O、FP32 LSE、8 个 MHA head 和 128 维 head。QueryLength 与 KVLength 可以不同，因果采用右下对齐；本例没有额外的 score 或 mask 修改。

固定入口 `attention_ref` 按右下对齐构造因果 mask，并处理全部 key 不可见的行。其 LSE 返回值会转换为传入 V 的原始 dtype，因此映射将 Q/K/V 都转换为 FP32，再仅将 O 窄化为 BF16。[^attention-ref]

本例展示有效域、空行分支、非张量函数 symbol，以及跨步骤的 shape 引用。公式中的行最大值只是稳定表达 softmax，不是在线 softmax 状态。

[^attention-ref]: `Dao-AILab/flash-attention@ce088ab9:flash_attn/cute/testing.py::attention_ref`；同文件的 `construct_local_mask` 定义因果对齐。

```yaml
meta_data:
  name: scaled_dot_product_attention
  describe: Compute right-aligned causal attention and natural-log normalizers.
  source: Dao-AILab/flash-attention@ce088ab9:flash_attn/cute/flash_fwd_sm100.py

contract:
  algorithm_requirement:
    constant:
      scale: {value: "1/sqrt(128)", meaning: Score scale}

    input:
      Q: {meaning: Query, shape: [batch: BatchCount, query: QueryLength, head: 8, d: 128], dtype: bf16, range: finite}
      K: {meaning: Key, shape: [batch: BatchCount, kv: KVLength, head: 8, d: 128], dtype: bf16, range: finite}
      V: {meaning: Value, shape: [batch: BatchCount, kv: KVLength, head: 8, d: 128], dtype: bf16, range: finite}

    output:
      O: {meaning: Attention output, shape: [batch: BatchCount, query: QueryLength, head: 8, d: 128], dtype: bf16}
      LSE: {meaning: Natural-log normalizer, shape: [batch: BatchCount, head: 8, query: QueryLength], dtype: fp32}

    compute:
      - step: 1
        name: Define causal scores
        math: |
          BatchCount, QueryLength, KVLength are positive integers; QueryLength and KVLength may differ.
          Each batch and head is independent; their indices are omitted.
          For 0 <= q < QueryLength:
            visible_key(q) = {j in integers | 0 <= j < KVLength and j <= q + KVLength - QueryLength}.
            For 0 <= k < KVLength:
              score[q,k] = sum_{d=0}^{127} (scale * fp32(Q[q,d])) * fp32(K[k,d]) if k in visible_key(q); otherwise -inf.
        symbol:
          visible_key: {meaning: Function returning the visible key set for a query, shape: not_applicable, dtype: not_applicable}
          score: {meaning: Masked attention score, shape: [batch: BatchCount, head: 8, query: QueryLength, kv: KVLength], dtype: fp32}

        math: |
          For 0 <= q < QueryLength:

              norm = sum_{j in visible_key(q)} exp(score[q,j] - row_max).

            Otherwise:
              probability[q,k] = 0 for 0 <= k < KVLength.
              O[q,d] = 0 for 0 <= d < 128.
              LSE[q] = -inf.
        symbol:
```

**Case 2：GDN**

本例选定 Q/K/V 为 BF16、g/beta 为 FP32，读出缩放为 `1/sqrt(128)`；这些是本案例的契约取值，不是对所有 GDN 任务的统一默认值。序列等长，Q/K 不在算子内归一化，g 是单步自然对数衰减，beta 直接按给定值使用。

固定入口采用 FP32 token 递推，依次衰减、修正、更新和读出，并返回 FP32 结果及最终状态；映射只将逐 token 输出窄化为 BF16。[^gdn-ref]

本例展示缺省零状态、更新后读出，以及“固定递推索引上的状态 shape”。没有 chunk 大小、三角求解或 phase 数量要求。

[^gdn-ref]: `fla-org/flash-linear-attention@954438d1:fla/ops/gated_delta_rule/naive.py::naive_recurrent_gated_delta_rule`。

```yaml
meta_data:

    constant:
      scale: {value: "1/sqrt(128)", meaning: Query readout scale}

      V: {meaning: Value, shape: [batch: BatchCount, token: SequenceLength, head: HeadCount, dv: 128], dtype: bf16, range: finite}
      g: {meaning: Per-token natural-log decay, shape: [batch: BatchCount, token: SequenceLength, head: HeadCount], dtype: fp32, range: finite}
      beta: {meaning: Activated update coefficient, shape: [batch: BatchCount, token: SequenceLength, head: HeadCount], dtype: fp32, range: finite}
      S0: {meaning: Initial state, shape: [batch: BatchCount, head: HeadCount, dk: 128, dv: 128], dtype: fp32, range: finite, default: 0}

        q: Q
        k: K
        v: V

        g: g
```

**Case 3：MoE FP8 Block**

本例采用 H=7168、分片中间维度 I=256、256 个专家、每 token 8 个给定 route，以及 128 元素激活量化组和 128×128 权重量化块。案例选定 X/Y 为 BF16、route_id 为 int64、route_weight 为 FP32。输入量化、专家计算和本分片合并在边界内；路由选择与跨分片归约在边界外。旧实现分析针对 SM90，本例只沿用数学任务，不据此声称已有 B200 实现验证。

`torch_experts` 用传入激活的 dtype 创建输出，并将其传给 block matmul helper；因此映射使用 `fp32(X)`，避免源入口引入本契约未定义的中间 BF16 窄化。它仍调用共享量化和激活实现，不能直接视为独立 golden。[^moe-ref]

普通 scale 分支还受量化 helper 的外部设置影响，`torch_experts` 的签名没有直接固定该设置的参数。[^moe-quant] `SiluAndMul` 也有共享自定义算子路径。[^moe-activation] 此外，block matmul helper 按块点积后乘 scale；这不能证明它与逐元素反量化后的求和逐位一致。[^moe-matmul] 这些限制保留为参考适配状态，不改变下方数学定义。

本例展示显式 FP8 码值、scale 解释、两次调用同一量化函数，以及只返回分片贡献的输出边界。两次量化共享定义，但分别从各自输入重新计算 scale。

[^moe-ref]: `vllm-project/vllm@28282ffe:tests/kernels/utils.py::torch_experts`。
[^moe-quant]: `vllm-project/vllm@28282ffe:vllm/model_executor/layers/fused_moe/utils.py::moe_kernel_quantize_input`；`vllm-project/vllm@28282ffe:vllm/model_executor/layers/quantization/utils/fp8_utils.py::per_token_group_quant_fp8`。
[^moe-activation]: `vllm-project/vllm@28282ffe:vllm/model_executor/layers/activation.py::SiluAndMul`。
[^moe-matmul]: `vllm-project/vllm@28282ffe:tests/kernels/quant_utils.py::native_w8a8_block_matmul`。

```yaml
  describe: Compute this shard's block-scaled FP8 SwiGLU expert contribution for supplied routes.
  source: vllm-project/vllm@28282ffe:vllm/model_executor/layers/fused_moe/experts/triton_moe.py

      I: {value: 256, meaning: Shard intermediate dimension}
      E: {value: 256, meaning: Expert count}

      G: {value: 128, meaning: Activation group length and weight block extent}
      epsilon: {value: 1.0e-10, meaning: Minimum activation amax}

      S13: {meaning: W13 block scale, shape: [expert: E, channel_block: "2*I/G", hidden_block: "H/G"], dtype: fp32, range: finite}
      S2: {meaning: W2 block scale, shape: [expert: E, hidden_block: "H/G", intermediate_block: "I/G"], dtype: fp32, range: finite}
      route_id: {meaning: Supplied expert index, shape: [token: TokenCount, route: TopK], dtype: int64, range: "0 <= route_id < E"}

    output:
      Y: {meaning: Shard contribution before cross-shard reduction, shape: [token: TokenCount, hidden: H], dtype: bf16}

    compute:

        name: Define activation quantization
        math: |
          TokenCount is a positive integer.
          Define quantize_dequantize(x) for a row of length L in {H,I}:
            group_scale[u] = fp32(max(epsilon, max_{j=u*G}^{(u+1)*G-1} abs(fp32(x[j]))) / fp8_max) for 0 <= u < L/G.

        math: |

        w2_scale: S2
        a1_scale: null
        a2_scale: null
        quant_dtype: torch.float8_e4m3fn
        per_act_token_quant: false
        block_shape: [G, G]
```
