# 算法要求

## 核心思想

`contract.algorithm_requirement` 从调用者视角定义计算任务：接收什么、返回什么、输入输出满足什么数学关系，以及用哪个 golden reference 验收、允许多大误差。读者不看 Design，也应能据此写出朴素的参考计算。

本区围绕输入输出关系组织，不按源码中的 kernel、phase 或优化步骤划分。公式可以引入中间量和递推状态，但不要求实现物化它们；数学改写、状态保存、工作划分和流水线属于 Design，具体代码属于 Coder。本区是 Design 的前提，也是数值测试的比较依据；Designer 和 Coder 都不能为了实现方便改变这里的任务边界、精度转换或输出语义。

元数据与任务组织见[公共约定](0.common.md#单份-plan-与元数据)。本区字段只在 `root.yaml` 中填写，派生节点使用 root 的共享 Contract；对应 CUE 定义为 [schema.cue](../schema_template/schema.cue) 中的 `#AlgorithmRequirement`。

## 字段定义

### 结构轮廓

下图中，`?` 表示可省略，`<name>` 表示实例自行命名的映射键，`[]` 表示列表条目。这些记号不写入实例。

```text
contract.algorithm_requirement
  constant?
    <name>: value / meaning
  input
    <name>: meaning / shape / dtype / range? / default?
  output
    <name>: meaning / shape / dtype
  compute[]
    name / math
    symbol?
      <name>: meaning / shape / dtype
  golden_reference
    source / tolerance / gap?
```

### 算法要求的主要字段

以下路径省略共同前缀 `contract.algorithm_requirement`。

| 字段路径 | 值的形式 | 填写条件 | 含义与约束 |
| --- | --- | --- | --- |
| `constant` | 具名映射 | 有需要按名称引用的固定数值时填写 | 登记的量只在这里定义一次，其他位置按名称引用。 |
| `input` | 非空具名映射 | 必填 | 调用者提供的全部对象，包括可缺省的输入。 |
| `output` | 非空具名映射 | 必填 | 调用者能得到的全部结果。原地写回某个输入的结果也登记为输出，并在 `meaning` 中写明；内部 workspace 不算输出。 |
| `compute` | 非空列表 | 必填 | 按先定义、后使用的顺序给出数学关系、递推、分支、边界和必要的转换。 |
| `golden_reference` | 固定结构映射 | 必填 | 标准答案的入口、各输出的误差判据，以及它与契约的已知差异。 |

代表性 shape 与 workload、优化目标也属于本区，但字段格式尚未确定，在此之前不自行增加字段。

### 常量、输入输出与数学步骤

| 字段路径 | 值的形式 | 填写条件 | 含义与约束 |
| --- | --- | --- | --- |
| `constant.<name>.value` | 数值，或只含固定值的表达式字符串 | 必填 | 不能依赖运行时输入。 |
| `constant.<name>.meaning` | 非空字符串 | 必填 | 说明该数值的含义。 |
| `input.<name>.meaning`、`output.<name>.meaning` | 非空字符串 | 必填 | 说明对象的外部含义，不重复 shape 和 dtype。 |
| `input.<name>.shape`、`output.<name>.shape` | 有序的具名维度列表 | 必填 | 每个元素是一个“轴名: 大小”的单项映射；标量写 `[]`。 |
| `input.<name>.dtype`、`output.<name>.dtype` | 数值格式名称 | 必填 | 例如 `bf16`、`fp32`、`int64`、`fp8_e4m3fn`。不是封闭枚举，但格式必须有明确定义。 |
| `input.<name>.range` | 二元素列表或约束字符串 | 值域与默认不同时填写 | 输入值的有效域。省略时，浮点输入取任意有限值，整数输入取 dtype 能表示的全部值。 |
| `input.<name>.default` | 标量值或默认值表达式 | 调用者可以省略该输入时必填 | 缺少此字段表示调用者必须提供该输入。张量的 `default: 0` 表示按该 shape 和 dtype 取全零。 |
| `compute[].name` | 非空字符串 | 必填 | 用简短名称概括这一步的数学关系。 |
| `compute[].math` | 非空字符串，通常为多行文本 | 必填 | 完整写出定义、范围、归约、分支和必要的转换。 |
| `compute[].symbol` | 具名映射 | 本步定义了需要登记的对象时填写 | 登记重要中间量、递推状态，以及被其他步骤或其他区引用的对象。 |
| `compute[].symbol.<name>.meaning` | 非空字符串 | 必填 | 说明对象及其索引含义，例如“处理完 token t 之后的状态”。 |
| `compute[].symbol.<name>.shape` | 具名维度列表、`ref:` 引用或 `not_applicable` | 必填 | 逻辑形状，不规定物理 layout。 |
| `compute[].symbol.<name>.dtype` | 数值格式名称、`ref:` 引用或 `not_applicable` | 必填 | 参考计算中的数值格式，不要求实现按该格式物化。 |

本区的 symbol 没有 `life`：这里只定义数学关系，状态保存多久、是否物化由 `math_reshape` 决定。

### `golden_reference`

| 字段路径 | 值的形式 | 填写条件 | 含义与约束 |
| --- | --- | --- | --- |
| `golden_reference.source` | 来源字符串 | 必填 | 使用 `repository@ref:path::function`，固定 commit 或不可变 tag，指向实际存在的参考入口。 |
| `golden_reference.tolerance` | 契约输出名到判据字符串的映射 | 必填 | 覆盖全部契约输出；每条判据给出误差度量和阈值，写法见“误差判据”。 |
| `golden_reference.gap` | 非空字符串 | 参考入口与 `compute` 存在已知差异时必填 | 写明差异及处理方式。省略表示没有已知差异。 |

本区不记录参考入口的参数和返回值：怎样调用由 `compute` 和参考代码本身决定。`gap` 只写从签名和 `compute` 看不出、却会让比较出错的差异，例如入口缺少所需参数、受外部设置影响、返回精度低于契约，或某段路径与 `compute` 的定义不一致；不记录核对、运行或验收进度。

没有可用的入口时，先按 `compute` 写出参考实现并固定版本，再引用它；不伪造入口，也不用空字符串或 `null` 占位。

### 固定结构与开放边界

| 位置类型 | 本区位置 | 允许的变化 |
| --- | --- | --- |
| 固定结构 | `algorithm_requirement`、常量条目、输入输出条目、compute 条目、symbol 条目、`golden_reference` | 只使用本节声明的字段。 |
| 具名映射 | `constant`、`input`、`output`、`compute[].symbol`，以及 shape 中的轴名 | 可以增加实例需要的名称，条目结构不变。 |
| 受限映射 | `golden_reference.tolerance` | 键是契约输出名，且覆盖全部输出。 |

增加张量名或 symbol 属于填写实例；结构变更遵循[公共扩展规则](0.common.md#结构与扩展)。

## 语法规则

### 名称与顺序

通用命名与 YAML 写法见[公共约定](0.common.md#通用写法)。常量、规模、输入、输出和 symbol 的名称在同一契约内唯一，使简短引用能唯一解析；公式中的局部下标可以在不同的求和或函数中复用。

`compute` 列表按先定义、后使用排列，这一顺序只表示定义关系，不表示执行顺序、kernel 划分或同步。

### shape 与规模

具名轴与整数表达式遵循[公共写法](0.common.md#shape-与整数表达式)。本区 shape 描述逻辑轴，例如：

```yaml
shape: [batch: BatchCount, token: SequenceLength, head: HeadCount, d: 128]
```

运行时规模由输入 shape 引入，不另设同名的标量输入；同名规模在整个契约中取同一个值。运行时规模默认是正整数，其余约束（允许为零、规模之间的关系、整除条件等）写进 `math`，放在首次用到该规模的步骤中。

同一个固定的量在多处使用时（如多个 shape 和公式），登记为常量并按名称引用；只用一次的可以直接写数值。数值相同但含义不同的量分别登记，例如 GDN 中同为 128 的 key 维与 value 维。

局部函数可以引入自己的规模参数，例如 `L in {H,I}`。函数内部 symbol 的 shape 可以使用该参数，参数的取值范围由 `math` 给出，不成为全局规模。

### symbol 与属性引用

只在一个步骤内使用、含义和范围都清楚的下标或临时量可以不登记。重要中间量、递推状态和被其他步骤或其他区引用的对象必须登记，不能为了省略属性而移出 symbol；输入输出已经定义的对象不重复登记。每个 symbol 登记在定义它的步骤下。

symbol 的 shape 描述一个实例的值：递推状态 `X(t)` 的 shape 不含 `t`，函数内部的量描述一次调用中的值。公式省略的独立轴（如 batch、head）仍要列入 shape。

symbol 的 `shape` 或 `dtype` 与某个已定义对象的同名属性相同时，可以写成引用：

```yaml
shape: "ref:S0.shape"
```

引用目标写作 `对象名.shape` 或 `对象名.dtype`，对象是本契约中的输入、输出或 symbol，属性与所在字段相同，引用不能成环。引用等价于直接写出目标的值，连同轴名、顺序和大小一起沿用；它不表示共享存储，也不表示数值相同。轴含义不同的对象直接填写，不勉强引用。本区不引用 Design 中的属性：任务的数学含义不能等下游的选择来确定。

| 写法 | 含义 |
| --- | --- |
| `shape: []` | 标量。 |
| `shape: [element: 0]` | 零长度张量，只在有效域允许时合法。 |
| `shape: not_applicable` | 对象不是张量，例如函数或集合。 |
| `dtype: not_applicable` | 对象没有需要指定的数值格式，例如函数、集合或数学整数。 |
| `"ref:S0.shape"` | 属性由引用的对象给出。 |

本区没有表示“未知”或“待定”的写法：Contract 必须完整，不能用 `not_applicable` 或猜测的 dtype 代填尚未确定的属性。数学整数（如下标）确需登记时，写 `shape: []`、`dtype: not_applicable`，并在 `meaning` 中说明它是整数，不指定 `int32` 之类的存储类型；数值对象则必须填写参考 dtype，不能因为“不要求物化”而写 `not_applicable`。

### 数学表达与参考精度

`math` 是数学描述，不是可执行的 Python 或 GPU DSL。可以使用简短定义、求和、递推、分情形和必要的说明句，不写正确性证明、源码分析或优化理由。

共同记号如下：

| 记号 | 含义 |
| --- | --- |
| `0 <= i < N` | 从 0 开始的整数索引范围。 |
| `sum_{i=0}^{N-1}`、`sum_{j in J}` | 在所写闭区间或集合上归约；`max` 等写法相同。 |
| `x[a:b]`、`x[:]` | 包含 `a`、不包含 `b` 的切片；整条轴。 |
| `X[i]`、`X(t)` | 方括号下标对应 shape 中的轴；圆括号表示递推实例或函数调用，括号内的索引不是轴。 |
| `fp32(x)`、`bf16(x)`、`fp8_e4m3fn(x)` 等 | 按 RNE 转换到函数名所示的格式。结果可能超出该格式的范围时，先在公式中写明处理方式，例如 `clamp`。 |
| `exp(x)`、`ln(x)` | 自然指数和自然对数。 |
| `clamp(x,a,b)` | 把值限制在闭区间 `[a,b]` 内。 |

浮点计算与累加默认使用 FP32，舍入采用 RNE，即就近舍入、恰在中点时取偶数。这一默认不涉及索引、集合和布尔条件，也不规定求值次序，因此不保证不同的等价写法逐位相同。

输入的 dtype 不决定计算精度：BF16、FP8 等输入按精确值参与 FP32 计算，不写加宽转换。窄化、量化等改变数值的转换必须在公式中写出，例如 BF16 输出写成 `bf16(...)`；不能由参考函数中间张量的 dtype 暗中引入。

相互独立的下标（如 batch、head）可以在公式中省略，但要写明它们独立。归约轴、迭代范围、初值、分支条件和边界输出都要写出，不留给读者猜测。递推的先后只表示取值依赖，不规定执行顺序。

函数在首次使用处定义，不放进 `constant`。公式中的 `-inf` 可以作为掩码值或约定的输出，这并不放宽输入的值域。

### range、default 与空值

浮点输入默认取有限值，整数输入默认取其 dtype 能表示的全部值；`range` 只写与默认不同的值域。`range: [a, b]` 表示闭区间，对张量逐元素成立；开端点或符号范围写成字符串，例如 `"0 <= route_id < E"`。浮点输入允许 `inf` 或 NaN 时必须在 `range` 中写明，例如 `"finite or -inf"`；没有写明时，`range` 只在有限值的基础上进一步收窄。

`range` 与 shape、dtype 和 `compute` 中的约束同时成立，不互相覆盖。省略 `range` 时只适用默认值域，不会从名称或 `meaning` 推出更窄的范围；例如 `meaning` 写“已激活”，不代表取值落在某个激活函数的值域内。

公式引用可缺省的输入时，指的是代入缺省值之后的对象。

本区不使用 `null`；其他缺项写法遵循[公共约定](0.common.md#通用写法)。

### 误差判据

`tolerance` 的每条判据比较实现的输出 `x` 与参考入口的结果 `g`，浮点值都转为 FP32 后计算。常用写法如下，其他判据在字符串中写出完整定义：

| 写法 | 判据 |
| --- | --- |
| `exact` | 逐元素相等。 |
| `atol=a, rtol=r` | 逐元素满足 `abs(x - g) <= a + r * abs(g)`；`g` 为 `±inf` 的位置，`x` 必须取相同的值。 |
| `rel_rmse <= e` | `sqrt(sum((x - g)^2) / sum(g^2)) <= e`，求和遍及该输出的全部元素。 |

## 关键原则

### 先定义调用者要什么，再选择怎样实现

输入的有效域、因果对齐、路由解释、量化定义、初末状态和输出边界属于本区。源码中的 tile 对齐、最大支持长度、分块大小、kernel 数量和 CTA 配置不能直接升级为算法要求：GDN 的 token 递推不要求某个 chunk 大小，而 MoE 的量化组长直接决定数值，必须保留。

### 压缩重复，不压缩会改变结果的条件

固定的量登记一次、按名称引用，多处使用的函数定义一次，属性已有唯一来源时用 `ref:` 引用。相反，全部 key 不可见时的输出、读出用更新前还是更新后的状态、两次量化各自的舍入点，不能因为“通常猜得到”而省略。

`meaning` 说明对象是什么，`math` 定义它怎样得到。不要把整条公式抄进 `meaning`，也不要只写一个模糊的名称，而把实际约束留在 YAML 之外。

### 数学中间量不等于实现缓冲

为说明算法而定义完整的 score、概率矩阵或状态序列，不要求实现创建对应大小的张量；是否融合、分块、保存或重算由 Design 决定。Contract 既不能强迫朴素物化，也不能因为担心物化而省掉重要的数学对象。

### 参考入口服从契约，设计出处不代替参考入口

设计出处与参考入口的职责见[来源与证据](0.common.md#来源与证据)，两者不能合并。

检查参考入口时，要沿调用路径核对掩码、量化、激活、路由和状态处理；函数名含 `torch` 或 `ref` 不证明它独立。参考入口与 `compute` 不一致时以 `compute` 为准，差异写进 `gap`，不修改 `compute` 去迁就入口。

### 数学定义、实现误差与测试验收分开

`compute` 定义标准答案的数学含义，`tolerance` 规定实现可以偏离多少。近似计算、累加次序等带来的实现误差都必须落在判据之内，不能从 `gap` 中获得额外许可；Designer 评估近似方案时，也以 `tolerance` 为误差预算。

## 具体案例

以下三个案例都作为各自任务的 root，只展开公共的 `meta_data` 与本节的 `contract.algorithm_requirement`。第一个案例省略可选的 `dispatch`，缺省 ID 即 `root`；后两个案例演示显式填写 root 的形式。派生节点规则见[公共约定](0.common.md#派生节点与-dispatch)；历史任务可按需查阅 `schema_wiki/aka-four-problems-20261020/`，其状态见 [README](../README.md#6-现状与-todo)。

### Case 1：因果 Attention

本例采用 BF16 Q/K/V/O、FP32 LSE、8 个 MHA head 和 128 维 head。QueryLength 与 KVLength 可以不同，因果采用右下对齐；本例没有额外的 score 或 mask 修改。

参考入口 `attention_ref` 按右下对齐构造因果 mask，并处理全部 key 不可见的行；它按传入 V 的 dtype 返回 LSE，这一差异写在 `gap` 中。[^attention-ref]

本例展示多处共用的固定维度登记为常量、空行分支、非张量函数 symbol、跨步骤的 shape 引用，以及参考入口与契约之间的精度差异。公式中的行最大值只是稳定表达 softmax，不是在线 softmax 状态。

[^attention-ref]: `Dao-AILab/flash-attention@ce088ab9:flash_attn/cute/testing.py::attention_ref`；同文件的 `construct_local_mask` 定义因果对齐。

```yaml
meta_data:
  name: scaled_dot_product_attention
  describe: Compute right-aligned causal attention and natural-log normalizers.
  source: Dao-AILab/flash-attention@ce088ab9:flash_attn/cute/flash_fwd_sm100.py
  version: 1

contract:
  algorithm_requirement:
    constant:
      HeadCount: {value: 8, meaning: Attention head count}
      D: {value: 128, meaning: Head dimension}
      scale: {value: "1/sqrt(D)", meaning: Score scale}

    input:
      Q: {meaning: Query, shape: [batch: BatchCount, query: QueryLength, head: HeadCount, d: D], dtype: bf16}
      K: {meaning: Key, shape: [batch: BatchCount, kv: KVLength, head: HeadCount, d: D], dtype: bf16}
      V: {meaning: Value, shape: [batch: BatchCount, kv: KVLength, head: HeadCount, d: D], dtype: bf16}

    output:
      O: {meaning: Attention output, shape: [batch: BatchCount, query: QueryLength, head: HeadCount, d: D], dtype: bf16}
      LSE: {meaning: Natural-log normalizer, shape: [batch: BatchCount, head: HeadCount, query: QueryLength], dtype: fp32}

    compute:
      - name: Define causal scores
        math: |
          Each batch and head is independent; their indices are omitted.
          For 0 <= q < QueryLength:
            visible_key(q) = {j in integers | 0 <= j < KVLength and j <= q + KVLength - QueryLength}.
            For 0 <= k < KVLength:
              score[q,k] = sum_{d=0}^{D-1} (scale * Q[q,d]) * K[k,d] if k in visible_key(q); otherwise -inf.
        symbol:
          visible_key: {meaning: Function returning the visible key set for a query, shape: not_applicable, dtype: not_applicable}
          score: {meaning: Masked attention score, shape: [batch: BatchCount, head: HeadCount, query: QueryLength, kv: KVLength], dtype: fp32}

      - name: Normalize and read values
        math: |
          For 0 <= q < QueryLength:
            If visible_key(q) is nonempty:
              row_max = max_{j in visible_key(q)} score[q,j].
              norm = sum_{j in visible_key(q)} exp(score[q,j] - row_max).
              probability[q,k] = exp(score[q,k] - row_max) / norm if k in visible_key(q); otherwise 0, for 0 <= k < KVLength.
              O[q,d] = bf16(sum_{k in visible_key(q)} probability[q,k] * V[k,d]) for 0 <= d < D.
              LSE[q] = row_max + ln(norm).
            Otherwise:
              probability[q,k] = 0 for 0 <= k < KVLength.
              O[q,d] = 0 for 0 <= d < D.
              LSE[q] = -inf.
        symbol:
          probability: {meaning: Probability over visible keys, shape: "ref:score.shape", dtype: fp32}

    golden_reference:
      source: Dao-AILab/flash-attention@ce088ab9:flash_attn/cute/testing.py::attention_ref
      tolerance: {O: "atol=1e-2, rtol=1e-2", LSE: "atol=1e-3, rtol=1e-3"}
      gap: The entry returns LSE in the dtype of V; call it with FP32 copies of Q, K, and V so that LSE keeps FP32 precision.
```

### Case 2：GDN

本例选定 Q/K/V 为 BF16、g/beta 为 FP32，读出缩放为 `1/sqrt(DK)`；这些是本案例的契约取值，不是对所有 GDN 任务的统一默认值。序列等长，Q/K 不在算子内归一化，g 是单步自然对数衰减，beta 直接按给定值使用。

参考入口在 FP32 中按 token 递推，依次衰减、修正、更新和读出，返回 FP32 的逐 token 输出和最终状态；按契约调用不会偏离 `compute`，因此没有 `gap`。[^gdn-ref]

本例展示数值相同但含义不同的常量 `DK` 与 `DV`、缺省零状态、更新后读出，以及用 `S(t)` 表示的递推状态（其 shape 不含 token 轴）。没有 chunk 大小、三角求解或 phase 数量要求。

[^gdn-ref]: `fla-org/flash-linear-attention@954438d1:fla/ops/gated_delta_rule/naive.py::naive_recurrent_gated_delta_rule`。

```yaml
meta_data:
  name: gated_delta_rule
  describe: Compute gated delta readouts and the final state.
  source: fla-org/flash-linear-attention@954438d1:fla/ops/gated_delta_rule/chunk.py
  version: 1
  dispatch:
    id: root
    when: Select for every input in the contract domain.

contract:
  algorithm_requirement:
    constant:
      DK: {value: 128, meaning: Key dimension}
      DV: {value: 128, meaning: Value dimension}
      scale: {value: "1/sqrt(DK)", meaning: Query readout scale}

    input:
      Q: {meaning: Query, shape: [batch: BatchCount, token: SequenceLength, head: HeadCount, dk: DK], dtype: bf16}
      K: {meaning: Key, shape: [batch: BatchCount, token: SequenceLength, head: HeadCount, dk: DK], dtype: bf16}
      V: {meaning: Value, shape: [batch: BatchCount, token: SequenceLength, head: HeadCount, dv: DV], dtype: bf16}
      g: {meaning: Per-token natural-log decay, shape: [batch: BatchCount, token: SequenceLength, head: HeadCount], dtype: fp32}
      beta: {meaning: Activated update coefficient, shape: [batch: BatchCount, token: SequenceLength, head: HeadCount], dtype: fp32}
      S0: {meaning: Initial state, shape: [batch: BatchCount, head: HeadCount, dk: DK, dv: DV], dtype: fp32, default: 0}

    output:
      o: {meaning: Updated-state readout, shape: [batch: BatchCount, token: SequenceLength, head: HeadCount, dv: DV], dtype: bf16}
      S_final: {meaning: Final state, shape: [batch: BatchCount, head: HeadCount, dk: DK, dv: DV], dtype: fp32}

    compute:
      - name: Apply the recurrence
        math: |
          Q and K are used without normalization.
          For each batch and head, with their indices omitted:
            S(-1) = S0.
            For 0 <= t < SequenceLength:
              S_decay(t) = exp(g[t]) * S(t-1).
              delta(t)[j] = beta[t] * (V[t,j] - sum_{i=0}^{DK-1} K[t,i] * S_decay(t)[i,j]) for 0 <= j < DV.
              S(t)[i,j] = S_decay(t)[i,j] + K[t,i] * delta(t)[j] for 0 <= i < DK and 0 <= j < DV.
              o[t,j] = bf16(sum_{i=0}^{DK-1} (scale * Q[t,i]) * S(t)[i,j]) for 0 <= j < DV.
            S_final = S(SequenceLength - 1).
        symbol:
          S: {meaning: State after token t, shape: "ref:S0.shape", dtype: fp32}
          S_decay: {meaning: Decayed state at token t, shape: "ref:S0.shape", dtype: fp32}
          delta: {meaning: Update vector at token t, shape: [batch: BatchCount, head: HeadCount, dv: DV], dtype: fp32}

    golden_reference:
      source: fla-org/flash-linear-attention@954438d1:fla/ops/gated_delta_rule/naive.py::naive_recurrent_gated_delta_rule
      tolerance: {o: "rel_rmse <= 5e-3", S_final: "rel_rmse <= 5e-3"}
```

### Case 3：MoE FP8 Block

本例采用 H=7168、分片中间维度 I=256、256 个专家、每 token 8 个给定 route；激活按 128 元素分组量化，权重按 128×128 分块量化，两者共用块长 G=128。案例选定 X/Y 为 BF16、route_id 为 int64、route_weight 为 FP32。输入量化、专家计算和本分片合并在边界内；路由选择与跨分片归约在边界外。旧实现分析针对 SM90，本例只沿用数学任务。

参考入口 `torch_experts` 按传入激活的 dtype 分配中间结果，量化 helper 是否把 scale 取整为 2 的幂取决于外部设置；这两处会让直接调用偏离 `compute`，写在 `gap` 中。[^moe-ref][^moe-quant] 它按块做点积后再乘 scale，与先逐元素反量化再求和只差 FP32 舍入次序，由误差判据吸收，不算差异。[^moe-matmul]

本例展示显式 FP8 码值、scale 解释、两次调用同一量化函数，以及只返回分片贡献的输出边界。两次量化共享定义，但分别从各自输入重新计算 scale。

[^moe-ref]: `vllm-project/vllm@28282ffe:tests/kernels/utils.py::torch_experts`。
[^moe-quant]: `vllm-project/vllm@28282ffe:vllm/model_executor/layers/fused_moe/utils.py::moe_kernel_quantize_input`；`vllm-project/vllm@28282ffe:vllm/model_executor/layers/quantization/utils/fp8_utils.py::per_token_group_quant_fp8`。
[^moe-matmul]: `vllm-project/vllm@28282ffe:tests/kernels/quant_utils.py::native_w8a8_block_matmul`。

```yaml
meta_data:
  name: mixture_of_experts
  describe: Compute this shard's block-scaled FP8 SwiGLU expert contribution for supplied routes.
  source: vllm-project/vllm@28282ffe:vllm/model_executor/layers/fused_moe/experts/triton_moe.py
  version: 1
  dispatch:
    id: root
    when: Select for every input in the contract domain.

contract:
  algorithm_requirement:
    constant:
      H: {value: 7168, meaning: Hidden dimension}
      I: {value: 256, meaning: Shard intermediate dimension}
      E: {value: 256, meaning: Expert count}
      TopK: {value: 8, meaning: Route count per token}
      G: {value: 128, meaning: Quantization block extent along every quantized axis}
      epsilon: {value: 1.0e-10, meaning: Minimum activation amax}
      fp8_max: {value: 448, meaning: Maximum E4M3FN magnitude}

    input:
      X: {meaning: Unquantized activation, shape: [token: TokenCount, hidden: H], dtype: bf16}
      W13: {meaning: FP8 weight concatenated as gate then up, shape: [expert: E, channel: "2*I", hidden: H], dtype: fp8_e4m3fn}
      W2: {meaning: FP8 down-projection weight, shape: [expert: E, hidden: H, intermediate: I], dtype: fp8_e4m3fn}
      S13: {meaning: W13 block scale, shape: [expert: E, channel_block: "2*I/G", hidden_block: "H/G"], dtype: fp32}
      S2: {meaning: W2 block scale, shape: [expert: E, hidden_block: "H/G", intermediate_block: "I/G"], dtype: fp32}
      route_id: {meaning: Supplied expert index, shape: [token: TokenCount, route: TopK], dtype: int64, range: "0 <= route_id < E"}
      route_weight: {meaning: Supplied route weight, shape: [token: TokenCount, route: TopK], dtype: fp32}

    output:
      Y: {meaning: Shard contribution before cross-shard reduction, shape: [token: TokenCount, hidden: H], dtype: bf16}

    compute:
      - name: Define activation quantization
        math: |
          Define quantize_dequantize(x) for a row x of length L in {H, I}:
            group_scale[u] = max(epsilon, max_{j=u*G}^{(u+1)*G-1} abs(x[j])) / fp8_max for 0 <= u < L/G.
            code[j] = fp8_e4m3fn(clamp(x[j] / group_scale[floor(j/G)], -fp8_max, fp8_max)) for 0 <= j < L.
            quantize_dequantize(x)[j] = code[j] * group_scale[floor(j/G)].
          Do not round group_scale to a power of two.
          X_dequantized[n,:] = quantize_dequantize(X[n,:]) for 0 <= n < TokenCount.
        symbol:
          quantize_dequantize: {meaning: Row-wise FP8 quantization and dequantization function, shape: not_applicable, dtype: not_applicable}
          group_scale: {meaning: Group scale for one function call, shape: [group: "L/G"], dtype: fp32}
          code: {meaning: FP8 code for one function call, shape: [element: L], dtype: fp8_e4m3fn}
          X_dequantized: {meaning: Input after quantization and dequantization, shape: "ref:X.shape", dtype: fp32}

      - name: Dequantize weight
        math: |
          For 0 <= e < E, 0 <= p < 2*I, 0 <= h < H, and 0 <= i < I:
            W13_dequantized[e,p,h] = W13[e,p,h] * S13[e,floor(p/G),floor(h/G)].
            W2_dequantized[e,h,i] = W2[e,h,i] * S2[e,floor(h/G),floor(i/G)].
        symbol:
          W13_dequantized: {meaning: Dequantized gate and up weight, shape: "ref:W13.shape", dtype: fp32}
          W2_dequantized: {meaning: Dequantized down-projection weight, shape: "ref:W2.shape", dtype: fp32}

      - name: Compute routed activation
        math: |
          Define silu(x) = x / (1 + exp(-x)).
          For 0 <= n < TokenCount and 0 <= r < TopK, let e = route_id[n,r]:
            gate_up[n,r,p] = sum_{h=0}^{H-1} X_dequantized[n,h] * W13_dequantized[e,p,h] for 0 <= p < 2*I.
            A[n,r,i] = silu(gate_up[n,r,i]) * gate_up[n,r,I+i] for 0 <= i < I.
            A_dequantized[n,r,:] = quantize_dequantize(A[n,r,:]).
        symbol:
          gate_up: {meaning: Gate-then-up projection, shape: [token: TokenCount, route: TopK, channel: "2*I"], dtype: fp32}
          A: {meaning: SwiGLU activation, shape: [token: TokenCount, route: TopK, intermediate: I], dtype: fp32}
          A_dequantized: {meaning: Activation after quantization and dequantization, shape: "ref:A.shape", dtype: fp32}

      - name: Combine the shard output
        math: |
          For 0 <= n < TokenCount and 0 <= h < H:
            Y[n,h] = bf16(sum_{r=0}^{TopK-1} route_weight[n,r] *
                         (sum_{i=0}^{I-1} A_dequantized[n,r,i] * W2_dequantized[route_id[n,r],h,i])).
          Use every supplied route slot, including repeated expert indices, without weight renormalization.

    golden_reference:
      source: vllm-project/vllm@28282ffe:tests/kernels/utils.py::torch_experts
      tolerance: {Y: "rel_rmse <= 2e-2"}
      gap: |
        Pass X as FP32; the entry allocates intermediates in the activation dtype, and BF16 intermediates would add roundings not defined in compute.
        The quantization helper reads power-of-two scale rounding from an external setting; keep it disabled so that group_scale stays unrounded.
```
