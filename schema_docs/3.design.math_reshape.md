#### 核心思想

`math_reshape` 记录在不改变 Contract 的前提下，实际计算哪些值、采用什么数学关系、使用什么精度，以及哪些状态和中间量需要保留。它做的是算法与硬件的 co-design：动机来自硬件——哪类单元更快、哪一级存储放得下、哪条依赖链太长——而改写本身是纯数学的，与流水线无关。它向下游交付的是可审阅的数学设计，而不是 GPU 执行程序。

本区以“数学决定”为基本单位组织 `rewrite`。一个决定可以包含定义、递推、分情形和显式类型转换；多个决定之间通过值的依赖连接。一个步骤应当能被单独审阅、替换或否决：切分的位置是物化值产生之后，以及迭代结构变化处；精度分叉不单独成步，在同一步里用两个名字表达。步骤不是 phase：一个数学步骤可以由多个工作实例完成，多个步骤也可以融合在同一份工作中。改写不按 representation、quantization、fusion 等类别分区，这些类别彼此交叉，只会把同一个决定拆散到多处。

本区使用 `thesis / rewrite / ledger`：

- `thesis` 概括这次改写最重要的主张、动机与主要代价。
- `rewrite` 是本区唯一的计算定义处，从 Contract 输入写到全部输出。
- `ledger` 不定义任何值，只对照一个明确的 baseline 记录改写造成的差额。

本区接收 Contract 的输入输出、数学要求和硬件条件，也可以引用由下游绑定的工作参数。它不决定 CTA、warp、lane、物理布局、缓冲槽位、屏障或流水重叠。

**设计着眼点**

改写的空间是开放的，本区不给它分类，也没有可以照着套的清单：继承下来的算子边界、数据表示和融合方式都可以重新考虑，只有 Contract 的输入输出与数学关系不能动。能落地的改写几乎都是同一种形状——拿一项充裕的资源换一项稀缺的资源，所以先确认瓶颈在哪一项，再去找能把它换下来的数学变换；账本的作用就是让这笔交易可核对。这类改写在源码里常常只剩一行阈值判断或一个分块常数，要从算法意图去识别，不能从代码结构反推。

| 问题 | 要看什么 | 落在哪里 |
| --- | --- | --- |
| 瓶颈是哪一项 | 硬件规格与 microbench 给出的相对代价，以及朴素算法在哪一项上离下界最远。 | `ledger` 中必须变小的那一行。 |
| 哪些量其实不必存在 | 随输入规模增长的中间量能否换成固定大小的状态；零散的计算能否聚成可复用的稠密块，省掉重复的搬运与扫描。 | `symbol.life`，`footprint` / `traffic` / `pass`。 |
| 串行链能不能变短 | 逐元素的递推能否折成块内并行、块间递推。 | 递推的 `math`，`depth`。 |
| 能不能换更便宜的单元 | 同一份计算能否交给吞吐更高的单元，或拼成它的原生形状。 | `matmul` / `vector` / `transcendental` 之间的移动。 |
| 精度在哪里改变 | 哪一步窄化、哪一步近似，`tolerance` 的预算还剩多少。 | 公式中的 cast，`arithmetic`，`error`。 |

#### 字段定义

**结构轮廓**

下面是字段结构，不是待填写的 YAML。`[]` 表示列表，`<name>` 表示实例名称，`?` 表示条件可省略。

```text
math_reshape
├─ thesis
├─ rewrite[]
│  ├─ step
│  ├─ name
│  ├─ math
│  ├─ symbol?                 named map
│  │  └─ <name>: meaning / shape? / dtype? / life? / binding? / value?
│  └─ arithmetic?
│     ├─ approx?
│     └─ accumulate?
└─ ledger?
   ├─ baseline
   └─ <resource>[]: item / change / by[]
```

**主体字段**

下表中的路径均相对于 `math_reshape`。

| 字段路径 | 值的形式 | 填写条件 | 含义与约束 |
| --- | --- | --- | --- |
| `thesis` | 非空字符串 | 必填 | 一两句说明改写、动机和主要代价，不写泛泛的性能口号。 |
| `rewrite` | 非空步骤列表 | 必填 | 从 Contract 输入写到全部输出。 |
| `rewrite[].step` | 非空字符串 | 必填 | 本区唯一的步骤 ID，供 `ledger.by` 引用。 |
| `rewrite[].name` | 非空字符串 | 必填 | 简短说明该步骤的数学决定。 |
| `rewrite[].math` | 非空多行字符串 | 必填 | 定义、递推、分情形、索引范围和显式 cast。 |
| `rewrite[].symbol` | 具名映射 | 该步骤首次引入必须登记的符号时必填 | 每个符号只登记一次；没有新增登记对象时省略。 |
| `rewrite[].arithmetic` | 固定结构映射 | 存在公式未完整表达的精度例外时必填 | 只允许 `approx`、`accumulate`，至少填写一项。 |
| `rewrite[].arithmetic.approx` | 非空字符串 | 存在公式未完整表达的主动近似时填写 | 说明近似方法、适用域和误差界；没有可靠误差界时明确写 `unknown:`。 |
| `rewrite[].arithmetic.accumulate` | 非空字符串 | 累加方式、归约分组或乘法输入精度不能从公式及默认规则确定时填写 | 不重复已经由 `mm32`、`mma32` 或显式 cast 表达的事实。 |
| `ledger` | 固定结构映射 | 改写相对 baseline 有可计量的变化时必填 | 记录变化的方向与数量；缺少某类资源的条目不是零变化的证明。 |
| `ledger.baseline` | 非空字符串 | `ledger` 出现时必填 | 一句话给出被比较的直算方式及其物化取法；共用的计量口径见“账本”，这里只写与它不同的部分。 |
| `ledger.<resource>` | 非空条目列表 | 该类资源存在需要记录的变化时填写 | 只记录变化项，不为凑齐资源类别填写空项。 |
| `ledger.<resource>[].item` | 非空字符串 | 必填 | 被比较的对象或计量对象。 |
| `ledger.<resource>[].change` | 非空字符串 | 必填 | 带单位和范围的定量增减或前后对照；其中的符号必须已由 `math` 定义。 |
| `ledger.<resource>[].by` | 非空步骤 ID 列表 | 必填 | 指向造成该变化的 `rewrite[].step`。 |

**符号属性**

`symbol.<name>` 的合法字段为 `meaning / shape / dtype / life / binding / value`，按需填写。

| 字段 | 值的形式 | 填写条件 | 含义与约束 |
| --- | --- | --- | --- |
| `meaning` | 非空字符串 | 必填 | 一句话说明符号是什么；不重复整段公式，也不承担缺项占位。 |
| `shape` | 具名维度列表，或属性引用、待绑定标记 | 公式不能确定，或该值要被下游取用时必填 | 描述一个逻辑实例的值形状，不描述线程 fragment。标量写 `[]`。 |
| `dtype` | 类型名字符串，或属性引用、待绑定标记 | 同 `shape` | 描述数值表示。类型名必须在任务环境中有定义；不是任意自造标签。 |
| `life` | 生命周期字符串 | 值跨迭代携带，或为后续步骤物化时必填 | 描述计算值的逻辑保留范围，不指定物理驻留位置。 |
| `binding` | `ref:` 或 `bind:` 引用字符串 | 整个符号由本区之外提供时必填 | 指定符号的定义来源或待绑定的提供者。 |
| `value` | 已知标量或数组字面值 | 本层选择一个固定值时填写 | 是该固定值的唯一来源；不用于装未知值或外部参数。 |

“被下游取用”指 `carried`、`stored` 或被其他区引用的值：它们是下游的接口，`shape` 与 `dtype` 必须填全。公式已经定死、又只在本步使用的属性不再复写一遍——`dot32` 的结果是 FP32，`0 <= u < Bk` 已经给出长度。

集合、映射、函数，以及只作参数使用的数学整数没有数值表示，省略 `shape` 与 `dtype`，也不写 `not_applicable`；它们的取值由 `value` 或 `binding` 给出。`value` 与外部 `binding` 不同时承担同一符号的定义权：外部已经固定的量使用引用，不在本区再维护一份数值。

**生命周期**

`life` 写成 `"<carried|stored> <实例>"`，存在递推时在分号后给出迭代范围。

| 写法 | 含义 |
| --- | --- |
| 省略 | 只在本步的一次计算中存在的值。 |
| `"carried (b,h,q); i=-1..N-1"` | 在给定迭代范围内携带的递推状态。每个查询行是一个实例，换到新实例就按公式重新初始化。 |
| `"stored (b,h)"`、`"stored invocation"` | 明确选择物化，在该实例范围内保留给后续步骤。 |

`life` 描述逻辑用途，不是内存空间枚举：递推状态一律写 `carried`，它是否需要在某处保存到全局内存不由这个词决定；`stored` 也不自动表示全局内存或跨 kernel，案例确实选择全局物化时在 `meaning` 中说明。初值、重置位置、有效迭代范围、消费者和最终输出关系都由 `math` 给出，本区不另设初始化、重置或终点字段；`life` 必须与这些公式一致。

**账本资源键**

下表是封闭集合：结构轮廓里的 `<resource>` 只能取其中之一，不同于可自造实例名的 `<name>`。

| 资源键 | 计量内容 |
| --- | --- |
| `matmul` | 内积、矩阵收缩或相关求解工作。 |
| `vector` | 逐元素运算、索引处理等非矩阵收缩工作。 |
| `transcendental` | 指数、对数、倒数等函数求值。 |
| `traffic` | 指定计量模型下的数据读写量。 |
| `footprint` | 指定作用域内的状态或物化数据大小。 |
| `depth` | 指定依赖链的长度。 |
| `pass` | 对同一数据集合的完整遍历次数。 |
| `comm` | 指定参与者之间的逻辑数据交换量。 |
| `error` | 改写新增的误差来源，以及已知的误差界。 |

这九项就是改写能够移动的量。一次有效的改写通常让其中一两项明显下降、另外一两项上升；如果所有条目都在增加，或者说不清哪一项下降，这次改写的收益还没有找到。

**固定结构与扩展边界**

| 位置 | 类型 | 允许的变化 |
| --- | --- | --- |
| `math_reshape`、`rewrite[]`、`symbol.<name>`、`arithmetic`、账本条目 | 固定结构 | 只使用本节声明的字段。 |
| `symbol` | 具名映射 | 可以增加当前设计需要的符号名。 |
| `ledger` | 固定资源集合 | 可以增加资源条目，不自行增加资源类别。 |

增加步骤、数学符号、辅助函数或账本条目属于填写内容；新增 `life` 取值、资源类别或固定字段属于结构修改，须另行确认。

#### 语法规则

**名称、ID 与定义范围**

字段名使用英文单数。符号名区分大小写，采用简短的英文或数学惯用名称；真实源码路径、函数名和参数名保留原样。

规模、常量和张量的名称沿用 Contract，不在本区另起别名，本区只登记新引入的量。每份 `math_reshape` 有独立的符号命名空间，一个已登记符号只出现一份定义，后续步骤直接使用该名称。局部求和下标、一次性代数缩写和明确的视图别名可以只在 `math` 中定义，但其范围必须能够确定。

`step` 使用字符串，例如 `"1"`、`"2"`；互不依赖的兄弟步骤可以写成 `"1(A)"`、`"1(B)"`。编号只是 ID，不表示执行顺序，也不表示二选一。

列表与映射的顺序都不表示执行顺序：执行先后只来自公式中的数据依赖、递推和下游安排。

**引用与缺项**

`shape: []`、`"ref:"` 引用，以及不用 `null`、NaN、`"-"` 占位的规则由 `contract.algorithm_requirement` 给出。目标写成 `<area>::<name>[.<attribute>]`，例如 `contract.algorithm_requirement::V.dtype`、`design.work_schedule::Bk`，本区内部的符号省略区名；指向固定版本材料时写 `repository@ref:path::symbol`。`::` 后的名称是语义定位，不要求目标区域新增同名字段，但接入完整 Plan 时必须解析到实际定义。

| 写法 | 含义 |
| --- | --- |
| `"ref:<target>"` | 目标已由上游或本区定义，且唯一可解析。 |
| `"bind:<target>"` | 提供者明确，取值将由下游固定。 |
| `"unknown:<reason>"` | 尚未确定或缺少依据；必须说明缺口。 |

`binding` 引用整个对象，`shape / dtype / life` 中的引用只引用相应属性，并且必须保持属性语义一致：不能把 Contract 中的数学定义域当成本层的保留范围。外部绑定的符号仍可填写已知属性，它们是对绑定结果的约束，不是第二份定义；冲突时报告问题，不由某一处静默覆盖另一处。

源码函数存在、但它到本区数学对象的映射尚未完成时保留 `bind:`，不能用函数名伪装成已经完成的数学定义。`unknown:` 用于连属性值或有效依据都尚未确定的情况，不出现在 `ledger.change` 中。

**数学表达与 shape**

`math` 只写实际求值的计算：定义、递推、分情形和显式转换。等价性证明、不变量和解释性文字不写在这里——改写是否与原定义等价，由实现与 golden reference 的数值对比检验。

记号沿用 `contract.algorithm_requirement`：标量乘与缩放写 `*`，`X[i]` 与 `X(t)`、切片、索引范围、`sum` 与 `max`、`clamp` 的写法相同，集合用英文写法（`{j in integers | ...}`、`j in visible_key(q)`）。不使用 LaTeX 源码、线程视图操作或实现代码。本区补充下表：

| 记号 | 含义 |
| --- | --- |
| `Aᵀ` | 转置。 |
| `A ⊙ B` | 逐元素乘法；广播轴必须明确。 |
| `X[:,None]` | 数学上的单例轴插入，不指定物理布局。 |
| `count(S)` | 集合的元素个数。 |
| `dtype(X)` | 已定义对象的 dtype，不是重新选择类型。 |
| `bytesize(dtype(X))` | 该 dtype 的每元素字节数。 |

矩阵乘一律由下面的精度记号表达，`*` 只用于标量乘与缩放，`⊙` 只用于逐元素乘；三者必须能够区分。`blk`、`group` 等辅助函数没有隐藏的全局定义，必须在当前案例中给出。

未被改写的计算直接引用 Contract 的定义，不重抄；改写发生在某个计算内部时，必须展开到能看见改动的粒度——per-tensor scale 的 GEMM 可以不展开，把 block scale 提到内积之外就必须展开。

shape 写成具名维度列表，轴名与大小的写法同 Contract，例如 `[kv: Bk]`、`[dk: DK, dv: DV]`；沿用 Contract 对象的轴时保持同名。它描述一个逻辑实例的完整值，不表示某个线程或 worker 一次持有整行，也不直接给出寄存器占用。

分情形只要求在有效分支上求值。不能把越界读取、`0/0` 或 `-inf-(-inf)` 当成无条件计算，再假设掩码会消除影响。空和为零，空最大值为 `-inf`；递推是否允许空范围，还必须有明确的最终关系。

**精度与辅助运算**

默认 FP32 与 RNE、`<dtype>(x)` 转换、窄化必须写出而加宽不写，都由 `contract.algorithm_requirement` 给出。该默认同样不覆盖整数索引、布尔谓词、集合和数学映射；输入保持 Contract dtype，窄化与量化这类改变数值的转换必须由公式写出，不能只靠 `symbol.dtype` 暗示。本区补充下表：

| 记号 | 数值含义 |
| --- | --- |
| `cast(dtype(X),Z)` | 将 `Z` 转为 `X` 已定义的 dtype。 |
| `fma32(A,B,C)` | FP32 融合乘加，乘加结果一次舍入。 |
| `dot32(A,B)`、`mm32(A,B)` | 所示 dtype 输入的内积或矩阵乘，零初始累加器和结果为 FP32。 |
| `mma32(A,B,C)` | 以 FP32 `C` 为初始累加器的矩阵乘加。 |
| `mm_tf32(A,B)` | TF32 乘法输入路径，FP32 累加与结果；不表示 TF32 存储张量。 |
| `sum32` | FP32 归约。未另行固定时，不由记号指定归约树。 |

这些是数学记法，不要求实现提供同名 API。FP32 累加器也不代表乘法输入、乘积内部处理和全部舍入都具有 FP32 精度，更不构成逐位一致性保证；影响设计的输入截断、累加分组和近似必须另外表达。

填写的 `dtype` 是对公式结果的断言，例如 `P = bf16(E)` 与 `dtype: bf16` 必须一致，不能由两处分别调参。`exp2_native` 这类带实现含义的辅助函数，必须由当前案例的公式、`arithmetic` 或绑定说明其来源；后缀 `native` 本身不定义算法或误差界。

`arithmetic` 只补充当前步骤。跨步骤沿用同一例外时必须引用其定义，不能把一个步骤的精度说明默认为整份 Plan 的覆盖规则。

**账本**

账本不是成本模型：计算量与访存量由 `math` 的公式和形状决定，账本只把“跟谁比、哪几项动了、各由哪一步造成”这个论证固定下来，让读者不必重新推导。条目因此有入选判据——删掉这一条，读者还能不能看出这次改写的收益或代价？不能，才写。一个决定在一类资源下只记一条，低阶项并入主项；`change` 写到能判断方向与量级即可，不必展开全部低阶项，也不为凑齐资源类别补条目。

默认计量口径是：一个 MAC 是一次乘加，不换算成两个 FLOP；字节按逻辑读写的有效载荷计，既不是峰值分配，也不是实测 DRAM 流量；元素按本区公式实际求值的个数计，被掩码或补齐的位置只要仍然求值就计入；`footprint` 计物化总量，同时存活量与峰值分配另行写明；`pass` 要指明遍历的对象。下游分块造成的重复计算与重复读取、cache 行为、launch 开销、流水重叠和编译器结果都不计入。`baseline` 只写被比较的直算方式及其物化取法，以及与这套口径不同的地方。

条目尽量写成一行流式映射，使它可以当表读。`change` 采用“前值 -> 后值”或带正负号的增减，并在末尾给出计量范围；其中的符号必须已由 `math` 定义，依赖下游参数时保留公式与绑定关系，不在本区抄一份调度配置。只在特定输入区域成立的条目，把条件写进 `change`。

`error` 记录改写新增的误差来源及其已知误差界，例如哪一次窄化进入了哪个乘法、近似覆盖哪些元素。实现与参考实现的最终输出差异由 `contract.algorithm_requirement.golden_reference` 回答，不在账本里预测。

**省略与注释**

不接受空的 `rewrite`、`symbol`、`arithmetic` 或资源条目列表。没有可选内容时省略对应字段，不填写 `{}`、`[]` 或空字符串；例外是作为合法数据的空值，例如标量 shape 的 `[]`。

注释等通用写法见 `contract.algorithm_requirement` 的语法规则；案例特有且影响设计的事实写入相应正式字段。

#### 关键原则

**符号只登记公式说不出的事。**

跨步骤的重要中间量、跨迭代状态、明确物化的值、精度分叉点和跨区参数必须登记：它们带着寿命、外部提供者或本层固定值，公式本身表达不了。一次性求和下标、简单视图和可直接理解的局部缩写只在公式中定义。

登记之后，属性要填到下游够用为止：`carried` 要给出迭代范围，`stored` 要在后续步骤中找得到用途。不能为了避开属性检查，把关键状态移出 `symbol`；也不应为了表格完整，把每一个数学临时变量都扩展成条目。

**数学对象与存储对象分开。**

`R` 是查询行集合，`sigma` 是访问映射，二者不必存在对应张量，也不必有 dtype。下游若物化索引数组，应为那个实际数组说明形状、dtype 和生命周期，而不是倒过来把本区的数学映射解释为已经存在的数组。

同理，物化不会自动产生独立 kernel 或屏障，逻辑 shape 也不会自动决定 buffer slot 与 worker 数。

**同一事实只有一个定义权。**

Contract 对象直接沿用或引用，不在本区改变其名称、shape、语义或量化规则。已由公式 cast 确定的 dtype 需要写出时，只作为一致性断言，不构成第二个选择。

块长按它改变了什么来归属，而不是按名字：GDN 的 `C=64` 改变三角系统与跨块递推，是本层选择；FA4 的 `Bk` 是工作分块参数，由下游绑定；MoE 的量化组长由 Contract 固定。

**精度是可以设计的，但每条数值路径都要留下痕迹。**

在哪里窄化、在哪里保持 FP32、哪里用带误差界的近似换吞吐，都是本层的决定，预算是 `contract.algorithm_requirement.golden_reference.tolerance`。代价是这些决定必须逐条落在公式里：GDN 的 `bf16(R)` 与 `bf16(decay*R)` 是从同一个 FP32 值出发的两条路径，不能合并为先窄化再加权；FA4 的分母使用 `E`、分子使用 `bf16(E)`，也不能被一句“FP32 累加”替代。跳过不可见项与近似本来必须计算的项是不同的决定，必须分别说明。

本区不另立误差标准，局部的多项式误差界也不是最终输出误差界。实现替换是否可接受，取决于它是否改变已声明的路径或 Contract 要求，而不是能否用“小于一个 ULP”概括。需要改动这些决定时返回设计或 Contract 讨论，不能移到 realization 后自行放宽。

**公式级账本不冒充完整 kernel 成本。**

本区只记录数学决定能解释的变化。默认口径排除的那些量要纳入账本，必须同时给出依据；硬件峰值推不出实现收益，另一架构上的累加行为和性能倍率也不能直接迁移过来。

#### 具体案例

以下两个案例的目标硬件均为 B200 / SM100，只展开 `math_reshape`；Contract 的名称、常量与记号按 `contract.algorithm_requirement` 的同名案例引用。保留的 `bind:` 是由下游绑定的未决项，不表示可以由 Coder 自由替换。

**案例一：FA4 因果单 CTA**

上游条件为 BF16 Q/K/V/O、FP32 LSE、8 个 head、`D=128`，因果右下对齐，空行返回 `O=0`、`LSE=-inf`。本例不包含 paged KV、varlen 或 split-KV。

本例展示下游绑定的非张量符号、逐查询行重置的递推状态，以及 `E`/`P` 的精度分叉：分母累加未窄化的 `E`，分子使用 `bf16(E)`。公式已经定死的 shape 与 dtype 不再登记，`P` 仍然填写这两项，因为 `realization` 要引用它。`Bk`、`sigma`、`R` 与多项式路径覆盖哪些元素都由下游绑定，本区只固定“一部分可见元素改走三次多项式”这个决定。

```yaml
math_reshape:
  thesis: Stream visible KV blocks with per-query state instead of global score and probability tensors. Let the reference maximum lag and evaluate part of exp2 by a cubic polynomial, accepting approximation and BF16 numerator operands.

  rewrite:
    - step: "1"
      name: Traverse only the blocks holding visible keys
      math: |
        Each batch and head is independent; b and h are omitted.
        R is a set of query rows with 0 <= q < QueryLength, and Bk is a positive integer.
        J = {j | 0 <= j < ceil(KVLength/Bk) and j*Bk+u in visible_key(q)
                 for some q in R and 0 <= u < Bk}
        N = count(J); sigma maps {0,...,N-1} one-to-one onto J.
        For q in R, 0 <= i < N and 0 <= u < Bk:
          k(i,u) = sigma(i)*Bk+u
          S(i)[u] = dot32(Q[q,:],K[k(i,u),:]) if k(i,u) in visible_key(q); otherwise -inf
          Vblk(i)[u,:] = V[k(i,u),:] if 0 <= k(i,u) < KVLength; otherwise 0
      symbol:
        R: {meaning: Query-row set sharing one KV traversal., binding: "bind:design.work_schedule::R"}
        Bk: {meaning: KV block length., binding: "bind:design.work_schedule::Bk"}
        sigma: {meaning: Traversal position to key-block map., binding: "bind:design.work_schedule::sigma"}

    - step: "2"
      name: Let the reference maximum lag by up to tau
      math: |
        c = scale*log2(e)
        m(-1) = -inf
        m_hat(i) = max(m(i-1),max_u S(i)[u])
        m(i) = m(i-1) if m(i-1) != -inf and c*(m_hat(i)-m(i-1)) <= tau
               otherwise m_hat(i)
        base(i) = m(i) if m(i) != -inf; otherwise 0
        alpha(i) = 0 if m(i-1) = -inf
                   1 if m(i-1) != -inf and m(i) = m(i-1)
                   exp2_native(c*(m(i-1)-m(i))) otherwise
      symbol:
        tau: {meaning: Allowed maximum lag in base-two units., value: 8.0}
        m: {meaning: Reference score maximum., shape: [], dtype: fp32,
            life: "carried (b,h,q); i=-1..N-1"}
      arithmetic:
        approx: |
          exp2_native is the hardware fast-exp2 path.
          unknown: certified native-exp2 error bound.

    - step: "3"
      name: Accumulate the online numerator and denominator
      math: |
        Define exp2_poly(x) with x_c = max(x,-127), n = floor(x_c) and f = x_c-n:
          p = fma32(f,fma32(f,fma32(f,coef[3],coef[2]),coef[1]),coef[0])
          exp2_poly(x) = 2^n*p if n >= -126; otherwise 2^-126*(p-1)
        x(i,u) = fma32(c,S(i)[u],-c*base(i))
        E(i)[u] = 0 if k(i,u) not in visible_key(q)
                  exp2_poly(x(i,u)) if use_poly(q,i,u)
                  exp2_native(x(i,u)) otherwise
        P(i) = bf16(E(i))
        Npoly = count({(i,u) | use_poly(q,i,u) and k(i,u) in visible_key(q)})
        Lsum(-1) = 0, Y(-1) = 0
        Lsum(i) = alpha(i)*Lsum(i-1)+sum_u E(i)[u]
        Y(i) = mma32(P(i),Vblk(i),alpha(i)*Y(i-1))
      symbol:
        coef: {meaning: Cubic coefficients in ascending power order.,
               value: [1.0, 0.69514614, 0.2275644, 0.07711909]}
        use_poly: {meaning: Selector for the entries evaluated by the cubic path.,
                   binding: "bind:design.tile_pipeline::use_poly"}
        P: {meaning: BF16 numerator operands; the denominator keeps the unrounded E.,
            shape: [kv: Bk], dtype: bf16}
        Lsum: {meaning: Online denominator., shape: [], dtype: fp32,
               life: "carried (b,h,q); i=-1..N-1"}
        Y: {meaning: Online numerator., shape: [d: D], dtype: fp32,
            life: "carried (b,h,q); i=-1..N-1"}
      arithmetic:
        approx: |
          exp2_native follows step 2. The cubic path applies for x <= 127; its n=-127 branch
          reconstructs the subnormal result instead of taking an extra FP32 multiply.
          unknown: certified error bound for the cubic path.

    - step: "4"
      name: Normalize once at the end
      math: |
        (O[q,:],LSE[q]) =
          (bf16(Y(N-1)*rcp_native(Lsum(N-1))),
           ln(2)*(c*m(N-1)+log2_native(Lsum(N-1))))
          if Lsum(N-1) > 0
          (0,-inf) otherwise
      arithmetic:
        approx: |
          rcp_native and log2_native are the hardware approximate reciprocal and fast-log2 paths.
          unknown: certified reciprocal and logarithm error bounds.

  ledger:
    baseline: Contract evaluation through dense FP32 score and probability tensors in global memory.
    matmul:
      - {item: Scored keys, change: "2*D*KVLength -> 2*D*N*Bk MAC per query row", by: ["1"]}
    vector:
      - {item: State rescaling, change: "0 -> D+1 multiplies per maximum update; the lag caps those updates at c*(m(N-1)-m(0))/tau per query row instead of one per traversed block", by: ["2", "3"]}
    transcendental:
      - {item: Cubic substitution, change: "Npoly native exp2 -> Npoly cubic evaluations of three FMA each, per query row", by: ["3"]}
    traffic:
      - {item: Score and probability tensors, change: "-16*QueryLength*KVLength bytes per (b,h)", by: ["1", "3"]}
    footprint:
      - {item: Per-row state, change: "4*KVLength bytes of scores -> 4*(D+2) bytes per query row", by: ["2", "3"]}
    depth:
      - {item: KV reduction, change: "one parallel reduction over KVLength -> N serial merges per query row", by: ["1", "3"]}
    error:
      - {item: BF16 numerator operands, change: "+1 BF16 rounding on every visible entry entering Y; Lsum keeps the unrounded E", by: ["3"]}
      - {item: Approximate elementary functions, change: "+approximate exp2 on every visible entry, of which Npoly take the cubic path; +approximate reciprocal and log2 in the readout", by: ["3", "4"]}
      - {item: Lagged maximum, change: "+E values up to 2^tau instead of at most 1, reducing headroom in the FP32 sums", by: ["2"]}
```

`N=0` 时最终引用落在 `-1` 初值上；某一行没有可见 key、但同一遍历内其他行有可见 key 时，该行也保持零分母并进入空行分支。

多项式选择不能用一个固定比例代替：即使替换数量相同，选择了不同元素也不是同一数值路径。

**案例二：GDN 分块前向**

上游为等长序列、BF16 Q/K/V、`DK=DV=128`，`g` 是单步自然对数衰减，`beta` 是已激活的更新系数，初始状态缺省为零。公式写在固定 `(b,h)` 的逻辑切片上，状态采用 key-by-value 轴顺序。

本例展示块内重置的递推、跨 chunk 携带的 FP32 状态、六个全局物化张量，以及同一个 FP32 值分叉出的两个 BF16 版本。`C=64` 是本层选择：它决定三角系统的规模与串行步数。`symbol` 只剩带寿命或固定值的量，`A`、`T32`、`R`、`B` 这些由公式完全确定的中间量不登记。本例没有主动近似，`arithmetic` 整段不出现——窄化与 TF32 乘法输入都已由公式写出。

```yaml
math_reshape:
  thesis: Replace the token recurrence by chunk-local triangular systems, shortening the state chain from one transition per token to one per chunk and turning the rank-one updates into matrix products. Reusable transforms and BF16 snapshots are materialized; the state itself stays FP32.

  rewrite:
    - step: "1"
      name: Accumulate decay within each chunk
      math: |
        Each batch and head is independent; b and h are omitted.
        Nc = ceil(SequenceLength/C), n(c) = min(C,SequenceLength-c*C), 0 <= c < Nc
        X(c) = X[c*C:c*C+n(c)] for every token-indexed value X
        G(c)[t] = log2(e)*sum32_{s=0}^{t} g(c)[s] for 0 <= t < n(c)
      symbol:
        C: {meaning: Mathematical chunk length., value: 64}
        G: {meaning: Base-two decay prefix restarted in each chunk.,
            shape: [token: SequenceLength], dtype: fp32, life: "stored (b,h)"}

    - step: "2"
      name: Write the intra-chunk dependence as a triangular system
      math: |
        A(c)[t,j] = (dot32(K(c)[t,:],K(c)[j,:])*exp2(G(c)[t]-G(c)[j]))*beta(c)[t]
                    if 0 <= j < t < n(c); otherwise 0
        sub(u) = [u*Ctri,min((u+1)*Ctri,n(c)))
        0 <= u,v < ceil(n(c)/Ctri)
        A_uv = A(c)[sub(u),sub(v)], T32_uv = T32(c)[sub(u),sub(v)]
        0 <= r,s < count(sub(u))
        D_u[r,r] = 1, D_u[r,s] = 0 if s > r
        D_u[r,s] = -A_uu[r,s]-sum_{s<k<r} A_uu[r,k]*D_u[k,s] if s < r
        T32_uu = D_u, T32_uv = 0 if u < v
        T32_uv = -mm_tf32(mm_tf32(D_u,A_uv),D_v) if u = v+1
        T32_uv = -mm_tf32(D_u,sum_{w=v}^{u-1} mm_tf32(A_uw,T32_wv)) if u > v+1
        T[c*C+t,j] = bf16(T32(c)[t,j]) if j < n(c)
                     0 if n(c) <= j < C
        0 <= t < n(c), 0 <= j < C
      symbol:
        Ctri: {meaning: Diagonal solve block length., value: 16}
        T: {meaning: Inverse of I+A for one chunk; tail columns are zero-padded.,
            shape: [token: SequenceLength, source_token: C], dtype: bf16, life: "stored (b,h)"}

    - step: "3"
      name: Apply one inverse to both right-hand sides
      math: |
        W(c) = bf16(mm32(T(c)[:,0:n(c)],
                         bf16((K(c) ⊙ beta(c)[:,None]) ⊙ exp2(G(c))[:,None])))
        U(c) = bf16(mm32(T(c)[:,0:n(c)],
                         bf16(V(c) ⊙ beta(c)[:,None])))
      symbol:
        W: {meaning: Transformed key., shape: [token: SequenceLength, dk: DK], dtype: bf16,
            life: "stored (b,h)"}
        U: {meaning: Transformed value., shape: [token: SequenceLength, dv: DV], dtype: bf16,
            life: "stored (b,h)"}

    - step: "4"
      name: Advance the state once per chunk
      math: |
        S(-1) = S0
        S_bar[c] = bf16(S(c-1))
        R(c) = U(c)-mm32(W(c),S_bar[c])
        R_bar(c) = bf16(R(c))
        decay(c)[t] = exp2(G(c)[n(c)-1]-G(c)[t])
        R_weight(c) = bf16(decay(c)[:,None] ⊙ R(c))
        S(c) = mma32(K(c)ᵀ,R_weight(c),exp2(G(c)[n(c)-1])*S(c-1))
        S_final = S(Nc-1)
      symbol:
        S: {meaning: Key-by-value state after the last token of chunk c.,
            shape: [dk: DK, dv: DV], dtype: fp32, life: "carried (b,h); c=-1..Nc-1"}
        S_bar: {meaning: Incoming-state snapshot per chunk., shape: [chunk: Nc, dk: DK, dv: DV],
                dtype: bf16, life: "stored (b,h)"}
        R_bar: {meaning: Readout copy of the residual; the state update takes a separately weighted copy.,
                shape: [token: SequenceLength, dv: DV], dtype: bf16, life: "stored (b,h)"}

    - step: "5"
      name: Read out from the snapshot and the intra-chunk term
      math: |
        B(c)[t,j] = dot32(Q(c)[t,:],K(c)[j,:])*exp2(G(c)[t]-G(c)[j])
                    if 0 <= j <= t < n(c); otherwise 0
        o(c) = bf16(scale*(exp2(G(c))[:,None] ⊙ mm32(Q(c),S_bar[c]))
                    + scale*mm32(bf16(B(c)),R_bar(c)))

  ledger:
    baseline: Contract token recurrence with the FP32 state held on chip and no chunk intermediates.
    depth:
      - {item: State dependency chain, change: "SequenceLength token transitions -> Nc chunk transitions per (b,h)", by: ["4"]}
    vector:
      - {item: Token recurrence, change: "-3*SequenceLength*DK*DV MAC and -SequenceLength*DK*DV decay multiplies per (b,h)", by: ["4"]}
    matmul:
      - {item: Block contractions, change: "0 -> 3*SequenceLength*DK*DV + SequenceLength*C*(3*DK+2*DV) MAC per (b,h), about 1.8x the recurrence they replace at C=64 and DK=DV=128", by: ["2", "3", "4", "5"]}
      - {item: Inverse construction, change: "0 -> Nc unit lower-triangular inverses of order n(c) per (b,h), counted apart from the contractions above", by: ["2"]}
    transcendental:
      - {item: Decay factors, change: "SequenceLength exp -> SequenceLength*(C+3) exp2 per (b,h)", by: ["1", "2", "4", "5"]}
    footprint:
      - {item: Materialized intermediates, change: "0 -> G, T, W, U, S_bar and R_bar, about 1.4 KB per token per (b,h) at C=64 and DK=DV=128", by: ["1", "2", "3", "4"]}
    traffic:
      - {item: Intermediate writes and reads, change: "0 -> about 3.3 KB per token per (b,h), each materialized tensor written once and read by every consuming step", by: ["1", "2", "3", "4", "5"]}
    pass:
      - {item: Chunk-set traversal, change: "1 -> 5 full traversals per (b,h)", by: ["1", "2", "3", "4", "5"]}
    error:
      - {item: BF16 intermediates, change: "+1 BF16 rounding each on T, W, U, S_bar, R_bar, R_weight and the B operand; S and R stay FP32", by: ["2", "3", "4", "5"]}
      - {item: TF32 inverse merges, change: "+TF32 multiply inputs in the off-diagonal blocks of T32, FP32 in the diagonal solve", by: ["2"]}
```

`S` 跨 chunk 携带，`S_bar` 是更新前状态的快照；`R_bar` 与 `R_weight` 都从 FP32 的 `R` 产生，全局快照不替代用于更新的 FP32 状态。

账本的五次遍历只是在该案例中对五项主要计算的计数，不是通用的步骤到 phase 或 launch 的映射；主收缩量与求逆算术分开记录，不能合起来宣称某个固定的总 MAC 倍率。
