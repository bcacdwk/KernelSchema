#### 核心思想

`math_reshape` 记录在不改变 Contract 的前提下，实际计算哪些值、采用什么数学关系、使用什么精度，以及哪些状态和中间量需要保留。它向下游交付的是可审阅的数学设计，而不是 GPU 执行程序。

本区以“数学决定”为基本单位组织 `rewrite`。一个决定可以包含定义、递推、分情形和显式类型转换；多个决定之间通过值的依赖连接。步骤不是 phase：一个数学步骤可以由多个工作实例完成，多个步骤也可以融合在同一份工作中。

三个外层字段各有明确用途：

- `thesis` 说明改写主张、动机和主要代价。
- `rewrite` 给出从 Contract 输入到全部输出的计算关系。
- `ledger` 相对明确的 baseline，记录改写带来的计算、流量、状态或误差变化。

不按 representation、quantization、fusion 等类别建立固定分区，因为这些决定经常交叉。采用步骤组织，可以把相关公式、符号属性和精度例外放在一起，避免同一个决定散落在多个分类中。

本区接收 Contract 的输入输出、数学要求和硬件条件，也可以引用由下游绑定的工作参数。它不决定 CTA、warp、lane、物理布局、缓冲槽位、屏障或流水重叠。数学块长是否属于本区，取决于它是否改变计算关系，而不是它是否叫作“块长”。

`symbol` 同时解决两件事：哪些量值得登记，以及已经登记的量是否说明完整。可以不登记一次性求和下标和简单代数缩写，但不能省略关键状态、物化中间量、精度分叉点或跨区符号的必要属性。

#### 字段定义

**结构轮廓**

下面是字段结构，不是待填写的 YAML。`[]` 表示列表，`<name>` 表示实例名称，`?` 表示条件可省略。

```text
math_reshape
├─ thesis
├─ rewrite[]
│  ├─ step
│  ├─ name
│  ├─ math
│  ├─ symbol?                          named map
│  │  └─ <name>
│  │     ├─ shape
│  │     ├─ dtype
│  │     ├─ life
│  │     │  └─ mode / scope / until     when life is an object
│  │     ├─ meaning
│  │     ├─ binding?
│  │     └─ value?
│  └─ arithmetic?
│     ├─ approx?
│     └─ accumulate?
└─ ledger?
   ├─ baseline
   └─ <resource>[]
      ├─ item
      ├─ change
      ├─ by[]
      └─ when?
```

**主体字段**

下表中的路径均相对于 `math_reshape`。

| 字段路径 | 值的形式 | 填写条件 | 含义与约束 |
| --- | --- | --- | --- |
| `thesis` | 非空字符串 | 必填 | 一两句说明改写、动机和主要代价，不写泛泛的性能口号。 |
| `rewrite` | 非空步骤列表 | 必填 | 覆盖全部输出。列表顺序用于阅读，不隐含执行屏障。 |
| `rewrite[].step` | 非空字符串 | 必填 | 本区唯一的步骤 ID，供 `ledger.by` 和生命周期引用。 |
| `rewrite[].name` | 非空字符串 | 必填 | 简短说明该步骤的数学决定。 |
| `rewrite[].math` | 非空多行字符串 | 必填 | 定义、递推、分情形、索引范围和显式 cast。 |
| `rewrite[].symbol` | 具名映射 | 该步骤首次引入必须登记的符号时必填 | 每个符号只登记一次；没有新增登记对象时省略。 |
| `rewrite[].arithmetic` | 固定结构映射 | 存在公式未完整表达的精度例外时必填 | 只允许 `approx`、`accumulate`，至少填写一项。 |
| `rewrite[].arithmetic.approx` | 非空字符串 | 存在主动近似，且其方法、适用域或误差信息未由公式完整表达时填写 | 说明近似方法、适用域和误差界；没有可靠误差界时明确写 `unknown:`。 |
| `rewrite[].arithmetic.accumulate` | 非空字符串 | 累加方式、归约分组或乘法输入精度不能从公式及默认规则确定时填写 | 不重复已经由 `mm32`、`mma32` 或显式 cast 表达的事实。 |
| `ledger` | 固定结构映射 | 对计算、流量、状态、深度或误差变化作出主张时必填 | 没有可报告的变化时可以省略；缺少分析不等于没有变化。 |
| `ledger.baseline` | 非空字符串 | `ledger` 出现时必填 | 给出比较对象和公共计量边界。 |
| `ledger.<resource>` | 非空条目列表 | 该类资源存在需要记录的变化时填写 | 只记录变化项，不为凑齐资源类别填写空项。 |
| `ledger.<resource>[].item` | 非空字符串 | 必填 | 被比较的对象或计量对象。 |
| `ledger.<resource>[].change` | 非空字符串 | 必填 | 带单位和范围的增减、前后对照或有明确对象的 `unknown:`。 |
| `ledger.<resource>[].by` | 非空步骤 ID 列表 | 必填 | 指向造成该变化的 `rewrite[].step`。 |
| `ledger.<resource>[].when` | 非空字符串 | 存在 baseline 未覆盖的适用条件、计算约定或下游依赖时必填 | 省略表示没有额外条件，不表示条件尚未提供。 |

`ledger` 当前允许的资源键为：

| 资源键 | 计量内容 |
| --- | --- |
| `matmul` | 内积、矩阵收缩或相关求解工作。 |
| `vector` | 逐元素运算、索引处理等非矩阵收缩工作。 |
| `transcendental` | 指数、对数、倒数等函数求值。 |
| `traffic` | 指定计量模型下的数据读写量。 |
| `footprint` | 指定作用域内的状态或物化数据大小。 |
| `depth` | 指定依赖链的长度。 |
| `pass` | 对明确对象的一次遍历、扫描或提交；必须写清计量对象。 |
| `comm` | 指定参与者之间的逻辑数据交换量。 |
| `error` | 相对 baseline 的数值偏差或误差界变化。 |

这些资源键是当前字段集合，不是可随意增加名称的实例映射。

**标准 symbol 行**

`symbol.<name>` 的合法字段为 `shape / dtype / life / meaning / binding / value`。前四项必须显式出现。

| 字段 | 值的形式 | 填写条件 | 含义与约束 |
| --- | --- | --- | --- |
| `shape` | 维度列表，或属性引用、待绑定标记、缺项标记 | 必填 | 描述一个逻辑实例的值形状，不描述线程 fragment。标量写 `[]`。 |
| `dtype` | 类型名字符串，或属性引用、待绑定标记、缺项标记 | 必填 | 描述数值表示。类型名必须在任务环境中有定义；不是任意自造标签。 |
| `life` | 生命周期对象，或属性引用、待绑定标记、缺项标记 | 必填 | 描述计算值的逻辑保留范围，不指定物理驻留位置。 |
| `meaning` | 非空字符串 | 必填 | 说明符号是什么；不重复整段公式，也不承担缺项占位。 |
| `binding` | `ref:` 或 `bind:` 引用字符串 | 整个符号由本区之外提供时必填 | 指定符号的定义来源或待绑定的提供者。 |
| `value` | 已知标量或数组字面值 | 本层选择一个固定值时填写 | 是该固定值的唯一来源；不用于装未知值或外部参数。 |

`dtype` 的具体类型名不是本区的封闭枚举。例如 `fp32`、`bf16`、`fp8_e4m3fn`、`int32`、`bool` 都必须对应任务环境中的真实类型。增加一个类型名，不等于定义了该类型。

`value` 与外部 `binding` 不同时承担同一符号的定义权。外部已经固定的量使用引用，不在本区再维护一份数值。

**生命周期对象**

当 `life` 使用对象形式时，三个字段都必须出现。

| 字段 | 值的形式 | 含义 |
| --- | --- | --- |
| `mode` | `temporary`、`carried`、`stored` 三选一 | 值的主要保留方式。 |
| `scope` | 非空字符串 | 逻辑实例身份；存在递推时还必须给出迭代范围。 |
| `until` | 一个用途引用，或非空用途引用列表 | 值必须保留到哪些消费者完成使用。 |

| `mode` | 含义 |
| --- | --- |
| `temporary` | 当前逻辑计算中使用的值，不要求作为后续独立计算的物化输入保留。 |
| `carried` | 在指定迭代范围内携带的递推状态。 |
| `stored` | 明确选择物化，保留给后续消费者。 |

`mode` 描述逻辑用途，不是内存空间枚举。递推状态采用 `carried`；它是否需要在某处保存到全局内存，不由这个词自动决定。`stored` 也不自动表示全局内存或跨 kernel；案例确实选择全局物化时，应在 `meaning` 中说明。

**固定结构与扩展边界**

| 位置 | 类型 | 允许的变化 |
| --- | --- | --- |
| `math_reshape` | 固定结构 | 只使用 `thesis / rewrite / ledger`。 |
| `rewrite[]` | 固定条目结构 | 增加步骤实例，不增加新的同级字段。 |
| `symbol` | 具名映射 | 可以增加当前设计需要的符号名。 |
| `symbol.<name>`、生命周期对象、`arithmetic`、账本条目 | 固定结构 | 只使用本节声明的字段。 |
| `ledger` | 固定资源集合 | 可以增加资源条目，不自行增加资源类别。 |
| `math`、`thesis`、`meaning`、`arithmetic` 文本 | 受约束的内容位置 | 可以表达新的数学决定，但必须遵守各字段职责。 |

本区当前没有授权实例作者自行增加模板字段的扩展路径。新增数学符号、辅助函数或步骤 ID 属于填写内容；新增 `life` 模式、资源类别或固定字段属于结构修改，需要另行确认。

未知字段不能静默忽略，也不能通过 `notes / misc / extra` 绕过结构限制。

#### 语法规则

**名称、ID 与定义范围**

字段名使用英文单数。符号名区分大小写，采用简短的英文或数学惯用名称；真实源码路径、函数名和参数名保留原样。

`step` 使用字符串，例如 `"1"`、`"2"`、`"1(A)"`。括号后缀只是 ID 的一部分；互不依赖的兄弟步骤可以这样命名，但不能仅凭命名推断独立性，更不能把它们解释为二选一。

每份 `math_reshape` 有独立的符号命名空间。一个已登记符号只出现一份定义，后续步骤直接使用该名称。局部求和下标、一次性代数缩写和明确的视图别名可以只在 `math` 中定义，但其范围必须能够确定。

`rewrite` 的顺序是阅读顺序。执行先后来自公式中的数据依赖、递推和下游安排，不来自 YAML 列表本身。`symbol` 映射顺序和 `ledger` 条目顺序没有执行语义。

**属性值、引用与缺项**

<!-- SYNC(1.contract)：shape: []、not_applicable、"ref:" 引用，以及不用 null / NaN / "-" 占位，已在 1.contract.algorithm_requirement.md 定义；本节改为引用，只保留 bind:、unknown: 等本区扩展。该文件规定契约内名称唯一，引用 Contract 对象可统一写成 contract.algorithm_requirement::<name>，不再混用结构路径与 .compute:: 两种形式。改完删除本注释。 -->

采用普通值和少量保留标记，不为每个属性再建立状态对象。

| 写法 | 含义 |
| --- | --- |
| `shape: []`、`dtype: bf16`、`value: 64` | 已知值。 |
| `"ref:<target>"` | 目标已经定义，引用其值或属性。 |
| `"bind:<target>"` | 提供者明确，但当前尚未完成绑定。 |
| `not_applicable` | 该属性不适用于这个对象。 |
| `"unknown:<reason>"` | 尚未确定或缺少依据；必须说明缺口。 |

`shape: []` 是标量，不是缺少 shape。`shape: [0, d]` 是合法的零长度张量。空集合是数学集合，不因此获得 `[0]` 这样的张量形状。

`not_applicable` 不等于“还没选好”。数学集合、映射和未要求物化的数学整数可以没有存储 dtype；已经决定物化、但还不知道整数宽度的索引数组，应使用 `bind:` 或 `unknown:`，不能写 `not_applicable`。

数值 NaN、`null` 和 `"-"` 不作为通用元数据缺项标记。NaN 只能在确有数值语义时作为数据值出现。

引用采用两种目标写法：

| 目标形式 | 用途 |
| --- | --- |
| `contract.algorithm_requirement.input.V.dtype` | 指向已经存在的结构化属性。 |
| `design.work_schedule::Bk` | 指向某一区域中的具名数学对象或语义定义。 |
| `design.math_reshape::P.dtype` | 指向本区唯一登记符号的属性。 |
| `repository@ref:path::symbol` | 指向固定版本材料中的具体定义。 |

`::` 后的名称是语义定位，不要求目标区域新增同名字段。接入完整 Plan 时，必须解析到目标区域的实际定义；不能因为字符串看起来像路径，就认定引用已经成立。

`binding` 引用整个对象；`shape / dtype / life` 中的引用只引用相应属性。引用必须保持属性语义一致。例如，不能把 Contract 中的数学定义域当成本层的存储生命周期。

外部绑定的符号仍可填写已经知道的属性。这些属性是对绑定结果的约束，不是第二份独立定义。冲突时应报告问题，不能由某一处静默覆盖另一处。

`ref:` 要求存在唯一可用的目标。源码函数存在，但它到本区数学对象的映射尚未完成时，应保留 `bind:`，而不是用函数名伪装成已经完成的数学定义。`unknown:` 则用于连属性值或有效依据都尚未确定的情况。

**数学表达与 shape**

<!-- SYNC(1.contract)：基础记号（X[i] 与 X(t)、切片、sum/max）和 shape 写法已在 1.contract.algorithm_requirement.md 的“数学表达与参考精度”“shape 与规模”定义；本节改为引用，只保留本区新增的记号（转置、⊙、单例轴、zeros、dtype()、bytesize() 等）。该文件的 shape 写成具名轴，本区只写大小，修改时决定统一写法或写明理由。改完删除本注释。 -->

`math` 使用可直接阅读的数学表达，不使用 LaTeX 源码、线程视图操作或实现代码。

| 记号 | 含义 |
| --- | --- |
| `X(i)` | 迭代实例或已定义的函数调用。 |
| `X[c]` | 元素、切片或数组下标。 |
| `[a,b)`、`X[a:b]` | 左闭右开的整数区间或切片。 |
| `Aᵀ` | 转置。 |
| `A ⊙ B` | 逐元素乘法；广播轴必须明确。 |
| `X[:,None]` | 数学上的单例轴插入，不指定物理布局。 |
| `sum`、`max` | 在明确范围内归约。 |
| `zeros(dk,dv)` | 给定逻辑形状的零值。 |
| `dtype(X)` | 已定义对象的 dtype，不是重新选择类型。 |
| `bytesize(dtype(X))` | 该 dtype 的每元素字节数。 |

矩阵乘、逐元素乘和标量乘必须能够区分。`blk`、`group` 等辅助函数没有隐藏的全局定义，必须在当前案例中给出。

shape 是有序维度列表。每个维度是非负整数、已定义的维度名，或可求值为非负整数的表达式；复合表达式写为字符串，例如 `["n(c)", dv]`。

shape 描述 `scope` 中一个逻辑实例的完整值。`shape: [H]` 不表示某个线程或 worker 必须一次持有整行，也不直接给出寄存器占用。

分情形只要求在有效分支上求值。不能把越界读取、`0/0` 或 `-inf-(-inf)` 当成无条件计算，再假设掩码会消除影响。空和为零，空最大值为 `-inf`；递推是否允许空范围，还必须有明确的最终关系。

**生命周期的实例与终点**

生命周期使用下面的紧凑写法：

```yaml
life:
  mode: carried
  scope: "(b,h,q); i=-1..N-1"
  until: "step 4"
```

分号前是固定的逻辑实例，分号后是状态跨越的迭代范围。这个例子表示每个查询行分别携带状态；换到新的查询行，就产生新实例并按公式初始化。

没有递推时只写实例范围，例如 `"(b,h,c)"` 或 `"invocation"`。

`until` 可以引用 `"step 4"`，也可以引用消费者符号或实例，例如 `R_weight`、`"S(c)"`。列表表示必须完成所有列出的用途，不表示消费者之间有先后顺序。单个字符串与只含该字符串的列表等价，优先使用较短的字符串写法。

初值、重置位置、有效迭代范围和最终输出关系写在 `math` 中，不再增加另一套初始化或重置字段。生命周期必须与这些公式一致。

`until: "step 5"` 不引入全局屏障。消费者可以按已经满足的数据依赖处理部分实例，不必等待该步骤涉及的所有实例同时完成。

**精度与辅助运算**

<!-- SYNC(1.contract)：默认 FP32 与 RNE、该默认不适用于索引/集合/布尔、<dtype>(x) 转换、窄化必须写出、加宽转换不写，已在 1.contract.algorithm_requirement.md 定义；本节改为引用，只保留 cast、fma32、dot32/mm32、mma32、mm_tf32、sum32 等本区扩展。改完删除本注释。 -->

默认 FP32 只适用于浮点数值计算，不覆盖整数索引、布尔谓词、集合和数学映射。输入保持 Contract dtype；已经登记的数值符号仍必须显式填写 dtype。

| 记号 | 数值含义 |
| --- | --- |
| `fp32(X)`、`bf16(X)` | 显式转换到指定类型；普通转换采用该类型的最近偶数舍入，另有约定时必须说明。 |
| `cast(dtype(X),Z)` | 将 `Z` 转为 `X` 已定义的 dtype。 |
| `fma32(A,B,C)` | FP32 融合乘加，乘加结果一次舍入。 |
| `dot32(A,B)`、`mm32(A,B)` | 所示 dtype 输入的内积或矩阵乘，零初始累加器和结果为 FP32。 |
| `mma32(A,B,C)` | 以 FP32 `C` 为初始累加器的矩阵乘加。 |
| `mm_tf32(A,B)` | TF32 乘法输入路径，FP32 累加与结果；不表示 TF32 存储张量。 |
| `sum32` | FP32 归约。未另行固定时，不由记号指定归约树。 |

这些是数学记法，不是要求实现同名 API。

FP32 累加器不代表乘法输入、乘积内部处理和所有舍入都具有 FP32 精度，也不构成硬件逐位一致性保证。影响设计的输入截断、累加分组和近似必须另外表达。

公式中的窄化必须写成 cast。`dtype` 行是对公式结果的属性断言；例如 `P = bf16(E)` 与 `dtype: bf16` 必须一致，不能由两处分别调参。

`exp2_native` 等带实现含义的辅助函数必须由当前案例的公式、`arithmetic` 或绑定说明其来源。后缀 `native` 本身不定义算法或误差界。

`arithmetic` 原则上只补充当前步骤。跨步骤沿用同一例外时，必须明确引用其定义；不能把一个步骤的精度说明默认为整份 Plan 的覆盖规则。

**账本、空值与省略**

`change` 优先采用“前值 -> 后值”或带正负号的增减。必须能判断单位、逻辑范围和计算依据。依赖下游参数时保留公式及绑定关系，不在本区再抄一份调度配置。

一个 MAC 表示一次乘加计数；只有明确采用该口径时，才可换算为两个 FLOP。把三角计算按密集矩阵计数时，必须写明这是密集等价计数，不是实际指令数。

`footprint` 必须区分物化总量、同时存活量和峰值分配；`traffic` 必须区分逻辑读写量与实测 DRAM 流量；`pass` 必须指明扫描、遍历或提交的对象。它们都不能由步骤数量直接推导。

`unknown:` 可以保留尚未建立的误差界或必要成本项，但不能伪装成测量值，也不能替代已经能够推导的数量。

不接受空的 `rewrite`、`symbol`、`arithmetic` 或资源条目列表。没有可选内容时省略对应字段，不填写 `{}`、`[]` 或空字符串。例外是作为合法数据的空值，例如标量 shape 的 `[]` 或零长度数组的 `value`。

所有 YAML 禁止独立注释和行内注释。通用规则写在本文；案例特有且影响设计的事实写入相应正式字段。

#### 关键原则

**只登记值得共享的符号，但登记后必须完整。**

跨步骤的重要中间量、跨迭代状态、明确物化的值、精度分叉点和跨区参数必须登记。一次性求和下标、简单视图和可直接理解的局部缩写可以只在公式中定义。

不能为了避开属性检查，把关键状态移出 `symbol`。也不应为了表格完整，把每一个数学临时变量都扩展成条目。

**数学对象与存储对象分开。**

`R` 是查询行集合，`sigma` 是访问映射，二者不必存在对应张量。`Bk` 是数学整数标量，`shape: []` 并不要求采用 `int32`。

下游若物化索引数组，应为那个实际数组说明形状、dtype 和生命周期，而不是倒过来把本区的数学映射解释为已经存在的数组。

**同一事实只有一个定义权。**

Contract 对象直接沿用或引用，不在本区改变其 shape、语义或量化规则。已由公式 cast 确定的 dtype 可以显式重复显示，但只能作为一致性断言，不能成为第二个选择。

GDN 的 `C=64` 改变三角系统和跨块递推，是本层选择；FA4 的 `Bk` 是工作分块参数，由下游绑定；MoE 的量化组长由 Contract 固定。三者不能因为都叫块长，就统一归入某个区域。

**生命周期表达保留关系，不表达物理安排。**

`carried` 必须说明跨哪一个迭代范围。`stored` 必须能找到后续用途。`temporary` 也不能省略关键的最后用途，尤其是同一个 FP32 值分叉产生两个窄化结果时。

物化选择不会自动产生独立 kernel，生命周期终点不会自动产生屏障，逻辑 shape 也不会自动决定 buffer slot 或 worker 数。

**压缩表达不能删除数值路径。**

<!-- SYNC(1.contract)：1.contract.algorithm_requirement.md 新增 golden_reference.tolerance（各输出的误差判据），它是本区近似与精度路径的最终误差预算。修改本节及 arithmetic.approx 的说明时引用它，不另立误差标准。改完删除本注释。 -->

GDN 的 `bf16(R)` 与 `bf16(decay·R)` 是从同一个 FP32 值出发的两条路径，不能合并为先窄化再加权。FA4 的分母使用 `E`、分子使用 `bf16(E)`，也不能被一句“FP32 累加”替代。

局部多项式误差界不是最终输出误差界。跳过不可见项与近似本来必须计算的项是不同的决定，必须分别说明。

实现替换是否可接受，取决于它是否改变已声明的路径或 Contract 要求，而不是是否能用“小于一个 ULP”概括。需要改动这些决定时，应返回设计或 Contract 讨论，不能移到 realization 后自行放宽。

**公式级账本不冒充完整 kernel 成本。**

本区记录数学决定能解释的变化。worktile 引起的重复计算与读取、实际提交、缓存行为和编译器结果，只有在明确引用相应依据时才能纳入。

不能从硬件峰值推出实现收益，不能把历史平台的累加行为和性能倍率直接迁移到另一架构，也不能把尚未验证的来源抽取写成验收结论。

以下三个案例的目标硬件均为 B200 / SM100。案例只展开 `math_reshape`；文前的输入名称和轴顺序是读取上游要求时使用的逻辑记法，不定义物理布局，也不新增 Contract 字段。

**案例一：FA4 因果单 CTA**

上游条件为 BF16 Q/K/V/O、FP32 LSE、8 个 MHA head、`d=128`，同次调用内等长，QueryLength 与 KVLength 可以不同。因果采用右下对齐，空行返回 `O=0`、`LSE=-inf`，LSE 使用自然对数。本例不包含 paged KV、varlen、split-KV 或额外 score/mask 修改。

逻辑索引使用 `Q[b,q,h,:]`、`K[b,k,h,:]`、`V[b,k,h,:]`。`visible` 引用 Contract 的合法 key 范围与右下因果谓词。所选来源分支是因果、单 CTA、双 Q 块、BF16、hdim 128；这里只读取该分支，不定义它的执行组织。

最大值阈值和指数选择参数依据 `Dao-AILab/flash-attention@ce088ab9:flash_attn/cute/flash_fwd_sm100.py`；在线状态和指数选择依据 `Dao-AILab/flash-attention@ce088ab9:flash_attn/cute/softmax.py`；多项式系数与低端重构依据 `Dao-AILab/flash-attention@ce088ab9:flash_attn/cute/utils.py`。

本例展示非张量符号、下游绑定、逐查询行重置和 `E/P` 精度分叉。正 scale 是该数学分支的适用前提；若完整 Contract 还要求覆盖零或负 scale，必须补充设计，不能缩小 Contract。源码指数选择到逻辑元素的映射尚未独立重建，因此 `use_poly` 保留待绑定状态。

**案例二：GDN 分块前向**

上游为等长序列、`dk=dv=128`，Q/K 不在本算子内归一化，`g` 表示单步自然对数衰减，`beta` 是已激活的更新系数。初始状态为 FP32、缺省为零；输出 `o` 为 BF16，最终状态为 FP32。本例沿用 BF16 Q/K/V 分支。

公式在固定 `(b,h)` 的逻辑切片上书写，`L` 表示序列长度；状态采用 key-by-value 轴顺序。输入的 `g`、`beta` 按公式转为 FP32 参与计算。

块内累计依据 `fla-org/flash-linear-attention@954438d1:fla/ops/utils/cumsum.py`；三角求解依据 `fla-org/flash-linear-attention@954438d1:fla/ops/gated_delta_rule/chunk_fwd.py`；W/U、状态推进和输出分别依据 `fla-org/flash-linear-attention@954438d1:fla/ops/gated_delta_rule/wy_fast.py`、`fla-org/flash-linear-attention@954438d1:fla/ops/common/chunk_delta_h.py`、`fla-org/flash-linear-attention@954438d1:fla/ops/common/chunk_o.py`。

本例保留数学块长 `C=64`，并保留来源求逆中的 16 阶对角子块与 TF32 块合并路径。它展示块内重置、跨 chunk 状态、全局物化和临时值的精度分叉。

`scale_o` 是黑盒读出系数的别名，不要求 Contract 新增同名字段。当前任务摘要没有给出该系数的最终绑定，因此保留待确认；黑盒读出无缩放时应绑定为一。不能直接采用 `fla-org/flash-linear-attention@954438d1:fla/ops/gated_delta_rule/naive.py::naive_recurrent_gated_delta_rule` 的默认 scale 替代 Contract。

  rewrite:

      name: Accumulate decay within each chunk
      math: |
        Nc = ceil(L/C), n(c) = min(C,L-c·C), 0 <= c < Nc

        G(c)[t] = fp32(prefix(c,t)·log2(e))

            meaning: Mathematical chunk length., value: 64}

                 life: {mode: carried, scope: "(b,h,c); t=-1..n(c)-1", until: "G(c)"},
                 meaning: Chunk-local natural-log prefix.}

            life: {mode: stored, scope: "(b,h)", until: "step 5"},
            meaning: Global base-two decay prefix.}

                  meaning: Contract readout scale; one for an unscaled readout.,
                  binding: "bind:contract.algorithm_requirement.compute::readout_scale"}

              life: {mode: temporary, scope: "(b,h,c)", until: T},
              meaning: Inverse before narrowing; D_u is its diagonal block.}
        T: {shape: [L, C], dtype: bf16,
            life: {mode: stored, scope: "(b,h)", until: "step 3"},
            meaning: Global chunk inverse with zero-padded tail columns.}
      arithmetic:
        approx: "unknown: inverse error from the declared TF32 block products and BF16 storage."

    - step: "3"
      name: Form W and U
      math: |
        W(c) = bf16(mm32(T(c)[:,0:n(c)],
                         bf16((fp32(K(c)) ⊙ fp32(beta(c))[:,None]) ⊙ exp2(G(c))[:,None])))
        U(c) = bf16(mm32(T(c)[:,0:n(c)],
                         bf16(fp32(V(c)) ⊙ fp32(beta(c))[:,None])))
      symbol:
        W: {shape: [L, dk], dtype: bf16,
            life: {mode: stored, scope: "(b,h)", until: "step 4"},
            meaning: Global transformed key.}
        U: {shape: [L, dv], dtype: bf16,
            life: {mode: stored, scope: "(b,h)", until: "step 4"},
            meaning: Global transformed value.}

      name: Advance the state
      math: |
        S(-1) = initial_state[b,h,:,:] if provided; otherwise zeros(dk,dv)
        S_bar[c] = bf16(S(c-1))
        R(c) = fp32(U(c))-mm32(W(c),S_bar[c])
        R_bar(c) = bf16(R(c))
        decay(c)[t] = exp2(G(c)[n(c)-1]-G(c)[t])
        R_weight(c) = bf16(decay(c)[:,None] ⊙ R(c))
        S(c) = mma32(K(c)ᵀ,R_weight(c),exp2(G(c)[n(c)-1])·S(c-1))
        final_state[b,h,:,:] = S(Nc-1)
      symbol:

            meaning: Key-by-value recurrent state.}
        S_bar: {shape: [Nc, dk, dv], dtype: bf16,
                life: {mode: stored, scope: "(b,h)", until: "step 5"},

                meaning: Global residual snapshot for output.}
        R_weight: {shape: ["n(c)", dv], dtype: bf16,
                   life: {mode: temporary, scope: "(b,h,c)", until: "S(c)"},
                   meaning: Decay-weighted residual for the state update.}

      name: Reconstruct output
      math: |
        B(c)[t,j] = dot32(Q(c)[t,:],K(c)[j,:])·exp2(G(c)[t]-G(c)[j])
                    if 0 <= j <= t < n(c); otherwise 0

        o(c) = bf16(scale_o·(exp2(G(c))[:,None] ⊙ mm32(Q(c),S_bar[c]))
                    + scale_o·mm32(B_bar(c),R_bar(c)))

            life: {mode: temporary, scope: "(b,h,c)", until: B_bar},
            meaning: Causal output coefficients.}

                life: {mode: temporary, scope: "(b,h,c)", until: "o(c)"},
                meaning: Narrowed output coefficients.}

  ledger:

    matmul:

`prefix` 每个 chunk 重新初始化，`S` 跨 chunk 携带，`S_bar` 是更新前状态的快照。`R_bar` 和 `R_weight` 分别从 FP32 `R` 产生；全局快照不替代用于更新的 FP32 状态。

账本的五次遍历只是在该案例中对五项主要计算的计数，不是通用的步骤到 phase 或 launch 的映射。主收缩量还排除了求逆算术，因此不能再用它直接宣称某个固定总 MAC 倍率。

**案例三：MoE FP8 block**

上游固定 `H=7168`、`I=256`、`E=256`、`top_k=8`、`G=128`。`M` 为 token 数，`I` 是本分片的中间维度，输出 `Y` 是分片部分和。给定路由下的专家计算、两次激活量化和本分片 top-k 合并在边界内；路由选择与跨分片归约在边界外。

逻辑权重形状为 `W13[E,2·I,H]`、`W2[E,H,I]`，W13 按 gate、up 顺序拼接。权重使用 128×128 block scale；激活沿最后一维按每行 128 元素分组量化。Contract 的量化函数使用 E4M3FN、FP32 普通 scale、`amax` 下界 `1e-10` 和 `scale=amax/448`，不把 scale 取整为二的幂。`quantize` 对各组应用同一 Contract 定义，返回量化值与 scale。输入 X 和输出 Y 的 dtype 从 Contract 引用，不在本区另选。

参考来源为 `vllm-project/vllm@28282ffe:vllm/model_executor/layers/fused_moe/fused_moe.py` 与 `vllm-project/vllm@28282ffe:vllm/model_executor/layers/fused_moe/experts/triton_moe.py`。其中 block-scale 路径将 scale 放在块内积外，并在输出类型转换前乘路由权重。

这是沿用既有数学关系的 B200 设计候选，不是已复现的 SM100 SOTA。`vllm-project/vllm@28282ffe:tests/kernels/utils.py::torch_experts` 仍是对照适配起点：其 helper 复用及路由加权附近的舍入边界需要核对，不能直接视为独立 golden。候选中的激活 cast、组间 FP32 累加和路由加权位置均是显式设计，不继承 Hopper 的内部累加精度或性能结论。

本例展示 Contract 量化参数与下游 GEMM 分块的区别，以及只保留路由索引、不按 route 复制输入量化结果的表达方式。

`rho` 保留原始 route-slot 身份，因此同一 token 的不同路由不会被合并丢失。它不规定索引数组的存储类型，也不规定每个 GEMM worktile 的行数。

`Hact` 不写入全局内存，但其 cast 仍然存在。采用融合激活与量化实现时，不能因为删除了中间存储，就同时删除这一舍入边界。输出 `Y` 只合并本分片的 route 贡献，不包含跨分片归约。
