#### 核心思想

`realization` 是 Designer 与 Coder 之间的最小实现交接区。它只记录 Contract 和 Design 尚未表达、但双方确实需要共享的实现条件，以及少数有具体理由优先尝试的选择。

本区的基本单位是一条**指向上游对象的实现选择**：`item` 说明约束谁，`choice` 说明选择什么，`reason` 说明为什么需要交接。条目按 `require / prefer / forbid` 分组，分别表示硬条件、优先建议和明确排除的路径。

本区不重新决定数学、精度、工作组织、角色、缓冲或依赖，也不重复固定设备、语言和库版本。设计主张已经属于 Design，因此不设置 `thesis`；单项选择的理由由 `reason` 承担。

不影响既定数值与执行语义的代码组织、地址计算、barrier 编号和精确线程 layout，默认留给 Coder。调试日志、待办事项和完整实验报告不进入本区。

**空区是合法的完整结果。** 没有新增交接信息时，省略 `realization`。这不会取消任何上游约束。

#### 字段定义

结构如下。图中的 `[]` 表示条目列表，不是字段名；各字段的可选条件见下表。

```text
realization
├── require[]
│   ├── item
│   ├── choice
│   └── reason
├── prefer[]
│   ├── item
│   ├── choice
│   ├── reason
│   └── feedback
│       ├── choice
│       └── evidence
└── forbid[]
    ├── item
    ├── choice
    └── reason
```

下表中的 `<kind>` 仅代指 `require`、`prefer` 或 `forbid`，不是新增字段。

| 字段路径 | 值的形式 | 填写条件 | 含义与约束 |
| --- | --- | --- | --- |
| `realization` | 映射 | 可省略 | 仅包含本区新增的实现条件与建议。 |
| `realization.require` | 条目列表 | 有额外硬条件时填写 | 既定设计成立所需的实现条件。Coder 不得自行替换或降级。 |
| `realization.prefer` | 条目列表 | 有具体优先理由时填写 | 在不改变 Contract 和 Design 的前提下，值得优先尝试的实现选择。 |
| `realization.forbid` | 条目列表 | 有明确排除结论需要保留时填写 | 排除容易重复尝试、且未被上游约束自然排除的路径。 |
| `realization.<kind>[].item` | 非空引用字符串，或非空引用列表 | 每条必填 | 指向上游已有对象或计算；不在本区定义对象。 |
| `realization.<kind>[].choice` | 非空英文字符串 | 每条必填 | 具体原语、实现选择或兼容性要求。不是封闭枚举。 |
| `realization.<kind>[].reason` | 非空英文字符串 | 每条必填 | 说明选择与既定前提、数据流或具体成本的关系。 |
| `realization.prefer[].feedback` | 映射 | 记录有真实实验依据的替代选择时填写 | 仅允许出现在 `prefer` 条目下，不覆盖原始选择。 |
| `realization.prefer[].feedback.choice` | 非空英文字符串 | `feedback` 出现时必填 | Coder 提出的替代选择。 |
| `realization.prefer[].feedback.evidence` | 单个固定版本记录引用 | `feedback` 出现时必填 | 指向支持该替代的真实实验记录。 |

**固定结构与扩展边界**

本区所有映射均为固定结构：

- `realization` 只接受 `require / prefer / forbid`。
- `require`、`forbid` 的条目只接受 `item / choice / reason`。
- `prefer` 的条目另可包含 `feedback`；`feedback` 只接受 `choice / evidence`。

未知字段属于结构错误，不应被静默忽略。本区没有具名映射，也没有已授权的字段扩展位置。增加条目、引用新的上游对象，或填写新的实现选择，都是增加实例内容，不是增加模板字段。

不得以算子名、phase 名或原语名新建并列区域，也不设置 `notes / misc / extra` 等兜底字段。现有字段确实无法表达的需求，应先指出结构缺口。

**省略、空值与默认含义**

`require / prefer / forbid` 没有内容时省略，不写空列表 `[]`；整个区域没有新增交接信息时省略 `realization`，不写 `{}`。

`item / choice / reason` 没有默认值。`feedback` 省略表示本区没有记录有证据的替代，不代表替代已经通过或已经被否定。

`null`、空字符串、仅含空白的字符串、空条目和 `feedback: {}` 不合法。`item: []` 也不合法，因为它没有约束对象。

#### 语法规则

**字段与文本**

字段一律使用单数。YAML 中的说明字符串使用英文，真实的仓库路径、函数名和 API 标识保持原样。

YAML 不使用独立注释或行内注释。通用填写规则放在本说明中；条目特有的实现选择及其理由分别进入 `choice` 和 `reason`。

**`item` 的引用与作用域**

`item` 只引用上游已经定义的对象或计算，不建立别名或本地对象表。

名称在整份 Plan 中能够唯一解析时，可以直接填写。需要限定作用域时，使用：

```text
<owner>::<name>
```

`owner` 是上游已有的区域或具名对象作用域，`name` 是该作用域内已有的名称。例如，`design.math_reshape::P` 指向该区域定义的 `P`，不要求该区域采用新的存储结构。

裸名称与限定名称仅在解析到同一个上游定义时等价。未知名称或重名引用必须解决，不能通过阅读源码猜测目标。

对于 phase 内的局部操作，`owner` 必须包含已有的 phase 身份；仍然重名时，继续使用上游已有的 lane 或动作归属限定。具体路径跟随上游发布的对象结构，本区不预设 phase 的内部字段，不复制 `flow`，也不使用列表下标充当长期身份。上游尚未提供唯一身份时，该引用接口待确认，不能在本区临时造名。

引用 Contract 时，使用当前路径 `contract.algorithm_requirement` 及其 `golden_reference`，不沿用旧名称。

**单个引用与引用列表**

单个引用与仅包含该引用的列表含义相同。多个对象只有在共享同一 `choice` 和 `reason` 时才合写；否则拆成独立条目。

引用列表不表示计算顺序、依赖关系或新的对象组合。不得重复填写同一对象来表达执行次数。

当 `item` 指向值而不是具名操作时，`choice` 必须说明约束该值的哪一段计算。例如，指向 `P` 时，应区分产生其输入分数的矩阵乘与其自身的多项式求值，不能笼统约束所有相关操作。

**`choice` 与 `reason`**

`choice` 写选择本身，约束强度由所在分组表达，不必重复写“必须”“优先”或“禁止”。在 `forbid` 中，`choice` 直接写被排除的路径，避免双重否定。

原语名可以保持简短，但不足以限定作用位置或数值行为时，必须补充必要条件。`reason` 应指出具体依赖或成本，不能只写“更快”“更好”或“源码如此实现”。

`reason` 可以引用已有设计前提，但不能借理由补入新的角色、搬运、状态或执行关系。

**顺序、重复与冲突**

映射顺序和条目列表顺序均不表示执行顺序，也不构成覆盖或优先级规则。

所有适用的 `require` 和 `forbid` 都必须同时满足；`prefer` 不能与它们或上游约束冲突。同一对象可以有多条约束，但应针对不同问题，且作用范围明确。重复条目应合并或删除；冲突属于 Plan 问题，不按“后写覆盖前写”处理。

**实验记录引用**

`feedback.evidence` 使用：

```text
repository@ref:path
```

`ref` 必须锁定支持当前结论的记录版本，`path` 指向真实实验记录。完整配置、结果和报告留在该记录中。

没有真实证据时省略 `feedback`，不填写假路径、假版本或占位反馈。设计源码出处不能代替实验记录；`meta_data.source` 也不是数值验收 oracle。

#### 关键原则

**先做删除测试，再判断强度**

| 判断结果 | 处理 |
| --- | --- |
| 上游已经完整表达同一约束，删掉本条不会丢信息 | 删除，不为保险重复。 |
| 替换选择会破坏已确定的角色、数据路径或交接方式，而上游尚未表达所需的实现兼容条件 | 写入 `require`。 |
| 替换后设计仍成立，但有具体成本理由优先尝试当前选择 | 写入 `prefer`。 |
| 某条路径未被上游自然排除，但 Designer 已明确排除，且值得避免重复尝试 | 写入 `forbid`。 |
| 只是在源码中出现，没有约束必要性或具体优先理由 | 留给 Coder。 |
| 无法判断，是因为上游角色、精度或依赖尚未明确 | 返回上游补齐，不用本区代替设计。 |

`forbid` 不机械罗列 `require` 的反面，也不收集所有错误实现。已经违反 Contract 或 Design 的路径，本来就不合法。

**实现自由不能只由最终误差判断**

替换是否属于 Coder 自由，取决于是否保持全部既定数学与执行条件，而不是指令名称是否相近，或一次测试的局部误差是否较小。

| 变化 | 处理边界 |
| --- | --- |
| 更换 API 封装、代码组织或指令表达，同时保持既定逐元素运算、舍入、角色和依赖 | 属于 Coder 可比较的实现选择。 |
| 改变舍入点、近似方法、量化顺序、换底计算位置或已声明的精度路径 | 返回 `design.math_reshape`。 |
| 改变物化、重算或逻辑状态保留方式 | 返回 `design.math_reshape`，并检查相关执行设计。 |
| 增加设计层可见的搬运，改变 lane、buffer 生命周期或 overlap | 返回 `design.tile_pipeline`；涉及工作分配时还需返回 `design.work_schedule`。 |
| 改变黑盒数学、量化规则、输出或验收要求 | 涉及 `contract.algorithm_requirement`，Designer 与 Coder 均不得自行修改。 |
| 更换已选设备、语言、库或接口环境 | 涉及 `contract.hardware_specification` 的 `device / arch / stack`，不能由本区覆盖。 |

<!-- SYNC(2.contract)：该区的 `arch` 只写架构身份，具体编译目标参数（如 `sm_100a`、`gfx950`）指向本区 `require`，可补一个同类条目。改完删除本注释。 -->

`ex2.approx`、`rcp.approx` 等名称不隐式授权额外的数值行为；使用近似原语不等于允许增加 FTZ、改变参数计算或放宽验收要求。同样，将标量计算改成 packed 指令，也不自动允许改变融合舍入点或 lane 分工。

无法实现 `require` 时，应报告阻碍，不能自行降为 `prefer`。更快或更准确的结果都不构成修改上游的权限。

**反馈保留入口，不保存实验历史**

`feedback.choice / feedback.evidence` 已足够表达有依据的替代。原始 `prefer.choice / reason` 保留，反馈不覆盖它们，也不为 `require` 或 `forbid` 提供豁免。

实验记录至少应支持以下判断：

| 判断 | 记录需要提供的内容 |
| --- | --- |
| 对比对象明确 | 原始与替代实现、它们对应的 Plan 与环境（按 `repository@ref:path` 固定版本引用），以及实际 workload。 |
| 替代符合要求 | 按原有要求检查契约输出及相关设计约束，不能只报告局部原语误差。 |
| 比较成立 | 在相同 workload 和可比较的测量范围下给出结果，并限定结论适用范围。 |

例如，用两条标量 FMA 替代一次 packed FMA，只有在逐元素运算、舍入和角色不变时，才可作为本区的替代反馈。实验细节留在记录中，无需增加 benchmark 表或审批字段。

一次更快的实验不能覆盖错误输出、遗漏最终状态、更换量化分支或改变计时范围的事实。多个历史实验也不应扩展成这里的新列表。

**来源、成本理由与实测结论分开**

源码采用某种选择，只能证明该实现存在，不能自动证明它是硬件必需或性能最优。

明确的重复计算成本可以支持一个 `prefer`，但不能写成已经获得的性能收益。设备、语言和版本由 Contract 决定；来源代码使用某种语言，不会自动将它变成本区的硬条件。

#### 具体案例

以下案例沿用固定版本的历史来源，只展开 `realization`。案例中的符号是上游输入接口，不在本区重新定义。来源不代替实验依据；这里不声称已经通过 GPU 数值测试、B200 性能测试或独立盲重建，也不填写虚构的 `feedback`。

**FA4 因果单 CTA**

来源：`Dao-AILab/flash-attention@ce088ab9:flash_attn/cute/flash_fwd_sm100.py` 与 `Dao-AILab/flash-attention@ce088ab9:flash_attn/cute/softmax.py`。选定因果、单 CTA、双 Q 块分支，不混入 CLC 或非因果双 CTA。

只读接口：`design.math_reshape::P` 是 BF16 指数权重，`design.math_reshape::Y` 是 FP32 在线输出累加状态；其数学与精度路径由上游定义。MMA、搬运、Softmax、Correction 角色及 buffer、依赖均已确定。

下面的 `require` 适用于**上游已经确定矩阵乘直接写 TMEM，但尚未绑定对应原语族**的情况。该条件须在合并完整 Plan 时核对，不能从本条反推 pipeline。packed FMA 建议仅用于已有的同一 lane 内元素对，不授权重新分配 lane。

```yaml
realization:
  require:
    - item: ["design.math_reshape::P", "design.math_reshape::Y"]
      choice: tcgen05.mma for the score product feeding P and the value product updating Y.
      reason: The MMA role writes directly to TMEM for Softmax and Correction.
  prefer:
    - item: "design.math_reshape::P"
      choice: fma.rn.f32x2 for existing same-lane polynomial pairs, preserving per-element operations and rounding.
      reason: Reduce FMA instruction count.
```

若 pipeline 已正式绑定 `tcgen05.mma`，删除重复的 `require`；若直接 TMEM 交接尚未确定，则该条目待确认，不能用于补定上游设计。独立搬运角色本身不足以推出必须使用 TMA，因此本例不追加 TMA 条目。

**MoE FP8 block**

来源：`vllm-project/vllm@28282ffe:vllm/model_executor/layers/fused_moe/experts/triton_moe.py` 与 `vllm-project/vllm@28282ffe:vllm/model_executor/layers/fused_moe/fused_moe.py`。旧实现分析面向 SM90；本例仅沿用数学任务，目标为 B200，不移植其架构特定结论。

只读前提：使用普通 FP32 scale 分支；量化语义、FP8 码值乘法、scale 位置、激活后量化及路由权重位置均已由 Contract 和 `math_reshape` 表达。当前没有额外的 B200 执行前提需要在本区绑定原语。

本例展示无新增交接信息时的完整写法，不重复上游数学约束。

```yaml
realization: {}
```

**GDN 分块前向**

来源：`fla-org/flash-linear-attention@954438d1:fla/ops/gated_delta_rule/chunk_fwd.py` 与 `fla-org/flash-linear-attention@954438d1:fla/ops/utils/op.py`。沿用 C=64 的分块前向方案，五趟计算、状态精度和三角求解方式均由上游确定。

只读接口：`design.math_reshape::G` 是上游登记的 base-2 衰减前缀，块内与块间的衰减因子都由它的差值取指数得到。其数学关系、FP32 base-2 参数及允许的求值范围必须由 `math_reshape` 给出。

本例只交接重复指数求值的候选原语，不增加换底步骤、近似许可或新的误差要求。

```yaml
realization:
  prefer:
    - item: "design.math_reshape::G"
      choice: ex2.approx.f32 for the decay factors derived from G, on existing FP32 base-2 arguments and only where allowed by math_reshape.
      reason: Decay factors require repeated exponential evaluation.
```

该建议不授权额外 FTZ。上游未明确允许的求值范围时，需先补齐 `math_reshape`；上游已固定不兼容的数值路径时，应删除本建议，不能用一次测试通过覆盖既定设计。
