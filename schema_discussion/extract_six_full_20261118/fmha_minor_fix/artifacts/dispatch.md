# fmha_mxfp8_qkv

## 范围

**收录范围。** 当前目录含三份完整设计：[root](root.yaml)、[split_kv](split_kv.yaml)、[mma_sync](mma_sync.yaml)；含 root 共三份，低于十份上限，root 唯一，没有未计划的草稿、备份 YAML，也没有改名、换扩展名或另藏目录继续交付的额外完整方案。三份互不派生，三个 Design 区域各自本地定义、没有任何整区 `from`，引用图因此无环；非 root 节点按规则省略 CONTRACT，共享的只有 root 保存的 Contract。三份各有独特完整设计价值：root 是 block-scaled 单内核 fused，split_kv 是跨内核状态物化与加权归并，mma_sync 是可移植 warp-level 路径；不为提供共享区域增加没有独立价值的文件。

**路由与三者关系。** 路由只述机制族，具体条件以各 YAML 的 `when` 为准：加载的二进制是 arch-specific、tcgen05 可用时，plan 保持 fused 的几何走 [root](root.yaml)，成本模型定价 split 更便宜且调用方 workspace 足够的几何走 [split_kv](split_kv.yaml)；二进制非 arch-specific（tcgen05 kernel body 是 inert stub、host 探针返回假）时，唯一可达的 tensor-core 路径是 [mma_sync](mma_sync.yaml)。三份的 `when` 互不重叠：root 与 split_kv 都要求 tcgen05 可用，而在 fused/split 与 base 对 2*sm_count 的大小上相反，mma_sync 要求 tcgen05 不可用；root 没有隐式兜底。三者关系是：共同 Contract 的 Request domain 含 head_dim ∈ {128,256}（shape_range 的八组 (head_count, kv_head_count, head_dim) 三元组）；本次任务要求交付的完整设计是 P2/P4 已定的这三份，均已落实并各自通过独立审阅；目录实际收录范围小于 Contract 有效域——三份 `when` 都只承担 head_dim = 128 的子域，下列子域没有任何完整 `when` 覆盖，只由变体记录承担，而记录不产生完整 schema 身份：head_dim = 256 的全部几何（“head_dim=256 fused 形式”“head_dim=256 与 split-KV 组合”“mma.sync 的 head_dim=256 形式”三条）；单波 D=128 fused 的 key-split、group-split 与 QK64=0 顺序形式（各自条目）；tensor-map descriptor 不可用时的 cp.async 降级（“K/V 物化”）；PSK、wide combine、融合 scan 与两遍 scan（各自条目）；派发序取 lpt=0/2/3 的 fused 几何，含无准备期掩码因而 lpt=0 的多波几何（“CTA 派发序 lpt”）。这些子域的实现事实都在源码里可达，只是本目录不为它们各交一份完整 YAML。

**调用与路径事实（影响理解与使用）。** `solution.py::Model.forward` 只解析 softmax scale 并把 14 个位置参数交给扩展：scale、causal、window 全部在准备期固定（`window_left` 为 None 或任何负哨兵都视为无左窗口），每次调用的 `scale_softmax` 实参被忽略；`sinks/seq_q_lens/amax_o/descale_q,k,v/scale_o/block_table/block_table_v/gate/sf_o` 不进内核，与 Contract 登记的 inert 参数一致；`current_stream=None` 传 -1 由 C++ 取当前流。C++ 侧顺序固定为 `fmha_mxfp8_forward`（TORCH_CHECK 校验、填 Params、`plan_geometry`）→ 可选 CUDA Graph 查找/捕获/重放 → `launch_sequence`（本次 forward 的全部 kernel launch）。TORCH_CHECK 拒绝 head_dim ∉ {128,256}、head_count 不是 kv_head_count 的整数倍、空 batch/序列、head_dim 轴不连续、三个 scale 缓冲字节数与 F8_128x4 不符。solution.py 依次以 `TORCH_CUDA_ARCH_LIST = {major}.{minor}a → {major}.{minor} → auto` 编译，只有 arch-specific 镜像定义 `FMHA_TCG_ARCH`（否则所有 tcgen05 kernel body 是 inert stub）；`compile()` 调一次 `tcg_available()` 并缓存，因此 tcgen05 与 mma.sync 两条路径之间的选择由加载的二进制决定，不是输入的函数。workspace 由调用方在准备期经 `scratch_workspace_bytes()` → `workspace_bytes(B,H,KH,Sq,Skv,D,causal,window_left,has_window)` 分配，与 forward 用同一个 `plan_geometry`，两处不会分歧；forward 只检查 `numel() >= plan.workspace`，不足时静默改走 fused。`use_split = use_tc && nsplit>1 && workspace 存在且足够`。CUDA Graph 缓存的是 launch 序列而不是结果：key 覆盖指针、stride、几何、掩码、scale 位与 `nsplit/gm_nsplit/use_split/maps_valid/workspace_bytes` 等字段，同 key 第二次调用才在侧流上只记录不执行地捕获，随后在调用方 stream 上重放，捕获或重放失败退回直接 launch，累计捕获达上限后永久直接 launch；`launch_sequence` 内故意不做错误检查，由 `fmha_mxfp8_forward` 在提交后统一 `cudaGetLastError`。split 链每个后继内核在入口处 `cudaGridDependencySynchronize()`（PDL）等待；等待侧的唯一例外是 scan → split 边界（`fmha_pdl_scan_wait()` 下移到首次读 p.mstate 之前），[split_kv](split_kv.yaml) 已按真实位置落实为 Tile_pipeline Step.SPLIT 的 Event.scan_wait 与 await:scan（排在 K/V prime、TMEM 预留、Q staging、scale 写与累加器清零之下），不是入口等待。trigger 侧按内核有三种实测位置：GM 与 split 两个 tcgen05 内核在退出前 trigger（入口 trigger 会让后继从恰好一个常驻波的网格里抢走槽位，s5 实测 -5.5% 被否决，全套 x0.9929 对退出位置的 x1.0062）；scan_flat 与 scan（pass B）在入口等待完成后、串行递推开始前 trigger——scan 是单 CTA、不可能被后继饿死，早释放让 split 的 TMEM alloc、Q payload staging 与 Q scale 写重叠 scan 的串行尾部，该边界独自值约 +1.8% 全套 geomean（三个其他边界合计的三倍），是这条链 PDL 收益的大头；segmax 在入口 trigger（其后继是 scan 的单 CTA，早 launch 不抢任何槽位，见“两遍 scan 变体”条目）。

**不可达的来源路径（只保留来源事实，不建设计、不改称参数）。** Contract 的八组 (head_count, kv_head_count, head_dim) 给出 G = head_count/kv_head_count ∈ {1,4,16}，全部是 2 的幂且 ≤ 64，`plan_geometry` 恒置 use_tc，故 scalar 路径 `fmha_scalar_kernel<CPT>`（一 warp 一 query row、warp shuffle 归约 QK、标量 FP32 FMA 做 PV）在 Contract 有效域内不可达，只服务 Contract 之外的几何；默认构建下 `FMHA_TCG_MIN_T=1`、`FMHA_TCG_PAD_T=1` 使 pad 门与 T 门恒真，`use_tcg = (D==128||D==256) && tcg_available()`，而 `use_tcv = (D==256) && tcg_ok && !use_tcg` 是矛盾式，Phase E（mma.sync QK + tcgen05 PV）恒不可达，保留为来源中的死分支。若共享 Contract 的有效域被放宽（例如允许非 2 的幂 G），这两个可达性判断需重新核对。

**只记录存在与默认值、不为其建设的实验臂。** 以下编译期开关是已测量否决或仅供 A/B 的臂，默认构建下不改变任何被选实例：`FMHA_GM_QK64=0`、`FMHA_PARTIALS_BF16=0`（见“partial 写出与格式”条目）、`FMHA_SCAN_B1B2=0`、`FMHA_COMBINE_DSLICE=0`、`FMHA_CTA_PHASE_STAGGER=0`、`FMHA_RED_MAX_SEQ=0`、`FMHA_FORCE_KEY_SPLIT_D128=0`、`FMHA_GSPLIT_FORCE_D128=0`、`FMHA_TCG_QK_AHEAD=0`、`FMHA_TMA_PIPE_D128=0`、`FMHA_SPLIT_MAX=0`（不施加额外上限）、`FMHA_FUSED_KSPLIT_D128/D256` 的 KSPLIT=4 臂（agv1 实测否决）。其否决测量随相应条目或源码注释保留。

**已知缺口与边界（继承，非阻塞）。** 外部验收器的比较公式与相对误差基准未提供（P1 登记的来源缺项），Contract `Tolerance` 在 root 中保留来源记录并须原样交付，该缺口只影响外部测试边界，不影响本目录取舍。源码注释引用的 harness/实验报告（results/summaries/…）不在冻结快照内，相关数值界已由 P2/P3 按注释内常数独立复推，本目录只转述有源码注释依据的测量。共享 Contract 的 `Hardware_specification` Device/Architecture/Feature 仍是 P1 已批准的占位状态：root 的容量条件已写成设计自持参数 sm_count（`device_sm_count()` host 查询；实测设备 148 SM，ncu 材料见证），split_kv/mma_sync 的容量类条件（resident、combine 选择、lpt 门）同样在各自 YAML 中按设计自持参数落实，不当成 Contract 已登记的硬件事实。“mma.sync 与 split-KV 的组合”带一处 head_dim=128 与 256 两条链共有的来源缺陷，见该组合条目，按事实保留、不补造初始化或隔离保证。

## 变体与组合

条目以 [root](root.yaml)、[split_kv](split_kv.yaml) 或 [mma_sync](mma_sync.yaml) 为基线，用对应 YAML 中的已有对象（数学 rewrite 名、step、role 动词、存储）定位差额；组合条目直接列出其完整基线，只补已知相容关系与新增限制。条目排列不产生 patch 应用顺序，也不修改基线的参数或 when。

### head_dim=256 fused 形式（局部）

- 基线：[root](root.yaml) 的 DESIGN 三区——Tile_pipeline::MAIN 的存储（k_ring/v_ring/s_tile/o_tmem/p_tmem/sf_cols）与 Role.MAIN 各动词、Work_schedule::MAIN 的 Mapping/Schedule、Math_reshape 的 “Numerator by block-scaled PV product” 与 “Reciprocal normalization and LSE epilogue”。
- 差异与联动：实例 fmha_tcg_kernel<256, PASS_FUSED, KSPLIT=2, TMA=1>（launch_tcg<256, PASS_FUSED, 2>）。CTA 变为 128*KSPLIT=256 线程 = 两个 warpgroup：QK 仍单发覆盖整组 128 键，score 读出与 softmax 按 KHALF=64 键各半（组最大值经共享 scratch 由 tcg_combine_halves(MAX) 跨 warpgroup 合并——max 精确且次序无关，与单一 128 宽归约位相同）；概率各写 P tile 的自己键段，PV 仍由单线程每组发一次、覆盖全部 128 键 × D 列；o_tmem 移入 [128,384)、ALLOC=512 列 → 1 CTA/SM（root Require#4 的 tmem_safe_smem 预算按 512 列生效）；O 的 rescale 与 epilogue 读出按 OCOLS=D/KSPLIT=128 个通道分半（两 warpgroup 读同样 128 个 TMEM lane、不相交的列）；行分母在组末经 tcg_combine_halves(sum) 按 key 序折叠（重结合差 ~1e-7，在 rtol 0.05 内五个数量级，且概率先于分母舍入到 E4M3，翻不动量化）；DCH=2 个 128B swizzle chunk；bias 由 16 变 1（Contract 值），exp_bias4 的 L=0、magic-constant 折叠退化为无操作；SF_AHEAD（scale atom 三组超前于所属 tile、3 槽 smem 环 + TMEM 双奇偶槽，删去循环内第二个每组 CTA 宽 barrier；仅 D=256、KSPLIT=2、非 GM、非 GSPLIT，QK64 因列图冲突被算术排除）；MIDPIPE（qk6：QK(g+1) 在迭代中段发出、PV(g−1) 在同一中点退休，K 环三槽超前两组、SFB_V 三槽环，实测对控制位相同）。
- 条件与依据：use_tcg && !use_split && D=256 时 FMHA_FUSED_KSPLIT_D256=2 恒选；lpt 规则与 root 相同但 slots=sm_count（1 CTA/SM）。ncu shape 4、6 实测 <256,0,2,1,0,0,0,0,0>。KSPLIT=4 臂已测量否决（agv1：s4 +1.8%、s6 +0.5%；D=128 上 s7/s1 +48%/+53%——独立流比 warp 数值钱）。类型判断（P2 交办）：两 warpgroup 的组成变化与每组跨 warpgroup 合并是围绕基线已有 step/role/存储的新决定加必要联动，边界外主体组织（单内核、一 CTA 一 worktile、组窗递推、派发序、epilogue 结构）仍成立，故记局部而非参数，也不构成新完整设计。

### D=128 key-split 流水形式（局部）

- 基线：[root](root.yaml) 的 Tile_pipeline::MAIN（Pipe 日程、k_ring/v_ring 深度 2、单块 s_tile、Waiting 边中 PV(g−1) 的退休位置）与 REALIZATION Require#2（bulk tensor staging）、Require#4（2 CTA/SM 预算）。
- 差异与联动：实例 fmha_tcg_kernel<128, PASS_FUSED, KSPLIT=2, TMA=0>（launch_tcg<128, PASS_FUSED, 2>），256 线程两 warpgroup，softmax 按 KHALF=64 键分半、跨 warpgroup 合并与 OCOLS=64 通道分半同上条；K/V 环加深到 4 槽（NSTAGE=4），新增第二块 score tile（S1=128，双缓冲对由两 warpgroup 共享），O 从寄存器移入 TMEM [256,384)、ALLOC=512 → 1 CTA/SM；日程改为软件流水：QK(g+1) 在迭代 g 中段发出（写另一块 score tile），PV(g−1) 的等待推迟到迭代 g+1 开头，tile 寿命因此比 root 多跨两个迭代；staging 回到 16B cp.async（bulk tensor 对该形式实测 +4~6%：它已用第二块 score tile 的 MMA 工作隐藏 staging，单条 bulk 流反而喂不满）。
- 条件与依据：D=128 fused 且 fused_ctas = qtiles128*B*KH <= sm_count（FMHA_KEY_SPLIT_D128=1；FMHA_FORCE_KEY_SPLIT_D128=0），且 gspan < 8（否则 group-split 形式优先）。依据是 wave-packing 测量（pH36/agk2：低于 1 CTA/SM 时 s0 41.1 对 53.4、d4 16.2 对 22.2 取胜；超过后 s7 233.2 对 205.4 落败）。无 frozen shape 见证（shape 0 被 group-split 优先取走）。

### D=128 group-split 形式（局部）

- 基线：[root](root.yaml) 的 Tile_pipeline::MAIN（Role.MAIN 的单 warpgroup 组织、k_ring/v_ring、s_tile/p_tmem）与 Work_schedule::MAIN 的 Mapping。
- 差异与联动：实例 fmha_tcg_kernel<128, PASS_FUSED, KSPLIT=2, TMA=0, GSPLIT=1>（launch_tcg<128, PASS_FUSED, 2, false, false, true>）。两 warpgroup 不再切同一组的键，而是交替处理整组：warpgroup w 取 cLo+w、cLo+w+2、…；每 warpgroup 自己的 K 三槽 / V 两槽环（槽按 warpgroup 划分，两侧永不触同一 tile）；rendezvous 全部收窄到 128 线程的 warpgroup barrier；(mstate, den) 经共享内存在两 warpgroup 间点对点交接（mbar_ms 每 warpgroup 一个 128-arrival 槽，mbar_den 每 warpgroup 两个按奇偶的槽）；每组 PV 必须等另一侧上一组 PV 退休才发，保证按组序累加进同一 O；两块 score tile（S1 是 warpgroup 1 自己的单缓冲 tile）与两块 P tile 都在 TMEM（P_TILE/P_TILE1 共占 512 列中的 64；smem P tile 未预算，两 warpgroup 写同一 smem tile 会 race）；O 占 [256,384)、1 CTA/SM；epilogue 前由拥有 cHi 的 warpgroup 经 scratch 把最终状态交给另一侧，den 是顺序值、不经折叠。
- 条件与依据：D=128 且 key-split 条件成立（fused_ctas <= sm_count）且 gspan = useful_key_span >= FMHA_GSPLIT_MIN_GROUPS(8)，派发优先于 key-split 流水形式；该形式下 lpt=0（shape 0 的 fused_ctas=128 <= 148）。ncu shape 0 实测 <128,0,2,0,0,0,1,0,0>。staging 恒 cp.async（agu8：bulk tensor 在一 CTA/SM 的 D=128 fused 几何上 +3.49%）。

### score tile 宽度（参数）

- 基线：[root](root.yaml) 的 Tile_pipeline::MAIN 存储 s_tile（64 列、两半轮流）与 Math_reshape “Block-scaled score tile, single readout”。
- 差异与联动：其他取值 QK64=0 → 128 列顺序形式 fmha_tcg_kernel<128, PASS_FUSED, KSPLIT=1>（launch_tcg<128, PASS_FUSED, 1>，默认构建下不发射）：每组的 QK 是一次 N=128 系列而非每半两次 N=64，O 回到寄存器（O_IN_TMEM 假），score tile 每组多次读出（源码称三读出形式），少一次每半的 mbar_wait 与 fence+barrier 对、多两次 TMEM 读出；ALLOC 仍 256 列、2 CTA/SM；P tile 位置随“概率 tile 位置”条目（该形式 P_TILE=192 仍在 TMEM）。两形式对同一组分数做同一 block-scaled 点积、逐半掩码后取 max（精确、次序无关）。
- 条件与依据：qk64 门 = FMHA_QK64_D128(=1) && D==128 && !key_split && !gsplit && fused_ctas >= FMHA_QK64_MIN_WAVES(=0)*slots，默认构建下对一切非 key-split 的 D=128 fused 启动恒真，故 128 列顺序形式仅当 FMHA_QK64_D128=0 或抬高 MIN_WAVES 时出现。依据 agu5/bd1 两轮测量：64 列形式每组多出的等待延迟在每 SM 两 CTA 时被隐藏、单 CTA 时暴露（波数次序）；MIN_WAVES=0 后 root 实例的 DPV 延迟退休（FMHA_QK64_DEFER_PV=1）覆盖该暴露，root 的 when 子域即此取值。

### K/V 物化（参数）

- 基线：[root](root.yaml) 的 Role.MAIN 动词 load:k_block / load:v_block（bulk copy）与 REALIZATION Require#2（cp.async.bulk.tensor + 每槽 mbarrier expect_tx）；root 的 when 末句（descriptor 可用条件）就是本条目的选择条件。
- 差异与联动：其他取值 TMA=0 → 16 字节 cp.async staging，写入同一 fp8_tile_offset XOR 布局（与 SWIZZLE_128B 逐字节相同），越界 key 由 cp.async 的 src-size 归零（对应 bulk 路径的 OOB fill）；完成机制由每槽 mbarrier expect_tx 变为 cp.async 的 commit/wait_group（scale atom 改由 tcg_stage_atoms 以 cp.async 在同一 commit 组内 staging，字节相同）；写出字节相同（源码注明 “produces identical bytes”）。该降级实例不在 root 的 when 内，且日程有一处联动差异：DPV 谓词含 TMA（DPV = FMHA_QK64_DEFER_PV && QK64 && PASS_FUSED && TMA && D==128），降级实例保持 PV(g) 在迭代脚部等待的 shipped 日程，不是 root 声明的延迟退休；其余存储与动词对象不变。
- 条件与依据：descriptor 不可用时自动降级——driver 入口缺失、base/stride 非 16B 对齐、extent 或 stride 关系不合法（encode_tile_map 返回 false → maps.valid 假 → launch_tcg 选 TMA=false 实例化）；descriptor 按 base + 三个 stride + 四个 extent 在 8 个槽缓存，键里没有任何元素值。一 CTA/SM 的 key-split 流水与 group-split 形式恒 cp.async（实测依据见各自条目）。

### 填充跳过行序 PSK（参数）

- 基线：[split_kv](split_kv.yaml) 的 Work_schedule Step.GMAX 与 Step.SPLIT 的 Decomposition.Strategy——两个 pass 共用同一行映射（row r at q0：i = q0 + (r mod qph128)，h = kh*group_count + floor(r/qph128)），与 [root](root.yaml) 的 Work_schedule::MAIN Decomposition.Strategy 内容一致，但两份 YAML 各自本地定义、无整区 `from`。
- 差异与联动：其他取值 PSK=1 把行序换成 query-major（i = q0 + (r >> log2G)，h = kh*G + (r & (G−1))），这是同一 128 行的纯置换，使死行（i >= query_len）成为 warp 级前缀；rowsLive = __any_sync(valid) 整块跳过死 warp 的 softmax（score 读出、组最大、延迟 rescale、概率、QDQ、概率存储），但保留全部 CTA barrier、mbar_wait 与 .sync.aligned tcgen05 操作（其他 warp 依赖其相位）；每行自己的算术、Q 字节、scale 字、输出与 LSE 地址不动，输出的每一位不变。fused 形式不启用 PSK。
- 条件与依据：host 门 FMHA_PAD_SKIP(=1) && 2*Sq*G <= qtiles128*128（每 tile 至少一半行槽是填充；shape_range 下等价于 Sq*G <= 64，此时 qtiles128=1、base=B*KH<=128，源码注明凡可能启用它的启动都已在 split 路径上）。ncu shape 2、3 的 GM 与 split pass 均 PSK=1，故这两个 shape 落在 split_kv 的 `when` 之外（其 `when` 以 2*query_len*group_count > ceil_div(query_len, qph128)*128 明确排除 PSK）。agv2 实测无门守卫在 s2 -8.0%、d7 -2.7%，对 s5 +7.0%——填充比低于 2x 时分支与寄存器成本收不回。

### CTA 派发序 lpt（参数）

- 基线：[root](root.yaml) 的 Work_schedule::MAIN Schedule.Worktile_order（qtile 外层降序、kv_pair 内层降序），即 lpt=1 的双射；Mapping 的 Preassigned(worker_id, 1)。
- 差异与联动：p.lpt 的其他取值：0 = 自然序；2 = pair-class 互补序（线性索引 d < pair_p 的重侧从最后一个 tile 降序走、d >= pair_p 的轻侧升序走且 head rank 反转，使共享边界 tile 不相交）；3 = 相邻交错（按 d 奇偶分侧）。cta_index 对任何 lpt 都是网格上的双射，每个 CTA 仍覆盖唯一一个 (tile, b*kv_head[, split])，数值结果不变，只改变 CTA→SM 的分配；pair_p = sm_count。host 规则：fused_ctas > slots 且有掩码 → 1；sm_count < fused_ctas <= slots 且有掩码 → FMHA_LPT_PAIR_MODE(=2)；否则 0；slots 取本形式常驻容量（root 形式 2*sm_count，key-split/group-split/D=256 形式 sm_count）。
- 条件与依据：lpt 只在 tcgen05 fused 分支设置，split 链各内核恒 lpt=0；mma.sync 路径同样恒 lpt=0（[mma_sync](mma_sync.yaml) 的 Work_schedule Step.MAIN Schedule.Strategy 记为升序、“no lpt remap”），因为 p.lpt 在 host 入口置 0 后只被 tcgen05 fused 分支改写（fmha_mxfp8_qkv.cu:2181 与 1826-1857）。依据：全局降序的 list-scheduling 模拟为 119 时间单位，自然序 153，而只反转 blockIdx.x 得 144 且 pH22 实测无效——本记录不得概括为“方向取反”，lpt=1 是整个网格线性序反转后按 (qtile 慢键, kv_pair 快键) 重分解（root 的 Worktile_order 即其表达）。见证：shape 7 取 1（root 的 when 内）；shape 1 取 2（跑与 root 相同的模板实例，但 fused_ctas=256 <= 2*148，不在 root 的 when 内，按本记录归类）；shape 0 取 0。该模拟与配套的 ncu 尾部空置数据都标注为 tcgen05 启动（fmha_common.cuh:304-322：frozen shape 7 的 fmha_tcg_kernel<128,0,2>、512 CTA 对 148 个一 CTA/SM 槽），mma.sync 路径没有自己的派发序代价见证。

### 概率 tile 位置（参数）

- 基线：[root](root.yaml) 的 Tile_pipeline::MAIN 存储 p_tmem（E4M3 概率 tile 在 TMEM [224,256)）与 REALIZATION Require#1（PV 的 TMEM-A 操作数）。
- 差异与联动：其他取值是 P tile 在 swizzled 共享内存（FMHA_P_IN_TMEM=0 或列图无余量时）：概率经每线程每组八次 sts128 写入 smem，再由 fence.proxy.async.shared::cta 加 CTA barrier 发布给 UMMA proxy；对 PV 指令而言两种驻留的 A 操作数数值相同（ba1：TMEM-A 对 FP64 参考位精确，与共享内存控制形同零误差）。TMEM 驻留省掉这些存储与 fence（ab1：只删存储就值 s7 -12.7%、s1 -5.6%），代价是 32 个 TMEM 列。
- 条件与依据：P_IN_TMEM = FMHA_P_IN_TMEM(=1) && NEEDS_O && 列图有余量（P_TILE 加宽度不超 ALLOC）且不与 O/S1 重叠；GSPLIT 形式必须 TMEM 驻留（两 warpgroup 写同一 smem tile 会 race，其布局未给 smem P tile 预算）。root 与当前全部被发射形式都取 TMEM 驻留。

### 概率 bias 折叠（参数）

- 基线：[root](root.yaml) 的 Math_reshape “Biased probability and E4M3 quantization”（exp_bias4：2^4 折进两个 magic 常量）与 REALIZATION Require#5、Forbid#1。
- 差异与联动：同一轴上三个开关：FMHA_BIAS_MAGIC_FOLD=1 为 root 当前值（2^4 折进 expf2_bias<4> 的 kmagic/kshift，nc、f、ex2(f) 不变而 d 恰大 2^4，两个乘积都精确、结果位相同，省每键对一次 packed 乘法）；取 0 回到独立的 f32x2_mul(pr, bias2) 后乘（结果仍位相同，只差指令数与构建期测量状态）。FMHA_UNIT_BIAS=1 让 bias 成为编译期常量 ProbabilityBias<D>（D=128 为 16、D=256 为 1），LSE 的 den/bias 变成乘以 0.0625f 的精确乘法。已否决取值 FMHA_FOLD_BIAS16：把 4<<23 直接加进移位后的位模式，2^32 模式穷举出 ~24% 经符号位回绕的差异（ex2），永久保持 0——与 root 的 REALIZATION Forbid#1 一致。
- 条件与依据：magic-constant 折叠的回绕反例需要 x >= 86.64，而 x = score − safe <= 4·ln2，不可达，故位相同成立；折叠只利好 D=128（D=256 的 bias=1、L=0，常量不变、codegen 无操作）。ls1/ls2 新树测量采纳为默认（s1 快态可复现、s9 −1.55~−1.62% 稳定，与 FMHA_LPT_PAIR_MODE=2 叠加）。

### 融合 scan 变体（局部）

- 基线：[split_kv](split_kv.yaml) 的 Work_schedule Step.SCAN 与 Flow.Launch 的第二段提交（本变体把它整段取消）、Tile_pipeline Step.SPLIT 的 load:m_init / load:m_next 与 Event.scan_wait、Step.COMBINE 的 Role.MAIN 各动词，以及 Math_reshape “Exact replay of the delayed maximum”；共享 Contract 的延迟 rescale 递推见 [root](root.yaml) 的 CONTRACT.Algorithm_requirement Compute “Delayed rescale probability groups”。
- 差异与联动：取消 scan 内核启动（两遍链必须整体跳过，否则其 mtail 写与 split 的重发布并存）；split pass 每线程对 bm 做前缀游走得到本 chunk 初态（递推与 scan 内核逐项相同，状态与 scan 物化位相同），循环内以 fb/bnxt 携带 bm[grp]/bm[grp+1] 取代重放出的 mstate；partial 未加权写出（wgt=1），另存 part_m[split][row] 为本 chunk 末态（空 chunk 也存，其权重有限且不起作用）；最后一个 chunk（blockIdx.z == nsplit−1）重发布 mtail[row] = mstate，每行恰写一次；combine 取 FWGT 形式，在共享内存里一次算出各 split 的 w_s = exp(m_s − mtail)（narrow 每 split 每 CTA 一次，wide 由所属 split-group 的 lane 每 split 一次；非有限侧为 0），同时加权分子与分母，LSE = mt + log(total_b/bias)；workspace 增加 off_pm 一区（plan_geometry 只在 scan_fused 时计入）。内核内不做跨 CTA 的 mtail 读（a 侧 fs1 的 race 已被否决）。
- 条件与依据：plan 拥有的 scan_fused = FMHA_FUSE_SCAN_FLAT(=1) && use_tcg && (D==128 || FMHA_FUSE_SCAN_D256(=0)) && span <= (两遍门成立时 FMHA_FUSE_SCAN2P_MAX_SPAN=160，否则 FMHA_FUSE_SCAN_MAX_SPAN=48)，span 为 useful_key_span；D=256 被 FMHA_FUSE_SCAN_D256=0 永久排除。ncu shape 2、3、8 实测（split pass FSCAN=1、combine FWGT=1），故这三个 shape 与上条的 PSK 一样落在 split_kv 的 `when` 之外（其 `when` 要求 span 选中 flat scan）。

### 两遍 scan 变体（局部）

- 基线：[split_kv](split_kv.yaml) 的 Work_schedule Step.SCAN（Decomposition.Strategy 的 scan_block、Partition.row_block、Mapping.Worker_count）与 Tile_pipeline Step.SCAN 的 Role.MAIN（await:gmax、compute:m_state、store:m_tail、signal:launch_permit），当前值是 flat 单遍；其重放递推是 Math_reshape “Exact replay of the delayed maximum”，共享 Contract 的延迟递推见 [root](root.yaml) 的 CONTRACT.Algorithm_requirement Compute “Delayed rescale probability groups”。
- 差异与联动：以两次 launch 取代单内核——pass A fmha_segmax_kernel 以 (ceil(rows/256), nseg) 网格、256 线程，每行一线程对每 FMHA_SCAN_SEG=16 组一段求段最大值写 segmax[seg][row]；pass B fmha_scan_kernel 递推与 flat 相同，但按段先用 segmax 证明整段不可能触发 (b−m)>4·ln2（m 单调不减，段最大不足以跳变则段内逐组比较必全假）；被跳过的段只省去 load 与逐项比较，段内全部 mstate 条目仍写入入态常量 m——两个 scan 内核都全量物化 rows×T 的 mstate（split pass 重放 mstate[cLo−1] 初态与逐组预取依赖它无空洞），有可跳变段时先常量写到首个可跳变段、再从其起精确走；nseg = ceil(T/16)，workspace 的 off_segmax 区由此使用。PDL 边界联动：segmax 在入口 trigger（其后继是 scan 的单 CTA，早 launch 不抢槽位）；scan（pass B）与 scan_flat 相同，在入口等待后、串行递推前 trigger，split 侧对应的 fmha_pdl_scan_wait 下移到首次读 p.mstate 之前（见范围节）。
- 条件与依据：scan2p = T >= FMHA_SCAN_TWO_PASS_T(128) && rows_total <= FMHA_SCAN_TWO_PASS_ROWS(512) && 无左窗口（FMHA_SCAN_TWO_PASS_NOWIN=1），且仅在 scan_fused 为假时生效（融合 scan 优先；两遍门成立时 FSCAN 的 span 上限升到 160）。agw4 测量：T<128 时段设计的额外 launch 比省掉的 load 贵（s3 +8.92%、d3 +7.09%），T>=128 时取胜（s2 −1.80%/−4.03%、s5 −6.32%/−6.93%）。ncu shape 5 实测（segmax + scan，D=256 链），该 shape 因此在 head_dim 与 scan 形式两个维度上同时落在 split_kv 的 `when` 之外。

### scan 块尺寸（参数）

- 基线：[split_kv](split_kv.yaml) 的 Work_schedule Step.SCAN Decomposition.Strategy 的 scan_block，launch 几何即其 Partition.row_block 的 tile 与 Mapping.Worker_count = ceil_div(rows_total, scan_block)；递推本体见 Math_reshape “Exact replay of the delayed maximum” 与 [root](root.yaml) 的 CONTRACT.Algorithm_requirement Compute “Delayed rescale probability groups”。
- 差异与联动：flat scan 的 block = scan_block_size(rows, T)：T < FMHA_SCAN_BLOCK_T(128) 时固定 256；否则取 32、64、128 中使 ceil(rows/block) <= sm_count 的最细者，都不满足则 256——即“网格仍满一波的最细块”。两遍的 pass B 不用此规则：固定 256 线程 × ceil(rows/256) 个 CTA。
- 条件与依据：flat scan 是 load 延迟瓶颈（long_scoreboard 48.9%、IPC 0.72，更细网格倍增在飞 128B 请求数），pass B 被段跳过删掉多数 load 后剩下 rows×T 的 store、是发射瓶颈（agz2/ap12 实测两内核想要相反几何）。见证：shape 9 的 flat_block=64、grid=129。

### combine narrow 与 wide 形态（参数）

- 基线：[split_kv](split_kv.yaml) 的 Work_schedule Step.COMBINE（Decomposition/Mapping/Schedule，当前值 narrow：fmha_combine_kernel<128, false, false>）与 Tile_pipeline Step.COMBINE 的 Storage.den_smem（shape [{split: 128}]，view den_row 取 [0, nsplit]）；归并公式在本节点是 Math_reshape “Merge and final normalization”，其 Contract 依据见 [root](root.yaml) 的 CONTRACT.Algorithm_requirement Compute “Output accumulation” 与 “Log-sum-exp output”。
- 差异与联动：narrow = 128 线程/CTA（FMHA_COMBINE_NARROW_BT），grid=(Sq,H,B) 每输出一行一个 CTA，每线程 D/128 个通道遍历全部 split（每轮 8 个独立 load），分母每 split 一线程载入 sB[128] 后升序求和；wide = fmha_combine_kernel_wide，128*FMHA_COMBINE_SP = 512 线程，四个 split-group 各取 chunk = ceil(nsplit/4) 个 split，组内部分和经 sPart[4][D/SL] 由 sg==0 的组做最终归约，分母每 split 一 lane 蝶形归约。两者的重结合差 <= ~1e-7（bf16 输出、rtol 0.05 下不可见）。末段归一相同：inv = 1/total_b、o = bf16(acc*inv)、lse = mtail + log(total_b/bias)（total_b<=0 或 mtail 非有限为 -inf）。FWGT/BF16 是两形态共有的模板轴（见融合 scan 与 partial 格式条目）。
- 条件与依据：host 规则 (rows < 2*sm_count && nsplit >= 8) || nsplit > 128——第二支是 narrow 的 sB 容量硬上限（nsplit <= FMHA_COMBINE_NARROW_BT，由 launch 位点显式保证而非跨文件推导）；FMHA_COMBINE_MAX_NSPLIT=512 是 wide 的正确性上限（chunk 不得超过 128），在 plan_geometry 钳制。pI25 实测：wide 在 rows 96/192/128 上 −5.2%/−3.4%/−1.0%，在 4096/8200/512 上 +42%/+20%/+10%。见证：shape 2、5 用 wide，shape 3、8、9 用 narrow。

### partial 写出与格式（参数）

- 基线：[split_kv](split_kv.yaml) 的 Tile_pipeline Step.SPLIT 的 store:part_a / store:part_b（Pipe 末段排在 compute:chunk_weight 之后、release:tmem 之前）与 Math_reshape “Chunk weight and weighted partials”（num_part/den_part 的 shape 与 fp32 dtype）；分子分母含义见 [root](root.yaml) 的 CONTRACT.Algorithm_requirement Compute “Output accumulation”。
- 差异与联动：写法轴——转置 staging（FMHA_PART_XPOSE 族：partial 先写进复用空闲 Q/K/V 区的共享 tile，pitch 带 16 字节 pad 保持 bank 相异，再由全 CTA 合作连续 16 字节写出，以发射槽换 sector 效率）对逐线程 stg128_scaled 直写；默认下 D=256 的 FP32 partial 恒转置（FMHA_PART_XPOSE_FP32=1），D=128 的 FP32 partial 仅在 !PSK 时转置（FMHA_PART_XPOSE_D128=2；PSK 形状 partial 小，转置的每槽开销收不回），BF16 partial 恒转置。格式轴 BF16PA：FP32（默认）或 BF16 part_a，是模板轴而非运行时分支（非 BF16 实例化字节不变）；part_b 恒 FP32。
- 条件与依据：BF16 已测量否决并禁用（FMHA_PARTIALS_BF16=0）：peaked 分布（operand×3 后量化）下 4 个 seed 有 3 个超出冻结容差（max_mismatch_fraction=0，一个元素超即失败），失败依赖输入分布而 shape_range 不把分布绑定到几何，任何门都无法修复（fp16 也溢出）；禁用代价约 +0.64% 固定 geomean（同 job A/B）。转置写法依据：s5 内核 cycles −7.78%、s8/s9（16.8 MB partial）+0.88% 固定 geomean，s3/s2（2.4 MB）实测 +5.5% 故被 D=128 的门排除。tc 路径永不 BF16（plan 门要求 use_tcg），mma.sync 组合链的 workspace 恒 FP32 布局。

### group-maximum pass 形式（参数）

- 基线：[split_kv](split_kv.yaml) 的 Work_schedule Step.GMAX（Schedule.Strategy 的 gm_nsplit、Partition.gm_chunk）与 Tile_pipeline Step.GMAX（3 槽 k_ring/sfk_ring、单块 128 列 s_tile、Role.MAIN 的 Pipe 与 Waiting），当前值 launch_tcg<128, PASS_GROUP_MAX, FMHA_GM_KSPLIT_D128=1>；它物化的量见 Math_reshape “Materialized group maximum over the key range” 与 [root](root.yaml) 的 CONTRACT.Algorithm_requirement Compute “Delayed rescale probability groups” 的 group_max。
- 差异与联动：GM pass 无 V staging、无 P tile、无 PV（NEEDS_O 假），把 score tile 归约成每行一个 float 写 bm[grp][row]，故 256 列即 2 CTA/SM。KSPLIT 轴：FMHA_GM_KSPLIT_D128=1 / FMHA_GM_KSPLIT_D256=2（取 2 时两 warpgroup 各持 KHALF=64 键，max 经 oSb 合并——精确、与单一 128 宽归约位相同）。循环轴：当前取值就是 [split_kv](split_kv.yaml) Tile_pipeline Step.GMAX 的流水循环体——K 环 3 槽，QK(g+1) 在迭代脚部发出：group_max(g) 先求出最大、有效行写 bm[grp*rows_total+rowG]、KSPLIT==1 时一次 __syncthreads() 证明全部 warp 的分数读出已退休，随后才由 tid 0 tcg_pipe_qk + tcg_commit（fmha_tcg.cuh:4242-4252），即其 Pipe 里 matmul:q_tile@k_block(g+1) 排在 store:gmax(g) 之后、Released 边 “{issue matmul:q_tile@k_block(g + 1)} ← [{done compute:group_max(g)}]” 所固定的位置；其他取值是顺序体，运行期门为 (cHi−cLo) >= FMHA_PIPE_GM_MIN_GROUPS(7)（fmha_tcg.cuh:4093；7 出自 pI19 的 warm-protocol 测量，源码注明该常数早于 TIMING_PROTOCOL_V2 与 agx1，引用前须读其 provenance），span 不足即落回顺序体，D=256 因 FMHA_PIPE_GM_D256=0 恒走顺序体（PIPE_GM 的 constexpr 定义要求 D==128 或该开关非 0）。GM 没有概率 pass 可藏 MMA，两种体的等待都完全暴露。网格 z 取 gm_nsplit 而非 nsplit：gm = resident/base，只受 T/2 上限与 >= nsplit 下限约束（GM 不写 partial，每 CTA 成本只有 prologue；shape 5 实测 GM 在 64 CTA 网格对 148 SM 上花 18.0us、占 forward 17%，填满常驻槽位不增加 partial 流量）。FMHA_GM_QK64=1 时 GM 用 64 列形式只占 128 列（3 CTA/SM、gm 改按 3*sm_count/base）——默认关闭。
- 条件与依据：p.nsplit 在 GM launch 前后被临时设为 gm_nsplit（p 是 launch_sequence 自己的副本，不泄漏给 scan/split/combine，它们都读 pl.nsplit）。D=256 KSPLIT=2 实测 s5 −4.02%、d3 −2.56%（两轮同号）；D=128 KSPLIT=2 测量不定（s9 +0.82%、s2 +1.03%、d7 −2.82% 跨轮变号），按来源保持 1。

### mma.sync 的 head_dim=256 形式（参数）

- 基线：[mma_sync](mma_sync.yaml) 的三个 Design 区域——Math_reshape “Block-rescaled score by rank-1 E8M0 fold”（head_dim/scale_block_size 个 block 的 rank-1 折算）、“Delayed rescale and scalar-exponential probability” 与 “Reciprocal normalization and LSE epilogue”（runtime bias）、“Numerator by BF16 PV on a decoded value tile”（v_bf16 与寄存器累加器），Work_schedule Step.MAIN 的 Decomposition.Strategy（qph = 64/group_count）与 Mapping.Strategy（一 CTA 四 warp、每线程相距 8 行的两行），Tile_pipeline Step.MAIN 的 Storage（q_tile、k_ring/v_raw_ring、v_decoded、sfk_raw_ring/sfv_raw_ring、sfq_words/sfk_words/sfv_words、score_regs、o_regs）与 Role.MAIN 各动词。
- 差异与联动：同一 kernel 族的 head_dim=256 实例化 fmha_tc_kernel<256, WARP=4, PASS_FUSED, PVMODE=0>，由 launch_sequence 的 use_tc && !use_split 分支在 D != 128 时启动（fmha_mxfp8_qkv.cu:2035-2039），grid=(qtiles, B*KH)、block=32*4=128 不变。BM 仍 16*WARP=64，行打包、每线程两行 fragment 与组窗循环结构都不变；随 D 变的只是计数与常量：CQ = KB = D/32 由 4 变 8（QK 每行 8 个 32 通道 block 的 rank-1 折算），NTOT = D/8 由 16 变 32、NTP = D/16 由 8 变 16，寄存器累加器由每线程 NTOT*4 = 64 个 FP32 增至 128 个（o_regs 由 64 行×128 通道变 64 行×256 通道，score_regs 与 D 无关、不变）；K 与 V 的 E8M0 raw atom 各由 CQ*128 = 512 与 (D/128)*512 = 512 字节变 1024 字节（V 侧即两个 512 字节 atom），v_decoded 变 128×256 的 BF16；bias 由 ProbabilityBias<128>=16 变 ProbabilityBias<256>=1，正是 Contract “Delayed rescale probability groups” 按 head_dim 登记的两个值，故 p = expf(x)*1、LSE 的 den/bias 退化为精确的乘 1，上述两处 rewrite 的 bias 值改绑而递推位关系不变。容量后果：TcSmem<256,4,PASS_FUSED>::bytes = 225344（q_tile 16384，K 与 V 的原始 payload 各两槽、各 65536，BF16 v_decoded 65536，K 与 V 的 raw atom 区各 2048，解码后的 q/k/v scale 区 2048/4096/2048，末尾 64），超过每 SM 233472 字节的一半而不足全额，常驻由 2 CTA/SM 降为 1 CTA/SM——REALIZATION Require#4 的 112704 字节请求与“常驻两 CTA”的结论都随 D 改变（launch bound 仍是 FMHA_TC_MIN_BLOCKS=2，实际常驻被 smem 钉在 1，源码注释：footprint already caps D=256 at 1）；plan_geometry 的 split 规则用同一 TcSmem<256,4,PASS_SPLIT>（WANT_V 同真，字节数与 PASS_FUSED 相同）求 per_sm，故该几何下 resident 由 2*sm_count 减半为 sm_count，base < resident 更难成立、ns = resident/base 的上界也随之减半。
- 条件与依据：进入条件与 mma_sync 的 `when` 相同（plan_geometry 置 use_tc，而 tcg_available() 为假，即加载的二进制非 arch-specific），差别只在 head_dim = 256；因此它既不在 mma_sync 的 `when`（限定 head_dim = 128）内，也不在 root 或 split_kv 的 `when` 内，属范围节列出的“head_dim = 256 全部几何”之一。类型判断：主要计算（rank-1 scale 折算、V 解码、跨 lane fragment 归约）、工作归属（BM=64、每线程两行）与主协作组织（相边界 CTA rendezvous、两级 cp.async 环）都不变，改变的只是 D 派生的循环与缓冲计数、bias 常量与常驻容量，故记参数；这与 root 的“head_dim=256 fused 形式（局部）”对称而判级不同，那一条改变了 warpgroup 组成并引入跨 warpgroup 合并。无 frozen 性能见证：performance/ncu 与 shapes 全部采自 tcgen05 构建，本条的 smem 与常驻数值是把 D=256、WARP=4、PASS_FUSED、PVMODE=0 代入 TcLayout 的 bytes 公式算得，不是实测。

### mma.sync 与 split-KV 组合（组合）

- 基线：[split_kv](split_kv.yaml) 的四内核链（Work_schedule Flow.Launch 的 GMAX → SCAN → SPLIT → COMBINE 与五条 global Handoff）与 [mma_sync](mma_sync.yaml) 的 fmha_tc_kernel<D,4,PASS>；共享 Contract 与延迟递推见 [root](root.yaml)。
- 差异与联动：launch_sequence 的 use_tc && use_split 分支把链的两个 tcgen05 pass 换成 fmha_tc_kernel<128,4,PASS_GROUP_MAX> 与 <128,4,PASS_SPLIT>（split 的 grid=(qtiles, B*KH, nsplit) 按 qph=64/G 分行，fmha_mxfp8_qkv.cu:1989 与 2005），scan 与 combine 内核完全共用，workspace 恒 FP32 布局、永不融合 scan（part_m 恒空，tc fallback epilogue 恒写 FP32）。head_dim=256 有对称的完整链（fmha_mxfp8_qkv.cu:2014-2032）：launch_tc<256,4>(PASS_GROUP_MAX, gm_grid) → 同一 scan（flat 或两遍，与 D=128 共用同一内核）→ launch_tc<256,4>(PASS_SPLIT, grid) → launch_combine<256>(bf16=false, fwgt=false)；GM 与 split 两个 pass 的 D=256 差额即上文“mma.sync 的 head_dim=256 形式”条目（PASS_GROUP_MAX 的 WANT_V 假，无 V 相关各区，其 smem 与常驻另按该分支算），resident 减半使该几何更难满足 nsplit>1。来源缺陷（两个 head_dim 分支共有，按事实保留，不补造初始化或隔离保证）：gm_grid.x 取 pl.qtiles128（fmha_mxfp8_qkv.cu:1979），而 fmha_tc_kernel（PVMODE=0）按 p.qph 分行、grid.x 取 pl.qtiles（cu:1950），于是 GM pass 只覆盖前 qtiles128*qph ≈ Sq/2 行；其余行的 bm——连首/末 split 应写的 -inf 头尾在内——从未被写入，scan 会读到未初始化的 workspace。qph = 64/G 与 gm_grid 的定义都不依赖 D，故该缺陷在 D=256 链上以完全相同的方式成立。
- 条件与依据：只在“非 arch-specific 构建（tcg_available 假）+ 需要 split 的几何（nsplit>1 且 workspace 足够）”下发生，head_dim=128 与 256 两条链同样受影响；默认认证构建（tcgen05）不受影响，已选 mma_sync 的 fused 实例也不受影响（其 grid 用 pl.qtiles、行列一致）。本组合只记录事实与缺陷、不交付完整 schema；缺陷已在 P2 的既有 issue 记录中定位。

### head_dim=256 与 split-KV 组合（组合）

- 基线：[split_kv](split_kv.yaml) 的四内核链（Work_schedule Flow.Launch 与 Step.GMAX/SPLIT，Tile_pipeline Step.GMAX/SPLIT）；内核族差额同“head_dim=256 fused 形式（局部）”条目；Contract 见 [root](root.yaml)。

### 融合 scan、PSK 与 wide combine 组合（组合）

- 基线：[split_kv](split_kv.yaml) 的四内核链，组合上文的“融合 scan 变体”“填充跳过行序 PSK”“combine narrow 与 wide 形态”三个条目；Contract 见 [root](root.yaml)。
- 差异与联动：没有新对象或新联动——ncu shape 2 即三轴同时成立（GM <128,1,1,1,0,1,0,0,0>、split <128,2,1,1,0,1,0,0,1>、wide combine <128,0,1>），shape 3 与 narrow FWGT combine 组合同样成立。psk 由 Sq、H、KH、qtiles128 决定（launch key 已覆盖的字段，两个相同 key 不会对它分歧），scan_fused 由 plan 拥有（workspace、launch 派发与 combine 形态看到同一个真值），fwgt 随 fuse_scan 传入 combine——三轴接口相容，不引入新的整体组织。
