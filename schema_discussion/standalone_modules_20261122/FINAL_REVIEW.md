## 接受的主要删除

1. 保留四个能力目录，接受删除根共享 runtime、公开 Python API、历史 CLI/Request 协议与 AKA 适配壳。
   三业务模块各有自己的小 runner/coder/SDK 适配，Workflow 用同一公开 CLI 即可，不需要先造接口包。
2. 接受 Workflow 只有一个业务脚本，删除额外 runner、独立 driver、backend 注册与逐阶段配置矩阵。
   state/result 和固定子目录足以支持有限循环，不需要调度数据库或事件总线。
3. 接受删除 qualification、owner 账户、promotion、best 排名、跨仓预算与发布对象。
   普通调用整数、单运行锁、固定 request/key/job 与不可变文件已能覆盖本次必要恢复。
4. 接受删除独立 Reviewer、写作效果验收、通用 Require 证明器与六类审查表。
   同一写作者处理 Template 诊断；coder 负责落实说明，实际测试与已知缺口必须如实报告。
5. 接受删除多份展开/seed/反馈镜像和 calls/selection/change 等重复日志。
   原稿、输入、每次候选、一次事实反馈分别有清楚位置，不需要围绕它们再复制一圈协议对象。
6. 接受删除隐藏基础设施终态自动重投、泛化上传恢复平台与跨运行写作会话引擎。
   保留原进程/原 job 定位，防止重复收费或把未知远端状态误当失败后另开候选。
7. 接受删除强制 helper、各模块重复 GPU 链、子集成绩累积、额外 ABBA/基线资格与环境矩阵。
   一个完整示例、每候选全部 cases、少量行为回归和一条共同真实主链足够；自然依赖仍须整包交付。
8. 接受删除强制新 Python、旧 SDK 精确 pin、整套旧环境/捕获归档与重复全面调查。
   采用现有解释器、正式 SDK、既有 Qwen/L20D/Agate，具体缺项仍要实际排障解决。

## 必要纠正与补回

1. **有限收尾不能被最后一次可选建议永久拖成 incomplete。**
   最终选择明确区分可用交付与可选未实施提案：末版纯优化 revise 可 complete+limit，仍保留真实 revise 和提案位置，不伪造 keep。
   complete 必须同时有本次已验证 kernel 与一次读取本次全案例正确性/计时反馈的有效 Optimize 决定；外部历史反馈或单纯设计诊断不能替代。
   真失败、必需缺陷、未结清运行或尚未形成有效本次决定仍不能 complete；有限流程不承诺无限改进或速度目标必达。
2. **补一个可派发的 Optimize.required_fix 布尔，取代让 Workflow 猜 notes。**
   repair 恒 true、keep 恒 false；revise 区分必需纠错与性能假设，诊断说明对应材料/源码。
   这是表达已有业务区别的最小字段，不增加审阅角色、资格或第二层动作协议。
3. **后验缺陷必须撤下广告中的可用配对。**
   required_fix/design_gap 出现时保守清空 last_usable，保留原不可变文件与原因，重新完整验证后才建立新配对。
   不恢复历史排名或自动挑旧版本；不让旧成功抵消最新真实失败，也不把可变 result 当已冻结产物。
4. **第三起点 keep 仍须本次 Implement，且留一次 Optimize 调用读取新反馈。**
   外部起点首次 Optimize 最多用同版 1 次，余下 1 次用于本次反馈；外部决定本身不算本次闭环。
   repair 首次可创建唯一 Implement，随后只能续原目录并累计次数；无 kernel 的真实 design_gap 可交 Optimize。
5. **关闭 CLI settings/hooks 必须保留当前 Qwen 连接。**
   现有 Extract 命令确实禁 settings，但另行从配置 env 恢复连接；只抄命令会漏掉关键半边。
   最终计划保持原登录/配置目录，子进程继承或补读 ANTHROPIC/代理/证书字段；不记录认证、不复制到产物、不向模型暴露。
   默认明确为 claude/qwen3.8-max[1m]/max，用户不必每次 --model；不导入 Extract runtime。
6. **补回可以直接落实的只读命令、DOC 路径、Template API 和 SDK 形态。**
   模型有 Read/Glob/Grep，真实完整来源、DOC1–6 与源码可读，host 接完整文件并落盘；不沿用旧 no-tools 论文式写作。
   Schema 原稿保留，normalize 后严格重读；Optimize 前后 Contract 解析值不漂移，写作不加效果验收门。
   SDK 基准 API、单文件/完整归档、原 key/job 与全部 cases 判定已内联，不依赖之后删除的调研稿。
7. **删除大框架不等于删除独立性和不可重放边界。**
   继续保留有限次数的调用前落盘、未知 job 不重投、已完成不重跑、同一修复反馈只消费一次。
   写作中断先定位原进程/稿件；真正未开始的动作才可启动，不从半份响应推进或另开目录洗次数。
8. **执行计划吸收清理与依赖的准确事实。**
