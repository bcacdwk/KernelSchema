# Extract 输出配置与时间限制盘点

2026-11-18，依据当前工作树代码及既有试跑记录。此次只新增审计文档，没有改代码或运行配置，也没有恢复提取。

## 1. 输出配置究竟做什么

`--max-output-tokens` 覆盖 Claude CLI **每个原生响应**的输出上限；不是整个 CLI 调用、阶段或算子的累计 token 配额。Extract 没有累计 token 用完就停止的判断，用量统计独立保留。

产品默认是 `None`。不传参数，CLI 使用自身默认值；此前同版本、同模型的本地捕获值为 **32000**。试跑显式传 **65536**，是为了扩大单响应连续生成空间。CLI 曾在原生输出触顶后自行续写，那两次调用最终停止的原因是时间超时。

因此，这一项应归为**可选调优能力**，不能称为已证明的缺陷修复，也没有证据证明提高它能加速。只想保留统计、沿用 CLI 默认时，不传该参数即可；不传不等于原生输出无限。此前短请求成功也未验证服务端允许实际生成满 65536 tokens。

依据：[backends.py](../../schema_extract/tools/backends.py#L154)、[LIVE04.md](LIVE04.md)、[LIVE05.md](LIVE05.md)。

## 2. 会限制提取进度的主时间规则

下面均为当前源码默认，数值以秒计。O、S、C 分别表示整算子、阶段和单调用配置。

| 规则 | 当前默认或公式 | 配置与实际作用 |
| --- | --- | --- |
| 整算子 | **7200 / 2小时** | `--operator-seconds`；从 run 注册起算，包含冻结准备、排队、暂停和恢复等待。决定派发/采纳余额，没有独立常驻的精确到点 kill 闸门 |
| 阶段 / P5节点 | **3600 / 1小时** | `--stage-seconds`；从该范围首次准备调用起算。P5各节点分别计时，共享整算子截止；开始后的等待仍扣时 |
| 普通 worker/reviewer 单调用 | 名义 **1800 / 30分钟** | `--call-seconds`；实际还被剩余时间和下面的预留压缩。两种角色共用同一配置。AgentCLI执行硬超时，准备和清理使实际返回时间不等于纯模型时间 |
| 裁决 / 签收单调用 | `A=min(C,S/4,O/12)`，默认各 **600 / 10分钟** | 没有独立CLI参数；派发时另为尚未执行的后续角色预留时间 |
| worker前的独审预留 | `R=min(C,max(0,(min(S,O)-2A)/2))`，默认 **1200 / 20分钟** | 没有独立CLI参数；R从worker额度扣除，不是reviewer的固定上限 |
| 首worker实际额度 | 默认最多 **1200 / 20分钟** | `min(C,剩余-未用裁决预留-未用签收预留-R)`；不能只看名义30分钟 |
| 完成回执的机器处理 | 最多 **120 / 2分钟**，还受剩余与预留限制 | 硬编码。同步检查不会被立即打断；完成后若超额，`complete/approve`即使检查通过也不能被本轮采纳，稿件保留 |
| 裁决候选准备 | 另一个最多 **120 / 2分钟**的窗口 | 同一额度公式；在候选边界判断是否停止继续准备，单个同步检查可超时返回 |
| 孤儿调用接管 | 整算子截止、范围截止、`attempt.created_at+实际timeout`任一到期 | 原Runner丢失后恢复接管仍在途的调用；没有另设新的工作额度 |
| 独立 `review-eval` | 默认 **240 / 4分钟**，允许 **1..1800** | 自己的 `--call-seconds`；每case一次，不使用提取的整算子/阶段预留体系 |

主参数均须正数，目前没有 unlimited 选项。除 `review-eval` 的1800秒上界外，O/S/C没有代码规定的数值上界。

依据：[runner.py:43](../../schema_extract/tools/runner.py#L43)、[budget.py](../../schema_extract/tools/budget.py)、[store.py:856](../../schema_extract/tools/store.py#L856)、[review_eval.py:120](../../schema_extract/tools/review_eval.py#L120)。起算、调用及检查边界的完整位置见 [流程审计](TIME_LIMITS_FLOW_AUDIT.md)。

### 实际额度为什么和参数不一样

| 配置 | 整算子 | 阶段 | 名义单调用 | 裁决/签收各预留 | 独审预留 | 首worker最多 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 当前产品默认 | 2小时 | 1小时 | 30分钟 | 10分钟 | 20分钟 | **20分钟** |
| 试跑r01 | 6小时 | 1小时 | 30分钟 | 15分钟 | 15分钟 | **15分钟** |
| 试跑r02 | 24小时 | 8小时 | 90分钟 | 90分钟 | 90分钟 | 90分钟 |
| 试跑后期 | 24小时 | 10小时 | 120分钟 | 120分钟 | 120分钟 | 120分钟 |

这组公式存在反直觉行为：仅把整算子从2小时加到6小时，首worker反而从20分钟减到15分钟。只提高单调用上限，也不能解除阶段和预留的压缩。

`resume --add-seconds N` 只把整算子及**已启动**范围的截止延至 `max(now,旧截止)+N`。它不改变C/A/R，也不增加未来阶段的初始S；暂停、维护、重开不会自动停表或重置额度。

另有32次调用、5次实质退修、2次自动修复/执行失败重试、各一次裁决/签收等**次数规则**。它们不属于时间上限，但时间失败可能消耗一次性裁决/签收机会。完整边界见流程审计第2、3节。

## 3. 底层超时与回收等待

| 位置 / 用途 | 当前值 | 到期影响 |
| --- | --- | --- |
| 每次CLI版本查询 | 最多 **15秒**，且不超过本次timeout | 模型启动前失败，记CLI错误；不代表生成只能持续15秒 |
| `ps`进程表查询 | 每次 **10秒** | 活跃AgentCLI中的扫描异常会进入清理，尝试终止本次模型；monitor只读观察中的同类错误则记录unknown。前者是此次源码发现的隐性中止风险 |
| Template局部Git元数据检查 | 每命令 **10秒** | 超时产生检查错误，可阻断验收/发布；仅对有本地仓库上下文的相关locator检查触发，不联网 |
| 模型及后代TERM/KILL回收 | 每个信号阶段各 **1秒**宽限，观察间隔 **0.05秒** | 发生在取消/超时/清理时；未确认退出则保留未结清状态。其间`ps`等操作可使总回收时间更长 |
| 等待调用wrapper退出 | **3秒** | 超时记终止未确认 |
| stdout/stderr排空 | 每线程join **3秒** | 任一未结束会阻止宣称已完整结清 |
| Runner退出时join调用线程 | 每线程 **3秒** | 收尾等待，不是正常工作时限 |
| `codex queue`提醒投递 | **30秒** | 只影响提醒；超时记投递不确定，并清理投递进程 |
| 提醒投递进程回收 | TERM后 **1秒**，必要时KILL后 **1秒** | 只回收该投递进程组 |
| 显式停止monitor时钟 | TERM **2秒**、KILL **1秒**，观察间隔 **0.05秒** | 只停时钟，不取消提取 |
| Codex用量SQLite锁等待 | **0.2秒** | 争用时走其他用量观察路径；不是模型工作时限 |

以上无公共Extract CLI独立配置。出处集中在 [agent.py](../../schema_extract/tools/agent.py)、[processes.py](../../schema_extract/tools/processes.py)、[wakeup.py](../../schema_extract/tools/wakeup.py)、[observation.py](../../schema_extract/tools/observation.py)、[Template values.py](../../schema_template/tools/rules/values.py#L491)。逐项行号和触发条件见 [运行时审计](TIME_LIMITS_RUNTIME_AUDIT.md)。

`ps`风险和120秒检查拒收是本轮静态审计发现；没有证据表明上次试跑实际命中过它们，不能据此解释13小时或未明的Runner消失。

## 4. 仅观察、提醒和退避的时间值

| 用途 | 当前值 | 性质 |
| --- | --- | --- |
| AgentCLI主循环 / 后代扫描 | **0.05秒 / 0.5秒** | 检查取消、退出、截止及归属的频率 |
| 失败后重试退避 | **5、10、20、40、60秒封顶** | 延后合法重试；次数门可能更早停止，主预算墙钟照走 |
| Runner孤儿观察 / 事件等待 / 空闲退避 | **1秒 / 0.1秒 / 0.01..0.25秒** | 调度与响应粒度 |
| monitor无进展提示 | `min(300,call_seconds)`，通常 **5分钟** | 需无在途/未结调用等条件；不是模型沉默5分钟就停止 |
| 后台观察 | 每轮完成或失败后 **30秒** | 轮转观察运行状态 |
| Supervisor提醒 | 初始scan立即；其后三次各 **5分钟**，再往后 **30分钟** | 从前次scan完成计时，不暂停Runner推进 |
| 提醒投递失败/不确定补送 | **120秒** | 同一提醒最多3次尝试 |
| 已入队未ack补送 / 无ack提示 / ack后scan未完成提示 | **1800秒** | 各自按对应投递/ack时间计算；不是提取时限 |
| clock心跳tick / 陈旧提示 | tick最多 **15秒**、最短 **0.05秒**；陈旧阈值 **75秒** | 更新或报告监督状态 |
| 提醒投递communicate轮询 | **0.01..0.25秒** | 响应投递截止和停止信号 |

这些条件本身不杀模型，也不追加提取额度。monitor的自动恢复另需明确授权及符合条件的已结清失败，不能仅凭超期或静默触发。完整条件见运行时审计C节。

## 5. 不应误认为已经存在的时间上限

来源Git、私有Git快照、同步Python检查/规范化/发布、`supervisor.lock`阻塞获取，没有统一硬超时。Runner/session/clock锁采取立即尝试，不使用按年龄过期的TTL。模型工具check-helper没有自己的Extract总超时，仍受外层CLI调用及原生工具规则影响。

Template PNG绘图的Graphviz有60秒超时，但Extract常规阶段、发布和check-helper不调用该渲染路径。历史诊断的25/180秒探针也不是产品配置。Claude/API内部网络、工具默认超时未在本次穷举，不能据仓库未配置就称其无限。

## 6. 建议共同确定的调整方向

1. **保留用量统计；单响应输出覆盖保持可选。** 不新增累计token停机条件，不把65536作为必须指定的数。
2. **减少主时间限制的层数。** 保留一个清楚可见的单调用超时；整算子/阶段优先改成统计或提醒，用户明确给总时限时再执行该约束。去掉提前预扣独审/裁决/签收时间的公式。
3. **检查结果决定采纳，取消120秒事后拒收。** 不因本地检查较慢而让模型重新写稿或重审；真正卡住的检查另按具体阻塞处理。
4. **进程观察失败与终止健康模型分开。** 处理`ps`10秒的异常路径；保留有明确回收用途的TERM/KILL、wait/join边界。执行失败是否消耗一次语义裁决机会，也应在调整超时恢复时一并澄清。

现有数据足以说明默认偏短：QSA一次P1写作加独审约74分钟，已超过阶段1小时；FA4 P3两次写作约206分钟，已超过整算子默认2小时。但没有完整成功样本支持精确的新默认值。先减少误停和重复劳动，再决定单调用时长，比把所有常数一起调大更直接；这也不能代替对Qwen/max自身耗时的评估。
