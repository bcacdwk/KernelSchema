# Extract 执行机制调整方案

2026-11-18。四位新的 xhigh 代理已完成两轮评估。本文件是综合建议，等待讨论后实施；本轮未改产品或配置，没有恢复提取。

## 确定的改动

| 方面 | 采用的方案 |
| --- | --- |
| Claude 输出 | backend 默认请求 **128000 tokens/原生响应**。删除逐次 `--max-output-tokens` 及 config/attempt/session/receipt 的重复额度字段；保留环境配置指纹、冻结源码和实际用量统计。不设累计 token 停止条件。 |
| 时间限制 | 删除 Extract 的调用、阶段、整算子、裁决/签收预留、检查120秒、补时和独立 review-eval 时间限制；删除实际执行链路中的短命令/退出 timeout。移除 `budget.py`，不换成大常数、软截止或其他名称的额度。 |
| 次数与验收 | 原有有限错误重试、退修/调用次数、独审、真实来源/权限、终止证明和发布要求继续工作。必要次数判断迁入已有流程代码，`--add-calls` 保留幂等授权；耗时与token只作为账目。 |
| 进程与日志 | 统一使用已有 Linux `/proc` 身份能力，删除 `ps` 及重复身份实现；stdout/stderr直接写现有日志文件，删除排空线程。版本探测可观察、可取消；不把命令 timeout 简单替换为阻塞控制面的无限 wait。 |
| 巡检 | 复用现有 clock、monitor、queue、ack、scan。保持心跳和提醒间隔；一次只有一份未结束的投递，投递等待不阻塞观察。删除 monitor 默认关闭的额外自动重启功能，由收到提醒的 supervisor 判断和调用现有恢复入口。Runner 正常有限重试保留。 |
| 控制 | `pause` 在正常调用边界停止；`cancel` 持久登记后直接终止已确认归属的任务进程，再非阻塞确认实际退出。取消请求与终止事实分别记录；未结清不重派同一范围。 |
| 已有修复 | 保留失效引用清理、配置登记前校验、worker规范化预览、JSON/代码材料区分、原生UUID及时登记、启动前错误结清、证据真实边界和精确报错。删除已无用途的输出参数/nullable身份配套分支及旧时间测试。 |
| 必修缺口 | 维护 worker 合法保存新稿后，回执格式错误导致恢复拿旧base比较，误报草稿漂移。允许沿该次已结清调用的 `result_checkpoint` 继续，复用现有来源和checkpoint核验；不采纳旧提案、不放开任意新稿。 |

范围是 Extract 执行及直接检查依赖，包括 Template 本地 Git 检查的 timeout。Template 独立 PNG/Graphviz 绘图不在提取路径，暂不扩大到该功能、GPU执行器或测试 harness。固定 schema 字段及 YAML 文本规范不变。旧试跑和讨论资料作为证据保留，活跃代码/文档只描述最终行为。

## 输出能力与 Atrex 的结论

本机 Claude Code 2.1.316 的离线协议捕获：不设置时请求32000；128000原样发送；131072、256000、262144均被CLI降至128000。当前路径把256K写进配置不会增加实际输出空间，不修改CLI或伪装模型来绕开它。

Atrex主路径也直接调用Claude CLI，但继承主机环境和settings、不固定同一模型；代码已有输出上限错误恢复，并有8小时调用、4小时Episode时间额度。它不能作为“原生没有限制或从不触顶”的证据。此次只读比较，不修改Atrex或用户全局配置。

128000是已证实可由本机CLI发送的请求值，服务端是否接受尚未验证。实施阶段建议只做一次要求固定短JSON的真实请求；它只能确认该请求配置被接受，不能证明填满128K或完整提取成功。服务拒绝时记录原生原因、按实际能力处理，不静默降级或新建自动探测框架。

## 巡检能力与取舍

`monitor start/status/stop/ack/scan`、`inspect`及对应提示均存在。上次只验证了后台启动和观察，首条提醒前已经终止，真实 queue→收到→ack→scan 尚未完成闭环。因此实施不能只改文案就宣称巡检可用。

周期巡检应查看阶段/角色、checkpoint、调用及进程归属、公开事件和日志增长、机器处理位置、未结状态与控制消费情况。运行久或日志静默只提示进一步查看；明确的取消和真实错误才触发相应处理。控制锁忙要如实返回未提交，不能假称取消已生效。

建议用户审阅两个行为取舍：

- **cancel立即强制终止，不再等TERM宽限。** 已落盘草稿和checkpoint保留，但会放弃最后刷盘的机会；希望当前调用自然完成时使用pause。这避免新增force命令及另一组等待额度。
- **删除monitor额外自动重启。** 后台只观察提醒，supervisor决定恢复；无需为少用的默认关闭能力增加后台恢复执行体。人工 `resume --scope` 和Runner正常错误重试继续保留。

若queue通道本身挂住，clock可以继续观察，但不能保证通过同一故障通道唤醒主线程。本方案不新增第二投递系统，不把任何“久未返回”阈值变回自动杀停规则。

## 实施：两轮、四位新的 xhigh 代理

| 轮次 | 分工 | 结果 |
| --- | --- | --- |
| 第一轮A | 调用、backend默认输出、进程身份、日志及实际检查依赖 | 无timeout的调用接口、可取消版本探测、真实终止确认；Codex可选后端继续可用 |
| 第一轮B | clock、queue、monitor、控制锁和取消交付 | 巡检不被投递卡住；删除额外自动重启；未完成投递不重发，控制结果准确 |
| 第二轮C | 主流程、状态、次数、统计和恢复 | 删除budget模块/时间字段/检查拒收；修复维护worker保稿恢复；完成与第一轮接口对齐 |
| 第二轮D | 正确性复核、外层CLI、prompt/MD及测试精简 | 保住已有真实修复，清理失效字段/注释/测试，验收完整集成；代码意见交对应文件owner修改 |

每轮每个文件只有一个owner，`store.py/cli.py`等跨轮明确接力；不为中间状态增加兼容层。具体文件表见 [精简实施分工](SIMPLIFICATION_IMPLEMENTATION_PLAN.md#6-四位新实施代理两轮明确文件所有权)。

验证以受影响的离线定向用例为主：虚拟长耗时仍正确采纳、显式取消及后代确认、投递在途不阻塞和不重发、维护worker新稿恢复、来源/JSON/preview/UUID必要回归。删纯时间公式和旧输出透传测试，不新增大测试体系。

不跑算子提取全流程。128000的短配置请求、以及一次不启动提取的真实提醒接管闭环可作为小范围在线验收；只有实际完成才报告通过，验证结束关闭临时监督。若未执行，明确保留这两项未验证状态，不以离线测试代替。
