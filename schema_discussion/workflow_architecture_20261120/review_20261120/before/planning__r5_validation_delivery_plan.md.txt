## 2. row_softmax_fp32_v1：可直接采用的验收规范

保留 R4 的四个合法 shape，不为测试平台增加非二幂或多 dtype 支持；以后扩域须发布新 Task 身份及资格记录。

| 项目 | 固定规范 |
| --- | --- |
| 入口 | kernel.py 暴露 class Model(torch.nn.Module)，Model() 无参数；forward(self, x, out) → out；支持以 x=、out= 调用 |
| 张量 | x/out 均 CUDA FP32、同设备、shape=(M,N)、stride=(N,1)、requires_grad=False；M∈{1,32}、N∈{128,1024}，任意合法 storage_offset |
| 输入域 | x 所有值有限且位于 [-20,20]；x/out 不共享 storage；输入值/shape 是数据，候选不能依赖测试编号、运行次序或预存结果 |
| 输出/副作用 | 返回对象必须 is out；全部 out 元素覆盖，入场 bits 可为任意 FP32；x 的字节、shape/stride/storage 身份不变；只有 out 允许写入 |
| 调用状态 | inference_mode、eager、单调用流；构造/编译与预热后可重复调用，合法 x 内容变化仍须重算；首发不支持 CUDA Graph 或多流并发 |
| 域外行为 | Task 准备/adapter 明确拒绝不支持的 shape/dtype/别名；候选不承担未声明域的数值承诺；不能用域外失败冒充域内负例 |
| Golden | 先保存 x 的原始 FP32 字节，提升 FP64 后按下式计算；不能从候选调用后可能被改过的 x 重算 reference |
| 比较基线 | 独立 baseline.py：forward 中 out.copy_(torch.softmax(x, dim=-1))，return out；FP32、同 ABI；不是 FP64 golden |

在 CPU FP64 中计算：令 z=FP64(x_before)，m_i=max_j z_ij，g_ij=exp(z_ij-m_i)/Σ_k exp(z_ik-m_i)。
对返回对象和调用后的 out 分别核对 shape、dtype、device、有限性；对每个元素要求：
abs(FP64(actual_ij)-g_ij) ≤ 2e-6 + 2e-5·abs(g_ij)。所有元素均须通过；相对项的基准是 g，不是 actual。
NaN/Inf 先失败，不能借 NaN 比较、均方误差、平均误差或 native 默认 allclose 绕过逐元素判据。
对象身份/写满 out/x 不变/guard 不变为独立硬项；数值过关不能覆盖它们。有限样本通过不是整个连续输入域的证明。

inputs.json 固定 4 shapes × 下列 9 个输入实例，共 36 个 case_id；每个输入各以 NaN 与 -123.0 初始化 out，合计 72 次正确性调用。
随机数使用所锁 torch 的 CPU Generator，分别 manual_seed(17)、manual_seed(23)，FP32 的 -20+40*rand；再复制到 GPU，记录实际输入字节摘要。

| 家族 | 每 shape 的实例 | 能区分的典型错误 |
| --- | --- | --- |
| 均匀随机 | seed=17、23，共 2 个 | 写错公式、跨行污染、只适配一个输入 |
| 常值 | 全 -20、全 0、全 +20，共 3 个 | 未除分母、按整个矩阵归一化；M=32 必测 |
| 两端交替 | x_ij=20 当 (i+j)%2=0，否则 -20 | 输入极值、错误索引、数值路径变化 |
| 每行单峰 | 峰值列 (N-1-17*i)%N 为 +20，其余 -20 | 漏末列、广播错误、返回均匀/全零 |
| 近等值 | x_ij=(-1)^i*19+((j%5)-2)*2^-12 | 低精度中间值、不同 row 混用统计量 |
| 行间置换 ramp | x_ij=-20+40*(((j*(2*i+1)+i)%N)/(N-1))，按 FP32 生成 | 只算第一行、行/列坐标错位、整批复制 |

out 放入带前后 canary 的独立 storage 连续 view；x 也保留入场字节副本；同步后检查 canary 与 x 原始字节。
这只提供有限越界/副作用证据，不宣称证明全部设备内存安全；候选不获 evaluator 文件写权限。
固定同一 Model 连续执行两个不同合法输入：宿主在两调用间覆写同一 x storage 为下一 case，重建 before 副本并毒化复用的 out；不另扩输入全集。

完整调用计时采用固定 timing.py：每 shape 用 seed=17 输入、独立预分配 out；候选/基线都通过 model.forward(x=x,out=out) 调用。
构造、首次编译、20 次预热单列，不计稳态；每批先同步，perf_counter_ns 开始，循环 100 次完整 forward，再设备同步，结束计时并除以 100。
每 shape 10 对批次，AB/BA 交替；原始批次顺序和纳秒值全部保留，报告中位数、IQR、最小/最大值和实际样本数。
该值是含 Python 提交与批末同步的摊销完整调用时间；不是单调用孤立延迟，也不是 NCU kernel-sum/CUDA event 纯设备时间。
输入生成/毒化/正确性比较在计时外；forward 内的分配、必要 copy、全部 kernel、必要同步都在计时内；两方条件一致。
目标按 4 shapes 等权几何均值 exp(mean(log(t_baseline/t_candidate))) ≥ 1；它是软目标，较慢但全部验收完成仍可 completed+unmet。
只有样本齐全、环境/代码/计时身份明确才给目标判定；噪声和缺样如实报告，不把“比值略大于 1”写成已证明提速。

| 最小反例 | 必须失败的项 | 不可接受的解释 |
| --- | --- | --- |
| 正确结果写在新张量返回，out 未写 | 对象身份、毒化 out、写满检查 | “return 数值正确，所以通过” |
| out 正确写满但 return out.clone() | return is out | 只比较 storage 内容而放过 ABI |
| 只写 out[0] 或漏最后一列 | M=32/单峰/NaN poison | 容差过松或只抽样几个元素 |
| 原位改 x 后用被改 x 算 golden | x 字节；golden 固定于调用前 | 把破坏输入后的自洽当正确 |
| 以 FP16 做归约或改比较器 | 固定 comparator + R0 fidelity | 改 rtol 让当前候选过关 |
| 删除 max-subtract 的 exp/sum | R0 fidelity；数值可以通过 | [-20,20] 内未必溢出，不能伪造“必然数值失败”的证据 |

## 3. R0、参考材料及三项真实入口

手审 R0 服务固定实现工程；design 输出记为 Rd，不要求与手审 R0 相同，也不把 R0 答案偷偷放进 design 输入。

| R0 必须表达并受 fidelity 约束 | 仍留给 coder 的实现自由度 |
| --- | --- |
| max-subtract → FP32 exp → FP32 行内 sum → FP32 除法/写出；无 FP16/BF16 中间量 | FP32 归约树、寄存器命名、编译器调度；近似 exp 仅在 Task 容差及已声明语义内 |
| 每个 Triton program/CTA 拥有一整行，grid=(M,)，每行宽 N；一轮读取/归约/写回 | num_warps∈{4,8}、未改变数值/所有权的编译参数；最终配置进入源码和证据 |
| x 行数据与中间指数在 program 内使用；无显式全局中间张量、无跨 CTA 通信或原子归约 | 编译器寄存器分配/溢出是实现事实，应报告，不假称静态表可证明无 spill |
| 每次 forward 一个自有 Triton kernel；不调用参考、torch.softmax 或外部实现替代计算 | host 封装、合法 shape 分支和 launch 写法；不能借 constructor 预计算输出 |
| out 全部覆盖、x 只读；无异步跨 program 生命周期义务 | 首发二幂 N 无额外尾 tile 义务；不因此声称任意 N 可用 |

产物包括 B/F/D 请求模板、预算映射、资料/seed 身份、运行顺序、失败枚举、原始记录到统计表的列映射；不等动态功能完成即可准备。
R0 默认取 KS-09 design 的首份通过写作 gate 的发布件并固定；选择依据是合法性，不按实现速度挑赢家；若换成手工 R0，记录 manual 来源和未计量成本。
EXP-01 通过条件：三组差异可逐项核对；消费来源/公共判据/成本无缺失；只产生配置与 CPU dry-run 身份记录，不生成效果结论。

EXP-02（受限 pilot/分析包）：运行前需 MIG-04 新捕获、AKA-P1、AKA-10 动态资格、同一 evaluator/profile 和 EXP-01；这些是未来条件，本轮不 launch。
第一批只选 row-softmax，一个 Task × B/F/D × 3 个独立重复，共 9 个 run；同 repeat 配对调用条件，组顺序按 BFD、FDB、DBF 轮换。
输入种子按 Task 固定；模型若不支持确定性 seed，就记录新会话/repeat id 与服务事实，不谎称随机性可复现。
建议先写入 policy 的试点上限：每 run 共 8 次模型调用、6 个逻辑 evaluator jobs、3 个 native episode、3600 秒 active wall；D 的一次 optimize 含在 8 次内。
这些数字是起始执行上限而非完成率/统计功效承诺；实施资格核实 bootstrap 成本后、任何样本启动前冻结最终数值，不能中途只加某组预算。
调用内 token 若无硬限保证，明确软边界；预算耗尽保留 partial，unknown 执行先结算，不能以超时为由补一个未登记 run。
第一批保留全部九个启动或未准入记录；资格失败与已启动后的算法/代码失败分列，取消/故障原因照实记录。
仅在三组身份/成本/评价一致且失败能归类后，才考虑第二批 F1 同样 9 run；先过 CuTe/源树/复杂 fidelity gate，不把换题失败隐藏掉。
首批目标是检验测量、完成边界、成本差额及失败类型；3 次重复没有足够方差信息支持任何预定统计功效或普遍提升结论。

主表逐 Task/条件列 Task 正确完成率、F/D fidelity 合格率、首次正确/首次 qualified 的耗时与累计成本、最终状态、预算内目标达成、终态计时及离散程度。
对失败/unknown 的耗时记右删失或未达，性能记 null+原因；同时展示所有样本与仅合格样本的条件性能，不能只报成功者几何均值。
保留 latest、qualified、G 的源码身份/选择理由，planner 的 keep/revise/阻碍依据、R 次数、episode 次数、实际调用与执行次数。
failure.json 至少区分材料/不支持、安装/服务、编译、数值、ABI/副作用、fidelity fail/unknown、预算/pause、unknown job、身份/恢复失败。
若问题是 evaluator 或环境差异，先修资格再启动新的预登记批次；保留原失败和新版本，不在原样本目录补写成功。

初始化成本单列 C_init=实际 design/extract+其审阅/必要准备；使用成本 C_use 含本次执行、planner/reviewer、失败/恢复。
同时报告已有 Schema 的边际 C_use、首次端到端 C_init+C_use、声明复用次数 m 的 C_init/m+C_use；m 用实际部署情景，不凭空设无限摊销。
上述式子对各可相加的成本维度分别计算，美元、token 和时间不混加；初始提取历史用量不可得时明确 unknown。
共享 R0 在实验总账中初始化只发生一次，F/D 的单次部署对比按同一 m 报告；人工投入不能填成零 token 等价零成本。

| extract 消费模式 | 允许的原码信息 | 单独报告的结论 |
| --- | --- | --- |
| 原码复验 | 原字节不变，固定 verify_only | 旧代码的当前资格；无新生成成功/设计传递结论 |
| 原码 seed 续改 | 原码为显式 seed，继续代价全计 | 适配/优化原实现的产品能力；不是纯 Schema 重建 |
| 纯 Schema 重建 | 同骨架；禁被提取优化源码/annotated/旧会话/二进制进入本次资料和工具 | 在已声明显式信息边界内的重建；不宣称模型从未预训练见过公开实现 |

普通文字 P 或原码 C 仅在特定异常需要诊断时各追加一个选定 Task；先审查 P 是否保留相同设计决定、C 的读取/seed 方式是否一致。
需要声称结构化表达优于普通计划才加 P，需要声称压缩交付优于直接原码才加 C；不做 B/F/D/P/C×全模式×全任务的笛卡尔积。
第二阶段扩任务/增加重复以实际失败率、计时噪声与成本为依据另定；本计划不承诺具体提速、样本量功效或现在启动正式研究。
