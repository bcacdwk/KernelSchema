# 语言精简三项建议：复核结论

**当前正式 docs 不需要再改：新增字段 0、删除字段 0、必需规则增量 0。** 六位新的 max 代理分三轮独立复核后，确认主要能力已由近期规则修改覆盖。需要收窄的是原建议表的删除口径，以及旧实例中未落实的表达。

范围是原表最后四项中的外部等待、组内分工、跨调用状态；分支复用、继承系统和 root/dispatch 不参与本轮判断。原表和正式文件未改，下面给出建议替文。

## 原表三行应怎样修改

| 项目 | 判断 | 建议替文 |
| --- | --- | --- |
| 外部等待不加新模块 | **方向保留，规则已覆盖。** “删除 host 操作过程”过宽。 | 用现有调用边界、flow 与相关 strategy，保留外部条件及实际启动、消费或必要 host 接续位置。删 API 步骤和重复解释，保留会改变观察值、版本、初始化、等待范围或重叠的事实。 |
| 组内分工不加新字段 | **方向保留，规则已覆盖。** “普通原语内部协作不记录”过宽。 | 用现有 member、角色 describe 与逐 noun 契约表达必要分工。需要独立引用的推进、发布或复用边界才拆 role/动作，并用已有等待关系连接；内部指令可省，设计依赖的参与范围、局部顺序和退休保证保留。 |
| 跨调用状态不加新模块 | **方向保留，撤回“只写次序＋写集”及“一律删容量”。** | 算法状态沿用输入输出，内部状态沿用 math/symbol、refill 和动作定义。共享 scratch 只补缺少的身份、初态、所读内容及复用前提。分配、替换和缓存过程可删；实际访问、主要占用或有据成本依赖的事实短保留。 |

这些是对已有规则的准确用法，不是三个待新增的规范模块。两组代理最初提出过补充说明，逐条对照现行条文后确认属于重复提示，已经撤回必需修改建议。

## 为什么这些事实不能一并删除

| 例子 | 设计上不能丢的区别 | 现有位置 |
| --- | --- | --- |
| MLA Geo、Sparse 输出回接 | 上传完成后才启动整核；两路输出汇合不等于把两路串行，也不等于让 CPU 阻塞 | DOC4 调用边界、相关 `schedule.strategy`、既有 flow；具体机制由 realization 绑定 |
| GDN 两 chunk 求逆 | 每个 warp 自己先处理第一块再处理第二块，不能改成全组做完第一块再开始第二块 | noun.describe；没有被外部独立使用的内部层次可留在一个动作内 |
| QSA 条件 PV 等待 | 部分 warp 需要等待，不代表整组都应提前等待；已命名的跨角色前驱不能只藏在文字里 | 现有 role、if、waiting；属于旧实例需要落实的关系 |
| FA4 decode 空 split | 未重写的 Opartial 仍被读取，需保留有限旧值；首次清零、每次清零和跳过读取是不同设计 | 既有输入含义、math、retention 和动作契约 |
| MoE、QSA、MLA 的私有状态 | MoE 首次零后由末次使用者自清；QSA ticket/base 持续推进；MLA queue 在末次 pop 归零 | math/symbol、refill、相关策略；不能统一改成“每调用重置” |
| 容量与预留 | 实际可读范围和必要 ABI 容量不能删；代码中未访问的预留量不自动是设计必需量 | 已有 shape/范围与必要实现绑定；仅在主要预算或成本有据时保留额外占用 |

其中三种 member 的区别已经写在现行规范里：`mapping.member` 是 worker 单元的数学分摊，`role.info.member` 选择执行成员，事件的 `Role[member]` 选择 worker 成员实例。需要修正原表的混称，不必再往 docs 复制一遍定义。

## 哪些内容可以删短

- **外部等待的机制叙述**：MLA 上传等待的子句可由 146 缩至 90 字符，保留整表、设备等待和整核启动位置，省掉事件命名与 record/wait 过程。见[外部等待删减报告](reports/02_external_deletion.md)。
- **重复原语展开与元解释**：FMHA 的一条动作契约从 619 缩至 450 字符，仍保留参与范围、写完成和 CTA 发布；GDN 后缀可删一段已被相邻事实覆盖的解释，1300 缩至 1211。见[组内分工反例报告](reports/04_group_counterexamples.md)。
- **无独立设计影响的缓存管理**：GDN 的 grow-only 管理细节可在容量已满足、共享和寿命不变的范围内省略；MoE 已由 shape/dtype 给出的元素数不再在策略里复述。见[状态删减报告](reports/06_state_deletion.md)。

短写不是一律减字。GDN 求逆原句为消除局部先后歧义需要增加一句；这比无实际使用者的一批新 role 和事件更轻。上述字符数只是被核查的局部候选，不是整份算子已迁移后的净收益或全仓可压缩比例。

## 由这三项进一步确认的问题

1. **先处理事实归属。** 已有值和状态在数学区定义，领取协议在 refill，调用前提在策略，动作保证在 noun.describe，已命名前驱在依赖结构。把长文搬到另一个自由字段不算解决问题。
2. **容量按作用分层。** 实际访问与必要绑定约束、主要资源代价、未证关键的额外预留应分别判断。GDN 未用 Q/K 预留与 QSA 的精确额外余量未被本轮判为一律必留。
3. **来源缺陷单独保留。** 缺读退休保证、旧 host writer 与新 reset 竞争、下一次侧流上传缺少先前读者完成顺序，不能靠新增字段或省掉文字变成安全设计。
4. **不把人读契约冒称完整机器模型。** 外部事件及跨请求全局存储关系仍缺少通用的结构化引用图；本轮没有证据要求它成为必备模块。现有短契约足以区分已查案例的重要设计。

本轮没有发现必须为这三项另起模块的遗漏。确认的主要待办是旧实例的消歧、必要边归位、来源限制分流和有据删短；不是继续增加语法义务。
