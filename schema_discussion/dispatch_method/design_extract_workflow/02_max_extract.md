# 第一轮 Extract 全链路评审

2026-11-15。独立阅读本轮 [BRIEF](BRIEF.md)、`EXTRACT_SCHEMA.md`、P2–P6、`REVIEW.md`，并核对 common、执行器对齐说明及指定历史材料；简读 `DESIGN_SCHEMA.md` 区分普通设计任务。本记录只提出方法文案建议，没有修改正式规范、YAML、执行器或检查脚本，没有真实提取、运行 GPU 或批准任何阶段。

**结论：P2 的实质要求已经相当完整，主要缺口是它与后续阶段的职责没有彻底收束。** 当前 P2 已要求追踪主要计算、输出形成、分配和协作，解决足以动摇选择的疑点，选择真实 root、少量完整代表，并区分轻量记录、未展开独立方案和未研究事项。应把这项选择明确交给后续写作采用，使 P3 写 root，P4 落实目录与写作依赖，P5 写其余代表。没有必要再为 P2 增加全路由矩阵、固定调查表或新的批准层级。

后续 reviewer 仍应独立读完本阶段有效全文、实际引用和使用上下文，核对源码及选择依据。减少的工作是每一阶段重新组织候选搜索、重新比较整个集合，不是减少独立理解和有据纠错。当前全文不支持既有判断时，不能靠 P2 批准放行；但命名、正文展开、局部引用和完整身份判断应分别处理。

需要主代理审定的实质边界是：**P2 负责机制识别及代表取舍，P4 负责把该选择变成可执行的写作安排。** 建议涉及取舍依据改变的增删/替换先修 P2 的相关判断，再由 P4 落实；仅文件登记、实际依赖和写作安排改变，由 P4 处理。不能一边宣称 P2 已完成选型，一边让 P4 常规逐份重新决定完整身份。

**P2 应研究到什么程度。** 建议主要调整现有第 1–6 步的组织顺序：从固定入口辨认本次实现范围和主要入口族，先沿一条真实路径形成可比较的 root 主线，再用其他有区分性的路径核对差异与取舍。此处形成的是有源码依据的具体主线，不是提前完成 P3 的全部字段。root 可以在调查中因明确事实调整；无需成为所有设计的祖先，也无需覆盖整个 Contract。

有意义的比较围绕当前需要作出的判断展开。对一个候选，读到能够解释它采用的主要计算、关键物化、输出形成、工作分配和协作方式，以及它相对最相关代表新增什么。能用已有值或工作接口说明差额时，再确认边界外的主体继续成立；需要重新解释主要组织时，承认它是独立方案，再决定本次是否值得完整保留。相互独立的轴无需展开所有配对；已有线索涉及接口或数值耦合时，应读清该关系。

例如，[nvfp4_moe.cu](../../../kernel_wiki/aka-cuda-operators-20261030/operators/moe/nvfp4_fused_moe/candidate/nvfp4_moe.cu) 第 7780–7817 行实际调用 cfg98/99 的两种 split-K 实例；第 9245–9272 行的预 gather 列表包含 cfg98 而不含 cfg99。P2 可以据此识别 split-K 与输入搬运并非同一个决定，选取一个真实混合实例并保存另一差异，不能只因目录标题是 split 就把 gather4 当作所有 split 的必备机制。这里核清两者关系已经有价值，不必先写齐两个实例的全部动作。

同一源码第 3948–3982 行显示 REDF 先将累加值舍入为 BF16，再乘权重并以 FP32 原子汇入 Acc32；第 9172–9191、9330–9338 行显示旁流清零、FC2 前 join 和后继 convert。若将它归为普通 rout 写回的参数，问题在于遗漏了输出形成与依赖变化。P2 应完成这项识别，随后决定代表取舍；不要求把每个 FC1 与 REDF 的配对都写成完整 YAML。

相反，源码第 7224–7259 行的 cfg23 对 FC1、FC2 指向不同实现，flat 实际入口又区分 `I == 256` 的 NK1 与一般实例。第 5822–5906 行能定位 flat 的 item 数、步进和跨 item 流线索。这足以提醒调查者不能只读族名或把所有 flat 当成同一特化；**本轮没有完整比较 flat 与单体主循环的所有关系，不据这些片段重新判定它必须完整保留或必须降级。** 当前 [common](../../../schema_docs/0.common.md) 第 124–130 行已经要求按主要组织与局部闭合判断，旧试写的“局部”标签不替代这项判断。

P2 的止点保持现有标准：已能有据说明主要机制、真实 root、所选代表及其他已识别知识的去处，没有悬置会动摇当前选择的重要疑点。可留给 P3/P5 的是正文所需的命名、精确展开和不改变已定机制的细节核实。若可用源码中的必要生产者、完成关系或接口仍未推清，应继续这项调查；不能把它改名为“待正文落实”。也不因还有未读行数就要求继续寻找新方案。

“采用 P2 选择”是作者的工作起点，不是 reviewer 的结论前提。当前草案或目录应保留选择所需的机制、理由和来源定位，让 reviewer 不靠旧批准或历史交接理解；历史材料只帮助找问题和追去向。P4/P5/P6 对完整身份的核实仍有必要，只是不再以阶段切换本身触发一轮新的方案竞选。

“依据不足”应按**当前能否作出判断**判定，不追究前一位实际读过多少代码。后续 reviewer 按职责读源码，已经能核实原选择，只是正文或证据定位漏写，便让相应作者补齐；不为补一次引文重开 P2。确实仍不清楚必要接口或关系、它又影响完整身份时，才要求具体补研究。P2 有历史批准既不能补足这项缺口，也不意味着所有此前判断一并失效。

共享 Contract 已知错误仍回 P1；真实任务或固定来源改变仍沿 Supervisor 手册的边界处理。本文不修改源实现缺陷、验收缺项和固定字段问题的现有分流。
