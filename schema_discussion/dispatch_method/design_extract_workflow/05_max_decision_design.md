# 第三轮 Design 决策

建议只替换 [DESIGN_SCHEMA.md](../../../DESIGN_SCHEMA.md) 第 1 节的任务起点段和第 5 节的多方案段。前者明确本轮集中形成 root，后者明确先判断并存价值、再投入其他完整方案。数学、调度、流水线的三层方法，以及现有推进、自检和回退条件均保留；common、模板、导航和字段无需修改。

[Planner 试读](03_medium_design.md)能够从给定任务与两个案例提出路线、比较主要成本、安排工作归属和后续文件，也能区分资料缺口与未完成设计。这支持“现有流程可以推进”，不证明其 FP32 在线路线、分块、split 数量、资源预算或两份代表已经成立。其有限推演没有完成逐层正文或验收，本轮不重做算法，也不将这些选择变成通用建议。第一轮 Design 的两处衔接建议可以采用，其解释无需全部移入正式页。

整条工作链的现有分工可以保留。§1 已说明如何从任务、workload、硬件条件和案例取得当前设计依据；§2 已要求以直接求值为参照，有限比较收益与代价后选择路线；§3–4 将工作和局部执行的成本带回上层。只需在起点点明 root，不另设候选调查阶段。为选择 root 提前比较其他路线仍属正常推导，不要求先实测 root 或让它覆盖整个 Contract。

多方案段需要把下一步说得更直接：root 的主要组织清楚后，判断已经发现的其他路线是否值得本次完整并存，再展开选定方案。参数、局部、组合和未完整展开的独立候选沿 [common](../../../schema_docs/0.common.md#选择条件与索引)各有去处，不增加记录格式。任务要求实现的范围在 §1 明确，交付时再对照各份设计的实际范围核对；不能由 root 身份或目录缺口说明代替这项核对。下层发现问题按 L7、L41、L49 返回最早受影响的决定，现有文字足够，不另加回退表。

Extract 的调整与普通 Design 可以兼容。支持 P2 独立审定机制与代表取舍、后续作者沿选择完成正文和目录；P4–P6 仍从当前内容和源码独立核实，具体问题修定义或返回受影响判断。它不要求普通 Planner 调查固定实现的全部主要机制、取得独立 P2 批准或保留每种来源行为。[Extract 试读](04_medium_extract.md)中的实例配对、激活差异和同步关系属于忠实调查，其外部验收缺项政策也不能变成新建设计的验收豁免。两条流程共用完整身份与记录判据，规则仍只由 [common](../../../schema_docs/0.common.md#派生节点与-dispatch)定义。

建议替换稿如下，链接按目标文件位于仓库根目录书写。

1. 替换 DESIGN §1 当前 L13，以“从任务说明明确优化目标”开头的整段：

```markdown
从任务说明明确优化目标、优先 workload、任务要求实现的范围和计量边界。先围绕主要 workload 逐层形成 root 的一套具体方案，不急于按 shape 拆节点；root 的定位见 [common](schema_docs/0.common.md#文件与共享-contract)，参数取值与输入工作量的区别见[差异规则](schema_docs/0.common.md#参数变化与结构变化)。按[模板说明](schema_template/README.md#2-创建文件或进入已有任务)创建或续写任务，保留给定 Contract，只登记本次设计的实际依据。
```

2. 替换 DESIGN §5 当前 L55，以“确有独特完整方案需要并存时”开头的整段：

```markdown
root 的主要计算、工作归属和协作关系清楚后，结合已经发现的候选，先判断是否需要其他完整方案并存。按 [common 的节点规则](schema_docs/0.common.md#派生节点与-dispatch)说明其独特价值和本次保留理由，再逐层完成选定方案；相同整区直接 `from`。其他参数取值、局部变化、已知组合和已研究但未完整展开的独立方案，按[目录规则](schema_docs/0.common.md#选择条件与索引)记录，当前各份 YAML 仍保持具体选择。各自承担范围按 `when` 规则写实，并核对本次交付是否满足任务要求的实现范围。
```

验收时检查以下几点即可：

- 普通 Planner 能从给定任务进入有限比较与 root 的三层推导，不需要先完成实验、全部候选正文或新增审批。
- 没有并存需要时可沿一份 root 完成交付；有需要时先说明完整价值，再展开，记录去处直接遵循 common。
- root 自身范围与任务交付范围没有混同；参数或目录记录不能补齐任务要求的完整设计。
- 原有资料缺项、数值自检和下层修上层的条件保持有效，未把 medium 的未验证选择写成推荐算法或验收事实。
- 修改仅涉及上述两个段落；原有导航锚点、common 语义与 Extract 的独立审阅边界不变。无新增字段 issue，F1/F2 保留原状态。
