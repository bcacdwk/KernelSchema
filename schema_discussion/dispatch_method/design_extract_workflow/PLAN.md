# 审定修改方案

主代理在两轮 max 评审与一轮 medium 角色推演后审定，现已完成实施。本轮只改 Design、Extract 的方法文字，保持现有字段、六阶段、角色分工与正式验收边界；实际结果见 [README](README.md)。

## 采用的结论

### Design

按 [第三轮 Design 意见](05_max_decision_design.md)只替换 `DESIGN_SCHEMA.md` 第 1、5 节的相关段落：

1. 明确任务目标、优先 workload、要求实现的范围和计量边界，集中逐层形成一份具体 root。
2. root 的主要计算、工作归属和协作关系清楚后，判断其他已发现方案是否具有独特完整价值且需要并存，再展开选定方案；其他变化沿 common 记录。

保留为选择 root 而进行的有限比较。先形成 root 不要求先实测或覆盖整个 Contract；既有三层推导、自检、资料边界与最早受影响层回退足够。普通 Planner 不增加 Extract 的固定源码调查或 P2 审批。

### Extract

采用 [第三轮 Extract 意见](06_max_decision_extract.md)的实质分工，正式稿压缩重复表述：

- P2 独立审定机制、真实 root、其他完整代表及已识别知识的去处。保留现有调查步骤与止点；不强制先选 root 再分类。
- P3/P5 按已选具体实例写完整正文。P4 将已定取舍落实为实际目录、对象定位与写作依赖。
- 后续 reviewer 仍独立核对当前有效全文、实际来源、使用上下文及保留依据。阶段切换不触发例行重新搜索和取舍。
- 机制分类或代表取舍的具体事实错误，或者影响取舍的必要关系仍无法核实，回 P2 修相关判断，再由 P4 落实受影响计划。已有源码中的误读也可纠正；指出具体关系及影响，不能只说理由不充分。
- 已确认机制的正文漏项先修正文；当前已能核实结论而只缺引文或定位时补记录。已定代表的登记和依赖安排在 P4 处理；本节点普通本地化按 P5 处理；P6 保留既有明确授权的限域修稿与集中记录职责。
- 不改变已定取舍或任务义务的已研究但未展开独立候选，按 common 记录；发现它不自动增加完整文件。

统一判断及返回原则集中在 REVIEW，阶段页说明自己的具体工作和写权限。保留 P5 现有返回表，不新增通用检查表、状态、回执字段、固定报告或审批。
