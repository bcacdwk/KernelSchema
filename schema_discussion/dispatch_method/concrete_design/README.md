# 具体设计与提取方法：落地结果

本轮已完成纯 Markdown/README 的规则与方法调整，并通过第四轮独立验收。八个新的 `gpt-6-astra`、`effort=max` 代理分四轮研究、审计、实施和验收；主代理审定方案、检查关键差异并汇总结果。没有尚需用户决定的规则分歧。

## 已落地的决定

- 每个算子的当前完整设计含 root 最多 10 份，在保留关键设计信息前提下越少越好；每份有独特价值，并固定一套具体配置与机制
- 不同配置的参数变化、局部改动、已有决定组合进入 `dispatch.md`；当前方案随输入产生的尺寸、工作量、尾块、空工作和必要算法/协议条件仍留在 YAML
- 相同完整区域直接 `from`，不同区域完整本地定义；不为共享造配置容器、片段库或没有独特价值的 provider
- 目录格式只在 common 定义：范围与完整设计表必需，变体有内容才出现；基线直接指当前完整 YAML，差额与条件只写一次，组合不层层充当新基线
- 候选发现可以多于十个；未选独立方案诚实说明未完整展开，不伪装参数、不产生隐藏的第十一份完整设计
- common 面向所有 schema 作者；提取的读码、识别、选型、阶段推进与验收方法放到 extract。原创设计不被要求伪造源码出处，目录笔记不自动产生完整 YAML 或额外审批义务

现行定义见 [common](../../../schema_docs/0.common.md#派生节点与-dispatch)，完整实施方案见 [PLAN](PLAN.md)。

## 六阶段如何配合

| 阶段 | 主要职责 |
| --- | --- |
| P1 | 建立共同 Contract，不提前批准 root Design |
| P2 | 根据实际机制线索作有界调查，再选择 root 和有限完整代表 |
| P3 | 完成一套具体 root，保留其真实输入行为与必要边界 |
| P4 | 整理目录与变体记录；未来文件和拟共享只作为明确计划 |
| P5 | 只写选中的非 root 完整设计，普通新事实与本节点共享调整在当前工作内审阅并汇集 |
| P6 | 新 reviewer 先审最终全部设计与记录，按需 worker 集中补写，再独立终审 |

改变集合、名额、未来依赖或其他设计成立前提时，提前回到对应阶段；普通本地化、换用已存在已审的相同整区不自动重走 P4。Worker/Reviewer 独立分工、有效全文审阅、Contract 权限及固定实现提取的硬件/GPU 边界保持。

方法导航：[EXTRACT_SCHEMA](../../../EXTRACT_SCHEMA.md)、[阶段页](../../../schema_extract/phases/02_dispatch_draft.md)、[REVIEW](../../../schema_extract/REVIEW.md)。Supervisor 的操作与冻结运行说明保留在[手册](../../../schema_extract/README.md)。

- 主代理的只读检查覆盖当前工作树 25 个修改或新增 Markdown（含前轮保留的修改）：436 个本地引用、44 个 YAML 片段通过检查
- `git diff --check` 通过；片段解析只证明语法，不替代 schema 语义或执行器验收
- 正式规则、提取方法与工具实际协议的适用范围已经分开；没有运行 extract、checker、绘图、GPU 或生产测试
- Python、starter、现有算子 YAML/PNG、运行状态和旧批准未改动；旧示例的 21 份及 FA4 prefill 的 11 份没有冒充迁移结果
