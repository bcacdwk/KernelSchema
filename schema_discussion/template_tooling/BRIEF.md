# Template 工具更新：范围与进度

## 当前目标

当前 DOC0–6、starter 与统一 `check_yaml.py` 已完成 [PLAN](PLAN.md) 的阶段 0–5。本次继续落实已经批准的[最新文本补充表](TEXT_RULES_PROPOSAL.md)，收齐名称、常见表达式与引用入口的形式和预算，并补齐工作调度的紧凑排版。具体交付与验证见 [IMPLEMENTATION](IMPLEMENTATION.md)。

阶段 6 的四案例整理单独延期。`schema_template/examples/` 全目录、schema/kernel wiki、Extract 执行器和运行状态不在本次修改范围。`text_limit_demo` 保留上轮满额快照及用户现场内容，本次不迁移、不重新填满，也不作为新规则验收输入。

## 已确认边界

- 最新补充表已批准实施，既有 `300/2` 保持；预算按字段位置和值分支选择，只在原允许类型中检查，不引入整动作、事件、Waiting 或外部定位符的兜底限额。
- 自取单名与真实类型/硬件身份分别分类；可解析的名称由工具检查，纯公式中的其余名称按约定审阅。真实外部名称和路径保留原形，依据原材料处理确实的超限。
- 数值文本拒绝空白、全标点和全运算符，保留原有 Unicode 数学、无穷、空集、切片与事件特殊记法。retention、引用和身份只承载各自语法内容。
- Mapping.Worker/Placement、Worktile_order、Preassigned、Refill 与 exit 按最新布局表执行。物理排版不改变逻辑换行、列表类型、顺序或值，必要 flow 引号保留。
- 格式器的严格保真、幂等、alias/merge 关系以及确定普通末句号清理保持；只读入口不写回。原权限、未变 mtime 和最终来源 hash 继续作为文件安全约束。
- 字符配置集中于工具，正式 DOC 只对齐名称分类、形式语义和必要示例，不在各章重复整张预算表，不新增字段、宏或通用表达式语言。
- 文件入口只核对已有上下文中能准确匹配 repo/ref 的本地路径；不配置新仓库、不扫描其他目录、不联网。入口语义不能可靠核对时交原件审阅，`validate_documents` 保持零 I/O。
- 只补有意义的关键回归。实施代理各跑相关模块，整合后统一跑一轮完整合成套件；新失败或实际修正再决定必要重跑。

## 实施分工

两位新的 max 代理分别负责文字预算/名称/形式规则，以及紧凑排版/正式说明/集成。双方直接协调共用接口与文件边界；主代理负责范围、分工与汇总，不代替独立代码审阅。

实施完成后由新的 xhigh 独立检查实际代码、文案和回归并作必要修正，尤其核对开放数学与真实名称的兼容、既定两行预算、源码定位边界及排版保真。
