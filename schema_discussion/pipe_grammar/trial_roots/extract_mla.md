- 实际入口是[固定源码](sources/extract_mla/solution.py)的 `Model.forward`（2082、2134–2150），`_PV_MODE=0`（80），经 `launch_impl`（1572）选择 `mla_fp8_kernel<0,3>` 或 `<0,4>`（2019–2024）。2007–2009 的 `2*WorkCount > 3*LaunchSMCount` 对应本稿 persistent 分流；同函数里的 bootstrap 和 FP16 路径不属于本 root。源码与 baseline 的 SHA-256 均匹配 manifest；源码字节由引用版本的输入锁核对，未把当前文件位置当成提交存在的证据。
- 完整保留 `w: worktile`、`t=[0,N(w))`、`n=flatten[w,t]`。`N(w)>0`，每份工作重置 M/D，环槽与通知编号不重置。末项直接用 `n[w,N(w)-1]`，不借用循环退出后的 `n`。所有角色的 `waits_for` 原样继承：域、动作签名、索引身份和依赖均无改动。局部 `n[w,t+1]` 不越过工作边界，`n+3` 与 `n+KVSlots` 则保留跨工作复用约束。
- 每个角色的工作序号相同，并不意味着角色锁步。源码的全局计数器分别前进，连续域对齐可引用事件；三槽分数／概率、两槽缩放及三／四槽键值环决定允许领先的距离。单槽查询的归还等待末次矩阵读取，单槽输出状态的归还等待修正角色读完；首份工作没有旧读者，初始信用仍由原契约提供。一次工作结束不会额外产生全角色栅栏。
- Softmax 非末项整组执行后，先发 `request:Next(w)`，再等待并读取末次 Scores；末次 Weights 后先 `produce:Final(w)`，再发布 P，最后 `wait:Next(w)` 消费描述符。请求与消费并非同一个等待。MMA 显列首 QK，随后本项 QK／前项 PV 交错，最后补末 PV；分段 QK 和四组 PV 留在既有动作内。
- Correction 依旧只修正非首项，随后按 prefix→release→tail 顺排。release 完成末 32 列读取即可归还 Y／Final 共享状态，尾部转换、写回和 LSE 可以继续；不能把释放点推到尾部存储后。tiny 与全一 scale 仍产生原有 P、PV、rescale 完成事件，未用条件删除空 payload 动作。
- Loader 首 Q 在初始化 join 前发出；后续 Q 在上一份末 QK 完成且 Next 已发布后发出，再 latch 本份几何。外层列表边界不排空异步矩阵或搬运。Queue 每份实工作都发布一次 Next；最后一次失败领取仍有发布完成事件及四方消费，不额外生成零 tile 工作。
- 未使用 `while`：运行时领取形成的工作序列已有上游 `worktile` 域，`for(w)` 遍历它；Queue 原子领取仍在原动作契约内。`bar_wait`（150–153）的底层轮询没有动作间反馈，不提升为 pipe 控制；这份迁移也不能代表已验证一般反馈循环。
